
Вот сравнение Elasticsearch, Cassandra и ClickHouse — трех популярных распределенных систем для работы с данными:

### **1. Elasticsearch**
**Назначение**:  
- Оптимизирован для полнотекстового поиска и анализа логов (ELK-стек)
- Использует инвертированные индексы для быстрого поиска

**Ключевые особенности**:
- **Документо-ориентированная** модель (JSON-документы)
- Поддержка сложных запросов: полнотекстовый поиск, фасетный поиск, гео-запросы
- **Near real-time** индексация (задержка ~1 сек)
- Горизонтальное масштабирование с шардированием и репликацией
- **Weak consistency** (AP-система в CAP)

**Использование**:
- Поиск на сайтах (как альтернатива Sphinx)
- Анализ логов (в связке с Logstash/Kibana)
- Поиск по товарам в e-commerce

**Ограничения**:
- Неэффективен для аналитических запросов с JOIN
- Сложности с транзакционностью

---

### **2. Apache Cassandra**
**Назначение**:  
- Колоночная NoSQL СУБД для записи интенсивных workloads
- Линейная масштабируемость и отказоустойчивость

**Ключевые особенности**:
- **Wide-column хранилище** (аналог Google Bigtable)
- **Masterless-архитектура** (все узлы равны)
- **Tunable consistency** (от eventual до strong)
- Оптимизирована для **высоких нагрузок на запись**
- Поддержка TTL и временных рядов

**Использование**:
- Хранение временных рядов (метрики, телеметрия)
- User profile stores (соцсети, банки)
- IoT-данные

**Ограничения**:
- Нет JOIN и сложных агрегаций
- Запросы только по PK (или с фильтрами по кластерным ключам)

---

### **3. ClickHouse**
**Назначение**:  
- Колоночная СУБД для аналитики в реальном времени (OLAP)
- Обрабатывает триллионы строк за секунды

**Ключевые особенности**:
- **Высокая скорость** аналитических запросов (векторизация)
- Эффективное **сжатие данных** (до 10x)
- Поддержка **SQL-синтаксиса** (с расширениями)
- Локальные **материализованные представления**
- Оптимизация под временные ряды

**Использование**:
- Аналитика в реальном времени (веб-аналитика, реклама)
- Хранение и обработка метрик (альтернатива Druid)
- Генерация отчетов по большим данным

**Ограничения**:
- Не предназначен для точечных запросов (по одному ключу)
- Нет транзакций (как в классических СУБД)

---

### **Сравнительная таблица**

| Характеристика       | Elasticsearch          | Cassandra              | ClickHouse            |
|----------------------|------------------------|------------------------|-----------------------|
| **Модель данных**    | Документо-ориентированная | Wide-column          | Колоночная           |
| **Оптимизация**      | Поиск                  | Запись                | Аналитика            |
| **Скорость записи**  | Средняя                | Очень высокая         | Высокая              |
| **Скорость чтения**  | Быстрый поиск          | Быстрый по PK         | Молниеносная аналитика |
| **Масштабируемость** | Горизонтальная         | Линейная              | Горизонтальная       |
| **CAP**              | AP                     | AP/CP (настраивается) | CP                   |
| **SQL**              | Limited (DSL queries)  | CQL (ограниченный)    | Полноценный ANSI SQL |

### **Когда что выбирать?**
- **Elasticsearch**: если нужен полнотекстовый поиск или анализ логов.
- **Cassandra**: для высоконагруженных запросов на запись с простым чтением по ключу.
- **ClickHouse**: когда требуется аналитика в реальном времени по большим данным.

Все три системы можно комбинировать в одной архитектуре (например, Cassandra для хранения сырых данных + ClickHouse для аналитики + Elasticsearch для поиска).
