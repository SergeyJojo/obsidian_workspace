## **1. Индексы: хардкорный уровень**

---

### **1.1. Индексы с опциями**

#### **1.1.1. Частичные индексы**

- Если нужно индексировать только подмножество данных:
    
    ```sql
    CREATE INDEX idx_partial_active_users
    ON users (last_login)
    WHERE status = 'active';
    ```
    
- Пример использования:
    
    ```sql
    SELECT * FROM users WHERE status = 'active' AND last_login > now() - interval '1 day';
    ```
    

---

#### **1.1.2. Функциональные индексы**

- Индексируйте вычисляемые значения:
    
    ```sql
    CREATE INDEX idx_lower_email ON users (LOWER(email));
    ```
    
- Пример:
    
    ```sql
    SELECT * FROM users WHERE LOWER(email) = 'example@gmail.com';
    ```
    

---

#### **1.1.3. Покрывающие индексы**

- Индексы, которые включают дополнительные колонки для оптимизации чтения:
    
    ```sql
    CREATE INDEX idx_covering_user_activity
    ON user_activity (user_id) INCLUDE (last_action, action_count);
    ```
    
- Ускоряет запросы:
    
    ```sql
    SELECT user_id, last_action, action_count
    FROM user_activity
    WHERE user_id = 123;
    ```
    

---

#### **1.1.4. Индексы для JSONB**

- Для поиска в массиве JSONB:
    
    ```sql
    CREATE INDEX idx_gin_json_tags ON posts USING gin (tags jsonb_path_ops);
    ```
    
- Пример запроса:
    
    ```sql
    SELECT * FROM posts WHERE tags @> '["postgres", "optimization"]';
    ```
    

---

### **1.2. Мониторинг индексов**

#### **Какие индексы используются:**

```sql
SELECT
    relname AS table_name,
    indexrelname AS index_name,
    idx_scan AS index_scans,
    idx_tup_read AS tuples_read,
    idx_tup_fetch AS tuples_fetched
FROM pg_stat_user_indexes
WHERE idx_scan > 0;
```

#### **Какие индексы не используются:**

```sql
SELECT
    relname AS table_name,
    indexrelname AS index_name
FROM pg_stat_user_indexes
WHERE idx_scan = 0;
```

---

### **1.3. Удаление мёртвых индексов**

- Если индекс больше не используется:
    
    ```sql
    DROP INDEX IF EXISTS idx_unused;
    ```

## **2. Агрегации: ускорение больших данных**

---

### **2.1. Агрегации с группировками**

#### **2.1.1. Группировка по выражениям**

- Группировка по временным интервалам:
    
    ```sql
    SELECT DATE_TRUNC('month', created_at) AS month, COUNT(*)
    FROM orders
    GROUP BY month
    ORDER BY month;
    ```
    

#### **2.1.2. Группировка в подзапросах**

- Эффективный способ уменьшить объем данных перед основной агрегацией:
    
    ```sql
    SELECT region, AVG(total)
    FROM (
        SELECT region, SUM(amount) AS total
        FROM sales
        GROUP BY region, sale_date
    ) subquery
    GROUP BY region;
    ```
    

---

### **2.2. Партицирование для агрегаций**

- Если таблица огромная, используйте партицирование:
    
    ```sql
    CREATE TABLE metrics (
        id SERIAL,
        metric_date DATE,
        value NUMERIC
    ) PARTITION BY RANGE (metric_date);
    
    CREATE TABLE metrics_2023 PARTITION OF metrics FOR VALUES FROM ('2023-01-01') TO ('2024-01-01');
    ```
    
- Ускоряет запросы:
    
    ```sql
    SELECT AVG(value)
    FROM metrics
    WHERE metric_date >= '2023-01-01';
    ```
    

---

### **2.3. Использование агрегатных индексов**

- Ускоряет поиск по предвычисленным значениям:
    
    ```sql
    CREATE MATERIALIZED VIEW sales_summary AS
    SELECT region, DATE_TRUNC('month', sale_date) AS month, SUM(amount) AS total
    FROM sales
    GROUP BY region, month;
    ```
    
- Обновление:
    
    ```sql
    REFRESH MATERIALIZED VIEW sales_summary;
    ```

## **3. JSONB и сложные структуры**

---

### **3.1. Динамические ключи**

- Поиск данных по ключу:
    
    ```sql
    SELECT jsonb_data ->> 'key' AS value
    FROM json_table
    WHERE jsonb_data -> 'nested_key' ->> 'subkey' = 'value';
    ```
    

---

### **3.2. Агрегация JSONB**

- Подсчёт вхождений:
    
    ```sql
    SELECT jsonb_column ->> 'category' AS category, COUNT(*)
    FROM jsonb_table
    GROUP BY category;
    ```
    
- Суммирование значений:
    
    ```sql
    SELECT SUM((jsonb_column ->> 'amount')::NUMERIC)
    FROM jsonb_table;
    ```
    

---

### **3.3. Индексация массивов JSONB**

- Если нужно проверить, содержит ли массив определённое значение:
    
    ```sql
    CREATE INDEX idx_jsonb_array ON json_table USING gin (jsonb_column);
    ```
    
- Пример:
    
    ```sql
    SELECT * FROM json_table WHERE jsonb_column @> '[123]';
    ```

## **4. Оптимизация шардирования и масштабирования**

---

### **4.1. Шардирование через `pg_shard`**

- Установка расширения:
    
    ```bash
    CREATE EXTENSION pg_shard;
    ```
    
- Распределение данных по шардам:
    
    ```sql
    SELECT master_create_distributed_table('users', 'user_id');
    SELECT master_create_worker_shard('users', 0, 'host1', 5432);
    SELECT master_create_worker_shard('users', 1, 'host2', 5432);
    ```
    

---

### **4.2. Citus: Распределённая база**

- Установка Citus:
    
    ```bash
    CREATE EXTENSION citus;
    ```
    
- Распределение данных:
    
    ```sql
    SELECT create_distributed_table('orders', 'customer_id');
    ```
    
- Запрос на всех шардах:
    
    ```sql
    SELECT COUNT(*) FROM orders;
    ```

## **5. Тюнинг PostgreSQL**

---

### **5.1. Конфигурация памяти**

1. **shared_buffers**:
    
    - Указывает, сколько памяти выделяется для кэширования данных.
    
    ```ini
    shared_buffers = 25% of total memory
    ```
    
2. **work_mem**:
    
    - Память на сортировку и агрегации:
    
    ```ini
    work_mem = 64MB
    ```
    
3. **maintenance_work_mem**:
    
    - Память для `VACUUM` и `CREATE INDEX`:
    
    ```ini
    maintenance_work_mem = 1GB
    ```
    

---

### **5.2. Тюнинг диска**

1. **wal_buffers**:
    
    - Размер буфера журнала WAL:
    
    ```ini
    wal_buffers = 16MB
    ```
    
2. **fsync**:
    
    - Гарантирует, что данные записаны на диск:
    
    ```ini
    fsync = on
    ```
    

---

### **5.3. Мониторинг производительности**

1. **Проверка текущих запросов**:
    
    ```sql
    SELECT * FROM pg_stat_activity WHERE state = 'active';
    ```
    
2. **Проверка блокировок**:
    
    ```sql
    SELECT * FROM pg_locks WHERE NOT granted;
    ```
    
3. **Проверка использования индексов**:
    
    ```sql
    SELECT
        relname AS table_name,
        idx_scan AS index_scans
    FROM pg_stat_user_indexes;
    ```
