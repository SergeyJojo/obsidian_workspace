### Разбор задач

1. **Задача с изменением строки в Go**: В Go строки неизменяемы (immutable), и вы не можете изменять отдельные символы строки напрямую, так как строка является просто последовательностью байтов, а не изменяемым массивом.
    
    Однако, вы можете преобразовать строку в массив байтов, изменить его и снова преобразовать в строку.
    
    Код:
    
    ```go
    package main
    
    import "fmt"
    
    func main() {
        s := "Hello world"
        // Преобразование строки в массив байтов ([]byte)
        bytes := []byte(s)
        // Изменение первого символа на "h"
        bytes[0] = 'h'
        // Преобразование массива байтов обратно в строку
        s = string(bytes)
        fmt.Println(s)
    }
    ```
    
    В этом коде:
    
    - Строка преобразуется в массив байтов, так как строки неизменяемы в Go.
    - Мы меняем первый символ массива байтов.
    - Затем снова преобразуем байты в строку и выводим результат.
2. **Задача с каналом (channel)**: Каналы в Go — это способ обмена данными между горутинами. В вашем примере канал используется для передачи данных с проверкой состояния канала.
    
    Код:
    
    ```go
    package main
    
    import "fmt"
    
    func main() {
        ch := make(chan int, 5)
        for i := 0; i <= 4; i++ {
            ch <- i
        }
        close(ch)
    
        for true {
            if val, ok := <-ch; ok {
                fmt.Println(val)
            } else {
                break
            }
        }
    }
    ```
    
    В этом коде:
    
    - Мы создаём канал `ch` с буфером на 5 элементов.
    - Заполняем канал числами от 0 до 4.
    - После этого канал закрывается с помощью `close(ch)`, и мы начинаем извлекать данные из канала с использованием цикла `for`.
    - `ok` возвращает `false`, когда канал закрыт и больше нет данных для чтения.
3. **Задача с использованием `defer`**: В Go ключевое слово `defer` откладывает выполнение функции до того момента, когда текущая функция завершит своё выполнение. В вашем примере используется `defer` для вывода значений.
    
    Код:
    
    ```go
    package main
    
    import "fmt"
    
    func main() {
        func() {
            defer fmt.Println(1)
        }()
        defer fmt.Println(2)
    }
    ```
    
    В этом коде:
    
    - Внутренняя функция вызывает `defer fmt.Println(1)`, которая откладывает вывод `1`.
    - Основная функция вызывает `defer fmt.Println(2)`, откладывая вывод `2`.
    - При завершении выполнения функции сначала будет вызван `fmt.Println(2)`, а затем `fmt.Println(1)`, так как отложенные вызовы выполняются в обратном порядке.
4. **Задача с запросом SQL**: В SQL задаче вам нужно получить **последние проценты для каждого пункта выдачи (pickpoint_id)**. Для этого используется конструкция **`DISTINCT ON`**.
    
    Пример SQL запроса:
    
    ```sql
    SELECT DISTINCT ON (pickpoint_id) * 
    FROM pickpoint_tariff
    ORDER BY pickpoint_id, created DESC;
    ```
    
    Объяснение:
    
    - `DISTINCT ON (pickpoint_id)` позволяет выбрать уникальные строки по полю `pickpoint_id`, где для каждой группы будет выбран первый элемент.
    - `ORDER BY pickpoint_id, created DESC` гарантирует, что для каждого `pickpoint_id` будет выбран последний (по времени) тариф, так как сортировка происходит по полю `created` в порядке убывания.
    - Этот запрос вернёт последние (по времени) значения процентов для каждого пункта выдачи.
    
    Если вы хотите вывести проценты для всех пунктов выдачи, это будет именно тот запрос, который вам нужен.

Вот красиво отформатированный код, с дополнительными комментариями, улучшением структуры и соблюдением стандартов Go:

```go
package main

import "errors"

// Интерфейс для работы с хранилищем изображений
type ImagesStorage interface {
	// В случае успеха возвращает уникальный внутренний id изображения.
	// Если загрузка не удалась из-за некорректного URL, возвращается ошибка ErrInvalidURL.
	UploadImage(url string) (string, error)

	// Получение сохранённой картинки по id (не требуется в данной задаче).
	GetImage(id string) ([]byte, error)
}

// Ошибка для некорректного URL
var ErrInvalidURL = errors.New("invalid url")

// Интерфейс для работы с вспомогательной базой данных (проверка и сохранение URL)
type ImageDatabase interface {
	// Проверка, был ли уже загружен URL
	GetImageID(url string) (string, bool)

	// Сохранение нового изображения в базе данных
	SaveImage(url string, id string) error
}

// Структура менеджера обработки запросов
type Manager struct {
	storage     ImagesStorage  // Сервис для хранения изображений
	imageDB     ImageDatabase  // Вспомогательная база данных для проверки URL
}

// Метод для обработки HTTP-запроса на загрузку изображения по URL
func (m *Manager) ProcessImageUpload(url string) (string, error) {
	// Шаг 1: Проверяем, если URL уже существует в базе данных
	if id, found := m.imageDB.GetImageID(url); found {
		// Если картинка уже есть, возвращаем существующий id
		return id, nil
	}

	// Шаг 2: Загружаем изображение в хранилище
	id, err := m.storage.UploadImage(url)
	if err != nil {
		// Если ошибка из-за некорректного URL
		if errors.Is(err, ErrInvalidURL) {
			return "", err // Возвращаем ошибку 400 (bad request)
		}
		// Другие ошибки (например, внутренние ошибки хранилища) — 500 (internal server error)
		return "", errors.New("500 internal server error: " + err.Error())
	}

	// Шаг 3: Сохраняем информацию о загруженном URL в базе данных
	err = m.imageDB.SaveImage(url, id)
	if err != nil {
		// Если произошла ошибка при сохранении в базу, возвращаем ошибку конфликта
		return "", errors.New("409 conflict: " + err.Error())
	}

	// Возвращаем ID нового изображения
	return id, nil
}
```

### Объяснение изменений и структуры:

1. **`ImagesStorage`** — интерфейс для работы с хранилищем изображений:
    
    - Метод `UploadImage(url string)` пытается загрузить изображение и возвращает уникальный `id` или ошибку, если URL некорректен.
    - Метод `GetImage(id string)` позволяет получить изображение по ID (но в данной задаче не используется).
2. **`ErrInvalidURL`** — это ошибка, которая возвращается, если URL некорректен.
    
3. **`ImageDatabase`** — интерфейс для работы с базой данных:
    
    - Метод `GetImageID(url string)` проверяет, существует ли уже загруженный URL в базе данных.
    - Метод `SaveImage(url string, id string)` сохраняет новый URL и его внутренний ID в базе данных.
4. **`Manager`** — это структура, которая будет обрабатывать запросы:
    
    - Метод `ProcessImageUpload(url string)` сначала проверяет базу данных, существует ли уже изображение с таким URL. Если изображение найдено, возвращает его ID.
    - Если изображение не найдено, метод вызывает хранилище для загрузки изображения и сохранения его ID в базе данных.
5. **Обработка ошибок**:
    
    - Если URL некорректен (ошибка `ErrInvalidURL`), метод возвращает ошибку с кодом `400 (Bad Request)`.
    - Если при сохранении в базу данных возникает ошибка (например, из-за конфликта), возвращается ошибка с кодом `409 (Conflict)`.
    - В случае других ошибок (например, проблемы с хранилищем) возвращается ошибка с кодом `500 (Internal Server Error)`.

Для реализации требуемого функционала с обработкой HTTP-запросов и взаимодействием с хранилищем изображений, нам нужно создать интерфейс для работы с вспомогательной базой данных, которая будет отслеживать, были ли уже загружены изображения с данным URL. Мы будем использовать этот интерфейс для предотвращения повторной загрузки одного и того же изображения.

### Основные шаги реализации:

1. **Создание интерфейса для вспомогательной базы данных**:
    
    - Мы создадим интерфейс, который будет отвечать за проверку наличия URL в базе данных и получение ID изображения.
2. **Менеджер, который будет использовать интерфейсы**:
    
    - Менеджер будет сначала проверять, есть ли уже изображение с таким URL в базе данных.
    - Если оно есть, возвращать существующий ID.
    - Если изображения нет, он будет пытаться загрузить его в хранилище и сохранять результат в базу данных.
3. **Обработка ошибок**:
    
    - Мы будем возвращать разные коды ошибок в зависимости от ситуации:
        - `400` — если URL некорректен.
        - `409` — если происходит конфликт параллельных запросов.
        - `500` — если происходит ошибка на сервере.

### Реализация:

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

var ErrInvalidURL = errors.New("invalid url")
var ErrConflict = errors.New("conflict: another request is processing the same URL")

// Интерфейс хранилища изображений
type ImagesStorage interface {
	UploadImage(url string) (string, error)
	GetImage(id string) ([]byte, error)
}

// Интерфейс базы данных для отслеживания загруженных изображений
type ImageDatabase interface {
	// Проверка, есть ли уже изображение с таким URL
	GetImageID(url string) (string, bool)

	// Сохранение нового изображения в базу данных
	SaveImage(url string, id string) error
}

// Структура менеджера
type Manager struct {
	storage     ImagesStorage
	imageDB     ImageDatabase
	mu          sync.Mutex // для защиты от конфликтов при параллельных запросах
}

func (m *Manager) ProcessImageUpload(url string) (string, error) {
	// Шаг 1: Проверка, если URL уже есть в базе
	m.mu.Lock()
	defer m.mu.Unlock()

	if id, found := m.imageDB.GetImageID(url); found {
		// Если картинка уже есть в базе, возвращаем существующий ID
		return id, nil
	}

	// Шаг 2: Загружаем картинку в хранилище
	id, err := m.storage.UploadImage(url)
	if err != nil {
		if errors.Is(err, ErrInvalidURL) {
			return "", fmt.Errorf("400 bad request: %w", err)
		}
		// Другие ошибки хранилища считаем ошибками сервера
		return "", fmt.Errorf("500 internal server error: %w", err)
	}

	// Шаг 3: Сохраняем URL и ID изображения в базе данных
	err = m.imageDB.SaveImage(url, id)
	if err != nil {
		// Если произошла ошибка при сохранении в базу, возвращаем ошибку конфликта
		return "", fmt.Errorf("409 conflict: %w", ErrConflict)
	}

	// Возвращаем ID изображения
	return id, nil
}

// Реализация для хранилища изображений (фейковое хранилище для примера)
type FakeStorage struct{}

func (fs *FakeStorage) UploadImage(url string) (string, error) {

	if url == "invalid-url" {
		return "", ErrInvalidURL
	}
	return fmt.Sprintf("image-id-for-%s", url), nil
}

func (fs *FakeStorage) GetImage(id string) ([]byte, error) {
	return nil, nil
}

// Реализация для базы данных изображений (фейковая база данных)
type FakeDatabase struct {
	mu     sync.Mutex
	images map[string]string // URL -> ID
}

func NewFakeDatabase() *FakeDatabase {
	return &FakeDatabase{
		images: make(map[string]string),
	}
}

func (db *FakeDatabase) GetImageID(url string) (string, bool) {
	db.mu.Lock()
	defer db.mu.Unlock()

	id, found := db.images[url]
	return id, found
}

func (db *FakeDatabase) SaveImage(url string, id string) error {
	db.mu.Lock()
	defer db.mu.Unlock()

	// Если уже есть изображение с таким URL, то возвращаем ошибку конфликта
	if _, found := db.images[url]; found {
		return ErrConflict
	}

	db.images[url] = id
	return nil
}

func main() {
	// Создание экземпляров для хранилища и базы данных
	storage := &FakeStorage{}
	imageDB := NewFakeDatabase()

	// Создание менеджера
	manager := &Manager{
		storage: storage,
		imageDB: imageDB,
	}

	// Пример запросов
	urls := []string{
		"valid-url-1",
		"valid-url-2",
		"valid-url-1", // Повторный запрос
		"invalid-url",  // Некорректный URL
	}

	for _, url := range urls {
		id, err := manager.ProcessImageUpload(url)
		if err != nil {
			fmt.Printf("Error processing URL %s: %v\n", url, err)
		} else {
			fmt.Printf("Successfully uploaded URL %s with ID %s\n", url, id)
		}
	}
}
```

### Пояснение:

1. **`Manager`** — это основной менеджер, который обрабатывает запросы на загрузку изображений.
    
    - Он сначала проверяет в базе данных, был ли уже загружен данный URL.
    - Если URL найден, возвращает существующий ID.
    - Если URL не найден, пытается загрузить изображение в хранилище, затем сохраняет его в базе данных и возвращает ID.
2. **`ImagesStorage`** — это интерфейс для взаимодействия с хранилищем изображений, который включает метод для загрузки изображений и получения их по ID.
    
3. **`ImageDatabase`** — это интерфейс для работы с базой данных, который предоставляет методы для получения ID изображения по URL и сохранения изображения в базе данных.
    
4. **Обработка ошибок**:
    
    - Если URL некорректен (например, неправильный формат), возвращается ошибка `400 Bad Request`.
    - Если возникает конфликт (например, два параллельных запроса на один и тот же URL), возвращается ошибка `409 Conflict`.
    - В случае других ошибок на сервере (например, при загрузке изображения), возвращается ошибка `500 Internal Server Error`.
5. **Фейковая реализация `FakeStorage` и `FakeDatabase`**:
    
    - В этом примере хранилище и база данных реализованы с помощью простых структур с картами, которые симулируют поведение реального хранилища и базы данных.
