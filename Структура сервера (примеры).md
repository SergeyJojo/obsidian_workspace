Для написания сервера на Go, придерживаясь современных практик и лучших практик архитектуры, можно создать структуру, которая разделяет логические компоненты, улучшает тестируемость, удобство масштабирования и поддержку. Давайте разберем простую, но продвинутую структуру сервера с пояснениями.

### Структура проекта

Предположим, что мы строим HTTP-сервер с RESTful API. Структура проекта будет выглядеть следующим образом:

```
/myapp
├── cmd
│   └── server
│       └── main.go         # Точка входа в приложение
├── internal
│   ├── handler
│   │   └── handler.go      # Логика обработки HTTP запросов
│   ├── service
│   │   └── service.go      # Логика бизнес-правил
│   ├── repository
│   │   └── repository.go   # Логика работы с базой данных
│   └── model
│       └── model.go        # Определения данных и структуры
├── pkg
│   └── utils
│       └── logger.go       # Утилиты, например, логирование
├── go.mod                  # Модуль
└── go.sum                  # Суммы зависимостей
```

### Основные компоненты:

1. **cmd/server/main.go** — это точка входа в приложение. Здесь мы инициализируем сервер, роутинг и запускаем приложение.
    
2. **internal** — это основная логика приложения, которая делится на несколько слоев:
    
    - **handler** — обработчики HTTP-запросов.
        
    - **service** — бизнес-логика и взаимодействие с репозиториями.
        
    - **repository** — работа с базой данных или другим хранилищем данных.
        
    - **model** — модели данных (например, структуры).
        
3. **pkg/utils** — утилиты, например, для логирования, валидации и т. д. (используется повторно в разных частях приложения).
    

### Реализация

#### main.go (cmd/server/main.go)

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"time"

	"myapp/internal/handler"
	"myapp/internal/service"
	"myapp/internal/repository"
	"myapp/pkg/utils"
)

func main() {
	// Инициализация логгера
	logger := utils.NewLogger()

	// Инициализация репозитория, сервисов и обработчиков
	repo := repository.NewRepository()
	svc := service.NewService(repo)
	h := handler.NewHandler(svc)

	// Инициализация маршрутов
	mux := http.NewServeMux()
	h.RegisterRoutes(mux)

	// Запуск сервера
	server := &http.Server{
		Addr:         ":8080", // Порт для сервера
		Handler:      mux,
		ReadTimeout:  10 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	fmt.Println("Сервер запущен на порту 8080")
	if err := server.ListenAndServe(); err != nil {
		logger.Fatal("Ошибка при запуске сервера: ", err)
	}
}
```

##### Пояснения:

- **`mux := http.NewServeMux()`** — это маршрутизатор, который будет управлять входящими HTTP-запросами.
    
- **`h.RegisterRoutes(mux)`** — регистрация маршрутов с соответствующими обработчиками.
    
- **`server := &http.Server{}`** — создание HTTP-сервера с тайм-аутами для чтения и записи.
    

#### handler.go (internal/handler/handler.go)

```go
package handler

import (
	"fmt"
	"net/http"

	"myapp/internal/service"
)

// Handler структуру для обработки запросов
type Handler struct {
	service *service.Service
}

// NewHandler создаёт новый обработчик
func NewHandler(svc *service.Service) *Handler {
	return &Handler{service: svc}
}

// RegisterRoutes регистрирует маршруты для API
func (h *Handler) RegisterRoutes(mux *http.ServeMux) {
	mux.HandleFunc("/api/v1/resource", h.ResourceHandler)
}

// ResourceHandler обрабатывает запросы к /api/v1/resource
func (h *Handler) ResourceHandler(w http.ResponseWriter, r *http.Request) {
	switch r.Method {
	case http.MethodGet:
		h.handleGet(w, r)
	case http.MethodPost:
		h.handlePost(w, r)
	default:
		http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
	}
}

func (h *Handler) handleGet(w http.ResponseWriter, r *http.Request) {
	// Логика обработки GET запроса
	data, err := h.service.GetResourceData()
	if err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}
	w.WriteHeader(http.StatusOK)
	fmt.Fprintf(w, "Data: %v", data)
}

func (h *Handler) handlePost(w http.ResponseWriter, r *http.Request) {
	// Логика обработки POST запроса
	if err := h.service.CreateResource(); err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}
	w.WriteHeader(http.StatusCreated)
}
```

##### Пояснения:

- **Handler** — это структура, которая инкапсулирует логику обработки HTTP-запросов.
    
- Методы обработчиков (например, **`handleGet`**) извлекают данные через сервис и отправляют ответы.
    
- Регистрация маршрутов происходит через **`RegisterRoutes`**.
    

#### service.go (internal/service/service.go)

```go
package service

import (
	"fmt"
	"myapp/internal/repository"
)

// Service предоставляет бизнес-логику
type Service struct {
	repo *repository.Repository
}

// NewService создаёт новый сервис
func NewService(repo *repository.Repository) *Service {
	return &Service{repo: repo}
}

// GetResourceData возвращает данные ресурса
func (s *Service) GetResourceData() (string, error) {
	// Логика работы с репозиторием
	return s.repo.FetchData()
}

// CreateResource создаёт новый ресурс
func (s *Service) CreateResource() error {
	// Логика создания ресурса
	return s.repo.SaveData()
}
```

##### Пояснения:

- **Service** — это слой бизнес-логики. Он управляет взаимодействием с репозиториями.
    
- В методах, таких как **`GetResourceData`**, вызываются методы репозитория, но сервис инкапсулирует логику приложения.
    

#### repository.go (internal/repository/repository.go)

```go
package repository

import (
	"fmt"
)

// Repository предоставляет доступ к данным
type Repository struct{}

// NewRepository создаёт новый репозиторий
func NewRepository() *Repository {
	return &Repository{}
}

// FetchData получает данные из базы данных
func (r *Repository) FetchData() (string, error) {
	// Пример возвращаемых данных
	return "Resource Data", nil
}

// SaveData сохраняет данные в базу данных
func (r *Repository) SaveData() error {
	// Пример сохранения данных
	fmt.Println("Данные сохранены")
	return nil
}
```

##### Пояснения:

- **Repository** — это слой доступа к данным (например, базы данных). В реальном приложении здесь будут запросы к базе данных, кешу и т. д.
    
- В **`FetchData`** и **`SaveData`** выполняются операции с данными.
    

#### logger.go (pkg/utils/logger.go)

```go
package utils

import (
	"log"
	"os"
)

// NewLogger создаёт новый логгер
func NewLogger() *log.Logger {
	return log.New(os.Stdout, "INFO: ", log.Ldate|log.Ltime|log.Lshortfile)
}
```

##### Пояснения:

- Логгер создается с использованием стандартного пакета **log**.
    
- В этом файле также могут быть утилиты для обработки ошибок, валидации данных и других задач.
    

### Преимущества текущей структуры:

1. **Модульность**: Каждый слой приложения разделен на логические компоненты.
    
2. **Тестируемость**: Логика обработки HTTP-запросов, бизнес-логика и работа с данными отделены друг от друга, что облегчает юнит-тестирование.
    
3. **Чистота кода**: Каждый компонент имеет четко определенные обязанности (например, обработка запросов в обработчиках, бизнес-логика в сервисах и т. д.).
    
4. **Масштабируемость**: Легко добавлять новые маршруты, бизнес-логику или модули для работы с данными без изменений в других частях приложения.
    

### Заключение:

Эта структура является одной из современных подходов для создания серверов на Go. Она позволяет соблюдать принципы SOLID, упрощает тестирование и поддержку, а также повышает масштабируемость проекта.
