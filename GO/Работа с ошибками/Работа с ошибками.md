
# **Полный гайд по работе с ошибками в Go**

Ошибки в Go — это не исключения, а обычные значения, которые явно возвращаются из функций. Такой подход делает код предсказуемым, но требует аккуратной обработки. Разберём всё: от базовых принципов до продвинутых практик.

---

## **1. Базовый подход: возврат ошибок**
В Go ошибки — это значения, реализующие интерфейс `error`:
```go
type error interface {
    Error() string
}
```

### **Пример простой ошибки**
```go
func Divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("деление на ноль")
    }
    return a / b, nil
}

// Использование
result, err := Divide(10, 0)
if err != nil {
    log.Printf("Ошибка: %v", err)
}
```

---

## **2. Типы ошибок и их сравнение**
### **Стандартные ошибки**
Используйте `errors.New` или `fmt.Errorf`:
```go
var ErrNotFound = errors.New("ресурс не найден")

func fetchData() error {
    return ErrNotFound
}

// Сравнение
if err == ErrNotFound {
    // Обработка
}
```

### **Ошибки с контекстом**
Добавляйте дополнительную информацию:
```go
if err != nil {
    return fmt.Errorf("не удалось загрузить конфиг: %w", err)
}
```

---

## **3. Обёртки ошибок (`%w`) и `errors.Is`/`errors.As`**
### **Заворачивание ошибок**
```go
if err := db.Query(); err != nil {
    return fmt.Errorf("db query failed: %w", err)
}
```

### **Проверка типа ошибки**
```go
// errors.Is — для сравнения
if errors.Is(err, sql.ErrNoRows) {
    // Обработка
}

// errors.As — для приведения типа
var timeoutErr *net.OpError
if errors.As(err, &timeoutErr) {
    fmt.Println("Timeout:", timeoutErr)
}
```

---

## **4. Кастомные ошибки**
Создавайте свои типы для сложных сценариев:
```go
type APIError struct {
    StatusCode int
    Message    string
}

func (e *APIError) Error() string {
    return fmt.Sprintf("API error: %d - %s", e.StatusCode, e.Message)
}

// Использование
func FetchAPI() error {
    return &APIError{StatusCode: 404, Message: "Not Found"}
}

// Проверка
err := FetchAPI()
if apiErr, ok := err.(*APIError); ok {
    fmt.Println("Status:", apiErr.StatusCode)
}
```

## **5. Паника (`panic`) и восстановление (`recover`)**
### **Когда использовать `panic`**
Только для критических ошибок (например, инициализация приложения):
```go
if config == nil {
    panic("конфиг не загружен")
}
```

### **Перехват паники**
```go
func SafeCall() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Recovered:", r)
        }
    }()
    panic("что-то пошло не так")
}
```

---

## **6. Логирование ошибок**
Используйте структурированные логи (например, через `slog` в Go 1.21+):
```go
import "log/slog"

func main() {
    err := DoSomething()
    if err != nil {
        slog.Error("Ошибка выполнения", "err", err, "time", time.Now())
    }
}
```

## **7. Практические советы**
1. **Документируйте ошибки** в godoc:
   ```go
   // GetUser возвращает пользователя или ошибки:
   //   - ErrNotFound если пользователь не существует
   //   - ErrTimeout если сервер не ответил
   func GetUser(id string) (*User, error)
   ```

2. **Тестируйте ошибки**:
   ```go
   func TestDivide(t *testing.T) {
       _, err := Divide(1, 0)
       if !errors.Is(err, ErrDivisionByZero) {
           t.Fatal("ожидалась ошибка деления на ноль")
       }
   }
   ```

3. **Избегайте паники** в библиотеках — это нарушает контракт.

4. **Используйте `errors.Join`** (Go 1.20+) для объединения ошибок:
   ```go
   err := errors.Join(
       fmt.Errorf("ошибка 1"),
       fmt.Errorf("ошибка 2"),
   )
   ```

## **8. Полезные пакеты**
- `github.com/pkg/errors` — улучшенные обёртки и стектрейсы.
- `golang.org/x/xerrors` — аналоги `fmt.Errorf` с поддержкой `%w`.
- `go.uber.org/multierr` — для агрегации множества ошибок.

## **Пример: обработка ошибок в HTTP-сервере**
```go
func handleRequest(w http.ResponseWriter, r *http.Request) {
    data, err := fetchData()
    if err != nil {
        if errors.Is(err, ErrNotFound) {
            http.Error(w, "Not Found", http.StatusNotFound)
            return
        }
        slog.Error("fetch failed", "err", err)
        http.Error(w, "Internal Error", http.StatusInternalServerError)
        return
    }
    fmt.Fprint(w, data)
}
```

---

## **Итог**
- Ошибки в Go — это **значения**, а не исключения.
- Используйте **обёртки (`%w`)** и **`errors.Is`/`errors.As`**.
- **Кастомные ошибки** помогают передавать контекст.
- **`panic`** — только для невосстановимых ситуаций.
- **Логируйте** ошибки структурированно.

Такой подход сделает ваш код надёжным и удобным для отладки.
