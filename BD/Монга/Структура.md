
MongoDB — это документо-ориентированная NoSQL-база данных, которая хранит данные в гибком JSON-подобном формате (BSON). Вот как она устроена внутри:

---

### **1. Основные компоненты**
#### **A. Документы (Documents)**
- **Единица хранения**: Аналог строки в SQL, но в формате BSON (бинарный JSON).
- Пример:
  ```json
  {
    "_id": ObjectId("5f8d8d8e8d8e8d8e8d8e8d8e"),
    "name": "Alice",
    "age": 25,
    "address": {
      "city": "New York",
      "zip": "10001"
    }
  }
  ```
  - `_id` — уникальный идентификатор (генерируется автоматически).

#### **B. Коллекции (Collections)**
- **Группа документов**: Аналог таблицы в SQL, но без строгой схемы.
- Документы в коллекции могут иметь разную структуру.

#### **C. Базы данных (Databases)**
- Содержат коллекции. Один экземпляр MongoDB может обслуживать несколько БД.

---

### **2. Физическое хранение**
#### **A. Файлы данных**
- **WiredTiger Storage Engine** (по умолчанию с MongoDB 3.2+):
  - Хранит данные в сжатом виде (snappy, zlib).
  - Использует B-деревья для индексов.
  - Поддерживает журналирование (write-ahead log, WAL) для восстановления после сбоев.
- **Файлы на диске**:
  - `.wt` — данные и индексы.
  - `journal/` — журнал операций.

#### **B. Распределённое хранение**
- **Chunks** (в шардированных кластерах): Данные делятся на "куски" (по 64 МБ), распределённые по шардам.
- **Replica Sets**: Данные реплицируются на несколько узлов (первичный + вторичные).

---

### **3. Индексы**
- **B-деревья**: Для быстрого поиска (аналогично SQL).
- **Типы индексов**:
  - Простые (`{ name: 1 }`).
  - Составные (`{ name: 1, age: -1 }`).
  - Уникальные, TTL, Geospatial, Text Search.
- **Пример создания**:
  ```javascript
  db.users.createIndex({ email: 1 }, { unique: true });
  ```

---

### **4. Оптимизация запросов**
#### **A. Query Planner**
- Анализирует запрос и выбирает оптимальный план (использование индекса или collection scan).
- Можно посмотреть через `explain()`:
  ```javascript
  db.users.find({ age: { $gt: 20 } }).explain("executionStats");
  ```

#### **B. Aggregation Pipeline**
- Обработка данных через последовательность этапов (`$match`, `$group`, `$sort`):
  ```javascript
  db.orders.aggregate([
    { $match: { status: "completed" } },
    { $group: { _id: "$customer_id", total: { $sum: "$amount" } } }
  ]);
  ```

---

### **5. Журналирование (Journaling)**
- **Write-ahead log (WAL)**: Операции сначала записываются в журнал, затем в данные.
- **Цель**: Устойчивость к сбоям. При перезапуске MongoDB восстанавливается из журнала.

---

### **6. Шардирование (Sharding)**
- **Горизонтальное масштабирование**: Данные распределяются по серверам (шардам).
- **Компоненты**:
  - **Config Servers**: Хранят метаданные о распределении данных.
  - **Mongos**: Маршрутизатор запросов.
  - **Shards**: Серверы с данными (реплика-сеты).

---

### **7. Пример работы запроса**
1. Клиент отправляет запрос (например, `find({ age: 25 })`).
2. **Mongos** (если шардировано) определяет, какой шард обрабатывать.
3. **Query Planner** выбирает: использовать индекс или сканировать коллекцию.
4. **Storage Engine** (WiredTiger) ищет данные в памяти/на диске.
5. Результат возвращается клиенту.

---

### **8. Отличия от SQL**
| **Аспект**       | **MongoDB**              | **SQL (MySQL, PostgreSQL)** |
|------------------|--------------------------|-----------------------------|
| **Схема**        | Гибкая (schemaless)      | Жёсткая (schema)            |
| **JOIN**         | `$lookup` (редко)        | `JOIN` (оптимизированы)     |
| **Масштабирование** | Горизонтальное (шарды) | Вертикальное                |
| **Транзакции**   | Поддерживаются (с 4.0+)  | Полная поддержка            |

---

### **9. Когда использовать MongoDB?**
- **Подходит**:
  - Гибкие/изменчивые схемы (например, контент-менеджеры).
  - Большие объёмы неструктурированных данных.
  - Быстрорастущие проекты (легко масштабируется).
- **Не подходит**:
  - Сложные транзакции (как в банковских системах).
  - Строгие JOIN между сущностями.

---

### **10. Полезные команды**
- **Просмотр коллекций**:
  ```javascript
  show collections;
  ```
- **Статистика по коллекции**:
  ```javascript
  db.users.stats();
  ```
- **Удаление индекса**:
  ```javascript
  db.users.dropIndex("email_1");
  ```

MongoDB сочетает гибкость JSON с мощью распределённых систем, но требует правильного проектирования индексов и шардинга для эффективной работы.
