## ⚙️ Opcode и Zend Engine

### 1. Что такое Zend Engine

**Zend Engine** — это «сердце» PHP.  
Он отвечает за:

- Парсинг и компиляцию PHP-кода в **опкоды (opcode)**.
    
- Выполнение этих опкодов в **виртуальной машине (VM)**.
    
- Управление памятью, переменными, GC, обработку исключений и др.
    

🔹 **Исторически**

- PHP 4 → Zend Engine 1
    
- PHP 5 → Zend Engine 2 (ввел ООП, исключения, типизацию)
    
- PHP 7 → Zend Engine 3 (полная переработка под производительность и memory model)
    
- PHP 8 → улучшенный JIT + оптимизации VM
    

---

### 2. Как работает интерпретатор PHP

1. **Парсер (Lexer + Parser)**  
    Разбивает PHP-код на токены (лексемы), строит **AST** (Abstract Syntax Tree).
    
2. **Компилятор (Compiler)**  
    Превращает AST в **opcode array** — последовательность инструкций для Zend VM.
    
3. **Интерпретатор (Executor)**  
    Последовательно выполняет опкоды с помощью **виртуальной машины Zend Engine**.
    

---

### 3. Пример работы на практике

Код:

```php
<?php
$a = 2;
$b = 3;
$c = $a + $b;
echo $c;
```

Можно посмотреть с помощью:

```bash
php -dvld.active=1 -dvld.execute=0 script.php
```

Вывод (примерно):

```
line     # *  op                           operands
-----------------------------------------------------
   2     0  ASSIGN                        $a, 2
   3     1  ASSIGN                        $b, 3
   4     2  ADD                           $a, $b, $c
   5     3  ECHO                          $c
   5     4  RETURN                        1
```

🧩 Это и есть **опкоды** — низкоуровневые инструкции для Zend VM.  
Каждая операция вроде `+`, `echo`, `if` компилируется в конкретный набор опкодов.

---

### 4. Почему PHP не "чистый интерпретатор"

PHP компилирует код в **байткод (opcodes)**, а потом выполняет его —  
поэтому это **интерпретируемый язык с компиляцией в байткод**, аналогично Python и Java (JVM).

---

### 5. Кэширование опкодов

Чтобы не компилировать код при каждом запросе, используется **OPcache**:

- Кэширует скомпилированные опкоды в shared memory.
    
- Ускоряет запуск PHP-скриптов в разы.
    
- Используется по умолчанию в PHP 7+.
    

Настройки (`php.ini`):

```ini
opcache.enable=1
opcache.memory_consumption=128
opcache.validate_timestamps=1
```

---

### 6. Zend VM

Zend VM — стековая виртуальная машина:

- Все вычисления ведутся через **операндный стек**.
    
- Есть три регистра: `op1`, `op2`, `result`.
    
- Каждая инструкция (`opcode`) манипулирует значениями на стеке.
    

---

### 7. Влияние на производительность

- PHP 7 ввел **compact zval structure**, уменьшив потребление памяти.
    
- Операции типа `$a + $b` стали в 2–3 раза быстрее.
    
- PHP 8 добавил **JIT** — Just-In-Time компиляцию части байткода в машинный код.
    

---

### 8. Что такое JIT (PHP 8+)

**JIT (Just-In-Time Compiler)**:

- Компилирует часто выполняемые опкоды в **машинный код** на лету.
    
- Ускоряет CPU-интенсивные задачи (парсинг, математику, графику).
    
- На веб-нагрузке эффект ограничен (больше выигрыша в CLI-скриптах).
    

Настройки JIT:

```ini
opcache.jit=1235
opcache.jit_buffer_size=64M
```

    ```bash
    pecl install vld

    ```
    
- **opcache-control.php** — просмотр состояния OPcache.
    
- **phpdbg** — отладчик на уровне байткода:
    
    ```bash
    phpdbg -qrr script.php
    ```
    

---

### 10. Связь с ZVAL и памятью

Каждая переменная в PHP представлена структурой **zval** (тип + значение + refcount).  
Zend Engine управляет памятью через **reference counting** и **GC**.  
Это важно, потому что каждый `opcode` работает с `zval` внутри VM.

---

### 11. Краткий итог

|Этап|Компонент|Назначение|
|---|---|---|
|Лексинг и парсинг|Zend Parser|Преобразует код в AST|
|Компиляция|Compiler|Генерирует opcode array|
|Исполнение|Zend VM|Выполняет опкоды|
|Оптимизация|OPcache / JIT|Кэширует или компилирует в машинный код|
