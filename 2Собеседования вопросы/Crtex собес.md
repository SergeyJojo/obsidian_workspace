
### Задача 1: Параллельный расчет квадратов чисел с использованием канала

Ваш код выполняет параллельный расчет квадратов чисел с использованием горутин и канала. Задача корректно решена, но есть несколько улучшений и разъяснений:

- В текущей реализации горутины отправляют в канал квадраты чисел.
- После того как все горутины завершены, канал закрывается.
- Главная горутина суммирует все значения из канала.

Код выглядит корректно и не требует изменений. Вот результат работы программы:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	ch := make(chan int)
	wg := &sync.WaitGroup{}
	wg.Add(3)

	for i := 0; i < 3; i++ {
		go func(v int) {
			defer wg.Done()
			ch <- v * v // Отправка квадрата числа в канал
		}(i)
	}

	go func() {
		wg.Wait()
		close(ch) // Закрываем канал после завершения всех горутин
	}()

	var sum int
	for v := range ch { // Суммируем значения из канала
		sum += v
	}

	fmt.Printf("result: %d\n", sum) // Вывод результата
}
```

### Задача 2: Ошибка с использованием `&m["1"]`

Вторая задача вызывает ошибку компиляции, потому что в Go нельзя получить указатель на значение, хранящееся в мапе напрямую. Мапа сама управляет памятью, и Go не позволяет безопасно получать указатели на значения мапы.

Вот исправленный вариант:

```go
package main

import "fmt"

func main() {
	m := make(map[string]int)
	m["1"] = 0 // Используем оператор `=` для присваивания значения

	// Печатаем значение элемента по ключу "1"
	fmt.Printf("%v", m["1"]) // Вывод значения, а не указателя
}
```

### Задача 3: Ниль-значение и сравнение интерфейсов

В вашем примере рассматривается сравнение двух переменных типа интерфейс, которые равны `nil`, но это разные виды `nil`. Одно значение является `nil` интерфейсом, а другое — `nil` указателем. В Go два `nil` могут означать разные вещи: один может быть `nil` указателем, а другой — `nil` интерфейсом. Эти два `nil` будут различны при сравнении.

Вот пример:

```go
package main

import "fmt"

type impl struct{}

type I interface {
	C()
}

func (*impl) C() {}

func A() I {
	return nil
}

func B() I {
	var ret *impl
	return ret
}

func main() {
	a := A()
	b := B()
	fmt.Println(a == b) // Вернет false, так как nil интерфейс и nil указатель разные
}
```

### Задача 4: Использование `defer`

В этом примере показывается, как работают отложенные вызовы в Go с использованием `defer`. Важно помнить, что отложенные вызовы выполняются **в обратном порядке** после завершения функции. Ваша программа вызывает `defer` в следующем порядке:

1. `defer fmt.Println("call 1 ", a+10)` (печатает 20, так как `a++` еще не выполнен).
2. `defer func() { fmt.Println("call 0 ", a+10) }()` (печатает 21, так как `a++` выполнится перед этим).
3. `fmt.Println("call 2 ", a)` (печатает 11, так как `a++` был вызван перед этой строкой).

Вот пример:

```go
package main

import (
	"fmt"
)

func main() {
	a := 10
	defer func() { fmt.Println("call 0 ", a+10) }() // 21
	defer fmt.Println("call 1 ", a+10)              // 20
	a++
	fmt.Println("call 2 ", a) // 11
}
```

**Результат вывода:**

```
call 2  11
call 1  20
call 0  21
```
