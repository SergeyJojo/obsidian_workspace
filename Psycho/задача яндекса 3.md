## 📝 Задача 2. Pipe: Producer → Consumer

Нужно передать данные из некоторого источника (**Producer**) в потребителя (**Consumer**).

Источник отдаёт данные **небольшими пачками** (~ десятки записей),  
а потребитель оптимальнее работает с **крупными батчами** (~ тысячи записей).

Пример: поставка данных из очередей типа Kafka в базу ClickHouse.

### Источник

- Условно бесконечный.
    
- Никогда не возвращает более `MaxItems` за один вызов `Next`.
    
- В рамках одной "сессии" (`Pipe`) источник каждый раз возвращает новые данные.
    
- После перезапуска источник начинает с прошлой подтверждённой позиции (`cookie`).
    
- Каждое значение `cookie`, которое вернул `Next`, после сохранения в приёмник должно быть зафиксировано вызовом `Commit`, строго в том порядке, в котором их вернул `Next`.
    

### Приёмник

- Не может обработать более `MaxItems` за один раз.
    

### Базовый уровень

Реализовать функцию:

```go
func Pipe(p Producer, c Consumer) error
```

Которая:

1. Читает данные из источника.
    
2. Группирует их в буфер (размер ≤ `MaxItems`).
    
3. Сохраняет в приёмник.
    
4. Фиксирует прогресс в источнике (`Commit`).
    

### Усложнение

- Методы `Next`, `Process` и `Commit` связаны с сетевыми вызовами и могут работать долго.
    
- Для ускорения нужно **распараллелить** чтение, запись и подтверждение прогресса.
    
- То есть, во время `Process` или `Commit` должно продолжаться чтение из источника и формирование нового буфера.

# ✅ Задача 1. RateLimiter

Для ограничения RPS лучше всего подходит алгоритм **Token Bucket** или **Sliding Window**.  
Я возьму **Token Bucket**, т.к. он проще и используется в реальных системах (Nginx, Envoy, Istio).

### Реализация

```go
package ratelimiter

import (
	"sync"
	"time"
)

type RateLimiter struct {
	rps         int           // лимит запросов в секунду
	interval    time.Duration // шаг пополнения токенов
	tokens      int           // текущее количество токенов
	lastRefill  time.Time     // время последнего пополнения
	mu          sync.Mutex    // защита от гонок
	maxCapacity int           // максимальное число токенов
}

func NewRateLimiter(rps int) *RateLimiter {
	if rps <= 0 {
		panic("rps must be > 0")
	}
	return &RateLimiter{
		rps:         rps,
		interval:    time.Second / time.Duration(rps),
		tokens:      rps,
		lastRefill:  time.Now(),
		maxCapacity: rps,
	}
}

// Allow возвращает true, если запрос можно пропустить
func (rl *RateLimiter) Allow() bool {
	rl.mu.Lock()
	defer rl.mu.Unlock()

	now := time.Now()
	elapsed := now.Sub(rl.lastRefill)

	// пополняем токены
	newTokens := int(elapsed / rl.interval)
	if newTokens > 0 {
		rl.tokens += newTokens
		if rl.tokens > rl.maxCapacity {
			rl.tokens = rl.maxCapacity
		}
		rl.lastRefill = now
	}

	// если есть токен — пропускаем
	if rl.tokens > 0 {
		rl.tokens--
		return true
	}
	return false
}
```

### Тесты

```go
package ratelimiter

import (
	"testing"
	"time"
)

func TestRateLimiterBasic(t *testing.T) {
	rl := NewRateLimiter(5) // 5 RPS

	// первые 5 должны пройти
	for i := 0; i < 5; i++ {
		if !rl.Allow() {
			t.Fatalf("request %d should be allowed", i)
		}
	}

	// следующий сразу же должен быть отклонён
	if rl.Allow() {
		t.Fatal("6th request should be blocked")
	}

	// ждём 1 секунду, токены восстановятся
	time.Sleep(time.Second)
	if !rl.Allow() {
		t.Fatal("request after 1s should be allowed")
	}
}
```

# ✅ Задача 2. Pipe (Producer → Consumer)

Тут важна архитектура: мы должны **читать, обрабатывать и коммитить параллельно**.  
Для этого можно использовать **pipeline с горутинами** + **каналы**.

### Реализация

```go
package pipe

import (
	"fmt"
	"sync"
)

const MaxItems = 9999

type Producer interface {
	Next() (items []any, cookie int, err error)
	Commit(cookie int) error
}

type Consumer interface {
	Process(items []any) error
}

func Pipe(p Producer, c Consumer) error {
	itemsCh := make(chan struct {
		items  []any
		cookie int
	}, 10)

	var wg sync.WaitGroup
	errCh := make(chan error, 1)

	// Чтение из Producer
	wg.Add(1)
	go func() {
		defer wg.Done()
		for {
			items, cookie, err := p.Next()
			if err != nil {
				if err.Error() == "EOF" {
					close(itemsCh)
					return
				}
				errCh <- fmt.Errorf("next error: %w", err)
				return
			}
			if len(items) == 0 {
				continue
			}
			itemsCh <- struct {
				items  []any
				cookie int
			}{items, cookie}
		}
	}()

	// Обработка Consumer + Commit
	wg.Add(1)
	go func() {
		defer wg.Done()
		for batch := range itemsCh {
			if err := c.Process(batch.items); err != nil {
				errCh <- fmt.Errorf("process error: %w", err)
				return
			}
			if err := p.Commit(batch.cookie); err != nil {
				errCh <- fmt.Errorf("commit error: %w", err)
				return
			}
		}
	}()

	// Ожидание завершения
	done := make(chan struct{})
	go func() {
		wg.Wait()
		close(done)
	}()

	select {
	case err := <-errCh:
		return err
	case <-done:
		return nil
	}
}
```

### Простейший тест

```go
package pipe

import (
	"errors"
	"testing"
)

type mockProducer struct {
	data   [][]any
	cookie int
	index  int
}

func (m *mockProducer) Next() ([]any, int, error) {
	if m.index >= len(m.data) {
		return nil, 0, errors.New("EOF")
	}
	batch := m.data[m.index]
	m.index++
	m.cookie++
	return batch, m.cookie, nil
}

func (m *mockProducer) Commit(cookie int) error {
	return nil
}

type mockConsumer struct {
	processed [][]any
}

func (m *mockConsumer) Process(items []any) error {
	m.processed = append(m.processed, items)
	return nil
}

func TestPipe(t *testing.T) {
	p := &mockProducer{
		data: [][]any{
			{"a", "b"},
			{"c"},
		},
	}
	c := &mockConsumer{}

	err := Pipe(p, c)
	if err != nil {
		t.Fatalf("unexpected error: %v", err)
	}

	if len(c.processed) != 2 {
		t.Fatalf("expected 2 batches, got %d", len(c.processed))
	}
}
```
