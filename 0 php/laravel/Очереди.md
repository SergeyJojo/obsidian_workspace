# 🧵 Работа с очередями в Laravel

---

## 1️⃣ Зачем нужны очереди

Очереди позволяют **вынести тяжёлые или не критичные по времени задачи** из основного запроса —  
чтобы **ускорить отклик** приложения и **распараллелить** обработку.

📦 Примеры:

- Отправка email после регистрации
    
- Генерация отчётов
    
- Индексация данных в поисковом движке
    
- Сложные API-запросы
    
- Обработка видео или изображений
    

---

## 2️⃣ Основные компоненты

Laravel реализует **единую абстракцию** для разных драйверов очередей:

|Компонент|Назначение|
|---|---|
|**Job**|Класс задачи, которую нужно выполнить|
|**Queue**|Хранилище задач (например Redis, Database, SQS)|
|**Worker**|Процесс, который обрабатывает очередь|
|**Dispatcher**|Отправляет задачи в очередь (`dispatch()`)|
|**Failed Jobs**|Лог неудачных задач|

---

## 3️⃣ Поддерживаемые драйверы очередей

|Драйвер|Характеристика|
|---|---|
|`sync`|Синхронное выполнение (для dev/test)|
|`database`|Очередь хранится в таблице БД|
|`redis`|Быстрая, предпочтительная для продакшена|
|`beanstalkd`|Оптимизированный брокер очередей|
|`sqs`|Amazon Simple Queue Service|
|`null`|Игнорирует все задачи (используется для тестов)|

Настройка в `config/queue.php`:

```php
'default' => env('QUEUE_CONNECTION', 'redis'),
```

## 4️⃣ Создание и использование Job

### Создать задачу:

```bash
php artisan make:job SendWelcomeEmail
```

Создаст файл `app/Jobs/SendWelcomeEmail.php`.

---

### Пример класса Job:

```php
<?php

namespace App\Jobs;

use App\Mail\WelcomeMail;
use Illuminate\Support\Facades\Mail;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;

class SendWelcomeEmail implements ShouldQueue
{
    use InteractsWithQueue, SerializesModels;

    public $user;

    public function __construct($user)
    {
        $this->user = $user;
    }

    public function handle()
    {
        Mail::to($this->user->email)->send(new WelcomeMail($this->user));
    }
}
```

🧩 Ключевое:  
Интерфейс `ShouldQueue` говорит Laravel — _"эту задачу не выполняй сразу, отправь в очередь."_

---

### Отправка задачи в очередь

```php
dispatch(new SendWelcomeEmail($user));
```

или сокращённо:

```php
SendWelcomeEmail::dispatch($user);
```

Можно указать задержку:

```php
SendWelcomeEmail::dispatch($user)->delay(now()->addMinutes(10));
```

## 5️⃣ Обработка очередей (Worker)

Запуск воркера:

```bash
php artisan queue:work
```

📌 Он будет слушать очередь и выполнять задачи по мере поступления.

Режимы:

```bash
php artisan queue:work --queue=emails
php artisan queue:work --sleep=3 --tries=5
```

Если ты обновляешь код — безопасно перезапусти воркер:

```bash
php artisan queue:restart
```

---

## 6️⃣ Работа с фейлами (Failed Jobs)

Laravel сохраняет задачи, которые упали с ошибкой.

Создание таблицы:

```bash
php artisan queue:failed-table
php artisan migrate
```

Просмотр неудачных задач:

```bash
php artisan queue:failed
```

Повторный запуск:

```bash
php artisan queue:retry all
```

Очистка:

```bash
php artisan queue:flush
```

---

## 7️⃣ Очередь в базе данных

Создать таблицу для хранения задач:

```bash
php artisan queue:table
php artisan migrate
```

`.env`:

```env
QUEUE_CONNECTION=database
```

Laravel будет писать задачи в таблицу `jobs`, а `queue:work` их обрабатывать.

---

## 8️⃣ Очередь в Redis (производственный вариант)

`.env`:

```env
QUEUE_CONNECTION=redis
```

Запуск Redis:

```bash
redis-server
```

Laravel хранит задачи в ключах Redis, а worker читает их в реальном времени.

---

## 9️⃣ Horizon — мониторинг очередей

**Horizon** — инструмент от Laravel для управления Redis-очередями:

- Веб-интерфейс мониторинга (`/horizon`)
    
- Контроль приоритета и кол-ва воркеров
    
- Балансировка нагрузки
    

Установка:

```bash
composer require laravel/horizon
php artisan horizon:install
php artisan migrate
```

Запуск:

```bash
php artisan horizon
```

В продакшене:

```bash
php artisan horizon:pause
php artisan horizon:continue
php artisan horizon:terminate
```

## 🔁 10️⃣ Повторные попытки и таймауты

В классе Job можно задать:

```php
public $tries = 5;         // число попыток
public $timeout = 60;      // секунд до таймаута
```

Если задача не завершилась — она попадёт в таблицу `failed_jobs`.

---

## 11️⃣ Цепочки задач (Chaining)

Можно выстраивать последовательность задач:

```php
Bus::chain([
    new ProcessVideo($video),
    new GenerateThumbnail($video),
    new NotifyUser($video),
])->dispatch();
```

Laravel гарантирует порядок выполнения — если одна упала, остальные не выполняются.

---

## 12️⃣ Batch-задачи

Группировка задач с мониторингом состояния:

```php
use Illuminate\Bus\Batch;
use Illuminate\Support\Facades\Bus;

$batch = Bus::batch([
    new ImportUsers,
    new ImportOrders,
])->then(function (Batch $batch) {
    // всё успешно
})->catch(function (Batch $batch, Throwable $e) {
    // ошибка
})->dispatch();
```

---

## 13️⃣ Очереди и транзакции

Задачи можно **отправлять только после успешной транзакции**:

```php
SendInvoice::dispatchAfterResponse($invoice);
```

или:

```php
SendInvoice::dispatch()->afterCommit();
```

---

## 14️⃣ Очереди и события (Events + Listeners)

Слушатель можно сделать асинхронным:

```php
class SendWelcomeEmail implements ShouldQueue
```

Laravel сам отправит listener в очередь.

## 15️⃣ Очистка и мониторинг

|Команда|Назначение|
|---|---|
|`php artisan queue:work`|Запуск воркера|
|`php artisan queue:listen`|Перезапуск воркера при изменениях|
|`php artisan queue:restart`|Мягкая перезагрузка|
|`php artisan queue:failed`|Список ошибок|
|`php artisan queue:flush`|Очистка failed jobs|
|`php artisan horizon`|Мониторинг Redis-очередей|

## 16️⃣ Типовые проблемы на собеседованиях

|Вопрос|Суть ответа|
|---|---|
|Как Laravel определяет, что задача должна идти в очередь?|Интерфейс `ShouldQueue`|
|Что делает `queue:restart`?|Отправляет сигнал воркерам безопасно перезапуститься|
|Как обрабатывать failed jobs?|Через `queue:failed-table` и `queue:retry`|
|Что лучше для продакшена — database или redis?|Redis (скорость, atomic pop/push, Horizon)|
|Как задать задержку или приоритет?|`$delay`, `$queue`|
|Что делает `dispatchAfterResponse()`?|Отправляет задачу после ответа клиенту|

## ✅ Итог

|Понятие|Назначение|
|---|---|
|`Job`|Описание задачи|
|`Queue`|Очередь задач (Redis, DB, SQS)|
|`Worker`|Обработчик|
|`Horizon`|Мониторинг и контроль|
|`Failed Jobs`|Отслеживание сбоев|
|`Bus::chain`, `Bus::batch`|Комплексные задачи|
|`dispatch()`|Отправка в очередь|
|`queue:work`|Основной воркер|
