
Давайте разберём всё про JWT (JSON Web Token): как он передаётся, что в нём хранится, шифруется ли, насколько сложно его взломать и можно ли передавать в нём логин и пароль. Я постараюсь объяснить всё максимально понятно и с примерами.

---

Что такое JWT?

JWT — это компактный токен в формате JSON, который используется для передачи данных между сторонами (например, клиентом и сервером). Он состоит из трёх частей, разделённых точками (.):

1. Header (заголовок): Описывает тип токена и алгоритм подписи.
    
2. Payload (полезная нагрузка): Содержит данные (claims), которые передаются.
    
3. Signature (подпись): Подтверждает целостность и подлинность токена.
    

Пример JWT:

```text
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

---

Как передаётся JWT?

JWT обычно передаётся в HTTP-заголовке Authorization с префиксом Bearer. Это стандартный способ для аутентификации в REST API.

Пример запроса:

```text
GET /api/users HTTP/1.1
Host: example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

- Альтернативы:
    
    - В теле запроса (например, в POST-запросе как {"token": "..."}).
        
    - В cookies (реже, из-за уязвимостей вроде CSRF).
        
- Где хранится на клиенте: Обычно в localStorage, sessionStorage или cookies браузера.
    

---

Что хранится в JWT?

JWT содержит данные в формате JSON в разделе Payload. Эти данные называются claims (утверждения). Есть три типа claims:

1. Зарегистрированные (Registered Claims):
    
    - iss (issuer): Кто выдал токен (например, "example.com").
        
    - sub (subject): Кому выдан (например, ID пользователя "12345").
        
    - exp (expiration): Время истечения (например, Unix timestamp 1698765432).
        
    - iat (issued at): Время выпуска.
        
    - aud (audience): Для кого предназначен.
        
2. Публичные (Public Claims): Определённые сообществом (например, name, email).
    
3. Приватные (Private Claims): Пользовательские данные, специфичные для приложения.
    

Пример Payload:

json

```json
{
  "sub": "1234567890",
  "name": "John Doe",
  "role": "admin",
  "iat": 1516239022,
  "exp": 1516242622
}
```

- Что можно хранить: Любые данные, но они должны быть компактными (JWT не предназначен для больших объёмов).
    

---

Шифруется ли JWT?

- Нет, JWT не шифруется, а подписывается.
    
    - Header и Payload кодируются в Base64URL (это не шифрование, а просто преобразование в строку).
        
    - Любой может декодировать их и прочитать содержимое (например, на jwt.io).
        
- Signature:
    
    - Создаётся с использованием секретного ключа (для HMAC, например, HS256) или пары ключей (для RSA, например, RS256).
        
    - Подпись гарантирует, что токен не подделан, но не скрывает данные.
        

Пример:

- Исходный Payload: {"sub": "123", "name": "John"}.
    
- Base64URL: eyJzdWIiOiIxMjMiLCJuYW1lIjoiSm9obiJ9.
    
- Подпись: HMAC-SHA256(Base64(Header) + "." + Base64(Payload), secret).
    
- Шифрованный JWT (JWE):
    
    - Существует отдельный стандарт JWE (JSON Web Encryption) для шифрования, но он редко используется в обычных сценариях аутентификации.
        

---

Сложно ли взломать JWT?

"Взлом" JWT зависит от того, что вы подразумеваете: подделку, кражу или чтение данных.

1. Чтение данных:
    
    - Сложность: Ноль. Любой может декодировать Base64 и увидеть Payload.
        
    - Защита: Не храните чувствительные данные (например, пароли) в JWT.
        
2. Подделка токена:
    
    - Сложность: Зависит от алгоритма и ключа:
        
        - HS256 (HMAC): Нужен секретный ключ. Если он слабый (короткий, угадываемый) или утёк — токен легко подделать.
            
        - RS256 (RSA): Требуется приватный ключ, который хранится на сервере. Взломать сложно, если ключ не скомпрометирован.
            
    - Уязвимости:
        
        - "Alg=None": Если сервер принимает токены без подписи ("alg": "none"), это дыра в безопасности.
            
        - Слабый секрет: Короткие ключи можно подобрать brute force.
            
    - Защита: Используйте длинные ключи (256 бит+), проверяйте алгоритм на сервере.
        
3. Кража токена:
    
    - Сложность: Средняя. Если токен украден (например, через XSS в браузере), злоумышленник может использовать его до истечения срока действия.
        
    - Защита:
        
        - Храните токен в HttpOnly cookies, а не в localStorage.
            
        - Установите короткий срок жизни (exp) и используйте refresh tokens.
            

---

Может ли передаваться логин и пароль в JWT?

- Технически да, но это плохая идея:
    
    - JWT не шифруется, и любой, кто перехватит токен, сможет декодировать логин и пароль.
        
    - Пример опасного Payload:
        
        json
        
        ```json
        {
          "username": "john",
          "password": "secret123",
          "exp": 1516242622
        }
        ```
        
    - Это нарушает принципы безопасности: пароли должны храниться в хэшированном виде на сервере, а не передаваться в токенах.
        
- Правильный подход:
    
    - JWT используется после аутентификации:
        
        1. Пользователь вводит логин и пароль в форму.
            
        2. Сервер проверяет их (например, через хэш в базе).
            
        3. Сервер выдаёт JWT с безопасными данными (например, sub, role).
            
    - Логин и пароль передаются только один раз в защищённом запросе (HTTPS POST), а не в токене.

Пример создания и проверки JWT в Go

Используем библиотеку github.com/golang-jwt/jwt/v5:

go

```go
package main

import (
    "fmt"
    "time"
    "github.com/golang-jwt/jwt/v5"
)

func main() {
    // Создание JWT
    secret := []byte("my-super-secret-key")
    token := jwt.NewWithClaims(jwt.SigningMethodHS256, jwt.MapClaims{
        "sub":  "12345",
        "name": "John Doe",
        "exp":  time.Now().Add(time.Hour).Unix(),
    })
    tokenString, err := token.SignedString(secret)
    if err != nil {
        panic(err)
    }
    fmt.Println("JWT:", tokenString)

    // Проверка JWT
    parsedToken, err := jwt.Parse(tokenString, func(token *jwt.Token) (interface{}, error) {
        return secret, nil
    })
    if err != nil {
        panic(err)
    }
    if claims, ok := parsedToken.Claims.(jwt.MapClaims); ok && parsedToken.Valid {
        fmt.Println("User ID:", claims["sub"])
        fmt.Println("Name:", claims["name"])
    }
}
```

---

Итог

1. Как передаётся: В заголовке Authorization: Bearer <token>.
    
2. Что хранится: Claims (ID, роли, время жизни), закодированные в Base64URL.
    
3. Шифруется ли: Нет, только подписывается. Для шифрования нужен JWE.
    
4. Сложно ли взломать: Зависит от ключа и защиты от кражи. Подделать сложно с сильным ключом, украсть проще через XSS.
    
5. Логин и пароль: Передавать можно, но не нужно — это небезопасно.
