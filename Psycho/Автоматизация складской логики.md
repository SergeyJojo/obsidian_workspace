## ⚙️ **Кейс: автоматизация ребалансировки ячеек на складе**

Разработчику ставится задача:  
📌 "Распознавать перегруженные зоны/ячейки, предлагать перемещения, строить маршруты и формировать задания".

---

## 🔽 1. **Распознаёт дисбаланс**

### Что это значит?

Некоторые ячейки перегружены (по количеству или по частоте доступа), другие — недозагружены или неэффективны.

### Что делает разработчик:

- **Собирает данные**:
    
    - Остатки по SKU в ячейках (`inventory`)
        
    - Частота доступа к SKU (из заказов за N дней)
        
    - Физическая нагрузка (по весу/объёму)
        
- **Реализует алгоритм/правила**:
    
    ```go
    if cell.CapacityUsed > 90% && sku.PickFrequency > threshold {
        markAsOverloaded(cell)
    }
    ```
    
- **Хранит агрегаты** в кэше или таблице `cell_stats`:
    
    - `cell_id`, `used_volume`, `sku_count`, `picking_rate`, `turnover_time`
        

---

## 🔽 2. **Предлагает перенести часть товаров**

### Что это значит?

Нужно найти, куда лучше переместить часть товаров, чтобы:

- **разгрузить ячейку**
    
- **оптимизировать маршрут сборки** (горячее — ближе)
    
- **учесть зону температур, габариты и пр.**
    

### Что делает разработчик:

- Создаёт сервис/функцию "slotting planner":
    
    - Ищет подходящие ячейки по правилам:
        
        ```sql
        SELECT * FROM cells
        WHERE available_volume >= sku.volume
          AND zone = 'hot_zone'
          AND sku_compatible = TRUE
        ORDER BY proximity_to_start
        LIMIT 1;
        ```
        
- Предлагает переместить часть или весь товар:
    
    ```json
    {
      "from_cell": "A15-3",
      "to_cell": "B02-1",
      "sku": "SKU12345",
      "quantity": 50
    }
    ```
    

---

## 🔽 3. **Строит маршрут и создаёт задания**

### Что это значит?

Нужно, чтобы **кладовщик или робот** знал:

- куда идти
    
- что взять
    
- откуда и куда переместить
    

### Что делает разработчик:

- **Генерирует задание на перемещение**:
    
    ```json
    {
      "task_type": "relocation",
      "worker_id": null,
      "sku": "SKU12345",
      "from": "A15-3",
      "to": "B02-1",
      "quantity": 50,
      "priority": "medium"
    }
    ```
    
- **Регистрирует маршрут**:
    
    - С помощью `graph-based` маршрутизатора (A* или Dijkstra)
        
    - Учитывает расстояния, этажи, лифты, блокировки
        
- **Создаёт запись в таблице `tasks`** и публикует в очередь (например, Kafka или RabbitMQ) → далее задание попадает на ТСД (терминал сбора данных) кладовщика или робота.

## 🧪 Что важно продумать разработчику:

|Вопрос|Что надо учесть|
|---|---|
|Как часто запускать анализ?|Каждые 30 минут, 2 раза в день, по cron, при триггерах|
|Что если в целевой ячейке уже товар?|Нужно учитывать совместимость SKU, габариты и лимиты|
|Кто исполняет перемещение?|Кладовщик, робот, механизм автопогрузки?|
|Как избежать конфликтов?|Транзакции, блокировки, очередь задач|
|Как откатить задание?|Если не удалось — статус `FAILED`, возврат на исходную ячейку|

## 📦 Технологии, которые могут быть задействованы:

- **БД**: PostgreSQL (таблицы `cells`, `inventory`, `sku_stats`, `tasks`)
    
- **Язык**: Go / Java / Python
    
- **Очереди**: Kafka / RabbitMQ
    
- **ТСД**: Android-приложение с REST API
    
- **Маршрутизатор**: своя имплементация A*, либо graph-библиотека
