
Вот **исходный код функции `joinChannels`**, **исправленный и отформатированный с комментариями**, включая защиту от захвата переменной цикла (`ch`):

---

### ✅ Исправленный исходный код `joinChannels`:

```go
package main

import (
    "fmt"
    "sync"
)

// Функция joinChannels объединяет несколько каналов типа int в один общий канал.
// Она принимает любое количество каналов и возвращает канал, из которого можно читать все значения.
func joinChannels(channels ...chan int) chan int {
    // Создаем канал, в который будем писать все значения из входных каналов.
    merged := make(chan int)

    // Используем sync.WaitGroup, чтобы дождаться завершения всех горутин.
    var wg sync.WaitGroup

    // Проходим по каждому входному каналу.
    for _, ch := range channels {
        // Увеличиваем счетчик ожидания.
        wg.Add(1)

        // Запускаем горутину для чтения из канала.
        go func(ch chan int) {
            // Когда горутина завершит работу — уменьшаем счетчик ожидания.
            defer wg.Done()

            // Читаем все значения из канала.
            for val := range ch {
                merged <- val
            }
        }(ch) // Обязательно передаём ch в аргументы замыкания!
    }

    // Отдельная горутина закрывает merged после завершения всех горутин.
    go func() {
        wg.Wait()     // Ждём, пока все горутины завершат чтение.
        close(merged) // Закрываем объединённый канал.
    }()

    // Возвращаем объединённый канал.
    return merged
}
```

### 🧪 Пример использования:

```go
func main() {
    ch1 := make(chan int)
    ch2 := make(chan int)

    // Заполняем первый канал
    go func() {
        defer close(ch1)
        for i := 0; i < 3; i++ {
            ch1 <- i
        }
    }()

    // Заполняем второй канал
    go func() {
        defer close(ch2)
        for i := 10; i < 13; i++ {
            ch2 <- i
        }
    }()

    // Объединяем каналы
    merged := joinChannels(ch1, ch2)

    // Читаем из объединенного канала
    for val := range merged {
        fmt.Println(val)
    }
}
```

### 🔧 Обновлённый, ускоренный и оптимизированный код:

```go
package main

import (
    "fmt"
    "io"
    "net/http"
    "sync"
    "time"
)

// Повторно используемый HTTP-клиент
var client = &http.Client{
    Timeout: 5 * time.Second,
}

// Быстрый запрос без fmt.Printf
func getPurchasesByID(urlTemplate string, id int) (string, error) {
    url := fmt.Sprintf(urlTemplate, id)

    req, err := http.NewRequest("GET", url, nil)
    if err != nil {
        return "", err
    }

    resp, err := client.Do(req)
    if err != nil {
        return "", err
    }
    defer resp.Body.Close()

    body, err := io.ReadAll(resp.Body)
    if err != nil {
        return "", err
    }

    return string(body), nil
}

func main() {
    url := "https://www.wildberries.ru/getPurchasesByID?id=%d"
    const workerCount = 500
    const idLimit = 100_000

    idChan := make(chan int, 10_000)
    var wg sync.WaitGroup

    // Генератор ID
    go func() {
        for id := 0; id < idLimit; id++ {
            idChan <- id
        }
        close(idChan)
    }()

    // Пул воркеров
    for i := 0; i < workerCount; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for id := range idChan {
                resp, err := getPurchasesByID(url, id)
                if err != nil {
                    // Ошибки лучше буферизовать или логировать отдельно
                    continue
                }
                _ = resp // Убери или логируй при необходимости
            }
        }()
    }

    wg.Wait()
    fmt.Println("Готово!")
}
```

## 🔍 Что делает функция `Search`:

Она параллельно запускает поиск по нескольким серверам и возвращает **первый успешный результат**. Если все серверы вернули ошибку, возвращается ошибка.

---

## 🧠 Пояснение по шагам:

### 1. Создание каналов:

```go
resultChan := make(chan []string, len(servers))
errorChan := make(chan error, len(servers))
```

- `resultChan` — буферизированный канал, чтобы получить **первый успешный результат**.
    
- `errorChan` — буферизированный канал, чтобы **отслеживать ошибки**.
    
- Буферизация нужна, чтобы не блокировать горутины, если основная функция ещё не готова читать.
    

---

### 2. Запуск горутин:

```go
for _, server := range servers {
    server := server // нужно для правильного захвата переменной в горутине
    go func() {
        result, err := search.Search(server, query)
        if err != nil {
            errorChan <- err
            return
        }
        resultChan <- result
    }()
}
```

- Каждая горутина выполняет `search.Search(...)` для одного сервера.
    
- Результат или ошибка отправляются в соответствующий канал.
    

---

### 3. Ожидание ответа:

```go
for i := 0; i < len(servers); i++ {
    select {
    case result := <-resultChan:
        return result, nil
    case err := <-errorChan:
        errCount++
        if errCount == len(servers) {
            return nil, fmt.Errorf("all servers failed: %v", err)
        }
    }
}
```

- Цикл `for i := 0; i < len(servers)` гарантирует, что мы прочитаем **столько сообщений**, сколько горутин запущено.
    
- `select` обрабатывает либо:
    
    - Успешный результат — и возвращает его немедленно.
        
    - Ошибку — увеличивает счётчик и, если ошибок столько же, сколько серверов, возвращает ошибку.
        

---

## ❗ Важный момент:

```go
server := server
```

Это **обязательно**! Без этого замыкание в горутине может использовать **одну и ту же переменную** `server`, которая уже изменилась к моменту вызова.
