В Go **контекст** (context) реализован через интерфейс **`context.Context`**, который предоставляет стандартизированный способ передачи сигналов отмены, дедлайнов и метаданных между горутинами. Этот механизм особенно полезен для координации выполнения горутин, например, для отмены операций или их завершения по тайм-ауту.

---

## **Как работает `context`**

### **Структура интерфейса `context.Context`**

Интерфейс `context.Context` определён следующим образом:

```go
type Context interface {
    Deadline() (deadline time.Time, ok bool)  // Дедлайн завершения (если установлен)
    Done() <-chan struct{}                   // Канал, который закрывается при отмене
    Err() error                              // Причина отмены (если есть)
    Value(key interface{}) interface{}       // Получение данных, связанных с контекстом
}
```

---

### **Типы контекста**

Go предоставляет несколько реализаций контекста, каждая из которых имеет свои особенности:

1. **`context.Background()`**
    
    - Корневой контекст, который обычно используется как начальная точка.
    - Никогда не отменяется, не имеет дедлайнов или значений.
2. **`context.TODO()`**
    
    - Используется, когда контекст требуется, но вы ещё не определились с его типом.
3. **`context.WithCancel(parent Context)`**
    
    - Создаёт новый дочерний контекст с функцией отмены (`cancel`).
4. **`context.WithDeadline(parent Context, deadline time.Time)`**
    
    - Создаёт контекст с конкретным дедлайном.
5. **`context.WithTimeout(parent Context, timeout time.Duration)`**
    
    - Создаёт контекст с дедлайном, установленным через тайм-аут.
6. **`context.WithValue(parent Context, key, value interface{})`**
    
    - Создаёт контекст, содержащий ключ-значение.

---

## **Как происходит закрытие горутин через `ctx.Done()`**

1. **Канал `Done`:**
    
    - Метод `ctx.Done()` возвращает канал типа `<-chan struct{}`.
    - Этот канал закрывается, когда контекст отменяется (например, через вызов `cancel()` или по истечении тайм-аута).
2. **Передача сигнала отмены:**
    
    - Когда канал `Done` закрывается, это сигнализирует всем горутинам, которые его слушают, что они должны завершить работу.
3. **Взаимодействие с горутинами:**
    
    - Горутины периодически проверяют канал `Done` в `select`, чтобы понять, нужно ли завершать выполнение.

---

### **Пример реализации: `WithCancel`**

Когда используется `context.WithCancel`, создаётся структура дочернего контекста, содержащая:

- Ссылку на родительский контекст.
- Канал `Done`.
- Ссылку на функцию `cancel`.

#### **Пример:**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())

	// Запуск горутины
	go func(ctx context.Context) {
		for {
			select {
			case <-ctx.Done(): // Проверяем, закрыт ли канал Done
				fmt.Println("Goroutine cancelled:", ctx.Err())
				return
			default:
				fmt.Println("Working...")
				time.Sleep(500 * time.Millisecond)
			}
		}
	}(ctx)

	time.Sleep(2 * time.Second)
	cancel() // Отправляем сигнал отмены
	time.Sleep(1 * time.Second)
	fmt.Println("Main function exits")
}
```

**Вывод:**

```
Working...
Working...
Working...
Working...
Goroutine cancelled: context canceled
Main function exits
```

---

### **Механизм закрытия в `WithCancel`**

1. **Создание контекста:**
    
    - При вызове `context.WithCancel(parent)` создаётся структура типа `cancelCtx`, которая наследует `Done` от родительского контекста.
2. **Сигнал отмены:**
    
    - При вызове `cancel()` закрывается канал `Done`, и все слушающие его горутины получают уведомление.
3. **Закрытие ресурсов:**
    
    - Любая горутина, получив сигнал через `Done`, завершает выполнение и освобождает свои ресурсы.

---

### **Пример: `WithTimeout`**

Контекст с тайм-аутом (`context.WithTimeout`) работает аналогично `WithCancel`, но автоматически вызывает `cancel` после истечения тайм-аута.

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel() // Всегда вызывать cancel для освобождения ресурсов

	go func(ctx context.Context) {
		for {
			select {
			case <-ctx.Done():
				fmt.Println("Goroutine timeout:", ctx.Err())
				return
			default:
				fmt.Println("Working...")
				time.Sleep(500 * time.Millisecond)
			}
		}
	}(ctx)

	time.Sleep(3 * time.Second)
	fmt.Println("Main function exits")
}
```

**Вывод:**

```
Working...
Working...
Working...
Goroutine timeout: context deadline exceeded
Main function exits
```

---

## **Как происходит передача сигнала и завершение**

1. **Передача сигнала через канал `Done`:**
    
    - Когда вызывается `cancel()`, функция закрывает канал `Done`, передавая сигнал всем слушателям.
2. **Обработка в горутинах:**
    
    - Горутины, слушающие `Done`, выполняют код в соответствующем блоке `select` и завершают выполнение.
3. **Дочерние контексты:**
    
    - Если дочерний контекст создаётся от родительского, отмена родительского контекста автоматически отменяет все дочерние.
4. **Очистка:**
    
    - Функции `cancel` освобождают связанные с контекстом ресурсы.

---

## **Как это реализовано внутри (структуры контекста)**

1. **`cancelCtx`:**
    
    - Основная структура для реализации отменяемого контекста:
        
        ```go
        type cancelCtx struct {
            Context    // Вложенный родительский контекст
            done chan struct{}  // Канал для передачи сигнала завершения
        }
        ```
        
2. **Метод `Done`:**
    
    - Возвращает канал `done`.
3. **Вызов `cancel`:**
    
    - Закрывает канал `done`:
        
        ```go
        func (c *cancelCtx) cancel() {
            close(c.done)
        }
        ```

## **Преимущества контекста**

1. **Удобное управление временем жизни горутин.**
2. **Масштабируемость:** Позволяет передавать сигнал завершения по всей иерархии задач.
3. **Централизованное управление:** Родительский контекст контролирует завершение дочерних.

---

**Итог:** Контекст в Go работает через каналы (`Done`), которые закрываются при отмене (`cancel`) или истечении времени (`WithTimeout`). Это уведомляет все связанные горутины о необходимости завершения. Такой подход делает управление горутинами простым, масштабируемым и безопасным.
