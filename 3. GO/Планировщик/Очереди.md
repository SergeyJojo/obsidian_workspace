
### **Очереди в модели GMP планировщика Go**

В модели GMP (Goroutine, M, P) планировщика Go существует несколько ключевых очередей, в которых хранятся горутины на разных стадиях выполнения.

---

## **1️⃣ Глобальная очередь (Global Run Queue, `GRQ`)**

- Глобальная очередь **общая для всех `P`** (процессоров).
    
- Если у `P` мало горутин, он может **украсть** (`work stealing`) горутины из `GRQ`.
    
- В нее попадают горутины, которые:
    
    - Были **разблокированы из системного вызова** (например, после I/O).
        
    - Были **"украдены" другим `P`**.
        
    - Созданы новым `go func()`, но локальная очередь `P` уже переполнена.
        

---

## **2️⃣ Локальная очередь (Local Run Queue, `LRQ`)**

- Каждое `P` (процессор) имеет **свою локальную очередь** горутин.
    
- Когда `P` хочет выполнить горутину, он сначала смотрит **в свою `LRQ`**.
    
- Если `LRQ` пуст, `P`:
    
    - Смотрит в **глобальную `GRQ`**.
        
    - Или **ворует горутину** из другой `P`.
        
- `P` может передавать горутины из `LRQ` в `GRQ`, если слишком много накопилось.
    

---

## **3️⃣ Очередь заблокированных горутин (`SudoG`)**

- Горутины, которые **заблокировались** (ожидание на `chan`, `mutex`, `syscall`), попадают в `SudoG`.
    
- Когда условие **разрешается** (например, разблокирован `mutex`), горутина **возвращается в `LRQ` или `GRQ`**.
    

---

## **4️⃣ Очередь сетевого планировщика (`NetPoller`)**

- Хранит горутины, ожидающие **событий ввода/вывода** (сокеты, файлы).
    
- Работает через **epoll/kqueue/io_uring**.
    
- Когда событие готово, горутина **разблокируется и попадает в `GRQ` или `LRQ`**.
- 
Когда горутина выполняет **сетевую операцию** (например, `net.Dial`, `http.Get`, `os.Open`), создаётся **объект `pollDesc`**, который регистрируется в `NetPoller`.
type pollDesc struct {
	lock    mutex      // Блокировка для синхронизации
	rapi    uintptr    // Дескриптор файла (socket, fd)
	ev      uint32     // События (например, POLLIN, POLLOUT)
	waiters uint32     // Количество горутин, ожидающих события
}

    

---

## **5️⃣ Очередь `Timers` (Таймеров)**

- Хранит горутины, которые ожидают **`time.Sleep()`, `time.After()` и `time.Timer`**.
    
- Как только таймер срабатывает, горутина **перемещается в `GRQ` или `LRQ`**.
    
- Оптимизирован с использованием **минимальной кучи**.
    

---

## **6️⃣ Очередь `Preempt Queue` (прерывания)**

- Хранит горутины, которые нужно **принудительно остановить** (`preempt`).
    
- Используется для **планирования работы garbage collector (GC)**.
    
- Например, если горутина **долго работает без переключений**, она **прерывается**, а `P` берет другую горутину.
    

---

## **7️⃣ Очередь `Syscall Queue`**

- Когда горутина делает **системный вызов (`syscall`)**, она **исчезает из `P`**.
    
- После завершения системного вызова горутина **возвращается в `GRQ`**.
    

---

## **Вывод**

|Очередь|Для чего используется?|
|---|---|
|**GRQ**|Глобальная очередь горутин|
|**LRQ**|Локальная очередь `P`|
|**SudoG**|Горутины, ожидающие разблокировки (`mutex`, `chan`)|
|**NetPoller**|Горутины, ожидающие ввода/вывода (`syscall`, `socket`)|
|**Timers**|Горутины, ожидающие `time.Sleep()`|
|**Preempt Queue**|Прерываемые горутины (для GC)|
|**Syscall Queue**|Горутины, выполняющие `syscall`|

Все эти очереди работают вместе, чтобы **эффективно балансировать выполнение горутин** между `P`.
