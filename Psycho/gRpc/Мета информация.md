
**gRPC** использует **HTTP/2** как транспортный протокол, что позволяет эффективно управлять сетевыми запросами и ответами. В отличие от стандартных HTTP-запросов, которые используют текстовые заголовки и тело запроса, запросы и ответы в gRPC более структурированы, так как они основаны на **Protocol Buffers** (protobuf), бинарном формате сериализации данных. Однако, несмотря на бинарный формат, gRPC сохраняет метаинформацию, аналогичную заголовкам в HTTP, но она организована иначе.

### Структура gRPC-запроса

1. **Заголовки (Headers)**
    
    - gRPC использует **метаинформацию**, аналогичную заголовкам в традиционном HTTP-запросе. Однако эти заголовки передаются через **мета-заголовки** в протоколе HTTP/2.
    - Мета-заголовки содержат такую информацию, как идентификаторы потока, контекст выполнения запроса, а также могут быть использованы для **аутентификации**, **авторизации**, **сжатия** и других целей.
    - В отличие от HTTP-заголовков, мета-заголовки в gRPC могут быть переданы как в запросе, так и в ответе.
    
    Пример мета-заголовков:
    
    ```go
    ctx := metadata.NewContext(context.Background(), map[string]string{
        "authorization": "Bearer token",
        "user-agent": "grpc-go/1.25.0",
    })
    ```
    
2. **Тело запроса (Payload)**
    
    - В gRPC данные (или **тело запроса**) передаются в бинарном формате через **Protocol Buffers** (protobuf). Это позволяет значительно уменьшить размер передаваемых данных по сравнению с текстовыми форматами, такими как JSON.
    - Когда клиент вызывает метод на сервере, он передает **protobuf-сообщение**, которое сериализуется в бинарный формат.
    - В отличие от HTTP, где данные могут передаваться в теле как текст или JSON, в gRPC данные всегда сериализуются с использованием схемы, определенной в **.proto** файле.
3. **Метод**
    
    - В gRPC каждый запрос включает вызов удалённой процедуры (RPC). В отличие от традиционных RESTful запросов, где используется стандартный HTTP-метод (например, `GET`, `POST`), в gRPC запросы всегда ориентированы на вызовы методов.
    - Например, в запросе указывается не только данные (тело), но и **имя метода**, который нужно вызвать, а также сервис, к которому этот метод принадлежит.
4. **Типы сообщений и ответов**
    
    - Запросы и ответы в gRPC бывают трех типов:
        - **Unary RPC** — клиент отправляет один запрос и получает один ответ.
        - **Server-streaming RPC** — клиент отправляет запрос и получает поток ответов.
        - **Client-streaming RPC** — клиент отправляет поток запросов и получает один ответ.
        - **Bidirectional streaming RPC** — и клиент, и сервер отправляют и получают потоки сообщений.
5. **Статус ответа (Status)**
    
    - Как и в случае с HTTP, каждый gRPC-ответ включает в себя статус, который описывает результат выполнения запроса.
    - Этот статус включает в себя **код статуса** (например, `OK`, `NOT_FOUND`, `INVALID_ARGUMENT`, `UNAUTHENTICATED` и т. д.), а также, если необходимо, сообщение об ошибке.

### Пример gRPC запроса и ответа

#### 1. **Protocol Buffers (Proto-файл)**

Для понимания структуры запроса и ответа нужно начать с описания сервиса в **.proto** файле.

```proto
syntax = "proto3";

service OrderService {
    rpc CreateOrder (CreateOrderRequest) returns (OrderResponse);
}

message CreateOrderRequest {
    string user_id = 1;
    string product_id = 2;
    int32 quantity = 3;
}

message OrderResponse {
    string order_id = 1;
    string status = 2;
}
```

В этом примере:

- Метод `CreateOrder` принимает сообщение `CreateOrderRequest` и возвращает сообщение `OrderResponse`.
- `CreateOrderRequest` содержит поля, такие как `user_id`, `product_id`, `quantity`.
- `OrderResponse` содержит поля `order_id` и `status`.

#### 2. **gRPC-запрос**

Запрос будет отправляться в бинарном формате (protobuf). Например, если мы вызываем метод `CreateOrder`, то структура запроса будет выглядеть так:

```go
order := &pb.CreateOrderRequest{
    UserId:   "123",
    ProductId: "456",
    Quantity: 1,
}

response, err := client.CreateOrder(context.Background(), order)
```

- `order` здесь — это объект типа `CreateOrderRequest`, который будет сериализован в бинарный формат с использованием protobuf.
- При вызове `CreateOrder` клиент отправляет это сообщение серверу.

#### 3. **gRPC-ответ**

Ответ от сервера может быть таким:

```go
type OrderResponse struct {
    OrderId string `json:"order_id"`
    Status  string `json:"status"`
}
```

Ответ также будет сериализован с использованием protobuf, и в случае успешного завершения запроса сервер вернёт статус и идентификатор заказа.

### Заголовки и метаинформация в gRPC

Хотя в gRPC запросах и ответах нет стандартных HTTP-методов (таких как `GET`, `POST`), всё равно существует метаинформация, которая может быть полезна для управления контекстом запросов и ответов, например:

- **Авторизация и аутентификация**: токены безопасности (например, `Bearer token`) могут быть переданы в мета-заголовках.
- **Трекинг**: можно передавать уникальные идентификаторы для отслеживания запросов (например, в заголовке `X-Request-ID`).
- **Контекст и сессии**: могут использоваться для отслеживания состояния сессий или передаваемых данных.

### Пример мета-заголовков

```go
// Создание контекста с мета-заголовками
md := metadata.New(map[string]string{
    "authorization": "Bearer your_token_here",
    "user-agent":    "grpc-go/1.25.0",
})

ctx := metadata.NewOutgoingContext(context.Background(), md)

// Вызов метода с мета-заголовками
response, err := client.CreateOrder(ctx, order)
```

Здесь мы передаем авторизационный токен и информацию о пользователе через мета-заголовки в контексте gRPC-запроса.

### Резюме

- **gRPC запрос** включает в себя **методы** удалённого вызова, которые обрабатываются на сервере. Запросы и ответы сериализуются в **Protocol Buffers** (protobuf) и передаются в бинарном формате.
- **Метаинформация** передается через **мета-заголовки** в HTTP/2.
- **gRPC не использует стандартные HTTP-методы** (GET, POST и т.д.), а использует **методы** для выполнения удалённых процедур.
- Ответы и статусы в gRPC аналогичны статусам в HTTP, но имеют более структурированное и бинарное представление.

gRPC позволяет эффективно передавать данные, используя HTTP/2 и protobuf, и при этом поддерживает мощную метаинформацию для управления контекстом запросов.
