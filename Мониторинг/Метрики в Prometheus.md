
### 22. Стандартный набор метрик Prometheus в Go-программе

Для того чтобы интегрировать Prometheus в Go-программу, необходимо использовать библиотеку **prometheus/client_golang**, которая предоставляет стандартные метрики, включая:

1. **Process Metrics**:
    
    - `go_gc_duration_seconds` — время, затраченное на сборку мусора.
    - `go_goroutines` — количество горутин, запущенных в процессе.
    - `go_memstats_alloc_bytes` — количество выделенной памяти в байтах.
    - `go_memstats_heap_alloc_bytes` — количество памяти, выделенной для кучи.
    - `go_memstats_heap_sys_bytes` — количество памяти, занятой системой для кучи.
    - `go_memstats_stack_inuse_bytes` — количество памяти, используемой стеками.
    - `go_threads` — количество потоков операционной системы, используемых приложением.
2. **HTTP Metrics**:
    
    - `http_requests_total` — общее количество HTTP-запросов, обработанных сервером.
    - `http_request_duration_seconds` — время, затраченное на обработку HTTP-запросов.
3. **Go Runtime Metrics**:
    
    - `go_runtime_alloc_bytes` — количество памяти, выделенной для объектов.
    - `go_runtime_heap_bytes` — количество памяти, выделенной для кучи.
    - `go_runtime_sys_bytes` — количество памяти, занятой системой.

Пример кода, который включает базовые метрики в Go-программе:

```go
import (
    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promhttp"
    "net/http"
    "log"
)

func init() {
    // Стандартные метрики Prometheus
    prometheus.MustRegister(prometheus.NewGoCollector())
}

func main() {
    http.Handle("/metrics", promhttp.Handler()) // Обработчик для /metrics
    log.Fatal(http.ListenAndServe(":8080", nil)) // Запуск HTTP-сервера на порту 8080
}
```

Этот код регистрирует стандартные метрики, и по запросу на `/metrics` будет доступна информация о текущем состоянии приложения.

### 23. Как встроить стандартный профайлер в свое приложение?

Для того чтобы встроить стандартный профайлер в приложение на Go, можно использовать пакет **net/http/pprof**, который предоставляет множество профилей для анализа производительности, таких как:

- **heap** — информация о куче памяти.
- **goroutine** — состояние горутин.
- **cpu** — профилирование использования процессора.
- **block** — блокировки.
- **threadcreate** — профилирование создания потоков.

Чтобы встроить профайлер, достаточно добавить следующий код:

```go
import (
    _ "net/http/pprof" // Импортируем ппрофиер
    "net/http"
    "log"
)

func main() {
    // Запуск стандартного HTTP-сервера на порту 6060 для профилирования
    go func() {
        log.Println(http.ListenAndServe("localhost:6060", nil)) // Слушаем на порту 6060
    }()

    // Ваши основные операции программы
    select {} // Чтобы программа не завершалась
}
```

Теперь профилирование будет доступно через HTTP-запросы:

- **/debug/pprof/heap** — профилирование памяти.
- **/debug/pprof/goroutine** — профиль горутин.
- **/debug/pprof/block** — блокировки.
- **/debug/pprof/threadcreate** — создание потоков.
- **/debug/pprof/cpu** — CPU профиль.

Для анализа данных профиля, можно использовать утилиту **pprof**:

```bash
go tool pprof http://localhost:6060/debug/pprof/heap
```

### 24. Overhead от стандартного профайлера?

Overhead от стандартного профайлера зависит от того, какие профили используются и как активно собирается информация. Например:

- **CPU профилирование**: Профилирование CPU имеет заметный overhead, так как оно собирает информацию о том, как программа использует процессор. Это может снижать производительность, особенно при активном профилировании, так как дополнительная информация о времени выполнения кода будет собираться в реальном времени.
    
- **Memory профилирование (heap)**: Профилирование памяти также может влиять на производительность, поскольку для каждого выделения памяти требуется отслеживание и создание отчетов, что добавляет накладные расходы.
    
- **Горутины и блокировки**: Профилирование горутин и блокировок также может влиять на производительность, так как профайлер должен отслеживать состояние горутин и блокировок в реальном времени.
    

В целом, **overhead** может варьироваться от минимального до значительного, в зависимости от интенсивности профилирования. Например, если вы активно профилируете CPU или создаете отчеты о блокировках, это может замедлить работу программы. Однако для большинства случаев стандартное профилирование добавляет небольшой overhead, который может быть приемлемым для большинства приложений.

Для минимизации overhead рекомендуется включать профилирование только в случае необходимости и использовать его в продуктивной среде только для отладки или мониторинга производительности в реальном времени.
