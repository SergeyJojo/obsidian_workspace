# Топ-20 каверзных вопросов и ответов по работе с Kubernetes и Docker

## 1. **Как работает Kubernetes с Docker-контейнерами?**
   Kubernetes использует контейнеры как основную единицу работы. Docker обеспечивает контейнеризацию, а Kubernetes управляет их развертыванием, масштабированием и отказоустойчивостью. Kubernetes использует CRI (Container Runtime Interface), чтобы взаимодействовать с контейнерными рантаймами, такими как Docker (через dockershim) или containerd.

---

## 2. **Какой формат используется для описания манифестов в Kubernetes?**
   Манифесты в Kubernetes описываются в формате YAML или JSON. YAML является наиболее популярным из-за своей читаемости. В манифестах описываются ресурсы, такие как `Pod`, `Service`, `Deployment`.

---

## 3. **Что делать, если Pod застрял в статусе "Pending"?**
   Причины:
   - Нехватка ресурсов (CPU, RAM) на нодах.
   - Неправильный `nodeSelector`, `taints` или `tolerations`.
   - Проблема с Persistent Volume (если Pod использует PVC).
   Решение:
   - Проверить статус нод: `kubectl get nodes`.
   - Оценить ограничения ресурсов: `kubectl describe pod <pod-name>`.

---

## 4. **Почему Docker-образ увеличился в размере?**
   - Используются лишние слои.
   - Установка временных файлов, которые не удаляются.
   - Неправильный порядок инструкций в Dockerfile (например, `RUN` перед `COPY`).
   - Использование базового образа с большим размером.
   Решение:
   - Оптимизировать Dockerfile, минимизировать слои (`RUN apt-get && rm`).
   - Использовать `multi-stage builds`.

---

## 5. **Как Kubernetes определяет, что контейнер "жив"?**
   Kubernetes использует **Liveness Probe**. Пример:
   ```yaml
   livenessProbe:
     httpGet:
       path: /health
       port: 8080
     initialDelaySeconds: 5
     periodSeconds: 10
   ```
   Если проверка не проходит, Pod будет перезапущен.

---

## 6. **Как обновить контейнер в Deployment без простоя?**
   - Kubernetes использует стратегию **Rolling Update**:
     - По умолчанию обновляются Pods по одному.
     - Устанавливается `maxUnavailable` и `maxSurge` для контроля обновления.
   Пример:
   ```yaml
   strategy:
     type: RollingUpdate
     rollingUpdate:
       maxUnavailable: 1
       maxSurge: 2
   ```

---

## 7. **Что делать, если контейнер постоянно перезапускается?**
   Причины:
   - Ошибка в коде (например, приложение падает при старте).
   - Неправильные `readinessProbe` или `livenessProbe`.
   - Нехватка ресурсов (лимиты CPU/RAM).
   Решение:
   - Проверить логи контейнера: `kubectl logs <pod-name>`.
   - Проверить статус Pod: `kubectl describe pod <pod-name>`.

---

## 8. **Почему Docker-контейнер не может подключиться к другому контейнеру в Kubernetes?**
   Причины:
   - Неправильная настройка `Service` или `NetworkPolicy`.
   - Подключение по IP вместо DNS-имени (`<service-name>.<namespace>.svc.cluster.local`).
   Решение:
   - Убедиться, что Service настроен правильно.
   - Проверить NetworkPolicy: `kubectl describe networkpolicy`.

---

## 9. **Какие проблемы могут возникнуть с Persistent Volume?**
   - PV недоступен или не привязан к PVC.
   - Неправильный StorageClass.
   - Отсутствие динамического провиженинга.
   Решение:
   - Проверить статус PVC: `kubectl get pvc`.
   - Посмотреть события: `kubectl describe pvc <pvc-name>`.

---

## 10. **Что делать, если `kubectl exec` или `kubectl logs` зависают?**
   Причины:
   - Проблемы с kubelet или network overlay.
   - Нода перегружена.
   Решение:
   - Проверить доступность ноды: `kubectl get nodes`.
   - Перезапустить kubelet.

---

## 11. **Как уменьшить размер Docker-образа?**
   - Использовать минимальные базовые образы, такие как `alpine`.
   - Удалять кеши и временные файлы после установки:
     ```dockerfile
     RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*
     ```
   - Использовать `multi-stage builds`.

---

## 12. **Как проверить, какой Pod использует больше всего ресурсов?**
   Используйте команду:
   ```bash
   kubectl top pod --namespace=<namespace>
   ```
   Или включите метрики через `metrics-server`.

---

## 13. **Что такое Init Containers и зачем они нужны?**
   - Init Containers — это контейнеры, которые выполняются перед основным контейнером.
   - Используются для:
     - Предварительной настройки окружения.
     - Подготовки данных.
     - Ожидания внешних зависимостей.

---

## 14. **Как работает readinessProbe?**
   **Readiness Probe** проверяет, готов ли контейнер принимать трафик. Если проверка не проходит, Pod исключается из Service.
   Пример:
   ```yaml
   readinessProbe:
     tcpSocket:
       port: 8080
     initialDelaySeconds: 3
     periodSeconds: 5
   ```

---

## 15. **Как управлять конфиденциальными данными в Kubernetes?**
   Используйте **Secrets**:
   ```yaml
   apiVersion: v1
   kind: Secret
   metadata:
     name: my-secret
   type: Opaque
   data:
     username: YWRtaW4= # base64(username)
     password: cGFzc3dvcmQ= # base64(password)
   ```

---

## 16. **Как ограничить ресурсы для Pods?**
   Установите `requests` (минимум) и `limits` (максимум):
   ```yaml
   resources:
     requests:
       memory: "64Mi"
       cpu: "250m"
     limits:
       memory: "128Mi"
       cpu: "500m"
   ```

---

## 17. **Почему Rolling Update может зависнуть?**
   Причины:
   - Неправильные `readinessProbe`.
   - Под ожидает внешней зависимости, которая недоступна.
   Решение:
   - Проверить состояние Pods: `kubectl get pods`.
   - Проверить события: `kubectl describe deployment`.

---

## 18. **Как отладить Pod, который не запускается?**
   Команды:
   - `kubectl describe pod <pod-name>` — для проверки событий.
   - `kubectl logs <pod-name>` — для просмотра логов.
   - `kubectl exec -it <pod-name> -- /bin/sh` — для запуска отладки.

---

## 19. **Что такое Node Affinity и для чего она нужна?**
   Node Affinity используется для размещения Pods на определённых нодах:
   ```yaml
   affinity:
     nodeAffinity:
       requiredDuringSchedulingIgnoredDuringExecution:
         nodeSelectorTerms:
         - matchExpressions:
           - key: disktype
             operator: In
             values:
             - ssd
   ```

---

## 20. **Как настроить автоматическое масштабирование Pods?**
   Используйте Horizontal Pod Autoscaler (HPA):
   ```bash
   kubectl autoscale deployment <deployment-name> --cpu-percent=50 --min=1 --max=10
   ```
   Или через YAML:
   ```yaml
   apiVersion: autoscaling/v2
   kind: HorizontalPodAutoscaler
   metadata:
     name: example-hpa
   spec:
     scaleTargetRef:
       apiVersion: apps/v1
       kind: Deployment
       name: example-deployment
     minReplicas: 1
     maxReplicas: 10
     metrics:
     - type: Resource
       resource:
         name: cpu
         targetAverageUtilization: 50
   ```

---

Эти вопросы помогут проверить ваш опыт работы с Kubernetes и Docker, а также продемонстрировать глубокое понимание архитектуры и инструментов.
