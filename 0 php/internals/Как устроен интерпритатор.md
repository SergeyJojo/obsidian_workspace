Отличный вопрос — вот как это устроено **в глубину**, если капнуть в PHP «под капот»:

---

### 🧱 1. Основной язык реализации — **C**

PHP написан в основном на **языке C**.  
Это значит, что под капотом PHP — не «интерпретатор на интерпретаторе», а полноценная **система на низком уровне**, работающая напрямую с памятью, файловой системой и системными вызовами ОС.

- Ядро PHP (Zend Engine)
    
- Стандартная библиотека PHP (ext/standard)
    
- Расширения (extensions) — тоже на C, загружаются динамически (`.so` / `.dll`)
    

---

### ⚙️ 2. Ядро PHP — **Zend Engine**

Zend Engine — это сердце PHP.  
Он отвечает за:

- **Парсинг** исходного кода PHP → в AST (абстрактное синтаксическое дерево)
    
- **Компиляцию** AST → в **opcode** (байткод)
    
- **Исполнение** этих opcodes через стековую виртуальную машину
    
- **Управление памятью**, сборку мусора (reference counting + cyclic GC)
    
- **Типизацию и структуры данных** (zval, HashTable и т.п.)
    

🧠 Пример:  
Когда ты пишешь

```php
$a = 1 + 2;
```

PHP делает примерно следующее:

1. Лексер (`zend_language_scanner.c`) превращает код в токены.
    
2. Парсер (`zend_language_parser.c`) строит AST.
    
3. Компилятор (`zend_compile.c`) превращает AST в опкоды.
    
4. Исполнитель (`zend_execute.c`) интерпретирует опкоды в рантайме.
    

---

### 🧩 3. Архитектура Zend Engine

Всё крутится вокруг **zval** — универсальной структуры для любого значения в PHP.

```c
typedef struct _zval_struct {
    zend_value value;
    zend_uint refcount;
    zend_uchar type;
    zend_uchar is_ref;
} zval;
```

Она может хранить и int, и string, и объект, и массив — любой PHP-тип.  
А "copy-on-write" (COW), кстати, тоже реализуется на уровне `zval` через `refcount`.

---

### 🧠 4. Расширения (extensions)

PHP можно расширять нативным C-кодом.  
Расширения подключаются через `.ini`, например:

```ini
extension=gd
extension=pdo_mysql
```

Расширения могут добавлять:

- функции (`PHP_FUNCTION`)
    
- классы
    
- потоки, обработчики, фильтры, сериализацию и т.п.
    

💡 Множество стандартных функций PHP (строки, JSON, cURL, PDO, sockets) — это просто **расширения на C**, входящие в дистрибутив.

---

### 🚀 5. JIT-компиляция (PHP 8+)

С версии **PHP 8** появился **JIT (Just-In-Time compiler)**, основанный на **DFA JIT (Dynamic Function Analysis)**, встроенном прямо в Zend Engine.  
Он компилирует горячие участки байткода в нативный машинный код (x86-64), ускоряя CPU-bound задачи.

---

### 📦 6. Веб-интеграция

PHP изначально запускался как модуль для Apache (mod_php),  
но сейчас чаще — через **FPM (FastCGI Process Manager)**, который написан на C и является частью PHP.

---

### 🧩 7. Ключевые внутренние компоненты и их реализация

| Компонент      | Назначение                    | Реализация |
| -------------- | ----------------------------- | ---------- |
| `zend_*`       | ядро движка                   | C          |
| `ext/standard` | стандартные функции           | C          |
| `sapi/*`       | интерфейсы (CLI, FPM, Apache) | C          |
| `TSRM`         | Thread Safe Resource Manager  | C          |
| `main/`        | загрузка ini, конфигурация    | C          |

---

### 🧰 8. Минимальный стек при сборке

Чтобы собрать PHP из исходников, нужны:

- **libxml**, **libcurl**, **libssl**, **libsqlite**, **zlib**, **oniguruma** и т.д.
    
- GNU autotools / CMake / make
    
- Компилятор C (`gcc` или `clang`)
    

---

### 💡 Итого:

- PHP написан **на C**, ядро — **Zend Engine**
    
- Интерпретирует код через **байткодовую виртуальную машину**
    
- Поддерживает **COW**, **GC**, **JIT**
    
- Расширяется **через C API**
    
- Работает как **FPM**, **CLI**, или **модуль веб-сервера**
