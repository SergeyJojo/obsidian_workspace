
Для синхронизации трёх горутин в строгом порядке `1 → 2 → 3 → 1 → 2 → 3 → ...` до завершения обработки данных можно использовать несколько подходов на каналах. Рассмотрим 3 способа:  

---

### **Способ 1: Каскад каналов (цепочка)**  
Каждая горутина ждёт сигнала от предыдущей и передаёт следующей.  

```go
func worker(id int, in <-chan struct{}, out chan<- struct{}, wg *sync.WaitGroup) {
    defer wg.Done()
    for range in { // Ждём сигнала от предыдущей горутины
        fmt.Printf("Worker %d\n", id)
        out <- struct{}{} // Сигнал следующей
    }
}

func main() {
    ch1 := make(chan struct{})
    ch2 := make(chan struct{})
    ch3 := make(chan struct{})
    var wg sync.WaitGroup

    wg.Add(3)
    go worker(1, ch3, ch1, &wg) // 3 → 1
    go worker(2, ch1, ch2, &wg) // 1 → 2
    go worker(3, ch2, ch3, &wg) // 2 → 3

    ch3 <- struct{}{} // Первый запуск (начинаем с 1)
    close(ch3)        // Завершение (если нужно)
    wg.Wait()
}
```

**Плюсы**:  
- Простота.  
- Чёткий порядок.  

**Минусы**:  
- Требует точной настройки цепочки.  

---

### **Способ 2: Управляющий канал + select**  
Централизованное управление через отдельный планировщик.  

```go
func worker(id int, in <-chan int, out chan<- int, wg *sync.WaitGroup) {
    defer wg.Done()
    for reqID := range in {
        if reqID == id {
            fmt.Printf("Worker %d\n", id)
            out <- id // Сообщаем о завершении
        }
    }
}

func scheduler(workersIn []chan<- int, workersOut []<-chan int, data []int) {
    current := 0
    for _, item := range data {
        workersIn[current] <- current + 1 // 1, 2, 3, 1, 2, 3...
        <-workersOut[current]            // Ждём подтверждения
        current = (current + 1) % 3
    }
    for _, ch := range workersIn {
        close(ch)
    }
}

func main() {
    var wg sync.WaitGroup
    workersIn := make([]chan<- int, 3)
    workersOut := make([]<-chan int, 3)

    for i := 0; i < 3; i++ {
        chIn := make(chan int)
        chOut := make(chan int)
        workersIn[i] = chIn
        workersOut[i] = chOut
        wg.Add(1)
        go worker(i+1, chIn, chOut, &wg)
    }

    data := []int{1, 2, 3, 4, 5, 6, 7} // Пример данных
    go scheduler(workersIn, workersOut, data)
    wg.Wait()
}
```

**Плюсы**:  
- Гибкость (можно менять порядок динамически).  
- Централизованное управление.  

**Минусы**:  
- Сложнее реализация.  

---

### **Способ 3: Мьютекс + условие ожидания**  
Используем `sync.Cond` для синхронизации по условию.  

```go
func worker(id int, turn *int, cond *sync.Cond, wg *sync.WaitGroup) {
    defer wg.Done()
    cond.L.Lock()
    for {
        for *turn != id { // Ждём своего хода
            cond.Wait()
        }
        fmt.Printf("Worker %d\n", id)
        *turn = *turn % 3 + 1 // 1→2→3→1...
        cond.Broadcast()      // Будим остальных
    }
    cond.L.Unlock()
}

func main() {
    var (
        mu   sync.Mutex
        cond = sync.NewCond(&mu)
        turn = 1
        wg   sync.WaitGroup
    )

    wg.Add(3)
    for i := 1; i <= 3; i++ {
        go worker(i, &turn, cond, &wg)
    }

    // Завершение по внешнему условию (например, через контекст)
    time.Sleep(1 * time.Second)
    // Здесь можно добавить graceful shutdown
    wg.Wait()
}
```

**Плюсы**:  
- Не требует множества каналов.  
- Работает даже без внешних данных.  

**Минусы**:  
- Риск deadlock, если логика нарушена.  

---

### **Выбор способа**  
1. **Каскад каналов** — если порядок фиксирован и известен заранее.  
2. **Управляющий канал** — если нужно обрабатывать внешние данные.  
3. **`sync.Cond`** — если требуется максимальная гибкость.  

Для вашего случая (данные извне + строгий порядок) лучше **Способ 2**.
