### 1. **Общее описание системы**

Предположим, что ты работал над облачным сервисом для B2B клиентов. Система позволяет компаниям интегрировать свои приложения с несколькими сервисами, управлять данными, анализировать их и использовать CRM-системы, такие как Yandex Direct. Этот сервис предоставляет различные облачные инструменты, включая аналитику, отчетность, кеширование и обработку данных через микросервисы.

### 2. **Компоненты системы**

#### 2.1 **API Gateway**

- Обрабатывает входящие запросы.
- Написан на Go с использованием gRPC для взаимодействия с микросервисами.
- Применяется для управления маршрутизацией, аутентификацией через OAuth2/OpenID.
- Внедряется логирование всех запросов для отслеживания ошибок и анализа производительности.

#### 2.2 **Микросервисы**

Микросервисы, взаимодействующие друг с другом через gRPC и Kafka для обмена сообщениями и асинхронной обработки данных.

- **Сервис для работы с данными**
    
    - Использует **PostgreSQL** для хранения данных клиентов и транзакций.
    - Предоставляет REST API для внешних сервисов.
    - Кеширует часто запрашиваемые данные в **Redis** для повышения производительности.
- **Сервис аналитики**
    
    - Использует **MongoDB** для хранения и анализа больших объемов данных.
    - Обрабатывает аналитические запросы и возвращает отчеты для пользователей.
- **Интеграции с внешними сервисами (например, Yandex Direct)**
    
    - Интегрируется с CRM-системами и рекламными платформами для передачи данных о рекламных кампаниях.
    - Использует gRPC или REST API для связи.

#### 2.3 **Логирование и мониторинг**

- Сервис для сбора логов и мониторинга состояний всех микросервисов с помощью **OAuth2** для аутентификации.
- Сбор статистики по сервисам и меткам, настройка алертов.

#### 2.4 **Кеширование**

- **Redis** используется для кеширования данных, что снижает нагрузку на базу данных.
- Установлены стратегии кеширования для часто запрашиваемых данных и агрегации.

### 3. **Как это будет выглядеть на собеседовании?**

#### Пример вопросов:

1. **Как вы проектировали взаимодействие между микросервисами?**
    
    - Я использовал **gRPC** для синхронного общения между сервисами с минимальной задержкой. Для асинхронной коммуникации использовали **Kafka**, чтобы снизить нагрузку на сервисы при массовых запросах.
2. **Как реализовано кеширование и почему выбрали Redis?**
    
    - Для кеширования часто запрашиваемых данных мы использовали **Redis**, так как это быстрое решение для кэширования в памяти. Мы применили подход с TTL (time-to-live) для автоматически очищаемых данных и реализовали стратегию сброса кеша при изменении данных в основной базе (PostgreSQL).
3. **Как реализовано масштабирование?**
    
    - Каждый сервис масштабируется независимо, благодаря микросервисной архитектуре. Мы использовали **Kubernetes** для автоматического масштабирования сервисов в зависимости от нагрузки. Kafka играет ключевую роль в организации масштабируемых асинхронных процессов.
4. **Что использовали для аутентификации и авторизации?**
    
    - Для аутентификации использовали **OAuth2** с **OpenID** для управления пользователями и правами доступа. Каждый сервис проверяет токен перед тем, как выполнить требуемое действие.
5. **Как работа с базами данных организована?**
    
    - Мы использовали **PostgreSQL** для реляционных данных и транзакций. Для аналитических данных и хранения больших объемов данных выбрали **MongoDB**. База данных поддерживала вертикальное масштабирование и репликацию для отказоустойчивости.
6. **Какие сложности возникали при интеграции с Yandex Direct?**
    
    - Мы интегрировали систему с **Yandex Direct** для получения и анализа рекламных данных. В процессе настройки использовалась **OAuth2** для безопасной аутентификации в системе, а также **gRPC** для ускоренной передачи данных между сервисами.
