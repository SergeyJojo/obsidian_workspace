
Структура стека горутин в Go — это важная часть runtime, которая обеспечивает выполнение кода в легковесных потоках (goroutines). Стек горутины отличается от традиционных стеков потоков ОС тем, что он динамически изменяет размер, начиная с небольшого объёма памяти и увеличиваясь по мере необходимости. Чтобы подробно разобрать, как устроен стек горутин, обратимся к его внутренней реализации в runtime Go (на основе исходного кода Go 1.21). Давайте разберём это "по полочкам".

---

Общая концепция стека горутин

- Стек — это область памяти, выделенная для каждой горутины, где хранятся локальные переменные, аргументы функций и информация о вызовах (call stack).
    
- В Go стек горутин:
    
    - Изначально мал: Начинается с 2 КБ (в Go 1.21).
        
    - Динамически растёт: Может увеличиваться до 1 ГБ (максимальный предел).
        
    - Управляется runtime: Go сам выделяет, расширяет и освобождает память для стека без прямого участия ОС.
        
- Стек описан в структуре g (goroutine) через поле stack и связанные с ним ограничительные указатели (stackguard0, stackguard1).
    

---

Структура стека в g

В файле runtime/runtime2.go стек горутины представлен следующим образом:

go

```go
type g struct {
    stack       stack   // Границы стека
    stackguard0 uintptr // Нижний ограничитель стека (для прерывания)
    stackguard1 uintptr // Дополнительный ограничитель (для C-кода)
    // ... другие поля
}

type stack struct {
    lo uintptr // Нижняя граница стека
    hi uintptr // Верхняя граница стека
}
```

---

Разбор структуры стека "по полочкам"

1. stack stack

- Что это: Структура stack, содержащая два указателя:
    
    - lo uintptr: Нижняя граница стека (начало выделенной памяти).
        
    - hi uintptr: Верхняя граница стека (конец выделенной памяти).
        
- Назначение: Определяет диапазон памяти, доступный горутине для выполнения кода.
    
- Особенность:
    
    - Стек растёт вниз (от hi к lo), как в большинстве архитектур (x86, ARM).
        
    - Изначально hi - lo = 2048 байт (2 КБ).
        
- Пример:
    
    - Новая горутина: lo = 0x1000, hi = 0x1800 → 2 КБ памяти.
        

2. stackguard0 uintptr

- Что это: Указатель, задающий "охранную зону" (guard) стека, чтобы предотвратить переполнение.
    
- Назначение:
    
    - Сравнивается с текущим стековым указателем (SP), чтобы определить, близок ли стек к исчерпанию.
        
    - Если SP опускается ниже stackguard0, runtime вызывает расширение стека.
        
- Значение:
    
    - Обычно stackguard0 = lo + StackGuard, где StackGuard = 928 байт (в Go 1.21 для 64-битных систем).
        
    - Это оставляет "буфер" в 928 байт между концом стека и точкой прерывания.
        
- Особенность: Используется для прерывания горутины через morestack перед переполнением.
    

3. stackguard1 uintptr

- Что это: Дополнительный ограничитель стека.
    
- Назначение:
    
    - Используется в специальных случаях, например, когда горутина вызывает C-код через cgo.
        
    - Обеспечивает совместимость с внешними стеками.
        
- Особенность: Обычно неактивен для чисто Go-кода, но может быть настроен для интеграции с другими языками.
    

4. Связанные неявные элементы

- Текущий стековый указатель (SP):
    
    - Хранится в регистре процессора (например, RSP на x86_64) и доступен runtime через g.sched.sp.
        
    - Указывает на текущую вершину стека во время выполнения.
        
- Программный счётчик (PC):
    
    - Хранится в g.sched.pc, указывает на текущую инструкцию.
        
- База стека:
    
    - Неявно определяется как stack.hi, откуда начинается рост вниз.
        

---

Как устроен стек физически

1. Выделение памяти:
    
    - При создании горутины через go runtime вызывает runtime.newstack, которая выделяет начальные 2 КБ с помощью системного вызова mmap (на POSIX) или эквивалента.
        
    - Память размещается в куче Go, а не в стеке ОС.
        
2. Рост стека:
    
    - Если стек заполняется (например, при глубоких рекурсивных вызовах), SP приближается к stackguard0.
        
    - Runtime вызывает morestack (вставляется компилятором перед каждым вызовом функции):
        
        - Проверяет SP < stackguard0.
            
        - Если да, выделяет новый стек в 2 раза больше текущего (2 КБ → 4 КБ → 8 КБ и т.д.).
            
        - Копирует старый стек в новую область через copystack.
            
        - Обновляет stack.lo, stack.hi, stackguard0.
            
3. Сжатие стека:
    
    - После завершения вызова функции runtime проверяет, используется ли менее 25% стека.
        
    - Если да, стек может быть уменьшен (но не менее 2 КБ) через shrinkstack.
        
4. Максимальный размер:
    
    - Ограничен 1 ГБ на 64-битных системах (StackLimit = 1<<30).
        

---

Механизм работы стека

Создание горутины:

go

```go
go func() {
    fmt.Println("Hello")
}()
```

- Runtime вызывает newproc:
    
    - Выделяет g и стек: stack.lo = 0x1000, stack.hi = 0x1800 (2 КБ).
        
    - stackguard0 = 0x13A0 (lo + 928).
        
    - SP устанавливается около hi (например, 0x17F8), растёт вниз.
        

Выполнение:

- Каждый вызов функции уменьшает SP, добавляя фреймы (локальные переменные, аргументы).
    
- Перед вызовом проверяется:
    
    go
    
    ```go
    if SP < stackguard0 {
        morestack()
    }
    ```
    

Расширение:

- При morestack:
    
    - Новый стек: lo = 0x2000, hi = 0x2800 (4 КБ).
        
    - Старый контент копируется, SP и stackguard0 обновляются.
        

Завершение:

- После выхода из функции g становится Gdead, стек освобождается через stackfree.
    

---

Особенности устройства

1. Динамический размер:
    
    - Начинается с 2 КБ, растёт экспоненциально (2^n), но не бесконечно (до 1 ГБ).
        
    - Это делает горутины легковесными по сравнению с потоками ОС (обычно 1-2 МБ фиксированного стека).
        
2. Охранная зона:
    
    - stackguard0 оставляет 928 байт запаса, чтобы runtime успел среагировать до переполнения.
        
3. Копирование стека:
    
    - При расширении весь стек копируется в новую область, что требует времени, но позволяет избежать сложных указателей на старый стек.
        
4. Управление памятью:
    
    - Стек выделяется в куче Go, что упрощает сборку мусора и переиспользование памяти.
        
5. Интеграция с GC:
    
    - Сборщик мусора сканирует стек от SP до stack.hi, используя g.gcscandone для отслеживания.

Пример жизненного цикла стека

Код:

go

```go
func recursive(n int) {
    if n > 0 {
        recursive(n - 1)
    }
}
go recursive(1000)
```

Процесс:

1. Начало: Стек 2 КБ, SP близко к hi.
    
2. Рекурсия: Каждый вызов recursive добавляет фрейм (~16-32 байта), SP уменьшается.
    
3. Переполнение: После ~60 вызовов SP < stackguard0, вызывается morestack.
    
4. Расширение: Новый стек 4 КБ, копируется старый контент.
    
5. Продолжение: Процесс повторяется (8 КБ, 16 КБ и т.д.) до завершения.
    

---

Итог устройства стека горутин

- Структура:
    
    - stack {lo, hi}: Границы памяти (2 КБ → 1 ГБ).
        
    - stackguard0: Охранная зона для прерывания.
        
    - stackguard1: Резерв для C-кода.
        
- Механизм:
    
    - Растёт вниз, динамически расширяется через morestack.
        
    - Копируется при росте, освобождается при завершении.
        
- Особенности:
    
    - Легковесный (2 КБ против 1-2 МБ у потоков ОС).
        
    - Управляется runtime, интегрирован с GC.
        
- Роль: Обеспечивает выполнение кода горутины с минимальными затратами памяти и гибкостью.
    

Если нужно углубиться в детали (например, morestack или интеграцию с GC), дайте знать!
