### **1. Основы SQL**

#### a. **Основные операции (CRUD)**

- **SELECT**: Извлечение данных из таблиц.
    - `SELECT column1, column2 FROM table WHERE condition;`
- **INSERT**: Добавление данных.
    - `INSERT INTO table (column1, column2) VALUES (value1, value2);`
- **UPDATE**: Обновление данных.
    - `UPDATE table SET column1 = value1 WHERE condition;`
- **DELETE**: Удаление данных.
    - `DELETE FROM table WHERE condition;`

#### b. **Фильтрация данных**

- Оператор `WHERE`:
    
    ```sql
    SELECT * FROM employees WHERE salary > 50000;
    ```
    
- Условия:
    - `=`, `<`, `>`, `<=`, `>=`, `!=`
    - `IN`, `BETWEEN`, `LIKE`, `IS NULL`
- Пример:
    
    ```sql
    SELECT * FROM products WHERE name LIKE 'Phone%' AND price BETWEEN 500 AND 1000;
    ```
    

#### c. **Сортировка**

- Оператор `ORDER BY`:
    
    ```sql
    SELECT * FROM employees ORDER BY salary DESC, age ASC;
    ```
    

#### d. **Агрегация данных**

- Функции: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.
    
    ```sql
    SELECT department, COUNT(*) AS employee_count, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
    HAVING AVG(salary) > 50000;
    ```

### **2. Работа с несколькими таблицами**

#### a. **Соединения (JOIN)**

1. **INNER JOIN**: Возвращает совпадающие записи из обеих таблиц.
    
    ```sql
    SELECT employees.name, departments.name
    FROM employees
    INNER JOIN departments ON employees.department_id = departments.id;
    ```
    
2. **LEFT JOIN**: Возвращает все записи из левой таблицы и совпадающие записи из правой.
    
    ```sql
    SELECT customers.name, orders.id
    FROM customers
    LEFT JOIN orders ON customers.id = orders.customer_id;
    ```
    
3. **RIGHT JOIN**: Возвращает все записи из правой таблицы и совпадающие записи из левой.
4. **FULL OUTER JOIN**: Возвращает все записи из обеих таблиц, включая несовпадающие.

#### b. **Подзапросы (Subqueries)**

- Используются для вложенных запросов.
    
    ```sql
    SELECT name, salary
    FROM employees
    WHERE salary > (SELECT AVG(salary) FROM employees);
    ```
    

#### c. **Объединение запросов**

- `UNION` и `UNION ALL`:
    
    ```sql
    SELECT id, name FROM table1
    UNION
    SELECT id, name FROM table2;
    ```

### **3. Индексы и производительность**

#### a. **Что такое индекс?**

- Индекс ускоряет поиск данных в таблице.
- Создается с помощью:
    
    ```sql
    CREATE INDEX idx_name ON employees (department_id);
    ```
    

#### b. **Виды индексов**

- Простые (`Single-column`): Для одного столбца.
- Составные (`Composite`): Для нескольких столбцов.
    
    ```sql
    CREATE INDEX idx_composite ON employees (department_id, salary);
    ```
    
- Уникальные (`UNIQUE`):
    
    ```sql
    CREATE UNIQUE INDEX idx_unique ON employees (email);
    ```
    

#### c. **Когда индекс не используется?**

- Для небольших таблиц.
- При использовании функций (`LOWER(column_name)`).
- При работе с очень низкой избирательностью (например, `WHERE gender = 'M'` при почти равномерном распределении значений).

#### d. **EXPLAIN**

- Для анализа производительности запроса.
    
    ```sql
    EXPLAIN SELECT * FROM employees WHERE department_id = 1;
    ```

### **4. Нормализация и денормализация**

#### a. **Нормализация**

- Процесс организации данных для минимизации дублирования.
- **Основные формы**:
    - **1NF**: У каждого столбца уникальное значение.
    - **2NF**: Удовлетворяет 1NF, все неключевые атрибуты зависят от первичного ключа.
    - **3NF**: Удовлетворяет 2NF, все неключевые атрибуты зависят только от первичного ключа.

#### b. **Денормализация**

- Обратный процесс нормализации, увеличивающий избыточность для ускорения чтения данных.

### **5. Транзакции и ACID**

#### a. **Что такое транзакция?**

- Группа операций, которые выполняются как единое целое.
- Пример:
    
    ```sql
    BEGIN TRANSACTION;
    UPDATE accounts SET balance = balance - 100 WHERE id = 1;
    UPDATE accounts SET balance = balance + 100 WHERE id = 2;
    COMMIT;
    ```
    

#### b. **Свойства ACID:**

1. **Atomicity**: Все операции либо выполняются, либо откатываются.
2. **Consistency**: Данные остаются в согласованном состоянии.
3. **Isolation**: Одновременные транзакции не влияют друг на друга.
4. **Durability**: После завершения транзакции данные сохраняются.

#### c. **Уровни изоляции:**

- **Read Uncommitted**: Могут быть "грязные чтения".
- **Read Committed**: Только подтвержденные данные доступны.
- **Repeatable Read**: Данные остаются неизменными в рамках транзакции.
- **Serializable**: Максимальная изоляция, транзакции выполняются последовательно.

### **6. Расширенные темы**

#### a. **Хранимые процедуры (Stored Procedures)**

- Используются для выполнения повторяющихся задач.
    
    ```sql
    CREATE PROCEDURE AddEmployee(IN name VARCHAR(100), IN salary DECIMAL(10,2))
    BEGIN
        INSERT INTO employees (name, salary) VALUES (name, salary);
    END;
    ```
    

#### b. **Триггеры (Triggers)**

- Выполняются автоматически при определенных событиях (вставка, удаление, обновление).
    
    ```sql
    CREATE TRIGGER update_salary
    AFTER UPDATE ON employees
    FOR EACH ROW
    BEGIN
        INSERT INTO salary_log (employee_id, old_salary, new_salary)
        VALUES (OLD.id, OLD.salary, NEW.salary);
    END;
    ```
    

#### c. **Вьюхи (Views)**

- Представления данных для упрощения работы с таблицами.
    
    ```sql
    CREATE VIEW employee_summary AS
    SELECT department, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department;
    ```
    

#### d. **CTE (Common Table Expressions)**

- Упрощает сложные запросы.
    
    ```sql
    WITH employee_count AS (
        SELECT department_id, COUNT(*) AS count
        FROM employees
        GROUP BY department_id
    )
    SELECT * FROM employee_count WHERE count > 10;
    ```
