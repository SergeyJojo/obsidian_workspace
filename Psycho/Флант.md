
### **Ответы на вопросы по Linux, Go, Kubernetes и системному администрированию**  

---

### **1. Какими способами можно посмотреть файлы, которые были открыты процессом?**  
**Ответ:**  
- `lsof -p <PID>` — список всех открытых файлов процессом.  
- `ls -l /proc/<PID>/fd/` — симлинки на открытые файлы в `/proc`.  
- `strace -e open,openat <command>` — логирование системных вызовов `open`.  

---

### **2. Как определить, почему тормозит приложение, если это бинарник без логов?**  
**Ответ:**  
- **`strace -c <command>`** — профилирование системных вызовов.  
- **`perf top`** — анализ потребления CPU.  
- **`htop`** — просмотр нагрузки на ядра.  
- **`vmstat 1`** — мониторинг нагрузки на память и CPU.  
- **`gdb`** — отладка бинарника (если есть символы).  

---

### **3. Как преобразовать строку в число в Go?**  
**Ответ:**  
```go
import "strconv"

s := "42"
num, err := strconv.Atoi(s)  // string -> int
floatNum, err := strconv.ParseFloat("3.14", 64)  // string -> float64
```

---

### **4. Для чего `defer`?**  
**Ответ:**  
`defer` откладывает выполнение функции до завершения текущей функции.  
**Пример:**  
```go
func readFile() {
    file, _ := os.Open("file.txt")
    defer file.Close()  // Закроет файл при выходе из функции
    // ...
}
```

---

### **5. Для чего `select`?**  
**Ответ:**  
`select` ожидает выполнения одного из операций с каналами:  
```go
select {
case msg := <-ch1:
    fmt.Println(msg)
case <-time.After(1 * time.Second):
    fmt.Println("Timeout")
}
```

### **6. Значение `LoadAverage` в `top` = 1.5 15. Что это значит?**  
**Ответ:**  
Средняя нагрузка за:  
- **1 минуту** = 1.5,  
- **5 минут** = (не указано),  
- **15 минут** = 15.  
**Интерпретация:**  
- `1.5` на 4-ядерном CPU — норма (25% загрузки).  
- `15` — перегрузка (если ядер меньше 15).  

---

### **7. Чем софт-линк отличается от хард-линка?**  
**Ответ:**  
| **Софт-линк (symlink)** | **Хард-линк** |  
|-------------------------|---------------|  
| Ссылка на имя файла | Ссылка на inode |  
| Работает между ФС | Только в одной ФС |  
| Удаляется, если оригинал удалён | Сохраняется, пока есть хард-линки |  

---

### **8. Потребляет ли память зомби-процесс?**  
**Ответ:**  
**Нет.** Зомби (Zombie) — это запись в таблице процессов, которая не занимает память, но блокирует PID.  

---

### **9. CPU Steal time = 10. Что это значит?**  
**Ответ:**  
Виртуальная машина **10% времени ждала** CPU у гипервизора (например, из-за перегрузки хоста).  

---

### **10. TCP — это протокол какого уровня модели OSI?**  
**Ответ:**  
**Транспортный уровень (4).**  

---

### **11. Сколько минимальных узлов нужно, чтобы поднять кластер Kubernetes?**  
**Ответ:**  
- **1 узел** (All-in-one, например, minikube).  
- **Production:** 3 master + N worker (для отказоустойчивости).

### **12. Namespace висит в состоянии Terminating уже сутки. Причины?**  
**Ответ:**  
- Зависли **Finalizers** (например, `kubernetes`).  
- Ресурсы не удаляются (CRD, PVC).  
**Решение:**  
```bash
kubectl get namespace <name> -o json | jq '.spec.finalizers = []' | kubectl replace --raw /api/v1/namespaces/<name>/finalize -f -
```

---

### **13. Что такое глобальная переменная в Go?**  
**Ответ:**  
Переменная, объявленная **вне функций** (доступна во всех файлах пакета).  
```go
var GlobalVar = 42  // Глобальная
func main() {
    fmt.Println(GlobalVar)
}
```

---

### **14. Чем метод отличается от функции?**  
**Ответ:**  
- **Метод** привязан к типу:  
  ```go
  func (u User) GetName() string { return u.Name }
  ```  
- **Функция** независима:  
  ```go
  func GetName(u User) string { return u.Name }
  ```  

---

### **15. Можно ли на Go писать драйверы для ядра Linux?**  
**Ответ:**  
**Нет.** Драйверы пишутся на **C** (Go не имеет низкоуровневого доступа к ядру).

### **16. Расшифровка аббревиатур:**

- **MTU** — Maximum Transmission Unit (макс. размер пакета, например, 1500 байт для Ethernet).

В Kubernetes есть несколько ключевых абстракций для **сетей** и **хранилищ**. Среди них часто встречаются термины **CNI** и **CSI**.

---

## 🔹 CNI (Container Network Interface)

**Что это:**  
CNI — это **стандарт и плагины для сетевого взаимодействия контейнеров**. Его разрабатывает Cloud Native Computing Foundation (CNCF).

**Зачем нужен:**  
Когда Kubernetes запускает Pod, ему нужно:

1. Создать **сетевой интерфейс** (veth, tap и т. д.).
    
2. Назначить **IP-адрес**.
    
3. Настроить маршрутизацию, чтобы Pod мог общаться с другими Pod-ами и внешним миром.
    

Kubelet вызывает CNI-плагин, который выполняет эти шаги.

**Примеры CNI-плагинов:**

- **Calico** — маршрутизация + NetworkPolicy через BGP.
    
- **Flannel** — простая оверлейная сеть (VXLAN/host-gw).
    
- **Cilium** — использует eBPF, мощный контроль безопасности и наблюдаемость.
    
- **Weave Net** — P2P-меш сеть.
    

👉 Без CNI поды не смогут «видеть» друг друга или выходить в интернет.

---

## 🔹 CSI (Container Storage Interface)

**Что это:**  
CSI — это **стандарт для интеграции внешних хранилищ** в Kubernetes.

**Зачем нужен:**  
Pod-ам часто нужны **персистентные данные** (например, база данных). Но у Kubernetes нет встроенной поддержки конкретных СХД (Ceph, NFS, AWS EBS, GCP PD, SAN и т. д.).

Решение:

- CSI-плагин умеет:
    
    - Создавать тома (provisioning).
        
    - Монтировать/отмонтировать к Pod-ам.
        
    - Удалять тома.
        

**Примеры CSI-плагинов:**

- **Rook Ceph CSI** — интеграция Ceph.
    
- **AWS EBS CSI** — тома EBS для Pod-ов.
    
- **GCP PD CSI** — Google Persistent Disks.
    
- **NFS CSI** — подключение к сетевым NFS-шарам.
    

👉 Без CSI Kubernetes не умеет работать с дисками и storage-классами.

---

## 🔹 Связь CNI и CSI

- **CNI** = "Как контейнеры будут общаться" (сеть).
    
- **CSI** = "Где контейнеры будут хранить данные" (диски).
    

И то и другое — это **плагины по стандартам**, которые kubelet вызывает при старте Pod-а.

### 🚀 kubelet — это основной агент Kubernetes, который запускается **на каждом рабочем узле (node)** кластера.

Его задача — следить, чтобы контейнеры (Pods), которые назначил на этот узел **kube-scheduler**, реально работали так, как описано в манифестах.

---

## 🔑 Основные функции kubelet:

1. **Регистрация узла в кластере**
    
    - kubelet сообщает API-server'у, что есть такой узел, его характеристики (CPU, память, диски, сеть).
        
    - Обновляет статус ноды (NodeStatus) — свободные ресурсы, здоровье и т.д.
        
2. **Запуск Pod’ов**
    
    - kube-scheduler решает, на какой ноде запустить Pod, и отправляет описание Pod в kube-apiserver.
        
    - kubelet получает это описание (через watch API) и передаёт контейнеры в **Container Runtime** (например, containerd, CRI-O, раньше Docker).
        
3. **Мониторинг и перезапуск контейнеров**
    
    - kubelet следит за состоянием контейнеров и перезапускает их при падениях (если так указано в `restartPolicy`).
        
    - Собирает логи, метрики и события.
        
4. **Работа с volumes (хранилище)**
    
    - kubelet монтирует тома в Pod'ы (через CSI плагины).
        
    - Отвечает за правильное подключение и отключение storage.
        
5. **Probe (liveness/readiness/startup)**
    
    - kubelet проверяет, жив ли контейнер, готов ли он обслуживать трафик.
        
    - На основе этого kube-proxy и сервисы могут или не могут направлять запросы.
        
6. **Секреты и конфиги**
    
    - kubelet подтягивает `ConfigMap` и `Secret`, монтирует их в Pod'ы.
        

---

## 📊 kubelet не делает:

- **Не решает, где запускать Pod’ы** (этим занимается **kube-scheduler**).
    
- **Не балансирует трафик** (этим занимаются kube-proxy / CNI плагины).
    
- **Не управляет самим кластером** (этим занимается kube-controller-manager).
    

---

## 🔗 kubelet взаимодействует:

- **С kube-apiserver** (получает задачи, отправляет статус).
    
- **С контейнерным runtime (через CRI)** — чтобы реально запускать контейнеры.
    
- **С CSI и CNI** — чтобы подключать storage и сеть.
