###  **Основные моменты про `recover()`**:

- `recover()` должен быть вызван **внутри функции с `defer`**. Только в этом случае он может поймать панику.
- Если `recover()` вызван в функции, которая не является `defer`, паника не будет поймана.
- `recover()` ловит панику только в том **горутине**, в котором она произошла. То есть если паника произошла в одной горутине, а `recover()` находится в другой, то паника не будет перехвачена.
- Если после паники программа не находит соответствующего блока `defer` с `recover()`, программа завершится аварийно.

### Пример с обработкой паники и продолжением работы программы:

```go
package main

import "fmt"

func test() {
	// Паника
	panic("A critical error")
}

func main() {
	defer func() {
		// Поймать панику и продолжить выполнение программы
		if r := recover(); r != nil {
			fmt.Println("Recovered from panic:", r)
		}
	}()

	test()
	fmt.Println("This will be printed after recovery.")
}
```

### 📌 `panic`

```go
// Встроенная функция panic останавливает нормальное выполнение текущей горутины.
// Когда функция F вызывает panic, её выполнение немедленно прерывается.
// Все отложенные (defer) функции внутри F выполняются, как обычно,
// затем F возвращается к своему вызывающему — функции G.
// Для вызывающей функции G вызов F теперь выглядит как вызов panic:
// выполнение G также завершается, отрабатывают её defer-функции и так далее.
// Это продолжается, пока все функции текущей горутины не завершатся — в обратном порядке вызовов.
// В этот момент программа завершает выполнение с ненулевым кодом выхода.
// Эта последовательность называется **panicking** (паника) и может быть прервана с помощью функции recover.
//
// Начиная с Go 1.21, вызов panic с nil-интерфейсом или с необtyped nil
// вызывает **ошибку времени выполнения** (это другой тип паники).
// Переменная окружения GODEBUG с флагом panicnil=1 отключает такую ошибку.
func panic(v any)
```

---

### 📌 `recover`

```go
// Встроенная функция recover позволяет программе управлять поведением горутины в состоянии паники.
// Вызов recover **внутри отложенной функции** (но не внутри функций, которые она вызывает)
// прерывает цепочку паники, возвращает выполнение в нормальный режим
// и возвращает значение ошибки, переданное в вызове panic.
// Если recover вызывается **вне отложенной функции**, он не остановит панику.
// В этом случае, или если горутина не в панике — recover вернёт nil.
//
// До Go 1.21 recover также возвращал nil, если panic вызывался с nil-значением.
// Подробнее см. в описании panic.
func recover() any
```
