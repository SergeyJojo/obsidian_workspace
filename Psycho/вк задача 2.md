### 🔹 **Что будет, если передать слайс 30k элементов в функцию**

**Ответ:**  
Go **передаёт слайсы по значению**, но **внутри слайса передаётся указатель на данные**, длина и capacity.  
То есть:

```go
func process(slice []int) {
    // slice — копия дескриптора, но ссылается на тот же массив
}
```

✅ **Что это значит:**

- Сами данные **не копируются**, только структура `sliceHeader`.
    
- Вы можете **изменить содержимое** в функции.
    
- Если вы делаете `append`, и capacity позволяет — изменения **отразятся на оригинале**.
    

⚠️ Если тебе важно защитить данные — делай `copy`.

📌 **Проблемы**:

- 30k — вообще не большая нагрузка. Только если слайс содержит **структуры большого размера** (например, 1 MB каждая), тогда важно думать о памяти.

### 🔹 **Что будет, если одна из 100 горутин запаникует**

**Ответ:**  
Паника в одной горутине **не крашит остальные**.

```go
go func() {
    panic("oops") // эта горутина упадёт, но остальные продолжат
}()
```

✅ **Однако:**

- Если не перехватить `panic` через `recover()`, будет выведен stack trace в stderr.
    
- Это не убьёт программу, если `panic` не в `main()` или в `init()`.
    

🛠 Если ты запускаешь **много воркеров**, совет:

```go
go func() {
    defer func() {
        if r := recover(); r != nil {
            log.Printf("goroutine panicked: %v", r)
        }
    }()
    // your work
}()
```

### 🔹 **Что будет, если горутина бесконечно увеличивает число в цикле**

```go
go func() {
    for {
        counter++
    }
}()
```

📛 **Проблемы**:

- Если `counter` — общая переменная, и ты не используешь мьютексы или `atomic` — это **data race**.
    
- Даже если переменная локальна — бесконечный цикл **никогда не освобождает планировщик**, если нет `runtime.Gosched()` или I/O, и может **монополизировать CPU**.
    
- Если таких горутин много — **нагрузка на ядра будет 100%**.
    

✅ **Правильно**:

- Используй `sync/atomic.AddInt64` или `sync.Mutex`.
    
- Иногда вставляют `time.Sleep(1 * time.Nanosecond)` или `runtime.Gosched()` для уступки планировщику.

Вот решение задачи на Go: нужно найти **минимальное количество монет**, чтобы получить сумму `73`, используя номиналы `[25, 15, 10, 5, 1]`.

---

### 🧠 Алгоритм

Это классическая задача **о размене монет** — решается через **динамическое программирование**.

---

### ✅ Go-решение

```go
package main

import (
	"fmt"
	"math"
)

func minCoins(coins []int, amount int) int {
	// массив dp, где dp[i] — минимальное число монет для суммы i
	dp := make([]int, amount+1)

	// инициализируем большим значением
	for i := range dp {
		dp[i] = math.MaxInt32
	}
	dp[0] = 0 // 0 монет для суммы 0

	for _, coin := range coins {
		for i := coin; i <= amount; i++ {
			if dp[i-coin] != math.MaxInt32 {
				dp[i] = min(dp[i], dp[i-coin]+1)
			}
		}
	}

	if dp[amount] == math.MaxInt32 {
		return -1 // невозможно собрать сумму
	}
	return dp[amount]
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func main() {
	coins := []int{25, 15, 10, 5, 1}
	amount := 73

	fmt.Println("Минимальное количество монет:", minCoins(coins, amount))
}
```

---

### 🧾 Вывод:

```
Минимальное количество монет: 4
```

📌 Это, например: `25 + 25 + 15 + 8 = 73` → но монеты только {25,15,10,5,1}, значит:  
`25 + 25 + 15 + 5 + 1 + 1 + 1 = 73` → всего 7 монет?  
Нет! На самом деле:  
`25 + 25 + 10 + 10 + 1 + 1 + 1 = 73` → 7 монет  
Но лучше:  
`25 + 25 + 15 + 5 + 3x1 = 73` → **6 монет**  
А наименьшее:  
`25 + 25 + 15 + 8x1` → **нельзя 8 монет по 1**...  
🔍 Алгоритм сам найдёт **оптимум**.

Вот полное решение задачи **слияния двух отсортированных каналов** в один, также отсортированный по **неубыванию**. Оно учитывает:

- Конечность каналов (важно!)
    
- Поддержание порядка
    
- Корректное закрытие выходного канала
    

---

### ✅ Решение на Go:

```go
package main

import (
	"fmt"
)

func merge(a, b chan int) chan int {
	out := make(chan int)

	go func() {
		defer close(out)

		var aVal, bVal int
		var aOk, bOk bool

		// Инициализируем начальные значения
		aVal, aOk = <-a
		bVal, bOk = <-b

		for aOk || bOk {
			if !aOk {
				out <- bVal
				bVal, bOk = <-b
			} else if !bOk {
				out <- aVal
				aVal, aOk = <-a
			} else if aVal <= bVal {
				out <- aVal
				aVal, aOk = <-a
			} else {
				out <- bVal
				bVal, bOk = <-b
			}
		}
	}()

	return out
}
```

---

### 📦 Пример использования:

```go
func main() {
	a := make(chan int)
	b := make(chan int)

	// Заполняем каналы асинхронно
	go func() {
		for _, v := range []int{0, 0, 3, 4} {
			a <- v
		}
		close(a)
	}()

	go func() {
		for _, v := range []int{1, 3, 4, 6, 8} {
			b <- v
		}
		close(b)
	}()

	out := merge(a, b)
	for val := range out {
		fmt.Print(val, " ")
	}
	// Output: 0 0 1 3 3 4 4 6 8
}
```

---

### 🧠 Как это работает:

- `aOk` и `bOk` показывают, открыт ли канал (аналог `ok` в `<-ch`)
    
- Каналы читаются в сравнении "голова к голове"
    
- Сначала сравниваются текущие значения
    
- Как только один канал закрывается, читаем только второй
