
Отличный вопрос. В Go паттерны вроде **rate limiter**, **throttler**, **fan-in**, **fan-out** — это **архетипы работы с горутинами и каналами**, которые повторяются. У них есть **общие структурные элементы**, которые ты можешь освоить один раз и переиспользовать во многих местах.

---

## 🧱 Общие строительные блоки

Вот ключевые элементы, которые встречаются почти в каждом из таких паттернов:

|Компонент|Роль|
|---|---|
|`chan T`|Каналы для передачи данных между горутинами|
|`select {}`|Реакция на несколько событий: таймеры, данные, context.Done() и т.п.|
|`time.Ticker`|Периодическое выполнение (например, для rate limiting)|
|`context.Context`|Контроль завершения (отмена, таймауты)|
|`sync.WaitGroup`|Ожидание завершения всех горутин|
|`close(chan)`|Завершение канала — сигнал, что больше данных не будет|

---

## 🌀 Универсальные заготовки

### 1. **Горутина с каналом и context**

```go
func worker(ctx context.Context, in <-chan string, out chan<- string) {
    for {
        select {
        case <-ctx.Done():
            return
        case val, ok := <-in:
            if !ok {
                return
            }
            out <- process(val)
        }
    }
}
```

- **Проверка контекста** — для отмены.
    
- **Проверка `ok`** — чтобы завершиться, если канал закрыт.
    
- **`process(val)`** — логика обработки.
    

Ты можешь это использовать **в fan-out, throttler, pipeline** — везде.

---

### 2. **Fan-out (разделение работы)**

```go
for i := 0; i < numWorkers; i++ {
    go worker(ctx, jobs, results)
}
```

- Один канал входных данных `jobs` → много воркеров обрабатывают.
    
- Это и есть fan-out.
    

---

### 3. **Fan-in (слияние каналов)**

```go
func merge(channels ...<-chan string) <-chan string {
    out := make(chan string)
    var wg sync.WaitGroup

    output := func(c <-chan string) {
        defer wg.Done()
        for val := range c {
            out <- val
        }
    }

    wg.Add(len(channels))
    for _, ch := range channels {
        go output(ch)
    }

    go func() {
        wg.Wait()
        close(out)
    }()

    return out
}
```

- Это можно использовать в **fan-in**, **логгерах**, **объединении результатов**.
    

---

### 4. **Rate Limiter (через Ticker)**

```go
rate := time.Second / 10 // 10 раз в секунду
limiter := time.NewTicker(rate)

for req := range requests {
    <-limiter.C
    handle(req)
}
```

- `Ticker` — это **ограничитель частоты**, не более X операций в секунду.
    

---

### 5. **Throttler (параллелизм, но с ограничением)**

```go
sem := make(chan struct{}, 5) // максимум 5 параллельных задач

for _, task := range tasks {
    sem <- struct{}{} // блокирует, если уже 5 активных
    go func(t Task) {
        defer func() { <-sem }()
        process(t)
    }(task)
}
```

- Подходит для ограничения количества одновременных операций.

## 📦 Что стоит запомнить и держать в сниппетах

Вот список "паттернов", которые можно превратить в сниппеты:

1. 🔁 **Воркеры с context и каналами** — универсальный шаблон.
    
2. 🔀 **Fan-in** через `merge()` функцию.
    
3. 🧵 **Fan-out** через запуск воркеров.
    
4. ⏱ **Rate Limiter** через `time.Ticker`.
    
5. 🚦 **Throttling** через семафорный паттерн (`chan struct{}` с буфером).
    
6. 🧹 **Контекст + cancel** + `WaitGroup` — шаблон завершения всех горутин.
