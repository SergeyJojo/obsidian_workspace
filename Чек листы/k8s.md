
Вот чек-лист для понимания устройства и архитектуры Kubernetes (K8s), который поможет тебе разобраться в его внутреннем устройстве и компонентах:

### 1. **Архитектура Kubernetes**:

- **Master Node**:
    - **API Server (kube-apiserver)**: Центральная точка взаимодействия с Kubernetes. Обрабатывает запросы от kubectl, и других компонентов Kubernetes, выполняет аутентификацию и авторизацию.
    - **Scheduler (kube-scheduler)**: Выбирает подходящие узлы (nodes) для запуска подов, основываясь на доступных ресурсах и других факторах.
    - **Controller Manager (kube-controller-manager)**: Управляет различными контроллерами (например, репликациями, развертываниями, масштабированием, управлением состоянием подов).
    - **etcd**: Распределенное хранилище данных, которое сохраняет конфигурации и состояние кластера.
- **Worker Node**:
    - **kubelet**: Агент на каждой рабочей ноде, который управляет подами и контейнерами на этой ноде. Отвечает за запуск и мониторинг контейнеров.
    - **kube-proxy**: Обеспечивает сетевой доступ к сервисам внутри кластера, а также балансировку нагрузки между подами.
    - **Container Runtime**: Компонент, который управляет запуском контейнеров, например Docker, containerd или CRI-O.

### 2. **Компоненты Kubernetes**:

- **Pod**:
    
    - Это минимальная единица развертывания в Kubernetes. Поды могут содержать один или несколько контейнеров, которые используют общие ресурсы, такие как сеть и тома.
- **ReplicaSet**:
    
    - Гарантирует, что в кластере всегда существует заданное количество одинаковых подов.
- **Deployment**:
    
    - Обеспечивает управление развертыванием подов и ReplicaSet, автоматизирует обновления и откаты.
- **StatefulSet**:
    
    - Используется для развертывания приложений с состоянием, которые требуют стабильных идентификаторов и персистентных томов.
- **DaemonSet**:
    
    - Обеспечивает запуск подов на каждом узле кластера (или на определенных узлах).
- **Job**:
    
    - Выполняет одноразовые задачи, такие как миграции баз данных или батчи обработки.
- **CronJob**:
    
    - Создает задачи по расписанию, аналогично cron в Unix-системах.

### 3. **Сетевые компоненты**:

- **Service**:
    
    - Абстракция для доступа к подам. Типы сервисов:
        - **ClusterIP** (по умолчанию): Доступ к сервису только внутри кластера.
        - **NodePort**: Открывает доступ к сервису снаружи кластера через порт на каждом узле.
        - **LoadBalancer**: Создает внешний балансировщик нагрузки, если поддерживается облачным провайдером.
        - **ExternalName**: Ссылается на внешний сервис по DNS-имени.
- **Ingress**:
    
    - Управляет входящими HTTP и HTTPS запросами, обеспечивает балансировку нагрузки, SSL-терминацию и маршрутизацию.
- **Network Policies**:
    
    - Правила для управления сетевым трафиком между подами, определение, какие поды могут общаться друг с другом.

### 4. **Хранение данных**:

- **Persistent Volumes (PV)**:
    
    - Абстракция, представляющая физический или облачный диск. PVы существуют независимо от жизненного цикла подов.
- **Persistent Volume Claims (PVC)**:
    
    - Запрос на использование определенного объема хранения. PVC связываются с PV, чтобы предоставить поду доступ к данным.
- **Storage Class**:
    
    - Определяет тип хранилища для динамического выделения томов.
- **EmptyDir**:
    
    - Временный том, который существует, пока существует под. Его можно использовать для хранения данных, которые не требуют постоянного хранения.

### 5. **Управление конфигурациями и секретами**:

- **ConfigMap**:
    
    - Используется для хранения конфигурационных данных в виде пар "ключ-значение", которые могут быть использованы подами.
- **Secret**:
    
    - Для безопасного хранения конфиденциальных данных, таких как пароли, токены или ключи API. Данные секретов хранятся в зашифрованном виде.
- **Secrets Management**:
    
    - Для интеграции с внешними хранилищами секретов (например, HashiCorp Vault или AWS Secrets Manager).

### 6. **Контроллеры и управляемые объекты**:

- **Replication Controller**:
    
    - Обеспечивает поддержание заданного числа подов для приложения. Обычно используется в сочетании с ReplicaSet и Deployment.
- **Horizontal Pod Autoscaler (HPA)**:
    
    - Автоматически масштабирует количество подов на основе нагрузки (например, CPU или памяти).
- **Vertical Pod Autoscaler (VPA)**:
    
    - Автоматически регулирует ресурсы (CPU/память) для подов на основе их использования.
- **Cluster Autoscaler**:
    
    - Автоматически масштабирует количество узлов в кластере на основе загрузки.

### 7. **Управление доступом и безопасности**:

- **RBAC (Role-Based Access Control)**:
    
    - Управление доступом к ресурсам Kubernetes с использованием ролей и привилегий.
- **ServiceAccount**:
    
    - Пользовательские учетные записи для подов для получения доступа к API Kubernetes.
- **Network Policies**:
    
    - Правила, регулирующие, какие поды могут взаимодействовать с другими подами по сети.
- **PodSecurityPolicies**:
    
    - Определяют, какие поды могут запускаться в кластере в зависимости от их конфигурации безопасности.

### 8. **Мониторинг и логирование**:

- **Prometheus**:
    
    - Система мониторинга и оповещения для сбора метрик из Kubernetes и приложений.
- **Grafana**:
    
    - Инструмент для визуализации метрик, собранных Prometheus.
- **Fluentd / EFK (Elasticsearch, Fluentd, Kibana)**:
    
    - Решение для централизованного логирования, которое собирает, анализирует и визуализирует логи из приложений и Kubernetes.
- **Kube-state-metrics**:
    
    - Сервис для экспорта метрик состояния ресурсов Kubernetes (например, состояние подов, репликаций и т.д.).

### 9. **Управление кластером и его состоянием**:

- **kubectl**:
    
    - Основной инструмент для взаимодействия с Kubernetes. Используется для создания, управления и отслеживания объектов в кластере.
- **Kubeadm**:
    
    - Инструмент для создания и управления кластером Kubernetes.
- **Helm**:
    
    - Пакетный менеджер для Kubernetes, который упрощает развертывание приложений и управление конфигурациями через чарты.
- **K3s**:
    
    - Легковесная версия Kubernetes, предназначенная для IoT и малых кластеров.
- **Minikube**:
    
    - Локальное развертывание Kubernetes для разработки и тестирования.

### 10. **Транзакции и планирование**:

- **Affinity/Anti-Affinity**:
    
    - Настройки, которые контролируют, на каких узлах или группах узлов должны запускаться поды, что позволяет эффективно распределять рабочую нагрузку.
- **Taints and Tolerations**:
    
    - Механизм для управления тем, на каких узлах могут запускаться поды в зависимости от "запахов" узлов.
