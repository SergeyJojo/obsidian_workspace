
# **Что сохраняется при переключении контекста: горутины, потоки, процессы**

В операционных системах и среде выполнения Go переключение контекста между разными единицами выполнения требует сохранения и восстановления состояния. Вот детальное сравнение.

---

## **1. Переключение горутин (Goroutine Switch)**
### **Что сохраняется:**
- **Регистры процессора** (RAX, RBX, RSP, RIP и др.) — сохраняются в стеке горутины.
- **Указатель стека (RSP)** — каждая горутина имеет свой стек.
- **Программный счетчик (RIP)** — точка, где была прервана горутина.
- **Состояние планировщика** — например, флаги блокировки (если горутина ожидает канал).

### **Что НЕ сохраняется:**
- **Глобальные переменные** — они общие для всех горутин.
- **Файловые дескрипторы** — управляются процессом, а не горутиной.
- **Состояние кучи (heap)** — общее для всех горутин в процессе.

### **Когда происходит:**
- При вызове `runtime.Gosched()`.
- При блокировке (каналы, мьютексы, системные вызовы).
- Каждые ~10 мс (если горутина не блокируется).

---

## **2. Переключение потоков (Thread Switch)**
### **Что сохраняется:**
- **Контекст процессора** (все регистры: RSP, RIP, RFLAGS, SSE-регистры).
- **Указатель на таблицу страниц (CR3)** — если потоки в разных процессах.
- **Состояние FPU/SSE** (если используется).
- **Локальные переменные потока (TLS)**.
- **Открытые файловые дескрипторы** (если поток разделяет их с процессом).

### **Что НЕ сохраняется:**
- **Память процесса** — общая для всех потоков.
- **Глобальные переменные** — общие для всех потоков процесса.

### **Когда происходит:**
- При системном вызове (например, `read()`).
- При исчерпании кванта времени (обычно 1-10 мс).
- При блокировке (I/O, мьютекс).

---

## **3. Переключение процессов (Process Context Switch)**
### **Что сохраняется:**
- **Полный контекст процессора** (все регистры).
- **Таблица страниц (CR3)** — у каждого процесса своя.
- **Состояние открытых файлов** (позиции в файлах, сокеты).
- **Учетные данные (UID, GID)**.
- **Состояние сигналов** (маска блокировки сигналов).

### **Что НЕ сохраняется:**
- **Виртуальная память процесса** — переключается полностью.
- **Глобальные переменные** — изолированы между процессами.

### **Когда происходит:**
- При системном вызове (если процесс блокируется).
- При прерывании (например, от таймера).
- При явном вызове `sched_yield()`.

---

## **4. Переключение контекста процесса (при перепланировании)**
### **Что сохраняется:**
- **Все, что входит в Process Control Block (PCB)**:
  - Регистры процессора.
  - Состояние памяти (CR3).
  - Информация о файловых дескрипторах.
  - Учетные данные и права.
  - Состояние сигналов.

### **Когда происходит:**
- При исчерпании кванта времени.
- При переходе процесса в состояние ожидания (например, `wait()`).
- При приоритетном вытеснении (например, реального времени).

---

## **Сравнительная таблица**
| Компонент                      | Горутины                | Потоки (Threads)           | Процессы               |
| ------------------------------ | ----------------------- | -------------------------- | ---------------------- |
| **Регистры CPU**               | Да (частично)           | Да                         | Да                     |
| **Стек**                       | Уникальный для горутины | Уникальный для потока      | Общий для всех потоков |
| **Таблица страниц**            | Нет                     | Да (если между процессами) | Да (уникальная)        |
| **Файловые дескрипторы**       | Нет                     | Да (если общие)            | Да                     |
| **Память (heap)**              | Общая                   | Общая                      | Изолированная          |
| **TLS (Thread-Local Storage)** | Нет                     | Да                         | Нет                    |
| **Время переключения**         | ~100 нс                 | ~1-10 мкс                  | ~1-100 мкс             |

---

## **Особенности в Go**
1. **Горутины легче потоков**:
   - Переключение происходит в пользовательском пространстве (без переключения режима CPU).
   - Нет необходимости сохранять FPU/SSE-регистры (если не используется `CGO`).

2. **M:N планирование**:
   - Go-рантайм мультиплексирует горутины на небольшое число потоков ОС.
   - Потоки привязаны к ядрам CPU (через системный планировщик).

3. **Нет переключения таблиц страниц** при смене горутин (так как они в одном процессе).

---

## **Примеры**
### **1. Переключение горутин**
```go
func main() {
    go func() { fmt.Println("Goroutine 1") }()
    go func() { fmt.Println("Goroutine 2") }()
    runtime.Gosched() // Явное переключение
}
```
- Сохраняются: регистры, стек, RIP.
- Не сохраняется: CR3, FD.

### **2. Переключение потоков (в Go через `CGO`)**
```go
// #include <pthread.h>
import "C"

func main() {
    C.pthread_create(...) // Создание нативного потока
}
```
- Сохраняются: все регистры, CR3 (если поток в другом процессе).

### **3. Переключение процессов**
```go
syscall.ForkExec("/bin/ls", []string{"ls"}, nil)
```
- Полное сохранение PCB.

---

## **Вывод**
- **Горутины** — переключение самое дешёвое (только стек + регистры).  
- **Потоки** — дороже (сохраняется FPU, TLS, CR3).  
- **Процессы** — самое дорогое (полное переключение контекста).  

В Go стараются минимизировать переключения потоков ОС, используя легковесные горутины.
