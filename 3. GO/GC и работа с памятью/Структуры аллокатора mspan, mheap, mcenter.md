
Ты привел структуру mspan из исходного кода runtime Go. Это ключевая структура в системе управления памятью Go, представляющая собой span — непрерывный участок памяти, который используется для выделения объектов определенного размера. mspan играет важную роль в куче (heap), управляемой garbage collector (GC), и связывает выделение памяти с потребностями горутин. Давай разберем ее поля, их назначение и как они работают в контексте управления памятью.

---

Общая идея структуры mspan

mspan — это базовая единица выделения памяти в Go. Каждый mspan содержит блок страниц памяти (обычно 8 КБ или больше), разбитый на объекты фиксированного размера (size class). Например, если size class = 16 байт, то mspan может содержать множество 16-байтовых объектов. Эти структуры хранятся в куче и управляются через списки (mSpanList), кэшируются в P (через mcache), и используются для выделения памяти горутинам.

---

Основные группы полей

1. Метаданные и связи

- _ sys.NotInHeap:
    
    - Маркер, указывающий, что эта структура не должна размещаться в куче (heap). Это оптимизация для предотвращения сканирования GC.
        
- next *mspan, prev *mspan:
    
    - Указатели на следующий и предыдущий mspan в двусвязном списке (например, в mSpanList).
        
- list *mSpanList:
    
    - Ссылка на список, в котором находится этот mspan (для отладки).
        

Назначение: Эти поля связывают mspan с другими span’ами в структуре кучи и помогают в отладке.

---

2. Адресация и размер

- startAddr uintptr:
    
    - Адрес первого байта этого span’а в памяти. Вычисляется как s.base().
        
- npages uintptr:
    
    - Количество страниц (обычно по 8 КБ) в этом span’е.
        
- elemsize uintptr:
    
    - Размер одного объекта в этом span’е (вычисляется из spanclass или npages для больших объектов).
        
- limit uintptr:
    
    - Адрес конца данных в span’е (граница памяти).
        

Назначение: Определяют физическое расположение и объем памяти, управляемой этим mspan.

---

3. Управление свободными объектами

- manualFreeList gclinkptr:
    
    - Список свободных объектов для span’ов типа mSpanManual (ручное управление памятью).
        
- freeindex uint16:
    
    - Индекс, с которого начинается поиск следующего свободного объекта в битовой карте allocBits. Если freeindex == nelems, свободных объектов нет.
        
- freeIndexForScan uint16:
    
    - Аналог freeindex, но используется GC для сканирования. Отличается, чтобы GC видел объекты как выделенные только после полной инициализации.
        
- nelems uint16:
    
    - Общее количество объектов в span’е.
        
- allocCount uint16:
    
    - Количество выделенных объектов в span’е.
        
- allocCache uint64:
    
    - Кэш битовой карты allocBits, начиная с freeindex. Содержит инвертированные биты, чтобы быстро находить свободные объекты с помощью ctz (count trailing zeros).
        

Назначение: Эти поля управляют выделением и освобождением объектов внутри span’а, ускоряя поиск свободных мест.

---

4. Битовые карты

- allocBits *gcBits:
    
    - Битовая карта, где каждый бит показывает, выделен ли объект (1 — выделен, 0 — свободен). Начинается с адреса объекта и выровнена по 8 байт.
        
- gcmarkBits *gcBits:
    
    - Битовая карта для GC, указывающая, какие объекты помечены как живые во время сборки мусора.
        
- pinnerBits *gcBits:
    
    - Битовая карта для объектов, закрепленных в памяти (pinned), например, при использовании unsafe. Доступ осуществляется атомарно.
        

Назначение: Используются для отслеживания состояния объектов (выделение, сборка мусора, закрепление). Перемещаются между аренами (free, next, current, previous) во время циклов GC.

---

5. Состояние и GC

- sweepgen uint32:
    
    - Поколение очистки (sweep generation). Сравнивается с глобальным h->sweepgen для определения состояния:
        
        - sweepgen == h->sweepgen - 2: Нужно очистить.
            
        - sweepgen == h->sweepgen: Очищен и готов к использованию.
            
- state mSpanStateBox:
    
    - Состояние span’а (например, mSpanInUse, mSpanFree). Хранится атомарно для потокобезопасности.
        
- needzero uint8:
    
    - Флаг, указывающий, нужно ли обнулить память перед выделением.
        
- allocCountBeforeCache uint16:
    
    - Копия allocCount, сохраненная перед кэшированием span’а.
        

Назначение: Управляют жизненным циклом span’а в контексте GC и повторного использования.

---

6. Специфичные свойства

- spanclass spanClass:
    
    - Класс размера (size class) и флаг noscan (нужно ли сканировать объекты на указатели). Хранится как uint8.
        
- divMul uint32:
    
    - Множитель для деления на elemsize. Оптимизация для вычислений.
        
- isUserArenaChunk bool:
    
    - Указывает, является ли этот span частью пользовательской арены (arena).
        
- userArenaChunkFree addrRange:
    
    - Диапазон свободной памяти для управления пользовательской ареной.
        
- largeType *_type:
    
    - Тип для больших объектов (если span используется для них).
        

Назначение: Определяют специфику span’а (размер объектов, тип использования).

---

7. Синхронизация и специальные записи

- speciallock mutex:
    
    - Мьютекс для защиты списка specials и изменений в pinnerBits.
        
- specials *special:
    
    - Связанный список специальных записей (например, финализаторы), отсортированный по смещению.
        

Назначение: Обеспечивают потокобезопасность и управление дополнительными метаданными.

---

Как это работает?

1. Создание:
    
    - mspan выделяется из кучи (mheap) для определенного размера объектов (size class) или как большой объект.
        
2. Выделение памяти:
    
    - Аллокатор использует freeindex и allocBits для поиска свободного объекта. Если объект найден, он помечается как выделенный, а allocCount увеличивается.
        
3. Сборка мусора:
    
    - GC использует gcmarkBits для пометки живых объектов. После очистки (sweep) allocBits обновляется из gcmarkBits.
        
4. Кэширование:
    
    - mspan кэшируется в mcache процессора P для быстрого доступа.
        

---

Пример использования

Предположим, у нас есть mspan с:

- startAddr = 0x1000, npages = 1 (8 КБ), elemsize = 16, nelems = 512.
    
- Аллокатор выделяет объект:
    
    - Смотрит на freeindex (например, 0).
        
    - Проверяет allocBits, находит свободный бит (0), выделяет объект по адресу 0x1000 + 0*16 = 0x1000.
        
    - Обновляет freeindex и allocCount.

- Управляет: Выделением и освобождением объектов через битовые карты.
    
- Интегрируется: С GC и кэшами процессоров P.
    

mHeap

Ты привел структуру mheap из исходного кода runtime Go. Это центральная структура, представляющая кучу (heap) в системе управления памятью Go. Она управляет всеми выделенными участками памяти (spans), аренами (arenas), и координирует работу с garbage collector (GC). Давай разберем ее поля, их назначение и как они используются в работе runtime.

---

Общая идея структуры mheap

mheap — это глобальная структура, которая хранит состояние всей кучи Go-программы. Она управляет:

- Выделением памяти через mspan (spans).
    
- Организацией памяти в аренах (больших блоках виртуальной памяти).
    
- Координацией с GC для очистки и повторного использования памяти.
    
- Кэшированием и статистикой для оптимизации производительности.
    

mheap — это singleton, доступный через глобальную переменную mheap_ в runtime.

---

Основные группы полей

1. Метаданные и синхронизация

- _ sys.NotInHeap:
    
    - Маркер, указывающий, что эта структура не размещается в куче (для исключения из GC).
        
- lock mutex:
    
    - Мьютекс для защиты структуры mheap. Должен приобретаться только на системном стеке (через g0), чтобы избежать самоблокировки горутины при росте стека.
        

Назначение: Обеспечивают потокобезопасность и исключают mheap из сканирования GC.

---

2. Управление страницами и очисткой

- pages pageAlloc:
    
    - Структура данных для управления выделением страниц памяти в куче.
        
- sweepgen uint32:
    
    - Поколение очистки (sweep generation). Увеличивается на 2 после каждого цикла GC. Используется для координации состояния mspan (см. описание в mspan).
        
- pagesInUse atomic.Uintptr:
    
    - Количество страниц, занятых span’ами в состоянии mSpanInUse.
        
- pagesSwept atomic.Uint64:
    
    - Количество страниц, очищенных в текущем цикле GC.
        
- pagesSweptBasis atomic.Uint64:
    
    - Базовое количество очищенных страниц для пропорциональной очистки.
        
- sweepHeapLiveBasis uint64:
    
    - Базовое значение живой памяти (heapLive) для расчета пропорциональной очистки (записывается с блокировкой).
        
- sweepPagesPerByte float64:
    
    - Коэффициент пропорциональной очистки (записывается с блокировкой, читается без).
        

Назначение: Управляют выделением страниц и пропорциональной очисткой (proportional sweeping), чтобы поддерживать баланс между живой памятью и очищенными страницами.

---

3. Список всех span’ов

- allspans []*mspan:
    
    - Срез всех когда-либо созданных mspan. Каждый span появляется здесь ровно один раз. Память для этого среза управляется вручную и может быть перевыделена при росте кучи. Защищается mheap_.lock.
        

Назначение: Хранит глобальный список всех span’ов для отладки и управления памятью.

---

4. Состояние регенерации страниц

- reclaimIndex atomic.Uint64:
    
    - Индекс следующей страницы для регенерации в allArenas. Если >= 1<<63, регенерация завершена.
        
- reclaimCredit atomic.Uintptr:
    
    - Запасной кредит для дополнительных очищенных страниц (если регенерация превысила запрос).
        

Назначение: Управляют процессом регенерации страниц (page reclamation) для повторного использования памяти.

---

5. Организация памяти (arenas)

- arenas [1 << arenaL1Bits]*[1 << arenaL2Bits]*heapArena:
    
    - Двухуровневая карта арен кучи. Хранит метаданные для каждой арены (больших блоков виртуальной памяти). nil для неиспользуемых регионов. Защищена mheap_.lock.
        
- arenasHugePages bool:
    
    - Указывает, могут ли L2-записи арен поддерживать huge pages (большие страницы памяти).
        
- heapArenaAlloc linearAlloc:
    
    - Предварительно зарезервированное пространство для выделения объектов heapArena (только на 32-битных системах).
        
- arena linearAlloc:
    
    - Предварительно зарезервированное пространство для самих арен (только на 32-битных системах).
        
- allArenas []arenaIdx:
    
    - Список индексов всех замапленных арен. Только для добавления, защищен mheap_.lock.
        
- sweepArenas []arenaIdx:
    
    - Снимок allArenas на начало цикла очистки. Безопасен для чтения при блокировке GC.
        
- markArenas []arenaIdx:
    
    - Снимок allArenas на начало цикла пометки GC. Не изменяется во время цикла.
        
- curArena struct { base, end uintptr }:
    
    - Текущая арена, в которую растет куча. Выровнена по physPageSize.
        

Назначение: Организуют виртуальное адресное пространство кучи в виде арен и отслеживают их использование.

---

6. Центральные свободные списки

- central [numSpanClasses]struct { mcentral mcentral; pad ... }:
    
    - Массив центральных свободных списков (mcentral) для каждого класса размера (spanClass). Поле pad выравнивает элементы по размеру кэш-линии CPU для избежания false sharing.
        

Назначение: Хранят свободные span’ы для каждого размера объектов, доступные глобально.

---

7. Аллокаторы

- spanalloc fixalloc:
    
    - Аллокатор для структур mspan.
        
- cachealloc fixalloc:
    
    - Аллокатор для mcache (кэшей процессоров P).
        
- specialfinalizeralloc fixalloc, specialCleanupAlloc fixalloc, ...:
    
    - Аллокаторы для специальных объектов (финализаторы, очистка, профилирование, достижимость, счетчики закрепления, слабые ссылки).
        
- arenaHintAlloc fixalloc:
    
    - Аллокатор для arenaHints.
        
- speciallock mutex:
    
    - Мьютекс для защиты аллокаторов специальных записей.
        

Назначение: Эффективно выделяют память для внутренних структур кучи.

---

8. Пользовательские арены

- userArena struct { arenaHints *arenaHint; quarantineList mSpanList; readyList mSpanList }:
    
    - Состояние пользовательских арен:
        
        - arenaHints: Список подсказок для размещения новых арен.
            
        - quarantineList: Span’ы, ожидающие освобождения после удаления ссылок.
            
        - readyList: Готовые к повторному использованию пустые span’ы.
            
- cleanupID uint64:
    
    - Счетчик для уникальных идентификаторов операций очистки. Защищен mheap_.lock.
        

Назначение: Управляют пользовательскими аренами (например, для больших объектов).

---

9. Прочее

- arenaHints *arenaHint:
    
    - Список подсказок для размещения новых арен в куче.
        
- unused *specialfinalizer:
    
    - Заглушка для включения типа specialfinalizer в DWARF (отладочную информацию).
        

Назначение: Дополнительные утилиты и отладочная информация.

---

Как это работает?

1. Инициализация:
    
    - mheap создается при старте программы и инициализирует арену виртуальной памяти.
        
2. Выделение памяти:
    
    - Запросы на память обрабатываются через mcache процессоров P, затем через mcentral, и, если нужно, через mheap, который выделяет новые mspan.
        
3. Сборка мусора:
    
    - GC использует sweepgen, pagesSwept, и битовые карты в mspan для очистки памяти.
        
4. Регенерация:
    
    - reclaimIndex и reclaimCredit управляют повторным использованием страниц.

mCentral

Ты привел структуру mcentral из исходного кода runtime Go. Эта структура представляет собой центральный список свободных span’ов в системе управления памятью Go и используется для координации выделения памяти между процессорами (P) и глобальной кучей (mheap). Она работает в связке с mcache (локальный кэш процессора) и mheap, обеспечивая доступ к span’ам определенного размера (size class). Давай разберем ее поля, их назначение и как они функционируют.

---

Общая идея структуры mcentral

mcentral — это часть механизма управления памятью, которая хранит span’ы (участки памяти, представленные структурой mspan) для определенного класса размера (spanClass). Она действует как промежуточный уровень между локальными кэшами mcache (привязанными к P) и глобальной кучей mheap. Основная задача mcentral — предоставлять свободные span’ы для выделения объектов и координировать их очистку (sweeping) с garbage collector (GC).

Каждая mcentral отвечает за один конкретный spanClass (комбинацию размера объекта и флага noscan), и их массив содержится в mheap.central.

---

Поля структуры mcentral

1. Метаданные

- _ sys.NotInHeap:
    
    - Маркер, указывающий, что эта структура не размещается в куче и не должна сканироваться GC. Это оптимизация для внутренних структур runtime.
        

Назначение: Исключает mcentral из управления GC, так как это системный объект.

---

2. Класс размера

- spanclass spanClass:
    
    - Идентификатор класса размера (size class) и флага noscan (указывает, нужно ли сканировать объекты на указатели). Это поле определяет, для каких объектов предназначены span’ы в данном mcentral. Тип spanClass — это uint8, где младшие 7 бит кодируют размер, а старший бит — флаг noscan.
        

Назначение: Связывает mcentral с конкретным типом объектов (например, 16-байтовые объекты без указателей).

---

3. Списки span’ов

- partial [2]spanSet:
    
    - Два множества span’ов, содержащих хотя бы один свободный объект (partially used spans):
        
        - Один набор для очищенных (swept) span’ов.
            
        - Один набор для неочищенных (unswept) span’ов.
            
- full [2]spanSet:
    
    - Два множества span’ов, в которых нет свободных объектов (fully used spans):
        
        - Один набор для очищенных span’ов.
            
        - Один набор для неочищенных span’ов.
            

Тип spanSet: Это структура, представляющая множество mspan, с потокобезопасным доступом (обычно через мьютексы или атомарные операции).

---

Как работают списки и их роли?

partial и full организованы как пары списков, которые меняются ролями на каждом цикле GC. Это связано с процессом очистки (sweeping) и поколением очистки (sweepgen), которое хранится в mheap.sweepgen и увеличивается на 2 после каждого цикла GC.

Логика ролей:

- sweepgen увеличивается на 2 (например, 0 → 2 → 4).
    
- Индексы массивов partial и full вычисляются как:
    
    - Очищенные span’ы: partial[sweepgen/2 % 2] и full[sweepgen/2 % 2].
        
    - Неочищенные span’ы: partial[1 - sweepgen/2 % 2] и full[1 - sweepgen/2 % 2].
        
- Например:
    
    - Если sweepgen = 2:
        
        - sweepgen/2 % 2 = 1: Очищенные в partial[1] и full[1].
            
        - 1 - sweepgen/2 % 2 = 0: Неочищенные в partial[0] и full[0].
            

Динамика:

1. Очистка (sweeping):
    
    - Во время GC неочищенные span’ы из partial[1 - sweepgen/2 % 2] обрабатываются:
        
        - Свободные объекты освобождаются.
            
        - Span’ы, оставшиеся в использовании, переносятся в очищенный набор partial[sweepgen/2 % 2] или full[sweepgen/2 % 2], если они полностью заполнены.
            
    - Неочищенные span’ы постепенно опустошаются либо аллокатором, либо фоновым очистителем (background sweeper).
        
2. Выделение:
    
    - Когда mcache запрашивает span у mcentral, он берет span из partial[очищенные]. Если span становится полным, он перемещается в full[очищенные].
        
3. Цикл:
    
    - После каждого цикла GC роли наборов меняются: бывшие очищенные становятся неочищенными, а неочищенные очищаются.
        

Примечание:

- Некоторые части очистителя могут работать с произвольными span’ами и добавлять их в очищенные списки, не удаляя из неочищенных. Поэтому код, работающий с неочищенными списками, должен игнорировать уже очищенные span’ы.
    

Назначение: Организуют span’ы по их состоянию (наличие свободных объектов и статус очистки), обеспечивая эффективное выделение и повторное использование памяти.

---

Как это работает?

1. Инициализация:
    
    - mcentral создается для каждого spanClass в mheap.central при старте программы.
        
2. Выделение памяти:
    
    - Когда mcache (локальный кэш процессора P) исчерпывает свободные span’ы, он обращается к соответствующему mcentral.
        
    - mcentral выдает span из partial[очищенные]. Если span’ов нет, запрашивается новый из mheap.
        
3. Очистка:
    
    - GC или фоновый очиститель обрабатывает span’ы из partial[неочищенные] и full[неочищенные], освобождая память и обновляя списки.
        
4. Координация:
    
    - После цикла GC sweepgen увеличивается, и списки меняются ролями.
        

---

Пример

Предположим:

- spanClass = 2 (16-байтовые объекты).
    
- sweepgen = 2:
    
    - Очищенные: partial[1] и full[1].
        
    - Неочищенные: partial[0] и full[0].
        

1. mcache запрашивает span:
    
    - Берет из partial[1] (очищенные span’ы с свободными объектами).
        
    - Выделяет объекты, и если span заполняется, переносит его в full[1].
        
2. GC запускает очистку:
    
    - Обрабатывает partial[0] и full[0], перенося очищенные span’ы в partial[1] или full[1].
        
3. После GC: sweepgen = 4:
    
    - Очищенные: partial[0] и full[0].
        
    - Неочищенные: partial[1] и full[1].
        

---

Итог

mcentral — это промежуточный уровень управления памятью в Go:

- Хранит: Span’ы для конкретного spanClass, разделенные на очищенные/неочищенные и частично/полностью заполненные.
    
- Управляет: Выделением span’ов для mcache и их очисткой для GC.
    
- Оптимизирует: Использует два набора списков для минимизации конкуренции и эффективной работы с циклами GC.
    

Если хочешь углубиться (например, как работает spanSet или процесс очистки), или увидеть пример в коде, дай знать!
