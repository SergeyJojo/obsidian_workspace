Сборщик мусора (Garbage Collector, GC) в PHP — это механизм, который **автоматически освобождает память**, занятую объектами и переменными, которые **больше не используются**. Он особенно важен для борьбы с **циклическими ссылками**, которые не могут быть уничтожены простым подсчётом ссылок.

Разберём, **как он устроен "под капотом"** — от базовых принципов до деталей реализации в Zend Engine.

---

## 🔁 1. **Основа: Reference Counting (подсчёт ссылок)**

PHP использует **комбинированный подход**:
- **Основной механизм** — **reference counting** (подсчёт ссылок),
- **Дополнение** — **цикловый сборщик мусора** (для циклических зависимостей).

### Как работает reference counting?
Каждый `zval` (внутренняя структура значения в PHP) содержит поле **`refcount`** — количество переменных, ссылающихся на это значение.

```php
$a = "hello";     // zval("hello").refcount = 1
$b = $a;          // zval("hello").refcount = 2
unset($a);        // refcount = 1
unset($b);        // refcount = 0 → память освобождается
```

✅ **Плюсы**:  
- Быстро, предсказуемо, освобождение сразу после `refcount=0`.

❌ **Минус**:  
- **Не справляется с циклическими ссылками**.

---

## 🔄 2. **Проблема: циклические ссылки**

Пример:
```php
$a = new stdClass();
$b = new stdClass();
$a->b = $b;
$b->a = $a;  // Цикл: $a → $b → $a

unset($a, $b); // refcount у объектов = 1 (ссылаются друг на друга)
// Память НЕ освобождается!
```

→ Без GC такие структуры **утекают в памяти**.

---

## 🧹 3. **Цикловой сборщик мусора (Cycle Collector)**

PHP реализует **алгоритм, основанный на работе Дэвида Уингера (1999)** — модификация алгоритма **"mark-and-sweep"** для reference-counting систем.

### Как он работает?

#### Шаг 1: **Обнаружение потенциальных "корней"**
- Когда создаётся новый `zval` с `refcount >= 2`, он попадает в **буфер корней (root buffer)**.
- Максимум **10 000 элементов** в буфере (по умолчанию).

#### Шаг 2: **Запуск GC**
Когда буфер заполняется, **автоматически запускается сборщик мусора** (или вручную через `gc_collect_cycles()`).

#### Шаг 3: **Алгоритм поиска "мусора"**
1. **Уменьшить `refcount`** у всех элементов в буфере и их зависимостей.
2. **Найти "возможный мусор"** — те, у кого `refcount == 0` после уменьшения.
3. **Восстановить `refcount`** у тех, кто **не мусор** (они достижимы извне).
4. **Удалить оставшиеся** — это и есть **циклический мусор**.

> 💡 Это **не полный обход всей памяти**, а только анализ подграфа из буфера.

## ⚙️ 4. **Управление GC в PHP**

### Проверить статус:
```php
var_dump(gc_enabled()); // bool(true)
```

### Включить/выключить:
```php
gc_enable();
gc_disable();
```

### Запустить вручную:
```php
$cycles = gc_collect_cycles(); // возвращает число собранных циклов
```

### Настройки (в `php.ini`):
```ini
zend.enable_gc = On
```

## 📊 5. **Производительность и накладные расходы**

- **Накладные расходы**: ~10–15% при активном создании объектов.
- **Память**: буфер корней занимает немного памяти.
- **В CLI-скриптах**: GC особенно полезен для долгих процессов (воркеров, демонов).
- **В веб-запросах**: часто **не критичен**, потому что память всё равно освобождается после завершения скрипта.

> 💡 В PHP 8+ GC стал **быстрее и эффективнее** (оптимизации в Zend Engine 4).

## 🧪 6. **Пример: как GC спасает память**

```php
function createCycle() {
    $a = new stdClass();
    $b = new stdClass();
    $a->b = $b;
    $b->a = $a;
    // Без GC: утечка 2 объектов
}

for ($i = 0; $i < 10000; $i++) {
    createCycle();
}

echo "Собрано циклов: " . gc_collect_cycles(); // Например: 20000
```

→ Без GC память росла бы до бесконечности. С GC — стабильно.

## 🆚 7. **GC в PHP vs другие языки**

| Язык | Механизм | Сборка циклов | Предсказуемость |
|------|--------|--------------|----------------|
| **PHP** | Refcounting + Cycle GC | ✅ Да | Высокая (освобождение почти сразу) |
| **Python** | Refcounting + Cycle GC | ✅ Да | Похоже на PHP |
| **Java/JS** | Mark-and-sweep / Generational GC | ✅ Да | Непредсказуемо (паузы) |
| **Go** | Tri-color mark-and-sweep | ✅ Да | Конкурентный, но с паузами |

> 💡 PHP — один из немногих, где **основной механизм — подсчёт ссылок**, а GC — "дополнение".

---

## ❗ 8. **Когда отключать GC?**

Редко, но бывает:
- В **очень производительных CLI-скриптах**, где **нет циклических ссылок**.
- При **ручном управлении памятью** (например, в пулах объектов).

⚠️ Но **не отключай GC без профилирования** — можешь получить утечки.
