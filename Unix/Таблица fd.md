# 🧠 Что такое файловый дескриптор?

> Файловый дескриптор (file descriptor) — это целое число, которое представляет открытый ресурс:  
> - Файл
> - Сокет
> - Pipe
> - stdin/stdout/stderr

Все операции ввода-вывода в Linux происходят через дескрипторы.

---

# 📋 Как устроен файловый дескриптор в процессе?

## 1. Уровень процесса

Каждый процесс имеет свою **таблицу файловых дескрипторов**

```text
struct task_struct {
    ...
    struct files_struct *files;  // ссылка на таблицу дескрипторов
}
```

### a) `files_struct`:

Содержит:
- Массив указателей на `struct file`
- Текущий лимит (`rlimit`)
- Блокировки

### b) Дескриптор — это просто индекс

| FD | Ресурс |
|----|--------|
| 0  | stdin |
| 1  | stdout |
| 2  | stderr |
| 3+ | Открытые файлы, сокеты, pipes и т.д. |

👉 То есть: **файловый дескриптор — это номер в таблице открытых файлов у процесса**

---

## 2. Уровень ядра: что хранится в ядре?

Когда ты открываешь файл или сокет:

```c
fd = open("file.txt", O_RDONLY);
```

→ Ядро делает следующее:

### a) Выделяет дескриптор (например, 3)
- Он уникален для каждого процесса

### b) Создаёт запись в глобальной таблице открытых файлов

```text
struct file {
    const struct file_operations *f_op;
    loff_t f_pos;         // текущая позиция в файле
    struct inode *f_inode;
    atomic_long_t f_count;
    ...
}
```

Это **глобальная структура**, которая описывает **открытый файл/сокет/устройство**

---

### c) Указатель на `file_operations`

```c
struct file_operations {
    ssize_t (*read) (struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write) (struct file *, const char __user *, size_t, loff_t *)
    ...
}
```

Тут определены функции чтения, записи, закрытия и другие методы.

# 🔁 Как всё взаимодействует между процессами и ядром

```text
+---------------------+
| Процесс             |
|                     |
| +-----------------+ |
| | Таблица FD       | | ← открытые файлы у процесса
| +-----------------+ |
+----------↓----------+
           ↓
+---------------------+
| Ядро                |
|                     |
| +-----------------+ |
| | Глобальная      | |
| | таблица файлов   | |
| +-----------------+ |
+----------↓----------+
           ↓
+---------------------+
| Файловая система /  |
| Устройства          |
+---------------------+
```

---

## 📦 Пример: открытие файла

```go
file, err := os.Open("data.txt")
```

Что происходит под капотом:
1. Системный вызов `sys_open()` создаёт дескриптор
2. Ядро выделяет `struct file`, заполняет `f_pos`, `f_inode`
3. Процесс получает дескриптор (например, 3)
4. При чтении/записи используется `sys_read(fd, ...)` / `sys_write(fd, ...)`

# 🛠 Как посмотреть открытые дескрипторы?

```bash
ls -l /proc/<pid>/fd
```

Пример:

```bash
ls -l /proc/1234/fd
```

```text
lrwx------ 1 user user 64 Apr 5 10:00 0 -> /dev/pts/0
lrwx------ 1 user user 64 Apr 5 10:00 1 -> /dev/pts/0
lrwx------ 1 user user 64 Apr 5 10:00 2 -> /dev/pts/0
lr-x------ 1 user user 64 Apr 5 10:00 3 -> /home/user/data.txt
```

## 🔄 Что хранится внутри ядра?

### a) `struct file *` → описание открытого файла
- Уникальна для каждого открытого файла
- Общая между процессами при `fork()`

### b) `struct fdtable` → массив открытых файлов у процесса

```c
struct files_struct {
    ...
    struct fdtable *fdt; // указатель на таблицу дескрипторов
}

struct fdtable {
    unsigned int max_fds;     // максимальное количество дескрипторов
    struct file __rcu **fd;   // массив указателей на struct file*
    ...
};
```

## 🧱 Как выглядит таблица дескрипторов?

```text
Процесс:
+----------------------------+
| fd=0 → stdin               |
| fd=1 → stdout              |
| fd=2 → stderr              |
| fd=3 → data.txt            |
| fd=4 → socket TCP          |
| fd=5 → pipe                |
+----------------------------+
```

## 🧩 Что такое `dup`, `dup2`, `close`?

| Системный вызов | Описание |
|----------------|-----------|
| `open()`        | Возвращает новый дескриптор |
| `close(fd)`     | Закрывает дескриптор |
| `dup(old_fd)`   | Копирует дескриптор |
| `dup2(old_fd, new_fd)` | Копирует дескриптор в конкретную ячейку |
| `fcntl(fd, F_DUPFD)` | Ещё один способ дублирования |

---

## 📊 Сравнение: процесс vs ядро

| Что? | Уровень | Хранится где? |
|------|---------|----------------|
| Файловый дескриптор (int) | Процесс | В `files_struct` |
| `struct file*` | Ядро | В ядре, общая для всех процессов |
| `inode` | Ядро | Указывает на реальный файл |
| `f_pos` | Ядро | Позиция в файле |
| `file_operations` | Ядро | Функции read/write/ioctl и т.д. |
| `rlimit` | Процесс | Лимит открытых дескрипторов |

---

## 🤔 Почему важно знать про дескрипторы?

Потому что:
- Неправильное использование → утечки дескрипторов
- Можно исчерпать лимит (`ulimit -n`)
- Это влияет на производительность серверов
- Сокеты, каналы, mmap — все используют файловые дескрипторы

---

## 🧪 Пример: дублирование дескриптора

```go
oldFd, _ := os.Open("/tmp/file.txt")
newFd, _ := syscall.Dup(int(oldFd.Fd()))
```

Теперь:
- `oldFd` и `newFd` указывают на один и тот же объект в ядре
- Но разные индексы в таблице дескрипторов

---

## 📌 Когда может быть больше дескрипторов?

| Использование | Число дескрипторов |
|---------------|--------------------|
| HTTP-сервер с 100 клиентами | ~100 сокетов |
| Go: `os.File`, `net.Conn` | Все используют дескрипторы |
| Redis, Nginx, PostgreSQL | Много открытых файлов и сокетов |
| `ulimit -n` установлен слишком низко | Получишь "too many open files" |

---

## 🧰 Как проверить и изменить лимит?

```bash
ulimit -n     # посмотреть текущий лимит
ulimit -n 8192  # установить новый
```

Или в `/etc/security/limits.conf`:

```text
* soft nofile 8192
* hard nofile 16384
```

## 🧠 Интересный факт

- Дескрипторы могут быть **разделяемыми**: например, `fork()` делает копию таблицы дескрипторов
- `execve()` обычно закрывает не-0/1/2 дескрипторы (если не установлен `FD_CLOEXEC`)
- `epoll`, `select`, `poll` работают с дескрипторами
- `mmap()` использует дескрипторы файлов
