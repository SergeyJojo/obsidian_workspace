Вот список продвинутых **фишек** Git, которые помогут тебе в сложных ситуациях и сделают работу с репозиторием эффективнее.

---

### 🔥 **Работа с отдельными коммитами**

#### 🔹 `git cherry-pick`

Вытянуть отдельный коммит из другой ветки:

```bash
git cherry-pick <hash>
```

📌 **Пример:**  
Ты сделал важный фикс в `feature-branch`, но теперь он нужен в `main`.

```bash
git checkout main
git cherry-pick a1b2c3d
```

✅ Теперь фикс добавлен в `main`.

#### 🔹 `git revert`

Отменить коммит, создав новый, который его "откатывает":

```bash
git revert <hash>
```

📌 Полезно, если **нужно сохранить историю**, но отменить изменения.

#### 🔹 `git reset`

Откатить изменения **без сохранения** истории (⚠ опасно):

```bash
git reset --hard HEAD~1  # Откатить 1 коммит
git reset --soft HEAD~1  # Оставить изменения в индексе
```

📌 `--soft` сохраняет файлы в **staging**, а `--hard` просто всё удаляет.

### 🏗 **Гибкое управление коммитами**

#### 🔹 `git commit --amend`

Изменить последний коммит (добавить файлы или исправить текст):

```bash
git commit --amend -m "Обновленный коммит"
```

📌 Полезно, если забыл добавить файл или допустил опечатку.

#### 🔹 `git rebase -i`

Изменить историю коммитов (объединить, удалить, исправить):

```bash
git rebase -i HEAD~5
```

📌 Открывается редактор, где можно:

- `pick` – оставить коммит
- `squash` – объединить с предыдущим
- `edit` – изменить коммит
- `drop` – удалить коммит

### 🏗 **Фишки по работе с ветками**

#### 🔹 `git switch`

Более удобная замена `checkout`:

```bash
git switch main
```

📌 Быстрее переключает ветки.

#### 🔹 `git worktree`

Работа с **разными ветками одновременно** (без `checkout`):

```bash
git worktree add ../new-folder feature-branch
```

📌 Теперь у тебя есть две папки с разными ветками.

#### 🔹 `git branch --merged`

Показать **слитые** ветки, которые можно удалить:

```bash
git branch --merged
git branch -d old-branch
```

#### 🔹 `git stash`

Сохранить незакоммиченные изменения перед переключением ветки:

```bash
git stash
git switch другая-ветка
git stash pop  # Вернуть изменения
```

📌 Если надо оставить файлы **неизменёнными**, используй:

```bash
git stash --keep-index
```

### 🔗 **Фишки работы с удалёнными репозиториями**

#### 🔹 `git push --force-with-lease`

Безопасный `force push`, который **не перезапишет** чужие изменения:

```bash
git push --force-with-lease
```

📌 Используй вместо `git push --force`, чтобы избежать конфликтов.

#### 🔹 `git remote prune origin`

Удалить **мертвые ссылки** на удаленные ветки:

```bash
git remote prune origin
```

#### 🔹 `git fetch --prune`

Сразу почистить удаленные ветки и обновить данные:

```bash
git fetch --prune
```

### 🔎 **Просмотр истории и поиска ошибок**

#### 🔹 `git log --oneline --graph --decorate --all`

Красивый и удобный вывод истории коммитов:

```bash
git log --oneline --graph --decorate --all
```

#### 🔹 `git bisect`

Автоматический поиск проблемного коммита:

```bash
git bisect start
git bisect bad  # Указываем, что текущая версия сломана
git bisect good <hash>  # Указываем, что эта версия работала
```

📌 Git сам найдет, **в каком коммите появилась ошибка**.

#### 🔹 `git blame`

Показать, **кто и когда изменил каждую строку** в файле:

```bash
git blame myfile.py
```

#### 🔹 `git diff`

Показать различия между коммитами:

```bash
git diff HEAD~1 HEAD
```

📌 Или просто разницу с последним коммитом:

```bash
git diff
```

### 🚀 **Оптимизация и чистка**

#### 🔹 `git gc`

Удалить мусор и оптимизировать репозиторий:

```bash
git gc --prune=now
```

#### 🔹 `git fsck`

Проверить репозиторий на ошибки:

```bash
git fsck
```

#### 🔹 `git clean -df`

Удалить **неотслеживаемые** файлы (⚠ осторожно!):

```bash
git clean -df
```

📌 Можно добавить `-n`, чтобы сначала посмотреть, что удалится:

```bash
git clean -dn
```

### 🚀 **Фишки для удобства**

#### 🔹 `git config --global alias.lg "log --oneline --graph --decorate --all"`

Добавить **короткую команду** для красивого лога:

```bash
git lg
```

📌 Теперь можно просто писать `git lg` вместо длинного `log`

#### 🔹 `git config --global rerere.enabled true`

Запоминать, как ты решаешь конфликты при мерже:

```bash
git rerere
```

📌 Если ты часто решаешь **одинаковые конфликты**, Git теперь сам их исправит.

2️⃣ `git stash` – спрятать изменения перед переключением ветки  
3️⃣ `git rebase -i` – исправить историю коммитов  
4️⃣ `git log --oneline --graph` – красиво посмотреть историю  
5️⃣ `git push --force-with-lease` – пушить без перезаписи чужих изменений
