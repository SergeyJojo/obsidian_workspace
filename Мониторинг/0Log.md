
Библиотека **0log** в Go — это простой и эффективный логгер, ориентированный на минимальные затраты ресурсов. Она предназначена для использования в высоконагруженных приложениях, где критически важна производительность и низкие накладные расходы при ведении логов.

### Основные принципы работы

0log разработан с акцентом на простоту и производительность. Он предоставляет базовые функции для логирования, но минимизирует оверхед, что позволяет использовать его в ситуациях, когда другие логгеры, такие как `log` из стандартной библиотеки, могут быть слишком медленными или неэффективными.

### Основные характеристики 0log:

- **Мало накладных расходов** — библиотека избегает использования дополнительных структур и операций, которые могут замедлить выполнение приложения.
- **Логирование без форматирования** — 0log минимизирует затраты, не предоставляя богатого форматирования, что делает его быстрее и легче в использовании для простых случаев.
- **Простота использования** — библиотека инкапсулирует простые, но мощные функции логирования.
- **Сериализация данных** — данные логирования могут быть сериализованы в различные форматы, например, в JSON.
- **Асинхронность** — поддержка асинхронной записи логов, что помогает повысить производительность в многозадачных системах.

### Структура библиотеки

Основные компоненты 0log:

1. **Логгер** (`Logger`) — основной объект, который управляет выводом логов. Логгер управляет форматированием, маршрутизацией вывода и асинхронной записью.
    
2. **Запись лога** (`LogEntry`) — структура, которая хранит конкретную запись логов. Это может быть как строковое сообщение, так и структурированные данные.
    
3. **Вывод** (`Output`) — абстракция вывода логов. 0log поддерживает различные виды вывода, например, консоль, файлы или удалённые системы (например, HTTP API или файловые системы).
    
4. **Транспорт** (`Transport`) — отвечает за доставку логов в нужное место. Важно, что транспорт может быть настроен как синхронным, так и асинхронным.
    

### Пример использования библиотеки 0log

Для начала работы с 0log нужно установить библиотеку:

```bash
go get github.com/zero-log/0log
```

Вот пример того, как можно использовать 0log:

```go
package main

import (
	"github.com/zero-log/0log"
	"os"
)

func main() {
	// Создаем новый логгер
	logger := 0log.NewLogger(os.Stdout) // Логировать в стандартный вывод

	// Логируем простое сообщение
	logger.Info("This is an info message")

	// Логируем с контекстом
	logger.WithFields(map[string]interface{}{
		"module": "myModule",
		"user":   "JohnDoe",
	}).Info("User logged in")

	// Логируем ошибку
	err := someFunctionThatReturnsError()
	if err != nil {
		logger.WithFields(map[string]interface{}{
			"error": err.Error(),
		}).Error("An error occurred")
	}
}

// Пример функции, которая может вернуть ошибку
func someFunctionThatReturnsError() error {
	return fmt.Errorf("something went wrong")
}
```

### Принципы работы и возможности

1. **Минимизация затрат**: Основной фокус 0log — это снижение накладных расходов при логировании. Он использует минималистичный подход к формату сообщений и меткам, не добавляя избыточных данных в каждый лог.
    
2. **Асинхронное логирование**: Для предотвращения блокировок и увеличения производительности можно настроить асинхронную запись логов. Это позволяет не блокировать основной процесс при записи логов, а записывать их в фоновом потоке.
    
3. **Поддержка структурированных логов**: Несмотря на свою минималистичность, 0log поддерживает структурированные данные. Вы можете добавлять произвольные метки и данные в логи.
    
4. **Логирование в файл или удалённые сервисы**: 0log позволяет конфигурировать различные типы выводов, такие как запись в файлы, вывод в stdout или отправка данных в удалённые сервисы. Транспорт можно настраивать как синхронным, так и асинхронным.
    
5. **Простота настройки**: Для большинства случаев достаточно просто создать новый логгер и начать использовать его с минимальной настройкой.
    

### Когда использовать 0log

0log будет полезен в следующих случаях:

- Когда нужно логировать данные с минимальными затратами на ресурсы.
- В высоконагруженных системах, где важно минимизировать время на запись логов.
- Когда приложение не нуждается в сложных форматах логов или дополнительных фичах типа уровней логирования.
- Когда нужна высокая скорость записи логов в фоновом режиме, например, при использовании асинхронного логирования.

Библиотека 0log идеально подходит для высоконагруженных Go-приложений, где важна производительность и низкие накладные расходы при логировании. Она позволяет просто и эффективно логировать события, не теряя в производительности, что делает её отличным выбором для ситуаций, где стандартные логгеры, такие как `log`, могут быть слишком медленными.

### Подробности работы с 0log

#### Основные характеристики

1. **Минимизация накладных расходов**: Основная цель **0log** — это логирование с минимальными затратами, как по времени, так и по ресурсам. В отличие от других популярных логгеров, 0log не использует тяжелые операции, такие как форматирование строки, которое может сильно замедлить работу при интенсивном логировании. Библиотека ориентирована на запись логов с низким оверхедом, что делает её отличным выбором для высоконагруженных систем.
    
2. **Интерфейсы и абстракции**:
    
    - **Logger** — главный интерфейс для логирования сообщений. Он предоставляет методы для записи логов с различными уровнями важности, например, `Info()`, `Warn()`, `Error()` и т.д.
    - **LogEntry** — структура, которая хранит информацию о конкретной записи лога, включая сообщение и дополнительные поля (например, метки или контекст).
    - **Field** — дополнительная информация, которая может быть добавлена к каждому логу. Это могут быть данные о пользователе, идентификаторы сессий, временные метки и другие важные контексты.
3. **Асинхронное логирование**: 0log поддерживает **асинхронное логирование**, что позволяет избежать блокировок при записи логов. Это важно в многозадачных приложениях, где каждое логирование может блокировать основной поток выполнения.
    
    В случае асинхронного логирования записи помещаются в очередь, и отдельный горутин их обрабатывает, что позволяет основной логике приложения продолжать работу без задержек.
    
4. **Гибкость вывода**: Логи могут быть направлены в разные каналы вывода:
    
    - **Консоль** (stdout/stderr)
    - **Файлы**
    - **Удалённые системы**, например, через HTTP API или для интеграции с такими системами, как **ELK stack** (Elasticsearch, Logstash, Kibana). 0log позволяет настроить вывод в нужный формат и интегрировать с внешними сервисами.

#### Структура и основные элементы библиотеки

1. **Logger (Основной объект)**:
    
    Логгер — это основной объект, через который выполняется логирование. Он может быть настроен с помощью различных **выводов** и **транспорта**.
    
    Пример создания логгера:
    
    ```go
    logger := 0log.NewLogger(os.Stdout) // Для записи в консоль
    ```
    
2. **LogEntry (Запись лога)**:
    
    Лог-энтеры в 0log имеют дополнительные данные, помимо самого сообщения. Это могут быть произвольные **поля** (key-value), которые позволяют сохранить больше информации для дальнейшего анализа.
    
    Например, добавление дополнительных данных в лог:
    
    ```go
    logger.WithFields(map[string]interface{}{
        "module": "auth",
        "user": "johndoe",
    }).Info("User login")
    ```
    
3. **Field (Поле)**:
    
    Лог-данные могут быть расширены различными дополнительными полями, которые можно добавлять в записи для удобства. Это могут быть идентификаторы сессий, данные о пользователе или метки, которые делают логи более полезными.
    
    Пример добавления произвольных данных:
    
    ```go
    logger.WithFields(map[string]interface{}{
        "user_id": "12345",
        "ip":      "192.168.1.1",
    }).Warn("Suspicious activity detected")
    ```
    

#### Вывод и обработка логов

0log предоставляет несколько способов обработки и маршрутизации логов:

4. **Стандартный вывод (stdout/stderr)** — удобен для простых приложений или при работе с контейнерами.
5. **Файлы** — можно настроить вывод логов в файлы для их дальнейшего анализа. 0log поддерживает ротацию файлов и может писать логи по определенному формату.
6. **Удалённые системы** — через HTTP API можно отправлять логи в удалённые сервисы. Это полезно для интеграции с системами централизованного логирования, такими как **ELK stack** или **Grafana Loki**.

Пример записи в файл:

```go
file, err := os.OpenFile("app.log", os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
if err != nil {
    panic(err)
}
defer file.Close()

logger := 0log.NewLogger(file)
logger.Info("Application started")
```

#### Асинхронное логирование

0log поддерживает асинхронное логирование с использованием внутренних очередей. Это позволяет логировать события в фоновом режиме, не блокируя основной поток выполнения программы. Логи записываются в очередь, а затем на другом горутине или процессе обрабатываются и записываются в хранилище.

Чтобы включить асинхронный режим, просто создайте логгер с включением асинхронной записи:

```go
logger := 0log.NewAsyncLogger(0log.NewLogger(os.Stdout))
logger.Info("This log will be processed asynchronously")
```

#### Поддержка структурированных логов

Одной из ключевых особенностей 0log является поддержка **структурированных логов**. В отличие от традиционных строковых сообщений, которые могут быть трудно интерпретировать, 0log позволяет добавлять произвольные поля в записи. Это может быть полезно для дальнейшего анализа логов с использованием инструментов лог-анализа (например, в ELK stack).

Пример структурированного лога:

```go
logger.WithFields(map[string]interface{}{
    "user": "john_doe",
    "action": "login",
    "status": "success",
}).Info("User action recorded")
```

Такие логи легко обрабатываются и анализируются, например, в Kibana или других инструментах, которые поддерживают парсинг JSON.

#### Поддержка различных форматов

0log позволяет настраивать формат логов. В большинстве случаев логируются сообщения в текстовом формате, но можно настроить вывод в **JSON** или другие форматы для интеграции с внешними сервисами.

Пример записи в JSON:

```go
logger := 0log.NewLogger(os.Stdout)
logger.WithFields(map[string]interface{}{
    "module": "database",
    "query":  "SELECT * FROM users",
}).Json().Info("Query executed")
```
