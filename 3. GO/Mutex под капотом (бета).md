
В Go мьютекс (`sync.Mutex`) устроен достаточно интересно и оптимизирован для разных сценариев работы. Давайте разберём его внутреннее устройство:

### 🔹 Базовая структура (из исходников Go)
```go
type Mutex struct {
    state int32  // Состояние мьютекса (битовая маска)
    sema  uint32 // Семафор для блокировки/разблокировки
}
```

### 🔹 Состояние (state) - битовая маска:
Младшие 3 бита `state` содержат флаги:
1. **mutexLocked** (1 << 0) - мьютекс заблокирован
2. **mutexWoken** (1 << 1) - есть "пробуждённая" горутина
3. **mutexStarving** (1 << 2) - режим "голодания"

Остальные биты (29) - счётчик ожидающих горутин

### 🔹 Основные режимы работы:
1. **Нормальный режим**:
   - Горутины конкурируют за блокировку
   - Первая пришедшая получает доступ
   - Оптимизирован для низких задержек

2. **Режим голодания (starvation mode)**:
   - Активируется, если горутина ждёт >1ms
   - Приоритет отдаётся ожидающим горутинам
   - Предотвращает "голодание" долгоожидающих

### 🔹 Алгоритм работы:
1. **Быстрая попытка (fast path)**:
   - CAS-операция для немедленного захвата
   - Работает, если мьютекс свободен

2. **Медленный путь (slow path)**:
   - Увеличивает счётчик ожидающих
   - Пытается установить флаги
   - При необходимости блокируется на sema

### 🔹 Семафор (sema):
- Использует runtime-семафоры из `runtime.semacquire/semrelease`
- Очередь FIFO для ожидающих горутин
- Реализован через futex на Linux

### 🔹 Оптимизации:
1. **Spin-ожидание** (до ~4 попыток на мультипроцессорах)
2. **Адаптивные алгоритмы** (переключение между режимами)
3. **Inlined fast-path** в коде (проверка без вызова функций)

### 🔹 Пример работы (псевдокод):
```go
func (m *Mutex) Lock() {
    // Fast path: сразу получаем блокировку
    if atomic.CompareAndSwapInt32(&m.state, 0, mutexLocked) {
        return
    }
    
    // Slow path
    m.lockSlow()
}

func (m *Mutex) lockSlow() {
    // Сложная логика с учётом:
    // - spin-ожидания
    // - режима голодания
    // - очереди ожидания
}
```

### 🔹 Важные особенности:
1. **Не реентерабельный** (один поток - одна блокировка)
2. **Несправедливый** (не гарантирует порядок получения)
3. **Нулевое значение** (`var m Mutex`) - рабочий мьютекс

### 🔹 Сравнение с RWMutex:
- `Mutex` проще (нет разделения на read/write)
- Нет оптимизаций для множественного чтения
- Занимает меньше памяти (8 байт vs 24 байта)

Реализация может меняться между версиями Go, но основные принципы сохраняются для обеспечения баланса между производительностью и справедливостью.
