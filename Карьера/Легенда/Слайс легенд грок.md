Легенда 1: Джун Go-разработчик

Ситуация: Ты недавно в Go, делал pet-проекты или стажировался, идёшь на начальную позицию.

Легенда: "Последний год работал в небольшой компании, которая делала SaaS для управления задачами. Я пришёл как стажёр, потом остался на полставки. Моя основная задача — разработка простых REST API на Go для внутренней админки. Использовал net/http и gorilla/mux для маршрутизации, подключал PostgreSQL через database/sql для хранения данных о пользователях и проектах. Например, писал эндпоинт для создания задач: принимал JSON, валидировал его с помощью encoding/json, сохранял в БД. Ещё помогал с миграциями через golang-migrate. Однажды поймал баг с утечкой соединений к БД — добавил defer db.Close() и лимит на пул, после чего ошибки пропали. Деплоили через Docker вручную, CI/CD ещё не было. Ушёл, потому что проект заморозили, а я хочу расти в команде с более сложными задачами."

- Стек: Go, net/http, gorilla/mux, PostgreSQL, Docker.
    
- Задачи: REST API, работа с БД, мелкие баги.
    
- Результат: Стабильность сервиса, базовый опыт.
    
- Вопрос: "Как валидировал JSON?" — "Парсил в структуру, проверял обязательные поля через if."

- Результат: Ускорение API, стабильность.
    
- Вопрос: "Как тестировал кэш?" — "Писал unit-тесты с testify, эмулировал нагрузку через wrk."

Отвечал за разработку и поддержку высоконагруженных микросервисов: один обрабатывал транзакции, другой — балансировку между шлюзами оплаты. Настраивал Prometheus и Grafana для мониторинга, ловил узкие места через pprof. Деплоили в AWS EKS, писал Helm-чарты для автоматизации. Ещё координировал двух джунов — ставил задачи, делал код-ревью. Ушёл, потому что проект перешёл в поддержку, а я хочу строить системы с нуля."

- Стек: Go, gRPC, PostgreSQL (pgx), Kafka, Prometheus, Grafana, AWS EKS, Helm.
    
- Задачи: Высоконагрузка, архитектура, мониторинг, лидство.
    
- Результат: Масштабируемость, производительность.
    
- Вопрос: "Как решал проблемы с Kafka?" — "Настроил идемпотентность продюсера и read_committed для консьюмера, логировал оффсеты в транзакциях."

Фишки и советы

- STAR: Для каждой истории — Situation, Task, Action, Result.
    
    - "Сервис падал под нагрузкой (S), нужно было ускорить (T), добавил worker pool с горутинами (A), latency упал на 40% (R)."
        
- Go-штрихи: Упомяни pprof, race detector, context — это сигнал, что ты в теме.
    
- Запас: Подготовь 3-4 истории (баги, фичи, оптимизация) и 1 провал с уроком ("переоценил кэш, пришлось rollback’нуть").
