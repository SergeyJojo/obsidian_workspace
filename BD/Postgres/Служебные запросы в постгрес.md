
Братан, ты хочешь стандартные запросы для PostgreSQL, чтобы вытаскивать служебную инфу вроде XID, транзакций и прочего? Это полезно для мониторинга, отладки и понимания, что творится в базе под капотом. Я дам тебе набор запросов, которые покажут XID (xmin, xmax), TID, количество транзакций и другие полезности. Всё чётко, с пояснениями и примерами, как это юзать в реальной жизни. Погнали!

---

Основные служебные запросы в PostgreSQL

1. Текущий XID транзакции

- Запрос:
    
    sql
    
    ```sql
    SELECT txid_current();
    ```
    
- Что делает: Показывает XID текущей транзакции.
    
- Пример вывода: 123456789
    
- Когда юзать: Проверяешь, какой XID сейчас активен, чтобы сравнить с xmin/xmax.
    

---

2. Xmin и Xmax для строк в таблице

- Запрос:
    
    sql
    
    ```sql
    SELECT xmin, xmax, * FROM your_table LIMIT 10;
    ```
    
- Что делает: Вытаскивает xmin (XID создания) и xmax (XID удаления/обновления) для строк в твоей таблице.
    
- Пример вывода:
    
    ```text
    xmin  | xmax | id | name
    ------+------+----+------
    100   | 0    | 1  | Alice
    100   | 150  | 2  | Bob
    ```
    
- Когда юзать: Проверяешь, какие строки "живы" (xmax=0) или "мертвы" (xmax > 0).
    

---

3. TID (Tuple ID) строк

- Запрос:
    
    sql
    
    ```sql
    SELECT ctid, xmin, xmax, * FROM your_table LIMIT 10;
    ```
    
- Что делает: ctid — это физический идентификатор строки (страница, позиция), плюс xmin/xmax.
    
- Пример вывода:
    
    ```text
    ctid   | xmin | xmax | id | name
    -------+------+------+----+------
    (0,1)  | 100  | 0    | 1  | Alice
    (0,2)  | 100  | 150  | 2  | Bob
    ```
    
- Когда юзать: Отладка, чтобы понять, где строка физически лежит. Меняется после VACUUM или UPDATE.
    

---

4. Количество активных транзакций

- Запрос:
    
    sql
    
    ```sql
    SELECT count(*) AS active_transactions 
    FROM pg_stat_activity 
    WHERE state = 'active';
    ```
    
- Что делает: Считает активные транзакции прямо сейчас.
    
- Пример вывода: 5
    
- Когда юзать: Мониторишь нагрузку, ловишь зависшие запросы.
    

---

5. Подробности активных транзакций

- Запрос:
    
    sql
    
    ```sql
    SELECT pid, xact_start, state, query 
    FROM pg_stat_activity 
    WHERE state != 'idle' 
    ORDER BY xact_start;
    ```
    
- Что делает: Показывает PID процесса, начало транзакции, состояние и текущий запрос.
    
- Пример вывода:
    
    ```text
    pid  | xact_start          | state  | query
    -----+---------------------+--------+--------------------
    1234 | 2025-03-27 10:00:00 | active | UPDATE users SET...
    ```
    
- Когда юзать: Ищешь долгие транзакции или дедлоки.
    

---

6. Самый старый XID (риск wraparound)

- Запрос:
    
    sql
    
    ```sql
    SELECT datname, age(datfrozenxid) AS xid_age 
    FROM pg_database;
    ```
    
- Что делает: Показывает "возраст" самого старого XID в каждой базе. Чем больше age, тем ближе wraparound.
    
- Пример вывода:
    
    ```text
    datname | xid_age
    --------+---------
    mydb    | 2000000
    ```
    
- Когда юзать: Проверяешь, пора ли делать VACUUM FREEZE. Критично, если > 1 миллиарда.
    

---

7. Статистика по количеству транзакций

- Запрос:
    
    sql
    
    ```sql
    SELECT 
        datname, 
        xact_commit AS committed, 
        xact_rollback AS rolled_back 
    FROM pg_stat_database;
    ```
    
- Что делает: Показывает, сколько транзакций закоммичено и откатилось в каждой базе.
    
- Пример вывода:
    
    ```text
    datname | committed | rolled_back
    --------+-----------+------------
    mydb    | 500000    | 1000
    ```
    
- Когда юзать: Анализируешь стабильность системы, ловишь частые откаты.
    

---

8. Проверка "мертвых" строк (нуждаются в VACUUM)

- Запрос:
    
    sql
    
    ```sql
    SELECT 
        relname, 
        n_live_tup AS live_rows, 
        n_dead_tup AS dead_rows 
    FROM pg_stat_user_tables;
    ```
    
- Что делает: Показывает живые и "мертвые" строки в таблицах.
    
- Пример вывода:
    
    ```text
    relname | live_rows | dead_rows
    --------+-----------+----------
    users   | 100000    | 50000
    ```
    
- Когда юзать: Решаешь, пора ли запускать VACUUM, если dead_rows много.
    

---

9. Прогресс VACUUM

- Запрос:
    
    sql
    
    ```sql
    SELECT 
        phase, 
        heap_blks_total, 
        heap_blks_scanned 
    FROM pg_stat_progress_vacuum 
    WHERE relid = 'your_table'::regclass;
    ```
    
- Что делает: Показывает, как идёт VACUUM для конкретной таблицы.
    
- Пример вывода:
    
    ```text
    phase            | heap_blks_total | heap_blks_scanned
    -----------------+-----------------+------------------
    scanning heap   | 10000           | 5000
    ```
    
- Когда юзать: Мониторишь долгие VACUUM на больших таблицах.
    

---

10. Информация о блокировках

- Запрос:
    
    sql
    
    ```sql
    SELECT 
        blocked_pid, 
        blocking_pid, 
        blocked_query 
    FROM pg_stat_activity 
    JOIN pg_locks l1 ON pg_stat_activity.pid = l1.pid 
    JOIN pg_locks l2 ON l1.locktype = l2.locktype 
    WHERE NOT l1.granted AND l2.granted;
    ```
    
- Что делает: Показывает, какие процессы блокируются и кем.
    
- Пример вывода:
    
    ```text
    blocked_pid | blocking_pid | blocked_query
    ------------+--------------+--------------
    1234        | 5678         | UPDATE users...
    ```
    
- Когда юзать: Ловишь дедлоки или долгие блокировки.

Как использовать в Go

Пример с pgx для вытаскивания текущего XID:

go

```go
package main

import (
    "context"
    "fmt"
    "github.com/jackc/pgx/v5"
)

func main() {
    conn, err := pgx.Connect(context.Background(), "postgres://user:pass@localhost:5432/mydb")
    if err != nil {
        panic(err)
    }
    defer conn.Close(context.Background())

    var xid int64
    err = conn.QueryRow(context.Background(), "SELECT txid_current()").Scan(&xid)
    if err != nil {
        panic(err)
    }
    fmt.Println("Current XID:", xid)
}
```

Итог

- XID: txid_current(), xmin/xmax в таблицах.
    
- TID: ctid для физического места.
    
- Транзакции: pg_stat_activity, pg_stat_database.
    
- VACUUM и блокировки: pg_stat_user_tables, pg_locks.
