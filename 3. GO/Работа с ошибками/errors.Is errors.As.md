В Go для обработки ошибок есть два ключевых метода: **`errors.Is`** и **`errors.As`**. Они служат разным целям, и выбор между ними зависит от того, что именно вы хотите проверить.  

---

## **1. `errors.Is` — проверка на конкретную ошибку**  
**Когда использовать:**  
- Когда нужно проверить, **является ли ошибка конкретным значением** (например, `io.EOF`).  
- Для сравнения с **синглтон-ошибками** (ошибки, созданные через `errors.New` или `fmt.Errorf` без обёрток).  

**Пример:**  
```go
if errors.Is(err, io.EOF) {
    // Обработка случая, когда ошибка — это io.EOF
}
```

**Как работает:**  
- Рекурсивно "разворачивает" (`Unwrap`) цепочку ошибок, чтобы найти точное совпадение.  
- Подходит для встроенных ошибок (`io.EOF`, `sql.ErrNoRows`) и кастомных, если они не обёрнуты в другие типы.  

**Когда не использовать:**  
- Если нужно проверить **тип ошибки**, а не её значение.  

---

## **2. `errors.As` — проверка типа ошибки**  
**Когда использовать:**  
- Когда нужно проверить, **реализует ли ошибка определённый интерфейс или тип**.  
- Для извлечения **дополнительных данных** из ошибки (например, поля кастомной структуры).  

**Пример:**  
```go
var myErr *MyCustomError
if errors.As(err, &myErr) {
    // Обработка случая, когда ошибка имеет тип *MyCustomError
    fmt.Println(myErr.Code) // Доступ к полям структуры
}
```

**Как работает:**  
- Ищет в цепочке ошибок ту, которую можно привести к целевому типу.  
- Если находит — сохраняет её в переданный указатель (`&myErr`).  

**Когда не использовать:**  
- Для сравнения с **конкретными значениями** (например, `io.EOF`).  

---

## **Сравнение в таблице**  
| Критерий                 | `errors.Is`                       | `errors.As`                                |     |
| ------------------------ | --------------------------------- | ------------------------------------------ | --- |
| **Что проверяет**        | Значение ошибки (`err == target`) | Тип ошибки (`err.(type) == target`)        |     |
| **Возвращает**           | `bool` (да/нет)                   | `bool` + записывает в переданный указатель |     |
| **Пример использования** | `if errors.Is(err, io.EOF)`       | `if errors.As(err, &myStructErr)`          |     |
| **Для чего**             | Проверка известных ошибок         | Извлечение структуры/данных из ошибки      |     |

---

## **Примеры**  

### **① `errors.Is` (сравнение значений)**  
```go
if errors.Is(err, sql.ErrNoRows) {
    // Обработка "нет данных в БД"
}
```

### **② `errors.As` (проверка типа)**  
```go
type APIError struct {
    Code    int
    Message string
}

func handleError(err error) {
    var apiErr *APIError
    if errors.As(err, &apiErr) {
        fmt.Printf("API Error: Code=%d, Message=%s\n", apiErr.Code, apiErr.Message)
    }
}
```

---

## **Когда что выбрать?**  
- Используйте **`errors.Is`**, если:  
  - Нужно проверить **конкретную ошибку** (например, `io.EOF`).  
  - Ошибка не содержит дополнительных данных.  

- Используйте **`errors.As`**, если:  
  - Ошибка **реализует кастомный тип** (например, ваша `struct` с полями).  
  - Нужно **извлечь данные** из ошибки (код ошибки, сообщение и т. д.).  

---

## **Важно**  
- Начиная с Go 1.13, **все ошибки должны поддерживать `Unwrap()`** для совместимости с `errors.Is` и `errors.As`.  
- Если вы создаёте кастомные ошибки, оборачивайте их через `fmt.Errorf` с `%w`:  
  ```go
  return fmt.Errorf("context failed: %w", err)
  ```  
  Это позволит `errors.Is` и `errors.As` работать корректно.  

**Плохо:**  
```go
if err == io.EOF { ... } // Не работает с обёрнутыми ошибками!
```

**Хорошо:**  
```go
if errors.Is(err, io.EOF) { ... } // Работает всегда
```  

Выбор между `Is` и `As` делает код надёжнее и удобнее для поддержки!
