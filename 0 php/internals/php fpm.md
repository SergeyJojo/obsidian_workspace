# 🧩 Что такое PHP-FPM

**PHP-FPM (FastCGI Process Manager)** — это **демон**, который управляет пулами PHP-процессов и обрабатывает HTTP-запросы, поступающие от веб-сервера (например, Nginx или Apache).  
Он заменяет старый способ работы PHP — **mod_php** (встраивание в Apache) — и даёт больше контроля и производительности.

---

# ⚙️ Архитектура

Типичная схема:

```
[ Клиент ] → [ Nginx ] → [ FastCGI (unix socket / tcp) ] → [ PHP-FPM ] → [ PHP scripts ]
```

🧠 Расшифруем:

1. Клиент делает HTTP-запрос.
    
2. Nginx видит, что запрашивается `.php` — и **проксирует его в PHP-FPM** через **FastCGI протокол** (обычно по Unix-сокету или TCP-порту).
    
3. PHP-FPM выбирает **один из воркеров**, запускает выполнение скрипта, возвращает результат обратно в Nginx.
    
4. Nginx отдаёт клиенту ответ.
    

---

# 🧱 Основные компоненты PHP-FPM

## 1️⃣ Master process

Главный процесс, который:

- запускает и следит за пулом воркеров,
    
- обрабатывает сигналы (reload, restart),
    
- управляет логикой форков.
    

## 2️⃣ Worker processes

Пулы воркеров — **реальные процессы PHP**, которые обрабатывают запросы.  
Каждый воркер:

- принимает запрос от Nginx через FastCGI,
    
- выполняет PHP-код,
    
- возвращает результат.
    

После ответа воркер **сбрасывает состояние** и ждёт нового запроса (в отличие от `mod_php`, который мог загрязняться памятью).

# 🧩 Пулы процессов

Файл конфигурации (например `/etc/php/8.2/fpm/pool.d/www.conf`):

```ini
[www]
user = www-data
group = www-data
listen = /run/php/php8.2-fpm.sock

pm = dynamic
pm.max_children = 10
pm.start_servers = 2
pm.min_spare_servers = 2
pm.max_spare_servers = 5
```

### Значения:

- **`listen`** — где слушает FPM (Unix-сокет или TCP-порт).
    
- **`pm`** — режим менеджера процессов:
    
    - `static` — фиксированное количество воркеров;
        
    - `dynamic` — FPM регулирует их в зависимости от нагрузки;
        
    - `ondemand` — воркеры создаются только при запросах и умирают при простое (экономия RAM).
        
- **`pm.max_children`** — максимальное количество одновременно работающих PHP-процессов.
    
- **`pm.start_servers`**, `pm.min_spare_servers`, `pm.max_spare_servers` — контроль количества воркеров при `dynamic`.

# 🧮 Как FPM помогает с производительностью

1. **Отделение веб-сервера от интерпретатора PHP**
    
    - Nginx обрабатывает статику и держит десятки тысяч соединений.
        
    - PHP-FPM отвечает только за вычисления — CPU-тяжёлая часть.
        
2. **Пулы процессов**
    
    - Несколько воркеров позволяют обрабатывать несколько запросов параллельно.
        
    - Каждый воркер — изолированная среда выполнения PHP.
        
3. **Распределение нагрузки**
    
    - Можно создать несколько пулов с разными юзерами, лимитами и настройками (например, API и админка отдельно).
        
4. **Persistent ресурсы**
    
    - Воркеры живут долго → можно хранить persistent-соединения (например, к Redis или MySQL) — экономия на коннектах.

# 🔬 Типичные настройки производительности

|Параметр|Назначение|Советы|
|---|---|---|
|`pm.max_children`|Кол-во воркеров|Зависит от RAM и среднего потребления PHP-процесса (считается вручную)|
|`pm.max_requests`|Сколько запросов обрабатывает процесс до перезапуска|Полезно для предотвращения утечек памяти|
|`request_terminate_timeout`|Лимит времени выполнения скрипта|Защищает от зависаний|
|`listen.backlog`|Очередь входящих соединений|Повышай при высокой нагрузке|
|`rlimit_files`|Лимит открытых дескрипторов|Увеличивай для API-нагрузки|

# 📊 Пример диагностики

### Проверить, сколько сейчас воркеров:

```bash
ps aux | grep php-fpm
```

### Проверить состояние FPM:

```bash
systemctl status php8.2-fpm
```

### Включить FPM status page:

В `/etc/php/8.2/fpm/pool.d/www.conf`:

```ini
pm.status_path = /status
```

А в nginx:

```nginx
location ~ ^/(status|ping)$ {
    fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    include fastcgi_params;
    allow 127.0.0.1;
    deny all;
}
```

После этого:

```
curl http://127.0.0.1/status
```

→ покажет метрики: `active processes`, `idle`, `max children reached` и т.д.

# 🔐 Почему PHP-FPM надёжнее `mod_php`

|Критерий|mod_php|PHP-FPM|
|---|---|---|
|Встраивается в веб-сервер|Да|Нет|
|Изоляция пользователей|Нет|Да (через пулы)|
|Настройка под нагрузку|Сложно|Гибко|
|Использование памяти|Высокое|Оптимальное|
|Безопасность|Средняя|Высокая (sandbox-пулы)|

# ⚡ Типичные проблемы и их причины

|Симптом|Возможная причина|
|---|---|
|Сайт "висит", но CPU 0%|Все воркеры заняты → `pm.max_children` слишком мал|
|Ошибка `502 Bad Gateway`|PHP-FPM не успевает ответить / сокет недоступен|
|Большое время ответа|Воркеры обрабатывают долгие скрипты без `max_execution_time`|
|Медленный старт|`ondemand` режим + частые запросы → воркеры не успевают подниматься|
|Утечки памяти|Нет `pm.max_requests` → процессы живут слишком долго|

# 🔧 Где лежат настройки

- `/etc/php/8.2/fpm/php-fpm.conf` — глобальные параметры
    
- `/etc/php/8.2/fpm/pool.d/*.conf` — конфиги пулов
    
- `/var/log/php8.2-fpm.log` — лог работы демона
    
- `/run/php/php8.2-fpm.sock` — сокет (или порт `127.0.0.1:9000`)
