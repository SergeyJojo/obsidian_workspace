
В Go моки (mocks) пишутся для замены настоящих реализаций интерфейсов или внешних зависимостей (БД, API и т.д.) на их "фиктивные" аналоги — **для изолированного тестирования**. Это может делаться вручную или с помощью генераторов, таких как `mockgen`.

---

## 🔧 Основные способы написания моков:

### 1. **Ручной мок**

Подходит для небольших интерфейсов.

```go
type UserRepository interface {
    GetByID(id int) (*User, error)
}

// Ручной мок
type MockUserRepo struct {
    GetByIDFunc func(id int) (*User, error)
}

func (m *MockUserRepo) GetByID(id int) (*User, error) {
    return m.GetByIDFunc(id)
}
```

#### Использование в тесте:

```go
func TestUserService_GetUser(t *testing.T) {
    mockRepo := &MockUserRepo{
        GetByIDFunc: func(id int) (*User, error) {
            return &User{ID: id, Name: "Alice"}, nil
        },
    }

    service := UserService{Repo: mockRepo}
    user, err := service.GetUser(1)
    assert.NoError(t, err)
    assert.Equal(t, "Alice", user.Name)
}
```

---

### 2. **Генерация с `mockgen` (GoMock)**

#### Установка:

```bash
go install go.uber.org/mock/mockgen@latest
```

#### Генерация:

```bash
mockgen -source=user.go -destination=mocks/user_mock.go -package=mocks
```

Где `user.go` содержит ваш интерфейс `UserRepository`.

#### Пример теста:

```go
ctrl := gomock.NewController(t)
defer ctrl.Finish()

mockRepo := mocks.NewMockUserRepository(ctrl)
mockRepo.EXPECT().GetByID(1).Return(&User{ID: 1, Name: "Bob"}, nil)

service := UserService{Repo: mockRepo}
```

---

### 3. **Fake-объекты**

Если нужно тестировать без зависимости от конкретных значений.

```go
type FakeUserRepo struct {
    users map[int]*User
}

func (f *FakeUserRepo) GetByID(id int) (*User, error) {
    if user, ok := f.users[id]; ok {
        return user, nil
    }
    return nil, errors.New("not found")
}
```

Да, ты прав — **мок (mock)** — это по сути **заглушка**, которая **эмулирует поведение реального объекта** (например, базы данных, внешнего API, сервиса и т.п.) с **предсказуемыми результатами**, чтобы можно было протестировать логику программы **в изоляции** от зависимостей.

Но давай разберём чуть глубже — моки бывают разные:

---

### 🔹 Что такое мок?

Мок — это **тестовый двойник**, который:

- Имплементирует тот же интерфейс, что и реальный объект;
    
- Возвращает заранее заданные ответы;
    
- Иногда отслеживает, **что и как к нему обращались** (например, сколько раз вызвали метод, с какими параметрами — это уже не просто stub, а именно mock).
    

---

### 🔹 Какие бывают типы тестовых двойников?

|Тип|Назначение|
|---|---|
|**Stub**|Заглушка, возвращающая фиксированные данные. Никакой логики.|
|**Mock**|Может проверять, вызывался ли метод, с какими аргументами. Может вести себя по-разному в зависимости от входа.|
|**Fake**|Упрощённая, но рабочая реализация (например, in-memory база вместо настоящей).|
|**Spy**|Следит за вызовами и аргументами (часто используется вместе с mock).|
|**Dummy**|Просто объект, который нужен для вызова метода, но сам не используется (например, `nil` или пустая структура).|

### 🔹 Пример мока в Go:

Допустим, у нас есть интерфейс:

```go
type UserRepository interface {
    GetByID(ctx context.Context, id int) (*User, error)
}
```

Мок:

```go
type MockUserRepo struct {}

func (m *MockUserRepo) GetByID(ctx context.Context, id int) (*User, error) {
    return &User{ID: id, Name: "Test"}, nil
}
```

Теперь в тесте:

```go
func TestGetUserByID(t *testing.T) {
    repo := &MockUserRepo{}
    service := NewUserService(repo)

    user, err := service.GetUserByID(context.Background(), 1)

    require.NoError(t, err)
    require.Equal(t, "Test", user.Name)
}
```

### 🔹 Автоматическая генерация моков

Ты можешь использовать [**mockgen** из пакета `golang/mock`](https://pkg.go.dev/github.com/golang/mock) или [**moq**](https://github.com/matryer/moq) для генерации моков по интерфейсам. Это полезно, если интерфейс сложный.
