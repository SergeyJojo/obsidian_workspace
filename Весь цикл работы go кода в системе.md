## 🧭 Уровни и этапы: от Go до процессора

---

### 🔹 1. **Go код** (User space, уровень приложения)

```go
func main() {
    x := add(2, 3)
    fmt.Println(x)
}

func add(a, b int) int {
    return a + b
}
```

- Компилятор (`gc`) компилирует Go-код в машинный код (через SSA-оптимизации, escape-анализ и др.).
    
- Функция `add` преобразуется в инструкции для архитектуры (например, x86-64).
    
- `fmt.Println` вызывает системный вызов (`write` через `runtime`).
    

---

### 🔹 2. **Go runtime и ABI**

- `main` вызывается из `runtime.main`.
    
- Stack, heap и goroutine управляются `runtime` Go.
    
- Переход между функциями осуществляется по ABI (Application Binary Interface).
    
- Сборка мусора (GC) проверяет, какие объекты достижимы.
    

---

### 🔹 3. **Syscall: переход в ядро**

- `fmt.Println` вызывает `write` → вызывает **системный вызов** `write` (через `syscall.Syscall`).
    
- В Linux/Unix системный вызов — это переключение в ядро через `int 0x80`, `syscall`, или `sysenter`.
    
- Контекст переключается: CPU переходит из user space в kernel space.
    

---

### 🔹 4. **Ядро ОС (Kernel space)**

- Ядро получает параметры системного вызова через регистры.
    
- `write(fd, buf, len)` пишет в буфер терминала (stdout).
    
- Ядро проверяет права доступа, блокирует ресурсы (если нужно).
    
- Переходит к взаимодействию с драйверами устройства вывода.
    

---

### 🔹 5. **Виртуальная память (MMU)**

- CPU работает **только с виртуальными адресами**.
    
- MMU (Memory Management Unit) преобразует виртуальный адрес в **физический** через **страничную таблицу (Page Table)**.
    
- Используется кэш TLB (Translation Lookaside Buffer) для ускорения.
    
    - Если адрес найден в TLB → используется немедленно.
        
    - Если нет → MMU ищет в page table, может вызвать page fault (если страница не загружена).
        

---

### 🔹 6. **Процессор: кэш и память**

#### Доступ к памяти происходит так:

```
Register → L1 Cache → L2 Cache → L3 Cache → RAM → Page Fault → Disk/Swap
```

1. CPU исполняет инструкцию (например, `MOV`, `ADD`, `CALL`).
    
2. Заглядывает в L1-кэш: если данные там → быстро.
    
3. Если промах (miss) → проверяет L2, затем L3.
    
4. Если промах везде → обращается в RAM (медленно).
    
5. Если страница в RAM отсутствует (page fault) → ОС загружает её с диска.
    

---

### 🔹 7. **Возврат: из ядра обратно в приложение**

- Когда `write()` завершён:
    
    - Ядро возвращает управление пользователю.
        
    - Результат возвращается в регистры.
        
- Go runtime получает результат, продолжает выполнение.
    
- `fmt.Println` завершает вывод.
    

---

### 🔹 8. **Завершение цикла**

- Все инструкции, кэш, память работают синхронно.
    
- Go runtime может в фоне запускать GC.
    
- Планировщик Go (M:N) переключает goroutines.
    
- CPU продолжает исполнение инструкций Go-программы.
    

---

## 📌 Визуально как слои

```
[Go Code] → [Go Runtime] → [Syscall] → [Kernel] → [MMU + Page Tables]
        ↓                ↓           ↓            ↓
   Stack/Heap       write()       Scheduler      Virtual → Physical Addr
                          ↓
                     [CPU Registers]
                          ↓
              [L1 → L2 → L3 Cache → RAM → Disk]
```

---

## 💡 Ключевые технологии

|Компонент|Назначение|
|---|---|
|MMU|Преобразует виртуальный адрес в физический|
|TLB|Кэш преобразований адресов|
|Syscall|Интерфейс приложения и ядра|
|Go Runtime|Управляет памятью, планировщиком, goroutines|
|Scheduler (kernel)|Планирует процессы/потоки|
|CPU pipeline|Исполняет инструкции, работает с регистрами|
|Кэш CPU (L1–L3)|Быстрый доступ к данным без RAM|
