Сергей, в Laravel **нет фиксированного списка сущностей**, как в каком-то фреймворке типа Symfony или в строго типизированной DDD-системе.  
Но в **типичном коммерческом Laravel-проекте** есть набор _основных сущностей фреймворка_ и _архитектурных сущностей_, которые используются почти всегда.

Разделю их на 2 группы:

---

# 🏛 1. **Сущности уровня фреймворка Laravel (встроенные)**

Это базовые элементы, которые Laravel предоставляет "из коробки".

### ✔ **1.1. Models (Модели)**

Работа с БД. Один класс — одна таблица.  
Главная точка входа для доменной логики + Eloquent ORM.

### ✔ **1.2. Migrations (миграции)**

Изменение схемы БД: создание таблиц, индексов, колонок.

### ✔ **1.3. Seeders (сидеры)**

Наполнение БД начальными данными.

### ✔ **1.4. Factories**

Генерация тестовых данных (для тестов, Faker).

### ✔ **1.5. Controllers**

Принимают запросы, вызывают сервисы, возвращают ответы.

### ✔ **1.6. Requests**

Валидация входных данных + авторизация.

### ✔ **1.7. Routes**

Определяют эндпоинты (API, WEB).

### ✔ **1.8. Middleware**

Фильтры на запросы: аутентификация, rate limit, CORS, логирование и т.д.

### ✔ **1.9. Jobs (Очереди)**

Фоновые задачи: обработка изображений, рассылки, интеграции.

### ✔ **1.10. Events**

События, которые происходят в системе.

### ✔ **1.11. Listeners**

Реакция на события.

### ✔ **1.12. Notifications**

Уведомления: email, Slack, Telegram, SMS.

### ✔ **1.13. Policies / Gates**

Авторизация по ролям (RBAC, ACL).

### ✔ **1.14. Commands (Console Commands)**

Консольные команды artisan.

### ✔ **1.15. Services providers**

Регистрация зависимостей, bootstrapping приложения.

### ✔ **1.16. Blade Views**

Шаблоны для фронта.

---

# 🧱 2. **Сущности архитектуры (которые создают разработчики)**

В серьезных проектах на Laravel почти всегда есть дополнительные сущности, которые фреймворк не создает сам, но которые нужны для нормального разделения логики.

---

## ✔ **2.1. Services**

Главный слой бизнес-логики.

Сущности:

- `UserService`
    
- `OrderService`
    
- `PaymentService`
    
- `InventoryService`
    

Они управляют процессами, транзакциями, вызовами сторонних API.

---

## ✔ **2.2. Repositories**

Отвечают за доступ к БД через модели.  
Слой абстракции, чтобы вынести SQL/Eloquent отдельно.

Например:

- `UserRepository`
    
- `OrderRepository`
    

---

## ✔ **2.3. DTO (Data Transfer Objects)**

Структуры данных, которые используются между слоями.

Например:

- `CreateOrderDTO`
    
- `UpdateProfileDTO`
    

---

## ✔ **2.4. Enums**

Часто используются с PHP 8.1+

Например:

- `OrderStatus`
    
- `UserRole`
    

---

## ✔ **2.5. Interfaces**

Контракты для подмены реализиции сервисов.

Например:

- `PaymentGatewayInterface`
    
- `SmsSenderInterface`
    

---

## ✔ **2.6. Exceptions**

Собственные ошибки для доменной логики.

Например:

- `InsufficientStockException`
    
- `UserBlockedException`
    

---

## ✔ **2.7. Helpers / Utils**

Функции или классы для повторяющейся логики:

- форматирование дат
    
- работу с массивами
    
- обёртки над внешними API
