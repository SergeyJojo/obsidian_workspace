2. **Какие знаешь виды инвалидирования кеша, пользовались ли ими, если да, то какими?**
    
    - Инвалидирование кеша бывает различных видов, например:
        - **Время жизни (TTL)**: после истечения времени кеш считается устаревшим.

3. **Какая разница pub/sub и Message Queue?**
    
    - **Pub/Sub (Publish/Subscribe)**: Модель, где отправитель сообщений (публикатор) отправляет данные всем подписчикам. Здесь нет гарантированной доставки и порядок сообщений может не быть сохранен.
    - **Message Queue**: Модель, где сообщения отправляются в очередь, и получатели могут забрать сообщения по мере готовности, с гарантией доставки и возможности обработки сообщений в определенном порядке.

7. **В чем разница между виртуализацией и контейнеризацией?**

**Вопросы по стеку:**

1. **Какими индексами пользуешься в PostgreSQL?**
    
    - Основными индексами в PostgreSQL являются **B-tree**, **Hash**, **GiST** (Generalized Search Tree), **GIN** (Generalized Inverted Index), **SP-GiST**, **BRIN** (Block Range INdex). Я использую B-tree для большинства запросов, так как он является наиболее универсальным и подходит для операций с равенством и диапазонами.
2. **В каких случаях нужно применять B-tree, а в каких хеши?**
    
    - **B-tree** используется для большинства случаев, например, для поиска по диапазонам и равенствам, а **Hash** индексы полезны для быстрого поиска по равенству, но не поддерживают диапазонный поиск.
3. **Что такое покрывающие индексы?**
    
    - **Покрывающие индексы** — это индексы, которые содержат все данные, необходимые для выполнения запроса. Это позволяет не обращаться к основной таблице, а просто использовать индекс для получения всех нужных данных.
4. **Составные индексы. Таблица: Люди. Поля: Фамилия, Имя, Отчество. Создаем индекс по 2м полям (фамилия, имя), какие запросы могут использовать этот индекс?**
    
    - Составной индекс по полям `Фамилия` и `Имя` будет использоваться для запросов, которые фильтруют данные по этим полям, например:
        
        ```sql
        SELECT * FROM Люди WHERE фамилия = 'Иванов' AND имя = 'Иван';
        ```
        
5. **Explain/Explain Analyze что показывает, из чего можно делать выводы по индексу и как его анализировать, что учесть?**
    
    - **EXPLAIN** показывает план выполнения запроса. **EXPLAIN ANALYZE** выполняет запрос и показывает фактическое время выполнения, включая использование индексов. Нужно смотреть на использование индексов, стоимость операций и наличие "Seq Scan" (полного сканирования) вместо использования индексов.
6. **В PostgreSQL какие изоляции, что они защищают?**
    
    - PostgreSQL поддерживает **READ COMMITTED**, **REPEATABLE READ** и **SERIALIZABLE**. Уровни изоляции защищают от феноменов, таких как **неповторяющиеся чтения**, **грязные чтения** и **фантомные чтения**.
7. **Что такое транзакции? Какие в PostgreSQL условия изоляции?**
    
    - Транзакция — это атомарная единица работы с базой данных. Условия изоляции в PostgreSQL позволяют контролировать, как транзакции взаимодействуют друг с другом и какие данные видны в процессе выполнения.
8. **Какую библиотеку для работы с PostgreSQL используешь? По сравнению с другими не сравниваешь? Почему ркх хороши?**
    
    - Я использую `pq` (для Go) или `psycopg2` (для Python), так как эти библиотеки просты в использовании, имеют хорошую документацию и активно поддерживаются.
9. **Как работает потребительская группа? Что такое партиции?**
    

- Потребительская группа в Kafka делит нагрузку между несколькими потребителями. Если партиций больше, чем потребителей, то некоторые потребители будут работать с несколькими партициями. Партиции — это способы разделения данных в топиках для параллельной обработки.

10. **Как архитектурно как общались сервисы? Мобилка куда обращается? grpc отличие от rest?**

- Сервисы могут общаться через **REST**, **gRPC**, **WebSockets** и другие. Мобильные приложения могут обращаться к серверу через **REST API** или **gRPC** в зависимости от скорости и требований. **gRPC** быстрее, так как использует двоичный формат передачи данных и HTTP/2.

**Вопросы по Go:**

11. **Горутины, планировщик как работает? По каким критериям горутины переключаются?**

- Горутины — это легковесные потоки. Планировщик Go использует алгоритм **M:N**, где несколько горутин выполняются на одном или нескольких потоках. Горутины переключаются, когда возникает блокировка (например, ожидание на канале).

12. **GOMAXPROCS что?**

- **GOMAXPROCS** — это переменная, которая определяет количество операционных системных потоков, которые могут работать одновременно. Обычно устанавливается равной числу процессоров на машине.

13. **Примитивы синхронизации виды? atomic что? синк мапа что?**

- **atomic** — это операции, которые выполняются без прерывания, чтобы избежать гонок. **sync.Mutex/RwMutex** — это блокировки для синхронизации горутин, где **Mutex** блокирует весь доступ, а **RwMutex** позволяет читать несколько горутинам одновременно, но блокирует запись.

14. **Каналы. Нужно написать функцию, которая принимает 2 канала и возвращает третий, как это сделать?**

- Можно использовать **select** для работы с несколькими каналами:
    
    ```go
    func merge(chan1, chan2 <-chan int) <-chan int {
        result := make(chan int)
        go func() {
            for {
                select {
                case v := <-chan1:
                    result <- v
                case v := <-chan2:
                    result <- v
                }
            }
        }()
        return result
    }
    ```
    

15. **Типы канала ренжем какие особенности?**

- Когда мы используем **range** с каналом, мы автоматически получаем значения из канала до тех пор, пока он не будет закрыт. Это упрощает чтение данных без необходимости проверок на закрытие.

16. **Как узнать сколько в канале элементов если он буферизирован?**

- Для буферизированных каналов нет прямого способа узнать их длину. Однако можно использовать `len(channel)` для получения количества элементов в канале.

17. **Условия задачи: какие-то сообщения поступают через Kafka и мы должны эти сообщения перенаправить в другую систему.**

- Для решения этой задачи можно использовать горутины, каналы и очереди, чтобы организовать параллельную обработку сообщений и их передачу в другую систему.

18. **Строки? Есть ли способ изменить строку?**

- Строки в Go неизменяемы. Чтобы изменить строку, нужно создать новую строку, например, используя `strings.Replace` или конкатенацию.

19. **Что такое SOLID?**

- **SOLID** — это набор принципов объектно-ориентированного дизайна:
    - **S**: Single Responsibility Principle
    - **O**: Open/Closed Principle
    - **L**: Liskov Substitution Principle
    - **I**: Interface Segregation Principle
    - **D**: Dependency Inversion Principle

20. **Контейнеризация в Docker это?**

- Контейнеризация — это процесс упаковки приложения и его зависимостей в изолированное окружение (контейнер), которое можно развернуть в любом месте.

21. **Виртуализация и контейнеризация отличия?**

- **Виртуализация** создает виртуальные машины с полноценными ОС, а **контейнеризация** использует одну ОС и изолирует процессы внутри контейнеров. В контейнерах процессы легче и быстрее, так как они используют ядро хостовой ОС.

    - go
        
        ```go
        func merge(ch1, ch2 <-chan int) <-chan int {
            out := make(chan int)
            go func() {
                defer close(out)
                for ch1 != nil || ch2 != nil {
                    select {
                    case v, ok := <-ch1:
                        if !ok { ch1 = nil; continue }
                        out <- v
                    case v, ok := <-ch2:
                        if !ok { ch2 = nil; continue }
                        out <- v
                    }
                }
            }()
            return out
        }
        ```
