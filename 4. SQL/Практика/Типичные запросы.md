
Работа бэкендера часто связана с использованием SQL для взаимодействия с базами данных. Вот список самых часто используемых запросов, с примерами, которые бэкендер может использовать в повседневной работе.

---

### 1. **Выборка данных: `SELECT`**

**Простой запрос на выборку всех данных из таблицы:**

```sql
SELECT * FROM users;
```

- Используется для получения всех данных из таблицы, например, для отображения всех пользователей.

**Выборка с фильтрацией:**

```sql
SELECT first_name, last_name, email FROM users WHERE status = 'active';
```

- Получаем только активных пользователей, отбираем конкретные поля.

**Выборка с сортировкой:**

```sql
SELECT id, first_name, last_name FROM users ORDER BY created_at DESC;
```

- Получаем всех пользователей, отсортированных по дате создания в порядке убывания.

**Лимитирование результата:**

```sql
SELECT * FROM orders LIMIT 10;
```

- Выводим только первые 10 записей из таблицы `orders`.

---

### 2. **Вставка данных: `INSERT`**

**Вставка одной строки:**

```sql
INSERT INTO users (first_name, last_name, email, status) 
VALUES ('John', 'Doe', 'john.doe@example.com', 'active');
```

- Добавляем нового пользователя в таблицу.

**Вставка нескольких строк:**

```sql
INSERT INTO products (name, price, category) 
VALUES 
  ('Laptop', 1200, 'Electronics'),
  ('Smartphone', 800, 'Electronics'),
  ('Table', 150, 'Furniture');
```

- Вставляем несколько продуктов за один запрос.

---

### 3. **Обновление данных: `UPDATE`**

**Обновление одной строки:**

```sql
UPDATE users SET status = 'inactive' WHERE id = 123;
```

- Меняем статус пользователя с id = 123 на 'inactive'.

**Обновление нескольких строк:**

```sql
UPDATE orders SET shipping_status = 'shipped' WHERE shipping_status = 'pending';
```

- Обновляем статус всех заказов, которые находятся в статусе 'pending', на 'shipped'.

---

### 4. **Удаление данных: `DELETE`**

**Удаление одной строки:**

```sql
DELETE FROM users WHERE id = 123;
```

- Удаляем пользователя с id = 123.

**Удаление нескольких строк:**

```sql
DELETE FROM orders WHERE order_date < '2025-01-01';
```

- Удаляем все заказы, сделанные до 1 января 2025 года.

---

### 5. **Группировка и агрегация: `GROUP BY`**

**Группировка по столбцу и подсчёт количества:**

```sql
SELECT category, COUNT(*) AS product_count
FROM products
GROUP BY category;
```

- Считаем количество товаров в каждой категории.

**Использование агрегатных функций:**

```sql
SELECT AVG(price) AS average_price FROM products WHERE category = 'Electronics';
```

- Рассчитываем среднюю цену товаров в категории 'Electronics'.

---

### 6. **Соединение таблиц: `JOIN`**

**INNER JOIN** (возвращает только те строки, где есть совпадение в обеих таблицах):

```sql
SELECT u.first_name, u.last_name, o.order_id
FROM users u
INNER JOIN orders o ON u.id = o.user_id;
```

- Получаем все заказы для каждого пользователя.

**LEFT JOIN** (возвращает все строки из левой таблицы, даже если нет совпадений в правой):

```sql
SELECT u.first_name, u.last_name, o.order_id
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;
```

- Получаем всех пользователей, включая тех, у которых нет заказов.

---

### 7. **Подзапросы: `WHERE IN`, `EXISTS`, `SELECT` в `FROM`**

**Подзапрос в `WHERE IN`:**

```sql
SELECT name FROM products WHERE category_id IN (SELECT id FROM categories WHERE name = 'Electronics');
```

- Получаем товары из категории 'Electronics'.

**Подзапрос с `EXISTS`:**

```sql
SELECT first_name, last_name FROM users WHERE EXISTS (SELECT 1 FROM orders WHERE user_id = users.id);
```

- Получаем всех пользователей, у которых есть хотя бы один заказ.

---

### 8. **Обновление с использованием подзапроса:**

**Обновление с подзапросом:**

```sql
UPDATE products
SET price = price * 1.1
WHERE category_id = (SELECT id FROM categories WHERE name = 'Electronics');
```

- Увеличиваем цену всех товаров в категории 'Electronics' на 10%.

---

### 9. **Условные выражения: `CASE`**

**Использование `CASE` для создания условных логик:**

```sql
SELECT order_id, 
       CASE 
           WHEN status = 'shipped' THEN 'Completed'
           WHEN status = 'pending' THEN 'In Progress'
           ELSE 'Unknown'
       END AS order_status
FROM orders;
```

- Возвращаем статус заказа, преобразованный в более читаемую форму.

---

### 10. **Работа с уникальностью и ограничениями**

**Использование `DISTINCT` для уникальных значений:**

```sql
SELECT DISTINCT city FROM customers;
```

- Получаем уникальные города из списка клиентов.

**Использование `LIMIT` и `OFFSET` для пагинации:**

```sql
SELECT * FROM products LIMIT 10 OFFSET 20;
```

- Получаем 10 продуктов, начиная с 21-го (для реализации пагинации).

---

### 11. **Проверка наличия данных: `EXISTS` и `NOT EXISTS`**

**Использование `EXISTS`:**

```sql
SELECT first_name, last_name FROM users
WHERE EXISTS (SELECT 1 FROM orders WHERE user_id = users.id);
```

- Получаем пользователей, у которых есть заказы.

**Использование `NOT EXISTS`:**

```sql
SELECT first_name, last_name FROM users
WHERE NOT EXISTS (SELECT 1 FROM orders WHERE user_id = users.id);
```

- Получаем пользователей, у которых нет заказов.

---

### 12. **Транзакции**

**Начало транзакции:**

```sql
BEGIN TRANSACTION;
```

**Коммит транзакции (сохранение изменений):**

```sql
COMMIT;
```

**Откат транзакции:**

```sql
ROLLBACK;
```

- Транзакции используются для обеспечения атомарности операций, например, при обновлении нескольких таблиц.

---

### Заключение

Бэкендеры используют SQL для выполнения операций с данными в базе данных, таких как выборка, добавление, обновление, удаление, группировка и соединение таблиц. Знание основных запросов и агрегатных функций помогает эффективно взаимодействовать с данными и решать различные задачи, такие как извлечение данных, оптимизация запросов и реализация бизнес-логики.
