4. **Какие боли с PostgreSQL? Пишете запросы, они выполняются и никаких проблем нет?** На практике с PostgreSQL могут возникать проблемы с производительностью при большом объеме данных, особенно если запросы не оптимизированы. Также могут возникать проблемы при масштабировании с большим количеством соединений и низким количеством памяти.
    
2. **Что такое индексы? Каким образом они ускоряют поиск в таблице? Какие бывают индексы? Отличие b-tree от хэш индекса?** Индексы — это структуры данных, которые ускоряют операции поиска, сортировки и фильтрации в базе данных. Они позволяют не сканировать всю таблицу, а сразу переходить к нужным данным. Существует несколько типов индексов:
    
    - **B-tree** — используется для сортированных данных, таких как строки и числа, эффективно работает с диапазонными запросами.
    - **Hash** — используется для поиска точных совпадений. Он быстрее для равенств, но не поддерживает диапазонные запросы. Разница в том, что **B-tree** работает для сортировки и диапазонных запросов, а **Hash** только для точных.
3. **Как в PostgreSQL хранятся данные?** Данные в PostgreSQL хранятся в таблицах в виде строк и столбцов. Внутри таблицы данные физически организованы в **heap** (кучу). Каждая строка данных называется кортежем и может быть связана с уникальным идентификатором (TID).
    
4. **Что такое транзакции? ACID. Рассказать про изоляцию каким способом она достигается? MVCC про него очень хотят услышать.** Транзакции — это набор операций, которые выполняются как единое целое. ACID — это четыре свойства транзакций:
    
    - **Atomicity (Атомарность)** — транзакция либо выполняется полностью, либо не выполняется вовсе.
    - **Consistency (Согласованность)** — транзакция переводит систему из одного корректного состояния в другое.
    - **Isolation (Изолированность)** — транзакции не должны влиять друг на друга.
    - **Durability (Долговечность)** — изменения, внесенные транзакцией, сохраняются даже в случае сбоя системы.
    
    Изоляция достигается с помощью **MVCC (Multi-Version Concurrency Control)**, который позволяет нескольким транзакциям работать параллельно, используя разные версии данных.
    
5. **Что такое VACUUM?** VACUUM — это процесс в PostgreSQL, который очищает таблицы и индексы от "мертвых" строк, которые были удалены или обновлены. Это важно для освобождения пространства и поддержания производительности.

8. **Что такое FOREIGN Key?** **FOREIGN KEY** — это ограничение целостности, которое связывает одну таблицу с другой. Он гарантирует, что значение в столбце с внешним ключом соответствует значению в столбце родительской таблицы, что предотвращает ссылочную целостность.
    
9. **Важна ли последовательность в условиях запроса для составного индекса?** Да, порядок столбцов в составном индексе имеет значение. Индекс эффективен только для запросов, которые используют столбцы в том порядке, в котором они указаны в индексе.
    
10. **Что такое конвейеризация?** Конвейеризация (pipelining) в базе данных позволяет выполнять несколько шагов обработки данных одновременно, не дожидаясь завершения предыдущего шага.
    
11. **Строка 37? Строку "Привет" интерпретирует как массив байт, какая длина строки? 13. **Слайс это? Append?** Слайс — это динамическая структура данных, которая представляет собой часть массива. Слайс может изменять свой размер, а также иметь ссылку на массив. `append` используется для добавления элементов в слайс, увеличивая его размер.
    
14. **Мапа как устроена? Что для программиста означает эвакуация данных на прикладном уровне?** Мапа — это ассоциативный массив, хранящий пары "ключ-значение". В Go мапы реализованы с помощью хеш-таблиц. Эвакуация данных означает удаление данных из памяти или передача данных в другое место, например, сериализация.
    
15. **Конкурентность и параллельность это?** Конкурентность — это способность выполнять несколько задач одновременно (не обязательно параллельно), в то время как параллельность — это выполнение нескольких задач одновременно, на разных процессорах или ядрах.
    
16. **Что такое потоки, горутины и чем они друг от друга отличаются?** Потоки — это единицы выполнения, управляемые операционной системой. Горутины — это легковесные потоки, управляемые Go runtime, которые позволяют эффективно использовать несколько потоков для выполнения задач.
    
17. **Рантайм как работает, как управляет потоками?** Go runtime управляет горутинами, использует планировщик для распределения горутин по доступным ядрам процессора, с минимальными накладными расходами.
    
18. **Чем многозадачность отличается от многопоточности?** Многозадачность — это способность выполнять несколько задач одновременно, не обязательно параллельно. Многопоточность — это использование нескольких потоков для выполнения задач параллельно.
    
19. **Вычисления это? Почему решили дать schedulerу возможность переключаться самостоятельно, зачем добавили выстраивающую?** Вычисления — это процесс получения результата из данных. Go использует встроенный планировщик, который помогает эффективно распределять нагрузку между горутинами.
    
20. **Атомик зачем нужны и от чего защита? Почему гонка возникает и какие примитивы синхронизации?** Атомарные операции позволяют безопасно изменять данные в многозадачной среде без блокировок. Гонка возникает, когда несколько горутин одновременно изменяют одну переменную. Для синхронизации можно использовать мьютексы, каналы или атомарные операции.
    
21. **Каналы? В чем отличие буферизированного канала с буфером 1 и небезопасного синхронного канала?** Каналы — это способ передачи данных между горутинами. Буферизированный канал с буфером 1 может хранить одно значение, а небезопасный канал блокирует горутину до тех пор, пока не получит данные.
    
22. **Select что обеспечивает? Что происходит если один канал не готов передать информацию? Повседневный кейс использования.** `select` позволяет работать с несколькими каналами одновременно. Если один канал не готов, программа переходит к следующему каналу, или выполняет default case, если таковой есть.
    
23. **Контекст? Есть параллельная работа, из верхней горутины ищем контекст, что происходит в нижней горутине? Как проверить контекст?** Контекст используется для управления сроками жизни горутин и передачи метаданных между ними. В дочерней горутине можно проверить контекст, чтобы увидеть, был ли он отменен или превышен лимит времени.
    
24. **Сборщик мусора как работает, зачем нужен? Как работает в языках программирования?** Сборщик мусора автоматически освобождает память, занятую объектами, которые больше не используются. Это помогает избежать утечек памяти.
    
25. **ESB? Это нужно защищать когда пишет код программист, от каких уязвимостей? Какое самое простое sql инъекции, а какие еще? XSS атака как работает?** ESB — это шина передачи сообщений между приложениями. Защита от уязвимостей включает проверку входных данных, использование параметрических запросов для защиты от SQL инъекций, и фильтрацию HTML-контента для защиты от XSS атак.
    
26. **cherry-pick что делает? merge от rebase чем отличается?** `cherry-pick` позволяет взять один или несколько коммитов из другой ветки и применить их к текущей. `merge` объединяет изменения из двух веток, а `rebase` пересаживает одну ветку на основание другой, сохраняя линейную историю.

2. Что такое индексы? Каким образом они ускоряют поиск? Какие бывают индексы? Отличие B-tree от хэш-индекса?

- Ответ: "Индексы — это структуры данных для ускорения поиска в таблице. Вместо полного сканирования PostgreSQL ходит по индексу, снижая сложность с O(n) до O(log n) для B-tree. Например, индекс на user_id позволяет найти запись за логарифмическое время. Типы: B-tree (для диапазонов и сортировки), Hash (для точного равенства), GIN (для массивов, JSON), GiST (геоданные). B-tree хранит упорядоченные ключи в дереве, поддерживает >, <, =. Hash — это хэш-таблица, только =, быстрее для точных совпадений, но не для диапазонов."
    
- Дополнение: "Ставил GIN на JSONB в аналитике — поиск по ключам ускорился в 10 раз."

3. Как в PostgreSQL хранятся данные?

- Ответ: "Данные в PostgreSQL хранятся в файлах на диске в виде страниц (обычно 8 КБ). Каждая таблица — это набор страниц в куче (heap), где строки лежат в порядке вставки. Индексы — отдельные структуры, тоже в страницах. Есть ещё WAL (Write-Ahead Log) для логов транзакций — это последовательный файл для восстановления. MVCC добавляет версии строк в те же страницы, старые помечаются как 'мертвые' до VACUUM."
    
- Дополнение: "Сталкивался с ростом размера из-за 'мертвых' строк, пока не настроил autovacuum."

4. Что такое транзакции? ACID. Как достигается изоляция? MVCC?

- Ответ: "Транзакции — это атомарные операции над БД. ACID: Atomicity (всё или ничего), Consistency (согласованность правил), Isolation (изоляция транзакций), Durability (данные сохраняются после коммита). Изоляция достигается через MVCC (Multi-Version Concurrency Control): каждая транзакция видит снимок данных на момент старта, старые версии строк хранятся для параллельных операций. Уровни: Read Committed, Repeatable Read, Serializable. Например, в Serializable PostgreSQL использует SSI, откатывая конфликты."
    
- Дополнение: "Писал retry-логику для Serializable в Go с pgx, чтобы обработать ошибки."

5. Что такое VACUUM?

- Ответ: "VACUUM — это процесс очистки 'мертвых' строк, которые остаются после UPDATE или DELETE из-за MVCC. Освобождает место в страницах, обновляет статистику для планировщика. VACUUM ANALYZE ещё и собирает данные для pg_statistic. Без него таблицы раздуваются, запросы тормозят."
    
- Дополнение: "Настраивал autovacuum на проекте, чтобы не бегать с ручным VACUUM."

6. Сделал 1 запрос aimed одной строки, транзакция запустится?

- Ответ: "Да, в PostgreSQL каждый запрос неявно запускается в транзакции, даже если это один SELECT. Если не указал BEGIN, он автоматически коммитится после выполнения. Для одной строки это незаметно, но всё равно проходит через MVCC — создаётся снимок."
    
- Дополнение: "Проверял через pg_stat_activity, видел неявные транзакции даже на простых запросах."

7. SAP терма, с помощью какого инструмента достигается согласованность в PostgreSQL?

- Ответ: "Думаю, тут опечатка, имели в виду CAP (Consistency, Availability, Partition Tolerance). PostgreSQL отдаёт приоритет Consistency и Availability в рамках одной ноды. Согласованность достигается через WAL и транзакции: все изменения логируются в WAL, реплицируются на слейвы через streaming replication. Если сеть рвётся, жертвуется Partition Tolerance."
    
- Дополнение: "Настраивал master-slave с WAL для аналитики, задержка репликации была ~50 мс."

8. Что такое FOREIGN Key?

- Ответ: "FOREIGN KEY — это ограничение, связывающее столбец одной таблицы с первичным ключом другой. Обеспечивает ссылочную целостность. Например, в таблице orders столбец user_id ссылается на users(id). Под капотом создаётся индекс для проверки."
    
- Дополнение: "Ставил ON DELETE CASCADE для очистки связанных записей — упростило логику."

9. Важна ли последовательность в условиях запроса для составного индекса?

- Ответ: "Да, для составного индекса (INDEX (a, b)) порядок условий важен. Если запрос WHERE a = 1 AND b = 2, индекс сработает. Если только WHERE b = 2, то нет — PostgreSQL использует индекс только с начала. Проверял через EXPLAIN."
    
- Дополнение: "Переписывал индексы на проекте, чтобы фильтры шли в порядке a, b."

10. Что такое конвейеризация?

- Ответ: "Конвейеризация (pipelining) — это когда запросы отправляются на сервер без ожидания ответа на предыдущий. В PostgreSQL это поддерживается в pgx через batch-запросы — ускоряет массовые операции вроде вставок."
    
- Дополнение: "Юзал batch в Go для вставки 100k строк — время упало с 10 с до 2 с."

Вопросы по Go

11. Строка 37? Строку "Привет" интерпретирует как массив байт, какая длина строки? Что если возьмем нулевой элемент массива?

- Ответ: "В Go строка — это срез байтов в UTF-8. 'Привет' — 6 символов, каждый по 2 байта, итого len("Привет") = 12. Нулевой элемент — это первый байт: []byte("Привет")[0] = 0xD0 (часть 'П'). Для символов — range или utf8.RuneCountInString."
    
- Дополнение: "Парсил кириллицу в логах, считал руны, чтобы не путать байты."
    

---

12. Массив это?

- Ответ: "Массив в Go — это фиксированная последовательность элементов одного типа, например [5]int. Размер задаётся при компиляции, память выделяется статически."
    
- Дополнение: "Редко юзал массивы, чаще слайсы из-за динамики."
    

---

13. Слайс это? Append?

- Ответ: "Слайс — это динамическая обёртка над массивом: указатель на данные, len и cap. append добавляет элементы, если cap хватает — в тот же массив, если нет — реаллоцирует с удвоением (до 1024, потом ~1.25x)."
    
- Дополнение: "Оптимизировал append, задавая cap заранее — меньше копирований."
    

---

14. Мапа как устроена? Что для программиста означает эвакуация данных на прикладном уровне?

- Ответ: "В Go 1.24 map — это Swiss Table: группы по 8 слотов, линейное пробирование, метаданные в Control Word. Эвакуация данных — это, скорее всего, опечатка ('eviction'?), значит удаление старых записей из кэша. На уровне кода — это логика вроде LRU или TTL."
    
- Дополнение: "Писал кэш с map и горутиной для очистки по TTL — выкидывал записи каждые 5 минут."

15. Конкурентность и параллельность это?

- Ответ: "Concurrency — это управление задачами, которые могут переключаться (горутины в Go). Parallelism — одновременное выполнение на разных ядрах. Concurrency возможен на 1 ядре, parallelism — нет."
    
- Дополнение: "Тестировал с GOMAXPROCS=1 — только переключение."
    

---

16. Что такое потоки, горутины и чем они отличаются?

- Ответ: "Потоки (threads) — это OS-уровень, тяжёлые, управляются ядром. Горутины — лёгкие потоки в Go, управляются рантаймом, дешевле (2 КБ vs 1 МБ). Горутины мультиплексируются на потоках через scheduler."
    
- Дополнение: "Писал worker pool с горутинами — 10k задач без проблем."
    

---

17. Рантайм как работает, как управляет потоками?

- Ответ: "Рантайм Go включает scheduler, который распределяет горутины по потокам (M:N модель). Использует work-stealing: каждый поток (P) имеет очередь горутин, крадёт задачи у других при простое. GOMAXPROCS задаёт число потоков."
    
- Дополнение: "Ловил узкие места через runtime.NumGoroutine() под нагрузкой."
    

---

18. Чем многозадачность отличается от многопоточности?

- Ответ: "Многозадачность — это выполнение нескольких задач, не обязательно параллельно (concurrency). Многопоточность — это parallelism через потоки OS. В Go многозадачность — это горутины, многопоточность — настройка GOMAXPROCS."
    
- Дополнение: "Юзал горутины для парсинга, потоков хватало 4."
    

---

19. Вычисления это? Почему решили дать schedulerу возможность переключаться самостоятельно, зачем добавили выстраивающую?

- Ответ: "Думаю, речь про preemption. Scheduler переключает горутины, чтобы избежать блокировок от долгих вычислений. Preemption добавили в Go 1.14 — если горутина висит (например, цикл), её прерывают. Это спасает от дедлоков."
    
- Дополнение: "Ловил зависания до 1.14, теперь runtime.Gosched() редко нужен."
    

---

20. Атомик зачем нужны и от чего защита? Почему гонка возникает и какие примитивы синхронизации?

- Ответ: "sync/atomic нужен для операций без блокировок (например, AddInt64). Защищает от data race — когда 2+ горутины пишут в одну переменную без синхронизации. Гонка возникает из-за непредсказуемого порядка. Примитивы: Mutex, RWMutex, WaitGroup, Once."
    
- Дополнение: "Юзал atomic для счётчиков в метриках — быстрее Mutex."

21. Каналы? В чем отличие буферизированного канала с буфером 1 и небезопасного синхронного канала?

- Ответ: "Каналы — это синхронизация между горутинами. Небуферизированный (make(chan int)) — синхронный, блокирует, пока нет читателя. Буферизированный с 1 (make(chan int, 1)) — асинхронный для 1 записи, дальше блокирует."
    
- Дополнение: "Юзал буфер 1 для логов — продюсер не ждал обработку."

22. Select что обеспечивает? Что происходит если один канал не готов? Повседневный кейс?

- Ответ: "select ждёт готовности нескольких каналов, выбирает первый доступный. Если канал не готов — ждёт или идёт в default. Кейс: таймауты через select с time.After для HTTP-запросов."
    
- Дополнение: "Писал graceful shutdown с select на сигналах и каналах."

23. Контекст? Есть параллельная работа, из верхней горутины ищем контекст, что происходит в нижней? Как проверить?

- Ответ: "context передаёт отмену и данные вниз по стеку. Если верхняя горутина вызывает cancel(), нижняя видит через <-ctx.Done(). Проверяю в select или if ctx.Err() != nil."
    
- Дополнение: "Юзал WithTimeout для обрыва долгих парсингов."

24. Сборщик мусора как работает, зачем нужен? Как работает в языках?

- Ответ: "GC в Go — это mark-and-sweep: помечает живые объекты, убирает мёртвые. Нужен для автоматического управления памятью. Работает асинхронно, триггерится по GOGC (по умолчанию 100). В других языках — свои алгоритмы (reference counting в Python)."
    
- Дополнение: "Тюнил GOGC=50 под высокую нагрузку — меньше пауз."

25. ESB? Это нужно защищать? От каких уязвимостей? SQL-инъекции, XSS?

- Ответ: "Думаю, речь про SQL (опечатка?). SQL-инъекции — это когда пользовательский ввод лезет в запрос (SELECT * FROM users WHERE id = '1; DROP TABLE users'). Защищаю через pgx с параметрами (db.QueryRow(ctx, "SELECT * FROM users WHERE id = $1", id)). XSS — это JS в браузере, не про Go, но фильтровал ввод через html.EscapeString."
    
- Дополнение: "Ловил инъекцию в legacy-коде, переписал на prepared statements."

26. Cherry-pick что делает? Merge от rebase чем отличается?

- Ответ: "git cherry-pick берёт конкретный коммит и применяет его в текущую ветку. Merge сливает ветки, сохраняя историю с merge-коммитом. Rebase переписывает историю, перенося коммиты на новую базу — чище, но опаснее для коллаборации."
    
- Дополнение: "Юзал rebase для чистоты feature-веток перед PR."
