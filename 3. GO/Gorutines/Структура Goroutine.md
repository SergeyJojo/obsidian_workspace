
Структура горутины в Go — это ключевая часть runtime, которая позволяет реализовать легковесные потоки (goroutines) для конкурентного выполнения задач. Горутины не являются потоками операционной системы, а управляются планировщиком Go (Go scheduler), что делает их значительно более эффективными. Чтобы глубоко разобрать устройство горутины, обратимся к её внутренней реализации в runtime Go, основываясь на исходном коде (на момент Go 1.21). Структура горутины представлена типом g в файле runtime/runtime2.go. Давайте разберём её "по полочкам".

---

Общая концепция горутины

- Горутина (goroutine) — это единица выполнения в Go, которая создаётся с помощью ключевого слова go.
    
- Она работает в модели M:N, где множество горутин (G) мапятся на меньшее число потоков ОС (M), управляемых логическими процессорами (P).
    
- Каждая горутина имеет свой собственный стек, контекст выполнения и состояние, которые хранятся в структуре g.
    

---

Структура g (goroutine)

Вот как выглядит определение структуры g в runtime/runtime2.go (сокращённая версия с основными полями):

go

```go
type g struct {
    // Стек горутины
    stack       stack   // offset known to runtime/cgo
    stackguard0 uintptr // offset known to liblink
    stackguard1 uintptr // offset known to liblink

    // Указатель на текущую инструкцию и данные для возобновления
    _panic       *_panic // ссылка на активную панику
    _defer       *_defer // ссылка на отложенные вызовы
    m            *m      // связь с потоком ОС
    sched        gobuf   // контекст выполнения (регистры, PC, SP)
    syscallsp    uintptr // стековый указатель для системных вызовов
    syscallpc    uintptr // программный счётчик для системных вызовов
    stktopsp     uintptr // указатель стека на момент входа в runtime

    // Параметры и состояние
    param        unsafe.Pointer // параметры, переданные при создании
    atomicstatus uint32         // текущее состояние горутины (Grunning, Gwaiting и т.д.)
    stackLock    uint32         // флаг блокировки стека
    goid         int64          // уникальный идентификатор горутины
    schedlink    *g             // ссылка на следующую горутину в очереди
    waitsince    int64          // время начала ожидания (для отладки)
    waitreason   waitReason     // причина ожидания
    preempt      bool           // флаг прерывания
    lockedm      *m             // поток, к которому привязана горутина (если есть)

    // Поля для планировщика и GC
    gcscandone    bool    // флаг завершения сканирования стека для GC
    gcAssistBytes int64   // помощь сборщику мусора
    timer         *timer  // таймер, если горутина ждёт его
}
```

---

Разбор структуры g "по полочкам"

1. Стек горутины

- stack stack
    
    - Что это: Структура, описывающая границы стека горутины (lo — нижняя граница, hi — верхняя).
        
    - Назначение: Хранит память, выделенную для стека горутины (локальные переменные, вызовы функций).
        
    - Особенность: Стек изначально мал (2 КБ в Go 1.21), но растёт динамически при необходимости (до 1 ГБ максимум).
        
- stackguard0 uintptr
    
    - Что это: Указатель-ограничитель, ниже которого стек не должен опускаться (для проверки переполнения).
        
    - Назначение: Используется планировщиком для прерывания горутины перед переполнением стека.
        
    - Особенность: Сравнивается с текущим SP (stack pointer) в коде runtime.
        
- stackguard1 uintptr
    
    - Что это: Дополнительный ограничитель стека (используется в специальных случаях, например, для C-кода).
        

2. Контекст выполнения

- sched gobuf
    
    - Что это: Структура gobuf, сохраняющая состояние процессора для возобновления горутины.
        
    - Поля:
        
        - sp uintptr — стековый указатель (stack pointer).
            
        - pc uintptr — программный счётчик (program counter).
            
        - g *guintptr — указатель на саму горутину.
            
        - ret uintptr — возвращаемое значение (для системных вызовов).
            
    - Назначение: Хранит точку, где горутина остановилась, чтобы планировщик мог её возобновить.
        
    - Пример: Если горутина прерывается на runtime.Gosched(), sched сохраняет текущие SP и PC.
        
- syscallsp uintptr и syscallpc uintptr
    
    - Что это: Указатели стека и программы для состояния во время системного вызова.
        
    - Назначение: Используются, когда горутина блокируется на syscall (например, read), чтобы сохранить контекст.
        
- stktopsp uintptr
    
    - Что это: Указатель на вершину стека на момент входа в runtime.
        
    - Назначение: Помогает восстановить стек после возврата из runtime-функций.
        

3. Состояние и идентификация

- atomicstatus uint32
    
    - Что это: Атомарное поле, хранящее текущее состояние горутины.
        
    - Значения:
        
        - Grunnable (2) — готова к выполнению.
            
        - Grunning (4) — выполняется.
            
        - Gwaiting (6) — ждёт (например, канал или мьютекс).
            
        - Gsyscall (8) — в системном вызове.
            
        - Gdead (10) — завершена.
            
    - Назначение: Управляет жизненным циклом горутины, обновляется через atomic.StoreUint32.
        
- goid int64
    
    - Что это: Уникальный идентификатор горутины.
        
    - Назначение: Используется для отладки и трассировки (доступен через runtime.GoID() в некоторых реализациях).
        
- waitsince int64 и waitreason waitReason
    
    - Что это: Время и причина, по которой горутина ждёт.
        
    - Назначение: Диагностика (например, "waiting for channel").
        

4. Связь с потоками и планировщиком

- m *m
    
    - Что это: Указатель на поток ОС (структура m), на котором выполняется горутина.
        
    - Назначение: Связывает горутину с текущим потоком.
        
- lockedm *m
    
    - Что это: Поток, к которому горутина "привязана" (если используется LockOSThread).
        
    - Назначение: Обеспечивает выполнение горутины на конкретном потоке ОС.
        
- schedlink *g
    
    - Что это: Указатель на следующую горутину в очереди планировщика.
        
    - Назначение: Используется для связывания горутин в списках (например, runq).
        
- preempt bool
    
    - Что это: Флаг, указывающий, что горутину нужно прервать.
        
    - Назначение: Сигнализирует планировщику о необходимости переключения (например, в долгих циклах).
        

5. Обработка исключений и отложенных вызовов

- _panic *_panic
    
    - Что это: Указатель на текущую структуру panic.
        
    - Назначение: Хранит информацию о панике, если она произошла в горутине.
        
- _defer *_defer
    
    - Что это: Указатель на список отложенных вызовов (defer).
        
    - Назначение: Связывает горутину с функциями, которые должны выполниться при выходе.
        

6. Параметры и управление

- param unsafe.Pointer
    
    - Что это: Указатель на параметры, переданные при создании горутины.
        
    - Назначение: Передача данных в новую горутину (используется runtime).
        
- stackLock uint32
    
    - Что это: Флаг блокировки стека.
        
    - Назначение: Предотвращает изменения стека во время операций вроде копирования.
        

7. Взаимодействие с GC и таймерами

- gcscandone bool
    
    - Что это: Флаг, показывающий, был ли стек отсканирован сборщиком мусора.
        
    - Назначение: Помогает GC отслеживать живые указатели в стеке.
        
- gcAssistBytes int64
    
    - Что это: Количество байтов, которые горутина должна "отработать" для помощи GC.
        
    - Назначение: Балансирует нагрузку сборки мусора между горутинами.
        
- timer *timer
    
    - Что это: Указатель на таймер, если горутина ждёт его срабатывания.
        
    - Назначение: Связывает горутину с time.Timer или time.Ticker.
        

---

Как это работает вместе

1. Создание горутины:
    
    - Вызов go func() создаёт новую структуру g через runtime.newg().
        
    - Выделяется начальный стек (2 КБ), заполняется sched с PC и SP для запуска функции.
        
    - Горутина добавляется в очередь runq логического процессора (P).
        
2. Выполнение:
    
    - Планировщик выбирает горутину со статусом Grunnable, устанавливает её в Grunning.
        
    - m связывает её с потоком ОС, sched восстанавливает регистры.
        
3. Прерывание:
    
    - Если preempt = true или стек близок к stackguard0, горутина прерывается (runtime.Gosched()).
        
    - Контекст сохраняется в sched, горутина становится Grunnable.
        
4. Ожидание:
    
    - При блокировке (например, на канале) статус меняется на Gwaiting, waitsince и waitreason заполняются.
        
5. Завершение:
    
    - После выхода из функции статус становится Gdead, стек освобождается, а структура g может быть переиспользована.
        

---

Пример жизненного цикла

go

```go
go func() {
    fmt.Println("Hello")
}()
```

1. Создаётся g: goid присваивается, stack выделяется, sched.pc указывает на начало функции.
    
2. Горутина в Grunnable, добавлена в runq.
    
3. Планировщик запускает её (Grunning), печатает "Hello".
    
4. Завершается (Gdead), ресурсы освобождаются.
    

---

Итог устройства g

- Стек: Динамически растущий, управляемый stack и stackguard.
    
- Контекст: sched для сохранения и возобновления.
    
- Состояние: atomicstatus для жизненного цикла.
    
- Связь: m, lockedm, schedlink для интеграции с потоками и очередями.
    
- Исключения: _panic, _defer для обработки ошибок и отложенных вызовов.
    
- GC и таймеры: Поддержка сборки мусора и временных операций.
    

Это делает горутину легковесной (несколько КБ памяти против МБ для потоков ОС) и гибкой для конкурентного выполнения в Go.
