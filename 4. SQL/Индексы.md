---

## **Что такое индекс?**

Индекс — это структура данных, которая ускоряет поиск и доступ к данным в таблице. Он работает как оглавление в книге: вместо того чтобы искать данные по всей таблице (полный сканирование), SQL-движок использует индекс для быстрого нахождения нужных строк.

---

## **Как работает индекс?**

1. **Без индекса**:
   - SQL-движок выполняет **полное сканирование таблицы (Full Table Scan)**, чтобы найти нужные строки.
   - Это медленно, особенно для больших таблиц.

2. **С индексом**:
   - SQL-движок использует индекс для быстрого поиска строк.
   - Индекс хранит значения определённых столбцов и ссылки на соответствующие строки в таблице.

---

## **Типы индексов**

### 1. **Одноуровневые индексы (Single-column Index)**
   - Индекс создаётся на одном столбце.
   - Пример:
     ```sql
     CREATE INDEX idx_name ON users (name);
     ```

### 2. **Составные индексы (Composite Index)**
   - Индекс создаётся на нескольких столбцах.
   - Пример:
     ```sql
     CREATE INDEX idx_name_age ON users (name, age);
     ```

### 3. **Уникальные индексы (Unique Index)**
   - Гарантирует, что все значения в индексируемом столбце уникальны.
   - Пример:
     ```sql
     CREATE UNIQUE INDEX idx_email ON users (email);
     ```

### 4. **Полнотекстовые индексы (Full-text Index)**
   - Используется для поиска по текстовым данным (например, ключевые слова в статьях).
   - Пример:
     ```sql
     CREATE FULLTEXT INDEX idx_content ON articles (content);
     ```

### 5. **Пространственные индексы (Spatial Index)**
   - Используется для геоданных (например, координаты).
   - Пример:
     ```sql
     CREATE SPATIAL INDEX idx_location ON places (location);
     ```

### 6. **Хэш-индексы (Hash Index)**
   - Используется для точного поиска (равенства), но не для диапазонов.
   - Пример:
     ```sql
     CREATE INDEX idx_name ON users USING HASH (name);
     ```

### 7. **B-деревья (B-tree Index)**
   - Наиболее распространённый тип индекса.
   - Поддерживает поиск по равенству и диапазонам.
   - Пример:
     ```sql
     CREATE INDEX idx_age ON users (age);
     ```

---

## **Преимущества индексов**

1. **Ускорение поиска**:
   - Индексы значительно ускоряют выполнение запросов с условиями `WHERE`, `JOIN`, `ORDER BY`, `GROUP BY`.

2. **Ускорение сортировки**:
   - Если данные уже отсортированы в индексе, SQL-движок может избежать дополнительной сортировки.

3. **Ускорение агрегации**:
   - Индексы помогают быстрее выполнять агрегатные функции (`COUNT`, `SUM`, `AVG`).

4. **Обеспечение уникальности**:
   - Уникальные индексы гарантируют, что значения в столбце не повторяются.

---

## **Недостатки индексов**

1. **Затраты на хранение**:
   - Индексы занимают место на диске.

2. **Затраты на обновление**:
   - При вставке, обновлении или удалении данных индексы также должны обновляться, что замедляет эти операции.

3. **Не всегда полезны**:
   - Индексы неэффективны для таблиц с частыми изменениями данных или для столбцов с низкой селективностью (например, столбец с полом, где всего два значения).

---

## **Когда использовать индексы?**

1. **Частые поисковые запросы**:
   - Если часто выполняются запросы с условиями `WHERE` по определённым столбцам.

2. **Сортировка и группировка**:
   - Если часто используются `ORDER BY` или `GROUP BY`.

3. **Соединения таблиц**:
   - Если часто выполняются `JOIN` по определённым столбцам.

4. **Уникальные значения**:
   - Если нужно гарантировать уникальность значений в столбце.

---

## **Когда не использовать индексы?**

1. **Маленькие таблицы**:
   - Для таблиц с небольшим количеством строк индексы могут не дать преимуществ.

2. **Столбцы с низкой селективностью**:
   - Например, столбец с полом (значения "M" и "F").

3. **Частые изменения данных**:
   - Если данные часто обновляются, индексы могут замедлить операции.

---

## **Примеры использования индексов**

### 1. **Создание индекса**
```sql
CREATE INDEX idx_name ON users (name);
```

### 2. **Создание уникального индекса**
```sql
CREATE UNIQUE INDEX idx_email ON users (email);
```

### 3. **Создание составного индекса**
```sql
CREATE INDEX idx_name_age ON users (name, age);
```

### 4. **Удаление индекса**
```sql
DROP INDEX idx_name ON users;
```

---

## **Оптимизация запросов с индексами**

### 1. **Использование `EXPLAIN`**
   - Команда `EXPLAIN` показывает, как SQL-движок выполняет запрос и использует ли он индексы.
   - Пример:
     ```sql
     EXPLAIN SELECT * FROM users WHERE name = 'Alice';
     ```

### 2. **Покрывающие индексы (Covering Index)**
   - Индекс, который содержит все столбцы, необходимые для выполнения запроса.
   - Пример:
     ```sql
     CREATE INDEX idx_name_age ON users (name, age);
     SELECT name, age FROM users WHERE name = 'Alice';
     ```

### 3. **Индексы для `JOIN`**
   - Индексы на столбцах, используемых в `JOIN`, ускоряют соединение таблиц.
   - Пример:
     ```sql
     CREATE INDEX idx_user_id ON orders (user_id);
     SELECT * FROM users JOIN orders ON users.id = orders.user_id;
     ```

## **Примеры задач с индексами**

### **Задача 1: Ускорение поиска**
- Таблица `users` с миллионами строк.
- Часто выполняется запрос:
  ```sql
  SELECT * FROM users WHERE email = 'alice@example.com';
  ```
- Решение:
  ```sql
  CREATE INDEX idx_email ON users (email);
  ```

### **Задача 2: Ускорение сортировки**
- Таблица `orders` с миллионами строк.
- Часто выполняется запрос:
  ```sql
  SELECT * FROM orders ORDER BY order_date DESC;
  ```
- Решение:
  ```sql
  CREATE INDEX idx_order_date ON orders (order_date);
  ```

### **Задача 3: Ускорение соединения**
- Таблицы `users` и `orders`.
- Часто выполняется запрос:
  ```sql
  SELECT * FROM users JOIN orders ON users.id = orders.user_id;
  ```
- Решение:
  ```sql
  CREATE INDEX idx_user_id ON orders (user_id);
  ```

Давайте разберём, как работают индексы в PostgreSQL, на простом примере с **B-tree** и **Hash** — это поможет понять "механику" целиком.

---

### 🔍 **Как индекс ускоряет запрос? (Общая схема)**
1. **У вас есть таблица** (например, `users` с 1 млн строк).  
2. **Создаёте индекс** на колонку (например, `CREATE INDEX idx_name ON users(name)`).  
3. **При запросе** (`SELECT * FROM users WHERE name = 'Иван'`):  
   - **Без индекса**: PostgreSQL сканирует всю таблицу (Seq Scan) — проверяет **каждую строку**.  
   - **С индексом**:  
     - Система ищет `'Иван'` в **индексной структуре** (B-tree/Hash).  
     - Находит **указатель** (TID) на нужные строки в таблице.  
     - Достаёт **только их** (Index Scan).  

---

### 🌳 **B-tree индекс (основной в PostgreSQL)**
#### Как устроен?
- **Балансированное дерево** (каждая нода содержит диапазон значений).  
- Пример для колонки `age`:  
  ```
        [10, 20, 30]  ← Корневая нода
         /   |   \
    [10,15] [20,25] [30,35]  ← Дочерние ноды
  ```
#### Как работает?
1. Запрос: `SELECT * FROM users WHERE age = 25`.  
2. PostgreSQL:  
   - Сравнивает `25` с корневой нодой → идёт в среднюю ветку `[20,25]`.  
   - Находит точное значение `25` → получает **TID** (адрес строки в таблице).  
   - Читает **только эту строку** с диска.  

#### Плюсы:
- Подходит для **диапазонов** (`WHERE age > 20 AND age < 30`).  
- Поддерживает `=`, `>`, `<`, `LIKE 'A%'`.  

---

### ⚡ **Hash индекс**
#### Как устроен?
- **Хэш-таблица** (ключ → TID).  
- Пример для `name`:  
  ```
  "Иван" → [TID1, TID2]
  "Пётр" → [TID3]
  ```

#### Как работает?
1. Запрос: `SELECT * FROM users WHERE name = 'Иван'`.  
2. PostgreSQL:  
   - Вычисляет **хэш** от `'Иван'`.  
   - Находит в индексе **список TID** для этого хэша.  
   - Читает **только нужные строки**.  

#### Плюсы:
- **Мгновенный поиск** по `=` (O(1)).  
#### Минусы:
- Не работает для `>`, `<`, `LIKE`.  
- Не поддерживается в `UNIQUE` и `PRIMARY KEY`.  

---

### ❓ **Как PostgreSQL выбирает индекс?**
1. **Планировщик** оценивает:  
   - Селективность (если `age > 20` охватывает 80% строк — индекс невыгоден).  
   - Размер индекса vs таблицы.  
   - Наличие `ORDER BY`, `JOIN`.  

2. **Принудительное использование**:  
   ```sql
   SET enable_seqscan = OFF;  -- Отключить полное сканирование
   SELECT * FROM users WHERE name = 'Иван';  -- Теперь будет Index Scan
   ```

---

### ⚠️ **Когда индекс НЕ сработает?**
1. **Низкая селективность** (например, индекс на колонку `gender` с 2 значениями).  
2. **Функции в условии** (`WHERE LOWER(name) = 'иван'` — индекс `name` не используется).  
3. **Не покрывающий индекс** (если нужны данные не из индекса — всё равно читается таблица).  

---

### 🔧 **Как проверить, использовался ли индекс?**
```sql
EXPLAIN ANALYZE SELECT * FROM users WHERE name = 'Иван';
```
Вывод:  
- `Index Scan using idx_name on users` — индекс задействован.  
- `Seq Scan on users` — индекс проигнорирован.  

---

### 💡 **Вывод**  
- **B-tree** — универсальный (диапазоны, сортировка).  
- **Hash** — только точные совпадения, но быстрее.  
- **Индекс не волшебство** — важен правильный дизайн под запросы.  

Если хотите глубже — можно разобрать **GIN** (для JSON/массивов) или **BRIN** (для временных рядов).
