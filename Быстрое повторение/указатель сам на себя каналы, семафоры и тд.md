## 📌 Что ты описал — это `waitq = sudog`, и **указатель, указывающий на самого себя**, означает "пустую/замкнутую очередь".

### 🔍 Разбор по шагам

Внутри рантайма Go, когда горутина блокируется на каком-либо примитиве (канал, mutex, sema и т.п.), она представлена через структуру `sudog` (`runtime/sync.go`).

**Синтаксис:**

```go
type sudog struct {
    g   *g
    next *sudog
    ...
}
```

Когда очередь ожидания пуста, например, в канале никто не ждет, она обозначается **не `nil`, а особым указателем — на саму себя**. Пример из `runtime/chan.go`:

```go
if c.sendq.first == nil {
    c.sendq.first = sg
    c.sendq.last = sg
    sg.next = nil
} else {
    c.sendq.last.next = sg
    c.sendq.last = sg
}
```

Но в других случаях, например, **в очереди блокировки** (например, в `semaRoot`), используется **магия:**

```go
sudog.next = sudog (сам на себя)
```

Это делается в целях **оптимизации и избегания гонок**. Такой указатель можно интерпретировать как:

> «ОЧЕРЕДЬ ЗАКРЫТА/НЕПРИМЕНИМА/ИЛИ СПЕЦИАЛЬНАЯ».

---

## 📦 Где это встречается

- `chan.sendq`, `chan.recvq` (в каналах).
    
- `selectgo` (выбор из нескольких каналов).
    
- `runtime/sema.go` — семафоры (на них mutex основан).
    
- `runtime/lock_sema.go` — низкоуровневая блокировка.
    

---

## ☠️ Почему это важно?

Если ты **попытаешься добавить в такую очередь**, или неправильно интерпретируешь указатель — ты получишь **вечную блокировку** или **panic**.

> Именно это могут проверять на собеседованиях: знаешь ли ты, как устроены эти очереди на нижнем уровне и какие используются sentinels / флаги.

---

## 🧪 Пример: вечная блокировка

```go
// Псевдокод
var sudog s
s.next = &s // указывает на самого себя
// Теперь кто-то будет интерпретировать это как непустую очередь,
// но при итерации попадёт в цикл
```
