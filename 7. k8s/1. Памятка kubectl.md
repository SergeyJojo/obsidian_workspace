# **Памятка по работе с `kubectl`**  
Основные команды и лучшие практики для управления Kubernetes-кластерами.  

---

## **1. Основные команды**  

### **Просмотр информации**  
| Команда                           | Описание                         |     |
| --------------------------------- | -------------------------------- | --- |
| `kubectl cluster-info`            | Проверить статус кластера        |     |
| `kubectl get nodes`               | Список нод в кластере            |     |
| `kubectl get pods -A`             | Список всех подов                |     |
| `kubectl get svc -A`              | Список всех сервисов             |     |
| `kubectl get deployments -A`      | Список всех Deployment           |     |
| `kubectl describe pod <pod-name>` | Подробная информация о поде      |     |
| `kubectl logs <pod-name>`         | Логи пода                        |     |
| `kubectl logs -f <pod-name>`      | Логи в реальном времени (follow) |     |
| `kubectl top nodes`               | Загрузка CPU и памяти нод        |     |
| `kubectl top pods`                | Загрузка CPU и памяти подов      |     |

---

### **Создание и удаление ресурсов**  
| Команда | Описание |  
|---------|----------|  
| `kubectl apply -f file.yaml` | Применить конфигурацию из файла |  
| `kubectl delete -f file.yaml` | Удалить ресурсы из файла |  
| `kubectl delete pod <pod-name>` | Удалить под |  
| `kubectl delete deployment <deployment-name>` | Удалить Deployment |  
| `kubectl delete svc <service-name>` | Удалить сервис |  

---

### **Работа с Pods**  
| Команда | Описание |  
|---------|----------|  
| `kubectl exec -it <pod-name> -- /bin/sh` | Зайти в контейнер (интерактивный режим) |  
| `kubectl cp <pod-name>:/path/to/file ./local-file` | Скопировать файл из пода |  
| `kubectl port-forward <pod-name> 8080:80` | Проброс порта (localhost:8080 → pod:80) |  

---

### **Масштабирование и обновления**  
| Команда | Описание |  
|---------|----------|  
| `kubectl scale deployment <deployment-name> --replicas=3` | Масштабировать Deployment |  
| `kubectl rollout status deployment/<deployment-name>` | Статус обновления Deployment |  
| `kubectl rollout history deployment/<deployment-name>` | История изменений Deployment |  
| `kubectl rollout undo deployment/<deployment-name>` | Откатить Deployment |  

---

## **2. Контексты и настройки**  

### **Переключение между кластерами**  
| Команда | Описание |  
|---------|----------|  
| `kubectl config get-contexts` | Список доступных контекстов |  
| `kubectl config use-context <context-name>` | Переключиться на другой кластер |  
| `kubectl config set-context --current --namespace=<ns>` | Сменить Namespace по умолчанию |  

---

## **3. Отладка и диагностика**  

### **Проверка состояния**  
| Команда | Описание |  
|---------|----------|  
| `kubectl get events -A` | Посмотреть события кластера |  
| `kubectl describe node <node-name>` | Проверить состояние ноды |  
| `kubectl get pods --field-selector=status.phase!=Running` | Найти неработающие поды |  

### **Диагностика сети**  
| Команда | Описание |  
|---------|----------|  
| `kubectl run -it --rm debug --image=busybox --restart=Never -- sh` | Запустить временный контейнер для тестов |  
| `kubectl get endpoints <service-name>` | Проверить Endpoints сервиса |

## **4. Полезные сокращения и алиасы**  
Добавьте в `~/.bashrc` или `~/.zshrc`:  
```bash
alias k="kubectl"
alias kgp="kubectl get pods"
alias kgs="kubectl get svc"
alias kaf="kubectl apply -f"
alias kdf="kubectl delete -f"
alias kd="kubectl describe"
alias kl="kubectl logs -f"
alias ke="kubectl exec -it"
```

---

## **5. Лучшие практики**  
✅ **Используйте `kubectl apply -f` вместо `create`** — idempотентность.  
✅ **Проверяйте `kubectl get events` при проблемах** — там часто есть подсказки.  
✅ **Используйте `--dry-run=client -o yaml` для генерации манифестов**:  
```bash
kubectl create deploy nginx --image=nginx --dry-run=client -o yaml > deploy.yaml
```  
✅ **Логируйте и мониторьте** с помощью `kubectl top` и `k9s`.

### **Пример файла `deployment.yaml`**  
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
```
