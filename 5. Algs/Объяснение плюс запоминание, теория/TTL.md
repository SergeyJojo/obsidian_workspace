### **Как реализовать TTL-кеш (Time-To-Live cache)?**  

TTL-кеш — это хранилище данных, в котором каждая запись автоматически удаляется по истечении заданного времени жизни.  

---

## **🔹 1. Основные компоненты TTL-кеша**  

### **1.1. Структура данных**  
- **Хэш-таблица (словарь)** – для быстрого доступа к данным по ключу.  
- **Приоритетная очередь (куча) или сортированный список** – для эффективного удаления устаревших записей.  

### **1.2. Механизм TTL**  
- Каждая запись хранится вместе с **временем истечения срока жизни** (expiration time).  
- При добавлении записи:  
  - Вычисляем `expiration_time = текущее_время + TTL`.  
  - Сохраняем в хэш-таблицу и приоритетную очередь.  

### **1.3. Удаление устаревших записей**  
- **Ленивое удаление (Lazy Expiration)** – проверяем срок при обращении к записи.  
- **Активное удаление (Active Expiration)** – фоновый процесс, который периодически чистит кеш.  
- **Гибридный подход** – комбинация ленивого и активного удаления.  

---

## **🔹 2. Алгоритм работы**  

### **2.1. Добавление записи (`Set`)**
1. Принимаем ключ, значение и TTL.  
2. Вычисляем `expiration_time = now() + TTL`.  
3. Сохраняем в хэш-таблицу: `cache[key] = {value, expiration_time}`.  
4. Добавляем в очередь для отслеживания срока жизни.  

### **2.2. Получение записи (`Get`)**
1. Проверяем наличие ключа в кеше.  
2. Если ключ есть:  
   - Сравниваем `expiration_time` с текущим временем.  
   - Если срок истёк → удаляем запись и возвращаем `nil`.  
   - Если срок актуален → возвращаем значение.  
3. Если ключа нет → возвращаем `nil`.  

### **2.3. Удаление устаревших записей**  
- **Ленивое удаление** (при каждом `Get`/`Set` проверяем срок).  
- **Фоновая горутина/поток** (раз в N секунд сканирует кеш и удаляет старые записи).  

---

## **🔹 3. Оптимизации**  

### **3.1. Эффективное хранение времени**  
- Использовать **timestamp (Unix-время)** вместо строк.  
- В Go: `time.Now().Add(ttl).UnixNano()`.  

### **3.2. Выбор структуры для приоритетной очереди**  
- **Min-Heap** – быстрый доступ к ближайшему сроку удаления.  
- **Сортированный двусвязный список** – если TTL фиксированный.  

### **3.3. Очистка в фоне**  
- Запустить **отдельную горутину**, которая раз в `N` секунд:  
  - Проверяет записи в очереди.  
  - Удаляет те, у которых `expiration_time <= now()`.  

---

## **🔹 4. Возможные проблемы и решения**  

### **4.1. Утечки памяти**  
- Если не чистить кеш, он будет бесконечно расти.  
- **Решение:** Фоновая очистка + ленивое удаление.  

### **4.2. Конкурентный доступ**  
- При многопоточном использовании нужна **синхронизация** (мьютекс, `sync.Map`).  

### **4.3. Производительность**  
- Если TTL очень маленький (миллисекунды), лучше использовать **кольцевой буфер**.

### **🔹 Итог**  
Чтобы реализовать TTL-кеш, нужно:  
1. **Хранить данные + время удаления**.  
2. **Проверять срок при обращении** (ленивое удаление).  
3. **Чистить устаревшие записи в фоне** (активное удаление).  
4. **Обеспечить потокобезопасность** (если кеш используется в многопоточной среде).
