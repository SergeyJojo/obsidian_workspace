**D7 (Современный стиль разработки)** — это архитектурная переработка ядра 1С-Битрикс, основанная на принципах **объектно-ориентированного программирования (ООП)**, использовании **пространств имён (namespaces)** и следовании современным стандартам PHP.

### 🎯 Основные принципы D7

| Принцип                           | Описание и выгода                                                                                         | Пример в Битрикс                                             |
| :-------------------------------- | :-------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------- |
| **ООП и пространства имён**       | Код структурирован в классы и пространства имён, что устраняет конфликты имён и делает код предсказуемым. | `\Bitrix\Iblock\ElementTable` — таблица элементов инфоблока. |
| **Автозагрузка классов (PSR-4)**  | Классы подключаются автоматически по их полному имени. Не нужны `require_once`.                           | Система сама найдёт класс `\Bitrix\Main\Data\Cache`.         |
| **Единая точка входа (ORM)**      | Работа с БД через унифицированный объектный интерфейс — **ORM (Object-Relational Mapping)**.              | `ElementTable::getList()`, `UserTable::add()`.               |
| **Компонентный подход**           | Компоненты строятся на базе классов, что упрощает их кастомизацию и наследование.                         | Класс `CBitrixComponent` и его наследники.                   |
| **Современная событийная модель** | Используется объектный менеджер событий `\Bitrix\Main\EventManager`.                                      | `$eventManager->addEventHandler(...)`.                       |
| **Встроенное кеширование**        | Кеширование — неотъемлемая часть ORM и компонентов.                                                       | Параметр `cache` в методе `getList()`.                       |
| **Безопасность по умолчанию**     | ORM автоматически экранирует данные, защищая от SQL-инъекций.                                             | Безопасность "из коробки" при использовании ORM-методов.     |

### 💻 Работа с таблицами: CRUD-операции

Работа с данными в D7 построена вокруг классов-таблиц (наследников `\Bitrix\Main\ORM\Data\DataManager`). Это обеспечивает единообразие и безопасность.

#### 1. Чтение данных (`*Table::getList()`)
Это основной метод для выборки данных. Его ключевая особенность — единый массив параметров с чёткими ключами.

```php
use \Bitrix\Iblock\ElementTable;

// Получение списка элементов с явным указанием полей и фильтром
$query = ElementTable::getList([
    'select' => ['ID', 'NAME', 'DATE_CREATE', 'PROPERTY_PRICE_VALUE'], // Какие поля выбрать
    'filter' => ['=IBLOCK_ID' => 2, '=ACTIVE' => 'Y'], // Условия WHERE
    'order'  => ['SORT' => 'ASC', 'ID' => 'DESC'], // Сортировка ORDER BY
    'limit'  => 50, // Ограничение LIMIT
    'offset' => 0, // Смещение OFFSET
    'cache'  => ['ttl' => 3600] // Кеширование результата на 1 час
]);

// Перебор результатов
while ($element = $query->fetch()) {
    // $element — ассоциативный массив
    echo $element['NAME'];
}
// Или получить всё сразу
$allElements = $query->fetchAll();
```

#### 2. Добавление записи (`*Table::add()`)
Метод принимает массив полей, валидирует данные и возвращает результат операции.

```php
use \Bitrix\Main\Entity\AddResult;

try {
    $result = ElementTable::add([
        'NAME' => 'Новый элемент',
        'IBLOCK_ID' => 2,
        'ACTIVE' => 'Y',
        'PROPERTY_VALUES' => [
            'PRICE' => 1000 // Добавление значения свойства
        ]
    ]);

    if ($result->isSuccess()) {
        $newId = $result->getId(); // Получаем ID созданной записи
        echo "Добавлен элемент с ID: " . $newId;
    } else {
        $errors = $result->getErrorMessages(); // Обработка ошибок
    }
} catch (\Exception $e) {
    // Обработка исключений
}
```

#### 3. Обновление записи (`*Table::update()`)
Для обновления необходимо указать первичный ключ (ID) и массив изменяемых полей.

```php
use \Bitrix\Main\Entity\UpdateResult;

try {
    $result = ElementTable::update($elementId, [ // $elementId — ID обновляемой записи
        'NAME' => 'Обновлённое название',
        'PREVIEW_TEXT' => 'Новый текст',
        'PROPERTY_VALUES' => [
            'PRICE' => 1200 // Обновление свойства
        ]
    ]);

    if ($result->isSuccess()) {
        echo "Элемент обновлён";
    } else {
        $errors = $result->getErrorMessages();
    }
} catch (\Exception $e) {
    // Если запись с таким ID не найдена, будет выброшено исключение
    echo "Ошибка: " . $e->getMessage();
}
```

#### 4. Удаление записи (`*Table::delete()`)
Метод для удаления записи по её первичному ключу.

```php
use \Bitrix\Main\Entity\DeleteResult;

try {
    $result = ElementTable::delete($elementIdToDelete);

    if ($result->isSuccess()) {
        echo "Элемент удалён";
    } else {
        $errors = $result->getErrorMessages();
    }
} catch (\Exception $e) {
    // Если запись не найдена или нарушены ограничения БД
    echo "Ошибка при удалении: " . $e->getMessage();
}
```

### 🚀 Практический пример: решение проблемы N+1 в D7
Проблема N+1 решается за счёт предварительной загрузки (eager loading) связанных данных в одном запросе через `select`.

```php
// ✅ ПРАВИЛЬНО (D7): Один запрос с JOIN
$query = ElementTable::getList([
    'select' => [
        'ID',
        'NAME',
        'IBLOCK_SECTION_ID',
        'SECTION_NAME' => 'SECTION.NAME' // JOIN с таблицей разделов
    ],
    'filter' => ['=IBLOCK_ID' => 2],
    'cache' => ['ttl' => 3600]
]);
// В цикле нет дополнительных запросов к БД
```

### 💎 Итог
D7 — это современный, безопасный и эффективный стиль разработки для 1С-Битрикс. Он требует понимания ООП, но в долгосрочной перспективе делает код:
*   **Более читаемым** благодаря чёткой структуре.
*   **Более безопасным** за счёт автоматического экранирования.
*   **Более производительным** благодаря встроенному кешированию и оптимизированным запросам.
*   **Лёгким в поддержке** из-за модульности и стандартизации.

Для начала работы с D7 изучите классы в пространствах имён `\Bitrix\Main`, `\Bitrix\Iblock`, `\Bitrix\Crm`. Официальная документация Битрикс содержит подробные примеры по ORM.
