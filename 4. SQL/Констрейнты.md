
В PostgreSQL **констрейнты (constraints)** — это правила, которые накладываются на столбцы таблицы для обеспечения целостности данных. Констрейнты помогают гарантировать, что данные в базе соответствуют заданным ограничениям и требованиям, что обеспечивает их корректность и надежность.

Ниже представлены основные типы констрейнтов, которые можно использовать в PostgreSQL на колонках:

### 1. **`NOT NULL`**

Констрейнт **`NOT NULL`** используется для того, чтобы столбец не мог содержать значение `NULL`. Это гарантирует, что каждая строка в таблице для данного столбца будет иметь действительное значение.

#### Пример:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);
```

В этом примере столбец `name` не может содержать `NULL` значения.

### 2. **`UNIQUE`**

Констрейнт **`UNIQUE`** гарантирует, что все значения в столбце (или в комбинации столбцов) будут уникальными. Это ограничение может быть полезным, если нужно обеспечить, чтобы в таблице не было двух одинаковых записей для определённого столбца.

#### Пример:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(100) UNIQUE
);
```

Здесь констрейнт **`UNIQUE`** гарантирует, что в таблице не может быть двух строк с одинаковым значением в столбце `email`.

### 3. **`PRIMARY KEY`**

**`PRIMARY KEY`** — это констрейнт, который не только гарантирует уникальность значений в столбце, но и устанавливает его как **основной идентификатор** для строк в таблице. Столбец с таким ограничением не может содержать `NULL` значения, а также все значения в нем должны быть уникальными.

#### Пример:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100)
);
```

В этом примере столбец `id` является **первичным ключом** и будет уникальным, не может содержать `NULL` значения.

### 4. **`FOREIGN KEY`**

Констрейнт **`FOREIGN KEY`** используется для создания **внешнего ключа**, который ссылается на столбец в другой таблице. Он гарантирует, что значения в одном столбце соответствуют значениям в другом столбце, обычно это используется для реализации связей между таблицами (например, отношение "один ко многим").

#### Пример:

```sql
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    user_id INT,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

Здесь столбец `user_id` в таблице `orders` ссылается на столбец `id` в таблице `users`, создавая внешний ключ. Это означает, что значение в столбце `user_id` должно существовать в столбце `id` таблицы `users`.

### 5. **`CHECK`**

Констрейнт **`CHECK`** используется для наложения условий на столбец, чтобы убедиться, что значения в нём соответствуют определённым правилам. Этот констрейнт позволяет задавать произвольные выражения, которые должны быть истинными для каждого значения в столбце.

#### Пример:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    age INT CHECK (age >= 18)
);
```

В этом примере столбец `age` должен содержать значения, которые больше или равны 18. Если при вставке данных значение будет меньше 18, операция вставки будет отклонена.

### 6. **`EXCLUSION`**

Констрейнт **`EXCLUSION`** позволяет указать более сложные ограничения, которые обеспечивают уникальность значений в столбцах на основе заданных условий. Это особенно полезно для ограничения значений в столбцах с типами данных, такими как **`range`** или **`array`**.

#### Пример:

```sql
CREATE TABLE reservations (
    room_id INT,
    period TSRANGE,
    EXCLUDE USING gist (room_id WITH =, period WITH &&)
);
```

Здесь создается таблица `reservations`, в которой определено, что два разных резервирования не могут совпадать по времени для одной и той же комнаты (с помощью констрейнта `EXCLUSION` с оператором `&&`, который проверяет, что два диапазона не пересекаются).

### 7. **`DEFAULT`**

Констрейнт **`DEFAULT`** используется для задания значения по умолчанию для столбца. Если при вставке записи не указано значение для этого столбца, будет использовано значение по умолчанию.

#### Пример:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Здесь для столбца `created_at` установлено значение по умолчанию — текущее время. Если при добавлении записи не указать значение для этого столбца, PostgreSQL автоматически подставит текущую метку времени.

### 8. **`NOT VALID`**

Констрейнт **`NOT VALID`** позволяет добавить ограничение, которое не будет немедленно проверяться на существующих данных в таблице, но будет проверяться при добавлении или изменении данных в будущем.

#### Пример:

```sql
ALTER TABLE users ADD CONSTRAINT age_check CHECK (age > 18) NOT VALID;
```

Этот констрейнт будет проверять данные только при добавлении или изменении строк после того, как он был добавлен.

### Резюме

В PostgreSQL существует несколько типов констрейнов, которые используются для обеспечения целостности данных в таблицах:

- **`NOT NULL`**: Запрещает `NULL` значения.
- **`UNIQUE`**: Гарантирует уникальность значений в столбце.
- **`PRIMARY KEY`**: Устанавливает столбец как уникальный идентификатор и запрещает `NULL`.
- **`FOREIGN KEY`**: Обеспечивает целостность данных между таблицами.
- **`CHECK`**: Устанавливает условия для значений в столбце.
- **`EXCLUSION`**: Обеспечивает уникальность значений с помощью более сложных условий.
- **`DEFAULT`**: Задает значение по умолчанию для столбца.
- **`NOT VALID`**: Позволяет добавлять ограничения без немедленной проверки на существующие данные.

Констрейнты играют важную роль в обеспечении корректности и целостности данных, предотвращая ошибки и несоответствия в базе данных.
