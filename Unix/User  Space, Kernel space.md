---

## 🟢 Что такое **User Space** и **Kernel Space**?

### 🔷 1. Kernel Space (пространство ядра)

- Это область памяти, где работает **ядро операционной системы (Linux Kernel)**.
    
- Ядро управляет:
    
    - Доступом к оборудованию (диски, сеть, устройства),
        
    - Управлением процессами,
        
    - Памятью,
        
    - Планировкой задач,
        
    - Безопасностью.
        

🔑 **Особенности:**

- Полный доступ к железу.
    
- Полный контроль над системой.
    
- Работает с привилегиями "Ring 0" (архитектура CPU).
    

---

### 🔷 2. User Space (пространство пользователя)

- Это область памяти, где работают **пользовательские программы**:
    
    - Твои приложения (`bash`, `vim`, браузер, твой Go-код).
        
    - Они изолированы друг от друга.
        
    - Не могут напрямую обращаться к оборудованию и памяти ядра.
        

🔑 **Особенности:**

- Ограниченные права.
    
- Нет прямого доступа к железу.
    
- Работает в "Ring 3" (ограниченный режим CPU).
    

---

## 🟡 Визуальная аналогия:

> Представь, что **Kernel Space — это охраняемая зона (как серверная в дата-центре)**.
> 
> **User Space — это обычный офис**, где сотрудники (процессы) работают с данными, но доступ в серверную им запрещён напрямую.

✅ Если сотруднику нужно получить данные с сервера → он оформляет **заявку (syscall)** → охранник проверяет → пускает/не пускает.

---

## 🟢 Как это выглядит в памяти:

|Адресное пространство процесса|Что там|
|---|---|
|**Kernel Space** (верхняя часть адресного пространства, например, 0xC0000000 - 0xFFFFFFFF)|Память ядра|
|**User Space** (нижняя часть, например, 0x00000000 - 0xBFFFFFFF)|Код, данные, стек процесса|

⚠️ Прямой доступ к kernel space → невозможен для обычных программ (это сделано аппаратно: MMU, привилегии CPU).

---

## 🟢 Как общаются User Space ↔ Kernel Space?

➡️ Через **системные вызовы (syscalls)**.

📦 Пример:

- Программа вызывает `read()`.
    
- Переход из user space в kernel space через "trap" инструкцию.
    
- Ядро выполняет чтение с диска.
    
- Возвращает данные в user space.
    

---

## 🟢 Почему их разделяют?

|Причина|Зачем это нужно|
|---|---|
|**Безопасность**|Пользовательские программы не могут испортить ядро или железо.|
|**Стабильность**|Если твоё приложение упало — ядро работает дальше.|
|**Изоляция**|Процессы не могут вмешиваться друг в друга.|

---

## 🟢 Пример: простая программа

```c
#include <stdio.h>

int main() {
    printf("Hello, world!\n");
    return 0;
}
```

Что реально происходит:

1. `printf()` вызывает библиотечную функцию.
    
2. Она вызывает системный вызов `write()`.
    
3. Переход из user space → kernel space → ядро пишет данные в stdout.
    
4. Возврат в user space.
    

---

## 🟡 Диаграмма связи (упрощённая):

```
[User Space (твоя программа)]
     │
     │  → библиотека (glibc, musl и т.п.)
     │
     │  → системный вызов (syscall)
     ▼
[Kernel Space (ядро Linux)]
     │
     │  → выполнение работы (диски, память, сеть)
     ▼
[User Space (результат вернулся)]
```

---

## 🟢 Важно:

- **User Space** — быстро, но ограничено.
    
- **Kernel Space** — мощно, но переход туда → медленный (syscall "дорогой").
    
- Ядро старается оптимизировать: кэширование, zero-copy, mmap для работы без постоянных syscalls.
