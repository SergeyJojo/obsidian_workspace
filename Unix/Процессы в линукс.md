---

Что такое процесс в Linux?

Процесс — это экземпляр запущенной программы в операционной системе. Это не просто код, а "живое" выполнение: программа + её состояние (память, регистры, ресурсы). В Linux всё крутится вокруг процессов — от твоего bash до демонов вроде nginx.

- Простыми словами: Процесс — это как машина на трассе. Код программы — это чертёж, а процесс — сама тачка, которая едет, жрёт бензин (CPU) и занимает место (память).
    

---

Как процесс устроен?

Linux (и Unix-системы) видит процесс как структуру с кучей компонентов. Вот как он устроен внутри:

1. PID (Process ID)

- Что: Уникальный номер процесса в системе.
    
- Зачем: Чтобы ядро и ты могли его опознать.
    
- Пример: PID=1234 — конкретный процесс.
    
- Особенность: PID=1 — это init (или systemd), первый процесс, от которого всё начинается.
    

2. Код программы

- Что: Исполняемый файл (например, бинарь ./myapp), загруженный в память.
    
- Где: Хранится в сегменте текста (text segment) — только для чтения.
    
- Как: Ядро берёт файл (ELF-формат в Linux), парсит его и готовит к выполнению.
    

3. Память процесса

Процесс получает свою виртуальную память, разделённую на сегменты:

- Стек (Stack): Локальные переменные, вызовы функций. Растёт вниз.
    
- Пример: int x = 5; → в стеке.
    
- Куча (Heap): Динамическая память (malloc, new).
    
- Пример: malloc(1024) → в куче.
    
- Сегмент данных (Data): Глобальные и статические переменные.
    
- Пример: static int count = 0;.
    
- Сегмент текста (Text): Код программы (инструкции CPU).
    
- Фишка: Виртуальная память изолирует процессы — каждый думает, что он один в системе.
    

4. Состояние процесса

- Что: Текущий статус процесса.
    
- Виды:
    
- Running: Выполняется на CPU.
    
- Ready: Ждёт CPU.
    
- Waiting: Ждёт I/O (диск, сеть) или сигнал.
    
- Stopped: Остановлен (например, Ctrl+Z).
    
- Zombie: Завершён, но ждёт, пока родитель заберёт статус.
    
- Где видно: ps aux → колонка STAT (R, S, Z и т.д.).
    

5. Регистры CPU

- Что: Состояние процессора для процесса (например, указатель команд RIP, стек RSP).
    
- Зачем: Когда процесс "бежит" на CPU, ядро загружает его регистры.
    
- Как: При переключении процессов ядро сохраняет/восстанавливает их.
    

6. Дескрипторы файлов

- Что: Список открытых файлов (stdin=0, stdout=1, stderr=2 + другие).
    
- Где: В структуре процесса в ядре.
    
- Пример: Открыл файл /log.txt → дескриптор 3.
    

7. Переменные среды

- Что: PATH, HOME, APP_ENV — настройки окружения.
    
- Как: Передаются от родителя или задаются вручную (export).
    

8. PPID (Parent Process ID)

- Что: PID родительского процесса.
    
- Зачем: Процессы — дерево. Если родитель умирает, дети "усыновляются" init (PID=1).
    
- Пример: Запустил bash, из него ./myapp → PPID myapp = PID bash.
    

9. Приоритет и nice

- Что: Уровень приоритета (от -20 до 19, меньше = выше).
    
- Зачем: Решает, кто получит CPU первым.
    
- Как менять: nice -n 10 ./myapp или renice 10 <pid>.
    

---

Как процесс создаётся?

1. Fork:
    

- Родительский процесс копирует себя через системный вызов fork().
    
- Ребёнок получает свой PID, но делит память (copy-on-write).
    
- Пример: fork() → два процесса, родитель и ребёнок.
    

2. Exec:
    

- Ребёнок заменяет свой код новым через execve() (или exec).
    
- Пример: ./myapp → fork() + execve("./myapp").
    

3. Запуск:
    

- Ты пишешь ./myapp в терминале → bash делает fork() + exec().
    

---

Жизненный цикл процесса

1. Создание: fork() + exec() или clone() (современный способ).
    
2. Выполнение: Ядро выделяет CPU через планировщик (scheduler).
    
3. Ожидание: I/O или сигналы (например, sleep).
    
4. Завершение:
    

- Процесс зовёт exit() → возвращает код (0 = ок, ≠0 = ошибка).
    
- Становится зомби → родитель читает статус через wait() → процесс умирает.
    
- Если родитель не читает, init убирает зомби.
    

---

Как это видно в Linux?

1. Посмотреть процессы:
    

- ps aux — все процессы.
    
- top или htop — в реальном времени.
    
- Пример вывода ps:
    

```text
USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
user 1234 0.1 0.2 12345 6789 pts/0 S 10:00 0:01 ./myapp
```

2. Дерево процессов:
    

- pstree — показывает иерархию.
    
- Пример: init ── bash ── myapp.
    

3. Детали процесса:
    

- /proc/<PID> — папка с инфой о процессе:
    
- /proc/1234/stat — состояние, память, PID.
    
- /proc/1234/fd — открытые файлы.
    
- Пример: cat /proc/1234/cmdline.
    

4. Сигналы:
    

- Управляй процессом: kill -SIGTERM 1234 (мягкий стоп).
    
- Список: kill -l (SIGINT=2, SIGTERM=15, SIGKILL=9).
    

---

Как ядро управляет процессами?

1. Планировщик (Scheduler):
    

- Решает, какой процесс бежит на CPU.
    
- Алгоритм: CFS (Completely Fair Scheduler) — делит время "справедливо".
    
- Пример: 3 процесса → каждый получает кусок CPU.
    

2. Контекстное переключение:
    

- Ядро сохраняет регистры одного процесса, загружает другого.
    
- Быстро (микросекунды), но жрёт ресурсы при частых переключениях.
    

3. Память:
    

- MMU (Memory Management Unit) мапит виртуальную память в физическую.
    
- Каждый процесс думает, что у него 4 ГБ (32-bit) или больше (64-bit).
    

4. Системные вызовы:
    

- Процесс общается с ядром через syscall (fork, exec, read, write).
    
- Пример: open("/file.txt") → ядро открывает файл.
    

---

Фишки и приколы

1. PID 0: Не процесс, а "idle" — ядро крутит его, когда CPU простаивает.
    
2. Зомби: Процесс завершён, но висит в таблице, пока родитель не заберёт.
    

- Убить: kill -9 <PPID> (родителя).
    

3. Орфаны: Процессы без родителей усыновляет init.
    
4. Демоны: Процессы в фоне (например, nginx), без терминала.
    

---

Пример в Go

go

```go
package main

import (
 "fmt"
 "os"
 "syscall"
)

func main() {
 pid := os.Getpid() // Мой PID
 ppid := os.Getppid() // PID родителя
 fmt.Printf("PID: %d, PPID: %d\n", pid, ppid)

 // Отправить себе сигнал
 syscall.Kill(pid, syscall.SIGTERM)
}
```

- Запусти → увидишь PID и завершится по сигналу.
    

---

Итог

- Процесс: Программа + память + состояние + ресурсы.
    
- Устройство: PID, код, стек, куча, регистры, дескрипторы.
    
- Жизнь: Fork → Exec → Run → Exit.
    
- Ядро: Планирует, переключает, изолирует.
    

Запомни как на трассе:

- Процесс — гонщик.
    
- Ядро — механик, даёт CPU и следит за порядком.
    
- PID — номер машины.
