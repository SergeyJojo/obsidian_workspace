## 🔐 Основные типы блокировок в PostgreSQL:

### 1. **Блокировки на уровне таблицы (Table-level Locks)**

> Используются при операциях, которые могут повлиять на всю таблицу.

|Тип блокировки|Кто берет|Конфликтует с|Примеры команд|
|---|---|---|---|
|`ACCESS SHARE`|`SELECT`|`ACCESS EXCLUSIVE`|Просто чтение|
|`ROW SHARE`|`SELECT FOR UPDATE`|`EXCLUSIVE`, `ACCESS EXCLUSIVE`|Чтение с намерением изменения|
|`ROW EXCLUSIVE`|`INSERT`, `UPDATE`, `DELETE`|`SHARE`, `EXCLUSIVE`, `ACCESS EXCLUSIVE`|Любая модификация строк|
|`SHARE UPDATE EXCLUSIVE`|`VACUUM`, индексация|`SHARE`, `EXCLUSIVE`, `ACCESS EXCLUSIVE`|Обслуживание|
|`SHARE`|`LOCK TABLE ... IN SHARE MODE`|`ROW EXCLUSIVE`, `EXCLUSIVE`, `ACCESS EXCLUSIVE`|Совместное использование|
|`EXCLUSIVE`|редко используется|почти со всеми||
|`ACCESS EXCLUSIVE`|`ALTER TABLE`, `DROP TABLE`, `TRUNCATE`|со всеми|Самая строгая|

> ❗ Эти блокировки ставятся **автоматически** во время выполнения команд.

---

### 2. **Блокировки на уровне строк (Row-level Locks)**

Используются при доступе к отдельным строкам таблиц.

|Тип|Кто берет|Конфликтует с|Примеры|
|---|---|---|---|
|`FOR UPDATE`|`SELECT ... FOR UPDATE`|Сам с собой и `FOR NO KEY UPDATE`|Блокирует строку для изменения|
|`FOR NO KEY UPDATE`|`SELECT ... FOR NO KEY UPDATE`|`FOR UPDATE`, `FOR NO KEY UPDATE`|Мягкий вариант, не блокирует ключи|
|`FOR SHARE`|`SELECT ... FOR SHARE`|`FOR UPDATE`, `FOR NO KEY UPDATE`, `FOR KEY SHARE`|Для чтения без изменений|
|`FOR KEY SHARE`|`SELECT ... FOR KEY SHARE`|Только с более строгими|Блокирует только ключи (foreign key refs)|

> Такие блокировки **не видны в `pg_locks` сразу**, пока не возникнет конфликт.

---

### 3. **Advisory Locks (Пользовательские / рекомендательные)**

- Это **ручные блокировки**, задаются напрямую приложением
    
- Не связаны с конкретными строками или таблицами
    
- Можно использовать для **распределенных блокировок**
    

```sql
SELECT pg_advisory_lock(1234);      -- Берём блокировку
SELECT pg_advisory_unlock(1234);    -- Снимаем
```

> Их часто применяют, когда нужно синхронизировать доступ к **внешнему ресурсу** (файл, API и т.д.).

---

## 🧮 Как посмотреть текущие блокировки?

```sql
SELECT * FROM pg_locks l
JOIN pg_stat_activity a ON l.pid = a.pid;
```

---

## ⚔️ Конфликты между блокировками

- **PostgreSQL использует матрицу совместимости**, где некоторые блокировки конфликтуют друг с другом.
    
- Например, если одна сессия делает `SELECT FOR UPDATE`, а другая — `DELETE`, будет ожидание.
