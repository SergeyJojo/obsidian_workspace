
Отлично! Давай разберём **уровни изоляции транзакций в SQL** максимально подробно. Это важная тема для собеседований, особенно если ты претендуешь на позицию, связанную с базами данных. Мы рассмотрим, что такое уровни изоляции, какие аномалии они предотвращают, и как они влияют на производительность.

---

## **Что такое уровни изоляции?**

Уровень изоляции определяет, как транзакции взаимодействуют друг с другом и какие аномалии могут возникать при одновременном выполнении нескольких транзакций. Уровни изоляции помогают балансировать между **производительностью** и **целостностью данных**.

---

## **Основные уровни изоляции**

В SQL стандартом являются четыре уровня изоляции, определённые в стандарте ANSI/ISO SQL:

1. **Read Uncommitted (Чтение незафиксированных данных)**
2. **Read Committed (Чтение зафиксированных данных)**
3. **Repeatable Read (Повторяемое чтение)**
4. **Serializable (Сериализуемый)**

---

## **1. Read Uncommitted**

### **Описание:**
- Самый низкий уровень изоляции.
- Транзакции могут видеть незафиксированные изменения других транзакций ("грязные" данные).

### **Аномалии:**
- **Грязное чтение (Dirty Read)**: Транзакция читает данные, которые ещё не были зафиксированы другой транзакцией. Если та транзакция откатывается, прочитанные данные оказываются неверными.

### **Пример:**
```sql
-- Транзакция 1
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;

-- Транзакция 2 (Read Uncommitted)
BEGIN;
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT balance FROM accounts WHERE id = 1;  -- Может прочитать незафиксированные данные
```

---

## **2. Read Committed**

### **Описание:**
- Транзакции видят только зафиксированные данные.
- Предотвращает грязное чтение, но возможны другие аномалии.

### **Аномалии:**
- **Неповторяющееся чтение (Non-repeatable Read)**: Если транзакция дважды читает одну и ту же строку, данные могут измениться из-за другой транзакции.
- **Фантомное чтение (Phantom Read)**: Если транзакция дважды выполняет запрос с условием, результат может измениться из-за вставки или удаления строк другой транзакцией.

### **Пример:**
```sql
-- Транзакция 1
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
COMMIT;

-- Транзакция 2 (Read Committed)
BEGIN;
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
SELECT balance FROM accounts WHERE id = 1;  -- Читает только зафиксированные данные
```

---

## **3. Repeatable Read**

### **Описание:**
- Гарантирует, что данные, прочитанные в транзакции, не изменятся до её завершения.
- Предотвращает грязное и неповторяющееся чтение, но возможны фантомные чтения.

### **Аномалии:**
- **Фантомное чтение (Phantom Read)**: Если транзакция дважды выполняет запрос с условием, результат может измениться из-за вставки или удаления строк другой транзакцией.

### **Пример:**
```sql
-- Транзакция 1
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
COMMIT;

-- Транзакция 2 (Repeatable Read)
BEGIN;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SELECT balance FROM accounts WHERE id = 1;  -- Данные не изменятся до завершения транзакции
```

---

## **4. Serializable**

### **Описание:**
- Самый строгий уровень изоляции.
- Транзакции выполняются так, как будто они идут последовательно.
- Предотвращает все аномалии: грязное чтение, неповторяющееся чтение и фантомные чтения.

### **Аномалии:**
- Нет аномалий, но возможны блокировки и снижение производительности.

### **Пример:**
```sql
-- Транзакция 1
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
COMMIT;

-- Транзакция 2 (Serializable)
BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
SELECT balance FROM accounts WHERE id = 1;  -- Данные не изменятся до завершения транзакции
```

---

## **Сравнение уровней изоляции**

| Уровень изоляции     | Грязное чтение | Неповторяющееся чтение | Фантомное чтение | Производительность |
| -------------------- | -------------- | ---------------------- | ---------------- | ------------------ |
| **Read Uncommitted** | Да             | Да                     | Да               | Высокая            |
| **Read Committed**   | Нет            | Да                     | Да               | Средняя            |
| **Repeatable Read**  | Нет            | Нет                    | Да               | Низкая             |
| **Serializable**     | Нет            | Нет                    | Нет              | Очень низкая       |

---

## **Как выбрать уровень изоляции?**

1. **Read Uncommitted**:
   - Используется, когда важна максимальная производительность, а целостность данных не критична.
   - Пример: аналитика, где допустимы неточности.

2. **Read Committed**:
   - Наиболее распространённый уровень.
   - Используется, когда важна целостность данных, но допустимы некоторые аномалии.
   - Пример: большинство OLTP-систем (онлайн-транзакции).

3. **Repeatable Read**:
   - Используется, когда важно, чтобы данные не изменялись в течение транзакции.
   - Пример: финансовые системы, где важно сохранять согласованность данных.

4. **Serializable**:
   - Используется, когда важна полная изоляция и целостность данных.
   - Пример: системы бронирования, где важно избегать любых аномалий.

## **Примеры настройки уровня изоляции**

### **PostgreSQL:**
```sql
-- Установка уровня изоляции для текущей транзакции
BEGIN;
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
-- Выполнение операций
COMMIT;
```

### **MySQL:**
```sql
-- Установка уровня изоляции для текущей сессии
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
-- Выполнение операций
```

### **SQL Server:**
```sql
-- Установка уровня изоляции для текущей транзакции
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
BEGIN TRANSACTION;
-- Выполнение операций
COMMIT;
```
