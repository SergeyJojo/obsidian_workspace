
### **Как происходит системный вызов (syscall) в Linux?**  
Системный вызов (syscall) — это механизм, с помощью которого пользовательские программы (user-space) запрашивают услуги ядра Linux (kernel-space), такие как работа с файлами, управление процессами, сетевое взаимодействие и т. д.  

---

## **1. Общая схема выполнения syscall**  
1. **Пользовательская программа** вызывает функцию libc (например, `open()`, `read()`, `write()`).  
2. **Библиотека C (libc)** подготавливает аргументы и передаёт управление ядру.  
3. **Процессор переключается в режим ядра** (из `ring3` в `ring0` на x86).  
4. **Ядро выполняет запрошенную операцию** (например, читает файл).  
5. **Результат возвращается в пользовательское пространство**.  

---

## **2. Детали реализации на примере x86_64**  
### **2.1. Как программа вызывает syscall?**  
На ассемблере это выглядит так:  
```asm
mov rax, 0x01  ; номер syscall (1 = sys_exit)  
mov rdi, 0      ; аргумент (код возврата)  
syscall         ; инструкция, вызывающая переход в ядро
```
- **`rax`** — номер системного вызова (например, `1` = `exit`, `0` = `read`).  
- **`rdi, rsi, rdx, r10, r8, r9`** — аргументы (до 6 штук).  
- **`syscall` / `int 0x80`** — инструкция для перехода в ядро.  

> На x86_64 используется `syscall`, на старых x86 — `int 0x80`.  

### **2.2. Таблица системных вызовов (syscall table)**  
Ядро хранит таблицу, где каждому номеру соответствует функция:  
```c
// Пример для Linux x86_64
void *sys_call_table[] = {
    [0] = sys_read,
    [1] = sys_write,
    [2] = sys_open,
    // ...
};
```
- Номера syscall можно найти в `/usr/include/asm/unistd_64.h`.  

### **2.3. Переключение в режим ядра**  
При вызове `syscall`:  
1. **Процессор переключает CPU в ring0** (режим ядра).  
2. **Сохраняет регистры и пользовательский стек**.  
3. **Загружает указатель на стек ядра**.  
4. **Начинает выполнять код ядра**.  

### **2.4. Обработка в ядре**  
- Ядро проверяет аргументы (чтобы не было доступа к чужим данным).  
- Выполняет запрошенную операцию (например, читает данные с диска).  
- Возвращает результат через `rax`.  

### **2.5. Возврат в пользовательский режим**  
- Инструкция `sysret` (или `iret` на старых CPU) переключает обратно в `ring3`.  
- Программа получает результат.  

---

## **3. Пример: как `read()` становится syscall**  
1. **Программа вызывает `read(fd, buf, size)` из libc**.  
2. **Libc записывает аргументы в регистры**:  
   ```asm
   mov rax, 0      ; syscall номер 0 (read)
   mov rdi, fd     ; файловый дескриптор
   mov rsi, buf    ; буфер для данных
   mov rdx, size   ; размер данных
   syscall
   ```  
3. **Ядро выполняет `sys_read()`**.  
4. **Результат (количество прочитанных байт) возвращается в `rax`**.  

---

## **4. Оптимизации: `vdso` и `vsyscall`**  
Некоторые частые syscall (например, `gettimeofday`) ускоряются через:  
- **`vdso` (Virtual Dynamic Shared Object)** — специальная область памяти, позволяющая получать данные ядра без переключения в ring0.  
- **`vsyscall`** — устаревший механизм для простых syscall.  

---

## **5. Как посмотреть syscall процесса?**  
- **`strace`** — трассировка всех системных вызовов:  
  ```bash
  strace ls -l
  ```
- **`/proc/<pid>/syscall`** — текущий syscall процесса:  
  ```bash
  cat /proc/self/syscall  # для текущей shell
  ```

---

## **Вывод**  
Syscall в Linux — это строго регламентированный способ взаимодействия пользовательских программ с ядром. Он включает:  
1. Подготовку аргументов в регистрах.  
2. Переключение CPU в режим ядра.  
3. Поиск обработчика в `sys_call_table`.  
4. Выполнение операции и возврат результата.  

Если хочешь глубже, можно изучить:  
- Исходники ядра (например, `arch/x86/entry/entry_64.S`).  
- `man syscalls` — список всех syscall в Linux.  
- Книгу **"Linux Kernel Development" (Robert Love)**.

## 🟢 Что такое системные вызовы (syscalls) в Linux?

🔹 **Системный вызов** — это способ, которым программы (пользовательское пространство, "user space") просят ядро Linux (kernel space) выполнить привилегированные операции.

➡️ Программы **не могут напрямую работать с железом, памятью, файлами, сетями** и прочим. Всё это делает ядро.  
➡️ Чтобы что-то "попросить у ядра" → используется системный вызов.

📦 **Пример:**

- Тебе нужен файл → делаешь `open()`.
    
- Тебе нужно прочитать из файла → `read()`.
    
- Ты хочешь отправить данные по сети → `sendto()`.
    
- Ты хочешь выделить память → `mmap()`.
    

---

## 🟢 Примеры популярных системных вызовов

|Категория|Системные вызовы|Назначение|
|---|---|---|
|**Файлы**|`open()`, `read()`, `write()`, `close()`|Работа с файлами|
|**Процессы**|`fork()`, `execve()`, `wait4()`, `exit()`|Создание и управление процессами|
|**Память**|`brk()`, `mmap()`, `munmap()`|Выделение и освобождение памяти|
|**Сеть**|`socket()`, `connect()`, `sendto()`, `recvfrom()`|Сетевые операции|
|**Сигналы**|`kill()`, `sigaction()`, `sigreturn()`|Управление сигналами|
|**Таймеры и события**|`nanosleep()`, `epoll_wait()`, `poll()`|Ожидание событий|
|**Информация о системе**|`uname()`, `getpid()`, `gettimeofday()`|Получение информации|
|**Безопасность**|`chmod()`, `chown()`, `capget()`|Права доступа|

## 🟢 Как часто вызываются системные вызовы?

- **Очень часто**.
    
- Любое чтение файла, вывод в терминал, запрос по сети — это системные вызовы.
    
- Даже вывод в консоль через `printf()` вызывает `write()` под капотом.
    
- В любом "пустом" цикле почти нет syscalls. Но как только идёт взаимодействие с внешним миром — syscalls.
    

📦 **Пример замера:**

```bash
strace ls >/dev/null
```

Покажет, сколько syscall вызвал обычный `ls`.

## 🟢 А можно ли читать из памяти без системного вызова?

▶️ **В своей памяти — да. В чужой — нет.**

### 📍 Чтение из своей памяти:

- **Локальная память процесса** уже отображена (`mapped`) в адресное пространство.
    
- Чтение/запись к переменным, массивам, указателям — это обычные инструкции CPU (`MOV`, `LOAD`, `STORE`), никакого системного вызова здесь нет.
    

📝 Пример:

```c
int x = 42;
int y = x + 5; // Тут нет syscall, чистая работа CPU
```

### 📍 Чтение из чужой памяти:

- Доступ к чужим процессам или к физической памяти требует прав суперпользователя.
    
- Тут нужны syscalls: например, `ptrace()`, `/proc/pid/mem` (через `read()`), либо mmap файлов устройств.
    

📦 Пример:

- `strace`, `gdb` читают память чужого процесса через системные вызовы.
    

### 📍 Итог:

|Ситуация|Нужен ли системный вызов?|
|---|---|
|Чтение своих переменных|❌ Нет|
|Чтение выделенной mmap памяти|❌ (только при map нужен был syscall)|
|Доступ к файлу|✅ Да (read())|
|Доступ к чужой памяти|✅ Да (ptrace, proc, etc.)|

---

## 🟡 Почему нельзя просто так читать чужую память?

- Линукс использует **изоляцию процессов** (user space / kernel space, virtual memory, page tables).
    
- Без этого процессы могли бы "воровать" пароли друг у друга.
    
- Поэтому только через ядро и контролируемые syscalls → ptrace, procfs и т.д.
    

---

## 🟢 Визуализация (упрощённо):

```
[Твой процесс (user space)]
 └─ доступ к своим переменным —> напрямую (MOV инструкции)
 └─ доступ к файлам/сети —> через системные вызовы (syscall)
 └─ доступ к чужой памяти —> ptrace() / procfs (через syscall)
```
