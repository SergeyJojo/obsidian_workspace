Сергей, хороший вопрос 👍. Давай разберём, **какие структуры данных Go использует для прохода по ссылкам (объектам в куче) при сборке мусора (GC)**.

---

### 1. Общая идея

В Go используется **трассирующий, трицветный, инкрементальный GC**. Его задача — найти все объекты, которые достижимы от **root-ов** (стеков горутин, глобальных переменных, регистров и т.д.), и освободить остальные. Для этого нужно обойти всю "графовую структуру объектов" в куче.

Чтобы это сделать, Go применяет **специализированные структуры данных** для хранения "списка ссылок" и для управления очередью обхода.

---

### 2. Основные структуры

1. **Mark Queue (очередь для обхода)**
    
    - Это специальная структура (ring buffer, иногда называют **work buffer**) для хранения адресов объектов, которые нужно ещё обработать.
        
    - В Go она реализована в `runtime/mgcwork.go` как `workbuf`.
        
    - Каждая воркер-нитка GC берёт себе `workbuf` и раскладывает туда новые найденные ссылки. Когда буфер переполняется, часть отдаётся другим воркерам (work stealing).
        
2. **Bitmaps и arena layout**
    
    - Память кучи делится на **арены** (обычно 64MB).
        
    - Для каждой арены есть **bitmap**, где для каждого слова (8 байт) помечается: содержит ли оно указатель, использовано ли, нужно ли просканировать и т.д.
        
    - Эти bitmaps — основной способ понять, какие поля структуры являются ссылками.
        
3. **Gray/Black/White marking (три цвета)**
    
    - GC не хранит отдельный список "серых" объектов, а использует **mark queue** для серых (объекты, найденные, но не обработанные).
        
    - Когда объект обрабатывается, его ссылки добавляются в очередь, а сам объект становится "чёрным".
        
    - "Белые" — ещё не посещённые.
        

---

### 3. Как происходит обход

1. Начало — сбор root-ов: регистры, стеки, глобалы.  
    Все найденные указатели помещаются в **mark queue** (серые).
    
2. Пока очередь не пуста:
    
    - Берётся объект, проверяется через **bitmap**, какие поля являются указателями.
        
    - Для каждого указателя: если объект ещё белый → красим его в серый и добавляем в очередь.
        
3. Когда очередь пуста — всё достижимое уже обработано. "Белые" объекты освобождаются.
    

---

### 4. Аналогии с классическими структурами данных

- По сути это **BFS (обход в ширину)** графа объектов:
    
    - Очередь (`mark queue`) → FIFO структура для серых объектов.
        
- Bitmaps → позволяют быстро проверить, где именно в объекте лежат ссылки.
    
- Work stealing queues → чтобы параллельные воркеры не блокировались друг о друга.
    

---

### 5. Особенности Go

- Go **не строит отдельный список ссылок для каждого объекта** (как в некоторых JVM).
    
- Вместо этого компилятор вставляет метаданные о расположении полей-указателей (pointer masks).
    
- GC использует эти **pointer masks + bitmap** для прохода.
    
- Очередь (`workbuf`) — это ключевая структура данных, без неё обход был бы невозможен.
    

---

👉 Итого:  
В Go GC использует **очередь (mark queue)** для хранения серых объектов и **битовые карты (bitmaps + pointer masks)** для нахождения ссылок внутри объектов.  
Алгоритм обхода — это фактически BFS по графу объектов в куче.
