## 1. 🧠 Философия проектирования Go

Go создавался как **системный язык**, который должен:

- быть **простым и понятным** (в том числе новичкам),
    
- компилироваться **быстро**,
    
- быть **предсказуемым** в поведении (в отличие от C++),
    
- обладать **сильной статической типизацией**,
    
- обеспечивать **большую производительность**, но без жертв читаемости.
    

**Функции в Go** проектировались как **основная единица композиции**, с чёткой сигнатурой и минимальным синтаксическим сахаром. Они:

- **не имеют перегрузки** (`overloading`) — один идентификатор = одна функция,
    
- не имеют **default-аргументов**,
    
- поддерживают **именованные возвращаемые значения** (для читаемости),
    
- поддерживают **variadic параметры** (`...`),
    
- допускают **замыкания** (closures),
    
- работают с **передачей по значению**, включая аргументы,
    
- могут быть **анонимными** и присваиваться переменным.
    

Это сознательный компромисс — **меньше гибкости ради большей читаемости и предсказуемости**.

## 2. ⚙️ Как функции устроены внутри (реализация Go runtime)

### ✅ Вызов функции:

- **Все аргументы передаются по значению**.
    
- Если передаётся ссылка (например, `*T`), ты сам явно управляешь этим.
    
- Передача аргументов идёт через **регистры или стек**, в зависимости от архитектуры (на уровне `go/asm`).
    
- Внутри функции:
    
    - создаётся **кадр стека (stack frame)**,
        
    - аргументы копируются в локальные переменные,
        
    - стек может **динамически расти**, если не хватает места (Go использует split stack).
        

Go использует **собственный ABI (Application Binary Interface)**, который может отличаться от системного (особенно на разных архитектурах и версиях Go).

### 🗂 Память:

- **Stack allocation** (по умолчанию) — эффективная и безопасная.
    
- Компилятор сам решает, **heap или stack** (через escape analysis).
    
- Возврат значений — через регистры (если короткие), либо через **"result parameter"**, который передаётся по указателю компилятором.
    

### 📈 Пример:

```go
func add(a, b int) int {
    return a + b
}
```

- `a`, `b` — копируются при вызове.
    
- Результат возвращается в регистре (если позволяет архитектура).

## 3. 🧰 Closure и лямбды

Анонимные функции в Go — это **closures**, которые при необходимости **захватывают переменные из внешней области видимости**.

```go
func adder(x int) func(int) int {
    return func(y int) int {
        return x + y
    }
}
```

- `x` **копируется** или **выносится в heap**, если жизненный цикл переменной выходит за рамки функции.
    
- Go **автоматически упаковывает окружение** и делает его частью структуры — closure.

## 4. 🔬 Особенности и ограничения

### Что _намеренно не включено_ в функции Go:

|Возможность|Статус|Причина|
|---|---|---|
|Перегрузка функций|❌|Сложность компиляции, неоднозначность|
|Дефолтные аргументы|❌|Усложняет интерфейс, можно заменить обёрткой|
|Генерация кода во время выполнения|❌|Нет JIT, язык строго компилируемый|
|Обработка исключений|❌|Вместо этого — `error` как возвращаемое значение|
|Функции с именованными аргументами (как в Python)|❌|Строгое соответствие порядку аргументов|

## 📦 Компилятор и внутренняя реализация

Функции обрабатываются:

- **На этапе компиляции (SSA-проход)** — упрощение и оптимизация графа вызовов.
    
- **Go compiler (`cmd/compile`)** → SSA → машинный код.
    
- **Рантайм (Go runtime)** управляет стеком, планировкой горутин, preemption, GC и т.д.
