# 🧠 Interned Strings в PHP

---

## 🔍 Что это вообще такое

**Interned strings** — это механизм Zend Engine, при котором одинаковые строковые значения **хранятся в памяти только один раз**, даже если встречаются в коде много раз.

Проще говоря:

> PHP держит глобальный пул уникальных строк, и если новая строка совпадает с уже существующей — она просто переиспользует тот же указатель, а не создаёт новую копию.

---

## ⚙️ Как это работает

Каждая строка в PHP представлена структурой `zend_string`:

```c
struct _zend_string {
    zend_refcounted_h gc;  // счётчик ссылок (в т.ч. GC info)
    zend_ulong h;          // precomputed hash
    size_t len;            // длина
    char val[1];           // сам текст (динамический массив)
};
```

Когда Zend создаёт строку:

1. Сначала он считает хэш (`h`).
    
2. Проверяет глобальный пул interned-строк.
    
3. Если строка уже есть — возвращает ссылку на существующую `zend_string`.
    
4. Если нет — добавляет новую в пул.
    

---

## 🚀 Почему это важно

### 1. Экономия памяти

Например:

```php
$a = "user_id";
$b = "user_id";
```

Без interning:

- создаются **два отдельных zend_string** со своими `val[1]`.
    

С interning:

- создаётся **один экземпляр строки** в пуле,
    
- обе переменные `$a` и `$b` просто указывают на один и тот же `zend_string`.
    

---

### 2. Быстрое сравнение строк

Если две строки interned, их сравнение происходит **по указателю**, а не побайтово.

```php
if ($a === $b)
```

→ просто проверка `a_ptr == b_ptr` → **O(1)**.

---

## 📦 Где используется интернирование

Zend автоматически интернирует строки:

|Место|Пример|Интернирована?|
|---|---|---|
|**Имя класса, функции, метода**|`class User {}`|✅|
|**Имена переменных**|`$foo`|✅|
|**Константные строки в коде**|`"hello"`|✅|
|**Ключи массива**|`$arr['key'] = 1`|✅|
|**Результат конкатенации**|`"a" . "b"`|⚠️ Только если compile-time|
|**Результат вычислений**|`$x = strtoupper("foo")`|❌ (runtime, не interned)|

---

## 🧩 Пул interned строк

Zend хранит interned строки в **хэш-таблице в глобальной памяти**, чтобы:

- каждая строка была уникальна по значению,
    
- доступ был быстрым (`O(1)` по хэшу),
    
- строки не удалялись при каждом завершении запроса.
    

### В CLI / long-running процессах (например, Swoole, RoadRunner)

Пул сохраняется на протяжении всего времени жизни процесса.

### В обычных PHP-FPM/Apache запросах

Пул очищается при завершении каждого запроса, но кэш PHP (opcache) может его поддерживать между запросами.

---

## ⚙️ Связь с OPCache

**OPCache** компилирует скрипты в байткод и кэширует их в памяти.  
Все строки, встречающиеся в этом байткоде (например, имена классов, ключи, литералы), **автоматически интернируются** и живут в shared memory.

Поэтому:

- интернированные строки **не пересоздаются между запросами**;
    
- меньше нагрузка на аллокатор памяти;
    
- меньше GC overhead.
    

---

## 🧠 Особенности работы в PHP 7+

С PHP 7 произошли ключевые изменения:

1. **zend_string immutable** — сами строки не изменяются.
    
2. **Interned строки refcount = 0**, чтобы они **не участвовали в подсчёте ссылок**.
    
3. **Copy-on-write**:
    
    - если строка не interned и кто-то меняет её — создаётся новая копия;
        
    - если строка interned — она **всегда неизменна**, любое изменение → новая zend_string.
        

Пример:

```php
$a = "foo";
$b = $a;
$b .= "bar";
```

- `$a` → `"foo"` (interned)
    
- `$b` → `"foobar"` (новая zend_string)
    

---

## 🧩 Влияние на память

```php
for ($i = 0; $i < 100000; $i++) {
    $arr[] = "hello";
}
```

- Без interning: 100k копий `"hello"`.
    
- С interning (и opcache): только одна `"hello"` в пуле.
    

💡 В реальном коде, где часто повторяются одинаковые ключи (`'id'`, `'user'`, `'created_at'`), выигрыш по памяти может быть десятки мегабайт.

---

## 🔬 Проверка interned строк на практике

Можно проверить, interned ли строка, по косвенным признакам.

```php
function is_interned($str): bool {
    static $s = [];
    $s[$str] = true;
    $keys = array_keys($s);
    return $str === $keys[0];
}
```

Если строка `"a"` interned, при повторном сравнении `$str === $keys[0]` даст true по указателю.


```php

```

---

## ⚡ Практические советы

1. **Не создавай одинаковые строки динамически** (особенно в циклах) — лучше использовать константы.
    
2. **Включай OPCache** — он хранит interned строки между запросами.
    
3. **Используй `define()` / `const`** для часто встречающихся строк.
    
4. **В больших CLI-приложениях** (Swoole, RoadRunner, Laravel Octane) интернирование особенно выгодно, т.к. процесс долгоживущий.
    
5. **Не пытайся вручную интернировать строки через кастомные расширения**, если не уверен — Zend сам делает это эффективно.

---

## 🧩 TL;DR

- Interned strings = _уникальный пул неизменяемых строк_ в Zend Engine.
    
- Работают автоматически, особенно в OPCache.
    
- В PHP 7+ interned строки не участвуют в GC и всегда `refcount = 0`.
    
- Это один из ключевых факторов, почему PHP 7+ стал гораздо быстрее и экономичнее по памяти.
