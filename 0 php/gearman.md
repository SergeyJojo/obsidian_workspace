Давай дам **чёткий, глубокий разбор**, что такое Gearman, как он устроен, чем отличается от современных очередей, и как им пользовались в PHP.

# 🚀 Что такое **Gearman**

**Gearman** — это высокопроизводительный _job server_, который распределяет задачи между воркерами, написанными на любом языке.

Это не брокер сообщений в классическом понимании (как RabbitMQ или Kafka), а именно система _task offloading_ — вынеси тяжёлую работу в фоновые воркеры.

---

# ⚙️ Внутреннее устройство Gearman

Gearman состоит из трёх ролей:

## 1) **Client** (клиент)

Приложение (например Laravel) отправляет задачу в Gearman:

- данные для работы
    
- имя задачи (`function name`)
    
- prioroty: low / normal / high
    
- тип: background job или foreground job
    

Клиент не выполняет задачу — только отправляет.

---

## 2) **Job Server** (сервер задач)

`gearmand` — бинарь, который:

- получает задачу от клиента
    
- получает список воркеров и их функций
    
- назначает задачу подходящему воркеру
    
- следит за прогрессом (если foreground)
    
- возвращает результат клиенту
    

Job server сам ничего не исполняет — это диспетчер и роутер.

---

## 3) **Worker** (исполнитель)

Процесс (чаще CLI-php), который регистрирует функции типа:

```
thumbnail_create
send_email
rebuild_index
```

Gearman посылает воркеру задачу → воркер выполняет → результат возвращается серверу.

### Важно:

- Воркеров может быть десятки и сотни.
    
- Всё в Gearman из коробки горизонтально масштабируемо.
    
- Работает быстро и стабильно.
    

---

# 📌 Как работает цикл выполнения задачи

1. PHP (Laravel) → отсылает Job:  
    `create_thumbnail(image_id)`
    
2. gearmand получает задание
    
3. Выбирает воркера, который может выполнять `create_thumbnail`
    
4. Воркер получает payload (например JSON)
    
5. Воркер делает работу
    
6. Возвращает результат клиенту (foreground) или просто заканчивает (background)

# 📦 Как в Laravel работали с Gearman

Laravel **не поддерживает Gearman из коробки** уже давно, но раньше использовали:

- пакет _ivkos/laravel-gearman_
    
- пакет _appcline/gearman-php_
    
- или чистый PHP Worker + Laravel client
    

Код клиента выглядел так:

```php
$client = new \GearmanClient();
$client->addServer();

$client->doBackground("send_email", json_encode([
    "user_id" => 123,
    "template" => "welcome"
]));
```

Воркер (обычно artisan-команда):

```php
$worker = new \GearmanWorker();
$worker->addServer();

$worker->addFunction("send_email", function($job) {
    $data = json_decode($job->workload(), true);
    Mail::to(User::find($data['user_id']))->send(new WelcomeMail());
});

while ($worker->work());
```

# ⭐ Плюсы Gearman

- Очень быстрый (написан на C)
    
- Лёгкий, простой протокол
    
- Многопроцессные воркеры, легко масштабировать
    
- Можно писать воркеров на Go, PHP, Python, C, Rust — всё что угодно
    
- Малые оверхеды и задержки
    
- Хорош для CPU-bound задач
    

---

# ❗ Минусы Gearman (почему ушёл в прошлое)

- Никакой персистентности  
    задачи исчезнут, если server/worker упадёт
    
- Нет концепции "ack", "dead-letter", "retry strategy"
    
- Нет нормального мониторинга как в RabbitMQ/Kafka/Redis
    
- Нет сохранения очереди в диск
    
- Архитектура устарела → не развивается
    

---

# 🆚 Gearman vs Laravel Queues (Redis/RabbitMQ)

|Возможность|Gearman|Redis Queue|RabbitMQ|
|---|---|---|---|
|Retry|❌|✔️|✔️|
|Персистентность|❌|⚠️ (только RDB)|✔️|
|Dead-letter queue|❌|❌|✔️|
|Monitoring UI|❌|Horizon|✔️|
|Сложные роутинги|❌|❌|✔️|
|Скорость|✔️✔️✔️|✔️✔️|✔️✔️|

# 🧠 Итог

**Gearman — это быстрый и очень простой сервер очередей, который распределяет задачи на воркеров.**  
Сегодня он почти вышел из употребления, потому что современные очереди дают:

- надёжность
    
- персистентность
    
- рейтраи
    
- мониторинг
    
- задержанные сообщения
    
- тонкую маршрутизацию
    

Но важно понимать его архитектуру — она крайне чистая и минималистичная.
