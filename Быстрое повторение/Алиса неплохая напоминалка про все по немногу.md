
### 1. Механизм context switching между горутинами

Go использует кооперативную многозадачность на уровне пользователя (user-level). Это означает:

- Переключение происходит только в определенных точках:
    
    - При блокирующих операциях (I/O, синхронизация)
        
    - При явном вызове `Gosched()`
        
    - При достижении кванта времени выполнения
        

Основные компоненты:

- **G (goroutine)** - абстрактное представление горутины
    
- **M (machine)** - операционная система нить (OS thread)
    
- **P (processor)** - виртуальный процессор
    

Процесс переключения:

NaN. Когда G блокирует M, текущий P ищет другую готовую к исполнению горутину
    
NaN. Если нет готовых - P может “уснуть” или ждать новых
    
NaN. При достижении кванта времени (10мс по умолчанию) происходит переключение
    

Ограничения по производительности:

- Overhead на переключение контекста
    
- Время на поиск следующей горутины
    
- Возможные блокировки при конкуренции за ресурсы
    

### 2. Структура mcache

Mcache - это локальный кэш для каждого M (OS thread), который используется для:

- Управления памятью
    
- Уменьшения конкуренции при аллокации
    
- Оптимизации работы с heap
    

Структура:

- Small object cache (для маленьких объектов)
    
- Large object cache (для больших объектов)
    
- Central cache pointer
    

Стратегии уменьшения contention:

NaN. Локальный кэш для каждого M
    
NaN. Использование локальных списков объектов
    
NaN. Минимизация доступа к центральному кэшу
    
NaN. Автоматическое расширение при необходимости
    

### 3. Реализация каналов

Каналы реализованы как:

- Двунаправленные очереди
    
- С использованием кольцевых буферов
    
- С поддержкой блокировки при необходимости
    

Buffered vs Unbuffered:

**Unbuffered:**

- Блокирует отправителя до получения
    
- Простой механизм синхронизации
    
- Используется для прямого взаимодействия
    

**Buffered:**

- Использует кольцевой буфер
    
- Отправитель блокируется только при полном буфере
    
- Получатель - при пустом буфере
    
- Оптимизирован для параллельной работы

Компоненты:

- Poller - основной компонент для опроса сокетов
    
- PolledSockets - набор отслеживаемых сокетов
    
- Epoll/Kqueue/IOCP - в зависимости от платформы
    

Стратегии оптимизации:

NaN. Группировка сокетов
    
NaN. Эффективное использование системных вызовов
    
NaN. Минимизация системных переключений
    
NaN. Балансировка нагрузки между poller’ами
    

### 5. Sysmon

Sysmon - системный монитор, который:

Функции:

- Отслеживает активность горутин
    
- Контролирует использование CPU
    
- Управляет preemption
    
- Следит за блокировками
    

Процесс принятия решений:

NaN. Периодический мониторинг активности
    
NaN. Проверка использования CPU
    
NaN. Анализ блокировок
    
NaN. Принятие решения о preemption
    

Критерии preemption:

- Достижение кванта времени
    
- Чрезмерное использование CPU
    
- Длительные блокировки
    
- Неравномерное распределение нагрузки
