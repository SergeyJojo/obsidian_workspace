Общая структура запросов к базе данных в 1С-Битрикс сильно отличается между старым процедурным стилем и современным ядром D7. Вот сравнительная таблица, которая наглядно показывает эту эволюцию.

### 📊 Сравнение структур запросов

| Аспект | **Старый процедурный стиль (Legacy)** | **Современное ядро D7 (ORM)** | **Выводы и рекомендации** |
| :--- | :--- | :--- | :--- |
| **Базовый синтаксис** | Функции-обёртки (`CIBlockElement::GetList`) с передачей массива параметров. | Объектно-ориентированный вызов методов цепочкой (Fluent Interface). | D7 код читается как предложение, последовательно описывающее задачу. |
| **Пример запроса** | `$res = CIBlockElement::GetList(<br> ['SORT' => 'ASC'],<br> ['IBLOCK_ID' => 2, 'ACTIVE' => 'Y'],<br> false, false,<br> ['ID', 'NAME', 'PROPERTY_PRICE']<br>);` | `$query = ElementTable::getList([<br> 'select' => ['ID', 'NAME', 'PROPERTY_PRICE_VALUE'],<br> 'filter' => ['=IBLOCK_ID' => 2, '=ACTIVE' => 'Y'],<br> 'order' => ['SORT' => 'ASC']<br>]);` | Синтаксис D7 интуитивно понятнее, имена параметров явно указывают их роль. |
| **Безопасность (SQL-инъекции)** | Зависит от разработчика. Нужно вручную экранировать значения в фильтрах (`CIBlock::SQLWhere`). | **Автоматическая защита**. ORM самостоятельно экранирует все переданные значения. | D7 устраняет самый частый источник уязвимостей. Это главное преимущество в безопасности. |
| **Кеширование** | Ручное, через `CPHPCache` или `$GLOBALS['CACHE_MANAGER']`. Легко забыть или сделать неправильно. | **Встроенное и простое**. Добавляется параметр `cache` в массив `getList()`. | В D7 кеширование становится стандартной практикой, а не сложной опцией. |
| **Работа с результатом** | Цикл `while ($arItem = $res->Fetch()) { ... }`. Метод `GetNext()` для ассоциативных массивов. | Цикл `while ($item = $query->fetchObject()) { ... }`. Возвращает объект или массив. | D7 поощряет работу с объектами, что удобнее для современных IDE (автодополнение, подсказки). |
| **Сложные JOIN и связи** | Сложно и неочевидно. Через `runtime` поля в старом API или прямое указание `__JOIN` в фильтре. | Естественно через **отношения (relations)** в описании сущности и параметр `runtime`. | D7 делает сложные связи управляемыми и декларативными, что сильно упрощает код. |
| **Создание/обновление** | Функции `CIBlockElement::Add` и `Update`. Нет встроенной валидации на уровне модели. | Методы `add()`, `update()` у объекта `DataManager`. Валидация через `Entity\Base`. | В D7 бизнес-логику (проверки, действия по умолчанию) можно инкапсулировать внутри класса сущности. |
| **Отладка** | Получить итоговый SQL очень сложно, часто нужно смотреть логи БД. | Легко получить SQL через `getQuery()` у объекта запроса перед выполнением. | D7 делает процесс отладки запросов прозрачным и контролируемым. |

### 🚀 Ключевые преимущества структуры D7

1.  **Безопасность по умолчанию**: Автоматическое экранирование — огромный шаг вперёд.
2.  **Производительность из коробки**: Встроенное, "однострочное" кеширование резко снижает нагрузку.
3.  **Читаемость и поддержка**: Код на D7 самодокументируется благодаря чёткой структуре и именованию.
4.  **Современность и экосистема**: Подход D7 позволяет использовать инструменты вроде **QueryBuilder**, **D7 Cache** и легко интегрировать сторонние библиотеки, совместимые с PSR.

### 📝 Практический пример: как избежать N+1 с D7

Проблема N+1 (когда в цикле делаются дополнительные запросы) в старом стиле решалась ручной оптимизацией. В D7 ORM даёт инструменты для её элегантного решения.

**Задача**: Получить список новостей (элементов инфоблока) и для каждой вывести название её раздела.

**Устаревший, проблемный подход (старый стиль)**:
```php
$res = CIBlockElement::GetList(...); // 1-й запрос: получили элементы
while ($element = $res->Fetch()) {
    // N запросов по количеству элементов!
    $sectionRes = CIBlockSection::GetByID($element['IBLOCK_SECTION_ID']);
    $section = $sectionRes->Fetch();
    echo $section['NAME'];
}
```

**Современное решение на D7 ORM** (загрузка связанных данных одним запросом):
```php
use Bitrix\Iblock\ElementTable;

$query = ElementTable::getList([
    'select' => [
        'ID',
        'NAME',
        'IBLOCK_SECTION_ID',
        'SECTION_NAME' => 'SECTION.NAME' // Делаем JOIN с таблицей разделов
    ],
    'filter' => ['=IBLOCK_ID' => 2],
    'cache' => ['ttl' => 3600] // И сразу кешируем результат
]);

while ($element = $query->fetchObject()) {
    // Раздел уже загружен, дополнительных запросов нет!
    echo $element->getSectionName();
}
```

### 💎 Заключение

Общая структура запросов в D7 — это **сдвиг от "как сделать запрос" к "как описать нужные данные"**. Она делает код безопаснее, быстрее и долговечнее.

**Что использовать?**
*   **Новые проекты и серьёзные доработки — только D7.**
*   **Работа с унаследованным кодом — старайтесь изолировать старые вызовы и постепенно переписывать их на D7, особенно в местах, критичных к производительности и безопасности.**

Если хотите разобрать конкретный тип запроса (выборка с группировкой, агрегатные функции, сложные связи) или увидеть, как выглядит миграция реального фрагмента кода — обращайтесь!
