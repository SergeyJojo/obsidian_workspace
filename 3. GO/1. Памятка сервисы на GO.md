# 📜 Памятка: Построение сервисов на Go

## 1. ✅ Структура проекта (Standard Go Project Layout)

```
cmd/
  myservice/
    main.go
internal/
  handler/
    http/
      user_handler.go
  service/
    user_service.go
  repository/
    user_repository.go
  model/
    user.go
  config/
    config.go
pkg/                 # публичные пакеты
  logger/
  middleware/
  utils/
config/
  config.yaml
  config.dev.yaml
web/
  static/
  templates/
scripts/
  build.sh
  deploy.sh
test/
  integration/
  mocks/
go.mod
go.sum
Makefile
README.md
```

> **`internal/`** — приватные пакеты, не экспортируются  
> **`pkg/`** — общие пакеты, которые могут использоваться другими сервисами

## 2. 🧱 Принципы проектирования

| Принцип | Как применять |
|--------|---------------|
| **Single Responsibility** | Каждый пакет, структура, функция — за одну вещь |
| **Dependency Injection** | Передавай зависимости в конструктор, не создавай внутри |
| **Interface Segregation** | Создавай узкие интерфейсы (`Repository`, `Service`) |
| **Don't Repeat Yourself (DRY)** | Выносите общую логику в `pkg/utils` |
| **Fail Fast** | Проверяй ошибки на входе, не молчи |
| **Use Context for Cancellation** | Всегда передавай `context.Context` в публичные методы |

## 5. 🧰 Логирование

Не используй `log.Println()` в production.

✅ Используй структурированное логирование:

```go
import "github.com/sirupsen/logrus"

log.WithFields(log.Fields{
    "user_id": 123,
    "action":  "login",
}).Info("User logged in")
```

Или `log/slog` (встроен в Go 1.21+):

```go
slog.Info("User created", "id", user.ID, "email", user.Email)
```

## 6. 🌐 HTTP-сервер (HTTP Handler)

### Используй роутер:
```go
r := mux.NewRouter()
r.HandleFunc("/users", handler.GetUsers).Methods("GET")
r.HandleFunc("/users", handler.CreateUser).Methods("POST")
```

### Пишите handler-ы так:
```go
func (h *UserHandler) CreateUser(w http.ResponseWriter, r *http.Request) {
    var input CreateUserRequest
    if err := json.NewDecoder(r.Body).Decode(&input); err != nil {
        http.Error(w, "Invalid JSON", http.StatusBadRequest)
        return
    }

    user, err := h.service.Create(r.Context(), input)
    if err != nil {
        handleError(w, err)
        return
    }

    json.NewEncoder(w).Encode(user)
}
```

## 7. 🔄 Context и Graceful Shutdown

Всегда используй `context`:

```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
```

Graceful shutdown:

```go
server := &http.Server{Addr: ":8080", Handler: router}
go server.ListenAndServe()

stop := make(chan os.Signal, 1)
signal.Notify(stop, os.Interrupt, syscall.SIGTERM)

<-stop
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()
server.Shutdown(ctx)
```

## 8. 🧩 Слои приложения

Разделяй на слои:

```
Handler (HTTP) → Service (бизнес-логика) → Repository (доступ к данным)
```

- **Handler** — принимает запрос, валидирует, вызывает сервис
- **Service** — содержит бизнес-логику, работает с несколькими репозиториями
- **Repository** — работа с БД, кэшем и т.д.

## 9. 🧪 Тестирование

    service := NewUserService(mockRepo)

## 10. 🧱 Работа с базой данных

- Используй `database/sql` + `sqlx` или `pgx`
- Пишите интерфейсы:
  ```go
  type UserRepository interface {
      Create(ctx context.Context, user *User) error
      Get(ctx context.Context, id int) (*User, error)
  }
  ```
- Используй транзакции через `sqlx`:
  ```go
  tx, _ := db.BeginTxx(ctx, nil)
  defer tx.Rollback()
  ```

## 11. 🔐 Ошибки

- Не игнорируй ошибки: `if err != nil { ... }`
- Создавай кастомные ошибки:
  ```go
  var ErrUserNotFound = errors.New("user not found")
  ```
- Используй `errors.Is()`, `errors.As()`:
  ```go
  if errors.Is(err, ErrUserNotFound) { ... }
  ```

## 15. 🧠 Best Practices

| Практика | Почему |
|--------|--------|
| Используй `var Err` вместо `errors.New()` в пакете | Для `errors.Is()` |
| Не возвращай `nil`, если ошибка — возвращай `error` | Читаемость |
| Используй `defer` для `Close()`, `Unlock()` | Безопасность |
| Не используй глобальные переменные | Тестируемость |
| Документируй публичные функции | `godoc` |
| Используй `sync.Pool` для тяжёлых объектов | Производительность |

## 16. 🧪 Примеры полезных шаблонов

### 1. Worker Pool
```go
for i := 0; i < workers; i++ {
    go func() {
        for job := range jobs {
            process(job)
        }
    }()
}
```

### 2. Retry с экспоненциальным отступом
```go
for i := 0; i < 3; i++ {
    err := doSomething()
    if err == nil {
        break
    }
    time.Sleep(time.Second << i)
}
```
