
### **📌 `xid`, `xmin`, `xmax` в PostgreSQL: что это и как работают**

PostgreSQL использует **механизм MVCC (Multi-Version Concurrency Control)** для управления конкурентным доступом к данным.  
Каждая строка содержит **метаданные о транзакциях**, которые контролируют её видимость и изменение.

---

## **1️⃣ `xid` (Transaction ID) – номер транзакции**

- В PostgreSQL **каждая транзакция получает уникальный ID** – `xid` (`Transaction ID`).
- Это **целочисленный счётчик**, который **увеличивается с каждой новой транзакцией**.
- `xid` **циклический**, его максимум – **2 миллиарда**, после чего он "перезапускается" (wraparound).

📌 **Как узнать `xid` текущей транзакции?**

```sql
SELECT txid_current();
```

**Пример результата:**

```
 txid_current 
--------------
      560123
```

Это означает, что текущая транзакция получила `xid = 560123`.

---

## **2️⃣ `xmin` – XID транзакции, которая создала строку**

Каждая строка в таблице имеет **поле `xmin`**, которое указывает, **какой транзакцией эта строка была создана**.

📌 **Пример:**

```sql
CREATE TABLE test_xid (id SERIAL, data TEXT);
INSERT INTO test_xid (data) VALUES ('Hello, XID!');
SELECT ctid, xmin, xmax, * FROM test_xid;
```

**Результат:**

```
 ctid  |  xmin  | xmax | id |    data    
-------+--------+------+----+------------
 (0,1) | 560124 |    0 |  1 | Hello, XID!
```

🔹 `xmin = 560124` – строка была создана транзакцией **560124**.  
🔹 `xmax = 0` – строка **не удалена** (активна).

---

## **3️⃣ `xmax` – XID транзакции, которая удалила или обновила строку**

- Если строка была **удалена (`DELETE`) или обновлена (`UPDATE`)**, PostgreSQL **не удаляет её физически**.
- Вместо этого он **ставит `xmax`**, указывая **XID транзакции, которая "пометила" строку как удалённую**.

📌 **Пример с `DELETE`**

```sql
DELETE FROM test_xid WHERE id = 1;
SELECT ctid, xmin, xmax, * FROM test_xid;
```

**Результат:**

```
 ctid  |  xmin  |  xmax  | id |    data    
-------+--------+--------+----+------------
 (0,1) | 560124 | 560130 |  1 | Hello, XID!
```

🔹 `xmin = 560124` – строка была создана транзакцией **560124**.  
🔹 `xmax = 560130` – строка **удалена транзакцией 560130**.  
🔹 **Строка теперь "мёртвая", но остаётся в таблице, пока её не почистит `VACUUM`.**

---

## **4️⃣ Как `xmin` и `xmax` управляют видимостью строк?**

Когда запрос (`SELECT`) читается, PostgreSQL проверяет:

1. **Если `xmin` больше, чем текущий `xid`** → строка **ещё не видна** (создана позже текущей транзакции).
2. **Если `xmax = 0`** → строка **активна и видима**.
3. **Если `xmax` меньше текущего `xid`** → строка **удалена и не видна** (если транзакция уже зафиксирована).

📌 **Пример с `UPDATE`**

```sql
UPDATE test_xid SET data = 'Updated!' WHERE id = 1;
SELECT ctid, xmin, xmax, * FROM test_xid;
```

**Результат:**

```
 ctid  |  xmin  |  xmax  | id |   data    
-------+--------+--------+----+------------
 (0,1) | 560124 | 560140 |  1 | Hello, XID!
 (0,2) | 560140 |      0 |  1 | Updated!
```

🔹 **Строка (0,1) "мёртвая"** → `xmax = 560140` (обновлена транзакцией **560140**).  
🔹 **Строка (0,2) новая** → `xmin = 560140`, `xmax = 0` (активна).

---

## **5️⃣ Как `VACUUM` чистит `xmax` строки?**

Строки, у которых `xmax ≠ 0`, остаются в таблице до тех пор, пока не сработает `VACUUM`.

📌 **Принудительно удалить мёртвые строки (`bloat`):**

```sql
VACUUM FULL test_xid;
```

📌 **Посмотреть "мёртвые" строки:**

```sql
SELECT ctid, xmin, xmax, * FROM test_xid WHERE xmax != 0;
```

---

## **6️⃣ Как `xid` влияет на transaction wraparound?**

PostgreSQL использует **2 миллиарда XID**, после чего XID **начинают "перезаписываться"**.  
Чтобы **предотвратить повреждение базы**, используется `VACUUM FREEZE`, который заменяет старые `xmin` **на "замороженные" XID (`FrozenXID`)**.

📌 **Проверить возраст транзакций:**

```sql
SELECT age(datfrozenxid), datname FROM pg_database ORDER BY 1 DESC;
```

Если `age(datfrozenxid) > 1.5 млрд`, нужно **срочно делать `VACUUM FREEZE`**, иначе база может остановиться.

📌 **Запустить `FREEZE`:**

```sql
VACUUM FREEZE test_xid;
```

## **📌 Итог**

|Поле|Описание|
|---|---|
|**`xid`**|Номер текущей транзакции|
|**`xmin`**|Транзакция, которая создала строку|
|**`xmax`**|Транзакция, которая удалила или обновила строку (если `0`, строка активна)|
|**`FrozenXID`**|Специальный XID, который предотвращает wraparound|
