
В контексте баз данных, **куча** (heap) — это структура хранения данных, в которой записи хранятся в таблицах без какого-либо конкретного порядка, как, например, в **индексированных** таблицах. Куча представляет собой "неупорядоченную" коллекцию строк, что означает, что записи в таблице могут быть физически расположены в произвольном порядке на диске.

### Что хранится в куче базы данных?

В куче базы данных хранятся **данные строк** таблицы. Каждая строка состоит из значений для всех колонок таблицы, и эти строки размещаются в **неупорядоченном** виде. В PostgreSQL, например, таблицы по умолчанию используют структуру хранения данных, называемую **heap storage**.

### Что конкретно хранится в куче?

1. **Строки данных**: Каждая строка таблицы представляет собой отдельную запись, которая включает значения всех столбцов. Эти строки могут быть записаны в том порядке, в котором они добавляются в таблицу, и не упорядочиваются автоматически.
    
2. **Метаданные строк**: В каждой строке данных могут храниться дополнительные метаданные, такие как:
    
    - **Тег транзакции**: Указывает, когда и какой транзакцией была записана строка.
    - **Состояние строки**: Например, она может быть помечена как удаленная (если был выполнен запрос на удаление, но данные ещё не были физически удалены из кучи).
    - **Данные о версии строки**: В некоторых системах с поддержкой версионирования строк, например, в **MVCC** (Multiple Version Concurrency Control) в PostgreSQL, каждая строка может содержать информацию о разных версиях, доступных для разных транзакций.
3. **Данные о свободном месте**: Когда записи удаляются или обновляются, пространство, которое они занимали в куче, может быть возвращено в пул свободного места. База данных может использовать это место для хранения новых или обновленных записей, вместо того чтобы выделять новое место.
    

### Индексы в куче базы данных

Индекс в базе данных — это структура данных, предназначенная для **ускорения поиска** и **сортировки**. Индексы не хранят данные напрямую, а указывают на **строки данных**, хранящиеся в куче. Каждый индекс в базе данных связан с конкретной таблицей и использует **уникальные значения столбцов** для создания структуры, которая ускоряет доступ к данным.

Индексы могут быть реализованы с использованием различных структур данных, таких как **B-деревья**, **хеш-индексы**, **Bitmap-индексы** и других.

#### Как индекс указывает на строки в куче:

1. **Каждый индекс хранит ссылку** на строку таблицы. Это обычно делается с использованием **указателей** или **идентификаторов строк** (например, в PostgreSQL это могут быть **TIDs** — tuple identifiers).
    
2. **Индексируемые столбцы** используются для построения индекса. Индекс будет хранить пару значений: одно для значения в индексируемом столбце и одно для ссылки на строку, содержащую это значение.
    
    Например, если у нас есть таблица сотрудников с индексом на столбец `employee_id`, индекс будет хранить:
    
    - Значение `employee_id` (например, 123).
    - Указатель на строку данных в куче, которая соответствует этому `employee_id`.
3. **Поиск через индекс**: Когда выполняется запрос с фильтрацией по индексируемому столбцу (например, `WHERE employee_id = 123`), база данных сначала использует индекс для быстрого поиска строки, а затем идет к куче, чтобы получить полную строку данных.
    

### Структура кучи в PostgreSQL

В PostgreSQL, куча (heap) хранится в **файлах таблиц** (с расширением `.tbl`), и эти файлы организованы следующим образом:

1. **Строки таблицы** — это записи, которые могут быть вставлены, обновлены или удалены. Каждая строка хранит данные для всех столбцов.
    
2. **TID (Tuple Identifier)** — каждый элемент в куче имеет уникальный идентификатор, называемый TID. TID состоит из двух частей:
    
    - **Page**: Страница, на которой хранится строка.
    - **Offset**: Позиция строки внутри страницы.
3. **Физическая структура**: Каждая таблица в PostgreSQL представляет собой последовательность страниц (размер страницы по умолчанию 8 КБ), и каждая страница может содержать несколько строк (в зависимости от размера данных в строке).
    
4. **Механизмы управления**:
    
    - В кучу добавляются данные, и место может быть перераспределено, если данные удаляются.
    - База данных PostgreSQL использует **MVCC** (Multiple Version Concurrency Control), что позволяет иметь несколько версий одной строки данных в куче. Каждая версия строки хранится с дополнительной информацией о транзакциях, что позволяет эффективно управлять параллельными запросами и обеспечивать консистентность данных.

### Пример индекса и его связи с кучей:

Предположим, что у нас есть таблица `employees` с индексом на столбец `employee_id`. Структура данных индекса может выглядеть следующим образом:

```sql
CREATE TABLE employees (
    employee_id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

При создании индекса на `employee_id`:

```sql
CREATE INDEX idx_employee_id ON employees(employee_id);
```

Индекс будет хранить пары `(employee_id, TID)`, где `TID` — это указатель на строку в куче, которая хранит все остальные данные (например, `name` и `age`). Когда запрос будет использовать индекс для поиска по `employee_id`, база данных сначала выполнит поиск по индексу, а затем с помощью `TID` получит соответствующую строку данных из кучи.

### Заключение

- **Куча** в базе данных — это место, где хранятся все строки таблицы в неупорядоченном виде.
- **Индексы** в базе данных используются для ускорения поиска и ссылок на данные в куче, но не хранят сами данные.
- **Таблицы** хранят данные в куче, и каждый элемент в куче имеет свой уникальный идентификатор (TID), который может быть использован в индексах для эффективного поиска.
