### Что такое джойн?
Джойн (join) — это операция в SQL, которая комбинирует строки из двух или более таблиц на основе условия (например, равенства столбцов). В PostgreSQL джойны выполняются оптимизатором запросов, который выбирает стратегию на основе статистики, индексов и объёма данных.

#### Основные типы джойнов
- **Inner Join**: Только совпадающие строки.
- **Left/Right/Full Outer Join**: Включают несовпадающие строки с NULL.
- **Cross Join**: Декартово произведение (все комбинации).

#### Пример таблиц (для "Learning Repeater")
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255)
);
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id),
    question TEXT
);
```

Запрос: `SELECT u.name, q.question FROM users u JOIN questions q ON u.id = q.user_id`.

### Основные стратегии джойнов в PostgreSQL
PostgreSQL использует три ключевые стратегии для выполнения джойнов. Выбор зависит от размера таблиц, наличия индексов и условий фильтрации.

#### 1. Nested Loop Join (Вложенный цикл)
- **Как работает**:
  - Перебирает каждую строку одной таблицы (внешней) и ищет совпадения во второй таблице (внутренней).
  - Для каждой строки внешней таблицы выполняется полный или индексированный поиск во внутренней.
- **Псевдокод**:
  ```pseudo
  for each row in outer_table:
      for each row in inner_table:
          if join_condition(row_outer, row_inner):
              output(row_outer, row_inner)
  ```
- **Когда используется**:
  - Маленькие таблицы (внешняя таблица небольшая).
  - Одна из таблиц сильно отфильтрована (`WHERE`).
  - Есть индекс на внутренней таблице.
- **Сложность**:
  - Без индекса: `O(n * m)`, где `n` и `m` — размеры таблиц.
  - С индексом: `O(n * log m)`.
- **Пример**:
  ```sql
  SELECT u.name, q.question
  FROM users u
  JOIN questions q ON u.id = q.user_id
  WHERE u.id = 1;
  ```
  - Если `users` отфильтрован до 1 строки, а на `questions.user_id` есть индекс (B-Tree), это эффективно.

- **Связь с проектом**: Подходит для выборки вопросов конкретного пользователя (`WHERE user_id = X`).

#### 2. Merge Join (Слияние)
- **Как работает**:
  - Сортирует обе таблицы по ключу джойна.
  - Проходит по отсортированным спискам, сливая совпадающие строки (как merge в merge sort).
- **Псевдокод**:
  ```pseudo
  sort outer_table by join_key
  sort inner_table by join_key
  i = 0, j = 0
  while i < len(outer_table) and j < len(inner_table):
      if outer_table[i].key == inner_table[j].key:
          output(outer_table[i], inner_table[j])
          j++
      else if outer_table[i].key < inner_table[j].key:
          i++
      else:
          j++
  ```
- **Когда используется**:
  - Обе таблицы большие.
  - Ключи джойна уже отсортированы (например, индексы B-Tree).
  - Условие — равенство (`=`).
- **Сложность**:
  - Сортировка: `O(n log n + m log m)`.
  - Слияние: `O(n + m)`.
- **Пример**:
  ```sql
  SELECT u.name, q.question
  FROM users u
  JOIN questions q ON u.id = q.user_id
  ORDER BY u.id;
  ```
  - Если есть индексы на `users.id` и `questions.user_id`, PostgreSQL может использовать их для сортировки.

- **Связь с проектом**: Подходит для отчётов с сортировкой (например, все вопросы по пользователям в порядке `user_id`).

#### 3. Hash Join (Хэш-джойн)
- **Как работает**:
  - Создаёт хэш-таблицу из одной таблицы (меньшей, "build table").
  - Проходит по второй таблице (большей, "probe table"), проверяя совпадения через хэш.
- **Псевдокод**:
  ```pseudo
  hash_table = {}
  for each row in build_table:
      hash_table[hash(row.join_key)] = row
  for each row in probe_table:
      if hash_table[hash(row.join_key)] matches join_condition:
          output(probe_table[row], hash_table[row])
  ```
- **Когда используется**:
  - Большие таблицы без сортировки.
  - Нет подходящих индексов.
  - Условие — равенство (`=`).
- **Сложность**:
  - Построение хэш-таблицы: `O(n)`.
  - Проба: `O(m)`.
  - Итого: `O(n + m)`.
- **Ограничения**:
  - Требует памяти для хэш-таблицы (может не поместиться в RAM для огромных таблиц).
- **Пример**:
  ```sql
  SELECT u.name, q.question
  FROM users u
  JOIN questions q ON u.id = q.user_id;
  ```
  - Если `users` маленькая (build), а `questions` большая (probe), хэш-джойн эффективен.

- **Связь с проектом**: Подходит для массовой выборки вопросов без фильтров (например, статистика по всем пользователям).

### Дополнительные аспекты в PostgreSQL
#### 1. Выбор стратегии
- **Планировщик** (Query Planner):
  - Использует статистику (`pg_statistic`) о размере таблиц, распределении данных.
  - Учитывает наличие индексов (B-Tree, Hash).
  - Оценивает стоимость (CPU, I/O) через `EXPLAIN`.
- **Пример вывода `EXPLAIN`**:
  ```sql
  EXPLAIN SELECT u.name, q.question FROM users u JOIN questions q ON u.id = q.user_id;
  ```
  ```
  Hash Join  (cost=20.00..100.00 rows=1000 width=40)
    Hash Cond: (u.id = q.user_id)
    -> Seq Scan on users u  (cost=0.00..10.00 rows=100 width=20)
    -> Hash  (cost=15.00..15.00 rows=500 width=20)
         -> Seq Scan on questions q  (cost=0.00..15.00 rows=500 width=20)
  ```

#### 2. Индексы
- **B-Tree**: Ускоряет Nested Loop и Merge Join.
- **Hash**: Подходит для Hash Join (но редко используется в PostgreSQL).

#### 3. Параллелизм
- С PostgreSQL 10+ джойны могут выполняться параллельно (например, Hash Join делит таблицы между потоками).

### Связь с "Learning Repeater"
В Content Service вы работаете с таблицами `users` и `questions`:
- **Запрос**: "Получить все вопросы пользователя X с его именем":
  ```sql
  SELECT u.name, q.question
  FROM users u
  JOIN questions q ON u.id = q.user_id
  WHERE u.id = 1;
  ```
  - **Nested Loop**: Эффективен, если фильтр `u.id = 1` возвращает мало строк, а на `questions.user_id` есть индекс.
- **Запрос**: "Список всех вопросов с именами пользователей":
  ```sql
  SELECT u.name, q.question
  FROM users u
  JOIN questions q ON u.id = q.user_id;
  ```
  - **Hash Join**: Подходит для больших таблиц без фильтров.

#### Оптимизация
- Создайте индекс:
  ```sql
  CREATE INDEX idx_questions_user_id ON questions(user_id);
  ```
- Для сортировки:
  ```sql
  CREATE INDEX idx_users_id ON users(id);
  ```

### Итог
- **Стратегии джойнов**:
  1. **Nested Loop**: Вложенные циклы, хорош для маленьких или отфильтрованных таблиц.
  2. **Merge Join**: Слияние отсортированных данных, эффективен с индексами.
  3. **Hash Join**: Хэш-таблица, для больших таблиц без сортировки.
- **Выбор**: Зависит от размера данных, индексов и условий.
- **Проект**: Используйте Nested Loop для точечных запросов, Hash Join для массовых.

Если хотите пример `EXPLAIN` для вашего запроса или углубиться в планировщик, дайте знать!
