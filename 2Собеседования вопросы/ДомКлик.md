### 2. Как у вас устроено взаимодействие фронтенда и бэкенда?

Фронтенд и бэкенд взаимодействуют через API. Бэкенд предоставляет данные или выполняет операции, которые фронтенд запрашивает. Чаще всего это осуществляется через HTTP запросы, использующие методы GET, POST, PUT и DELETE. Для обмена данными часто используется формат JSON, так как он легко обрабатывается и на серверной, и на клиентской стороне.

Пример:

- **Фронтенд** делает запрос на API бэкенда (например, через fetch или axios в JavaScript).
- **Бэкенд** обрабатывает запрос, взаимодействует с базой данных или другими сервисами и отправляет ответ, обычно в формате JSON.

### 3. Вопрос про http протоколы. Что знаешь о протоколе http?

HTTP (HyperText Transfer Protocol) — это протокол, который используется для передачи данных в интернете, в основном для веб-страниц. Это протокол прикладного уровня, который работает по модели "клиент-сервер". В HTTP используются методы, такие как GET, POST, PUT, DELETE для взаимодействия с сервером.

- **HTTP/1.1** был стандартом долгие годы, но имеет ограничение в том, что каждый запрос в отдельном соединении.
- **HTTP/2** улучшает производительность, используя мультиплексирование, что позволяет отправлять несколько запросов в одном соединении.
- **HTTP/3** использует QUIC протокол и работает быстрее, с меньшими задержками, особенно для мобильных сетей.

### 4. Как тебе после питона go?

Go — это гораздо более строго типизированный язык по сравнению с Python, что помогает избегать ошибок и улучшать производительность. Система типов в Go проста и эффективна, что позволяет быстро разрабатывать параллельные приложения, благодаря поддержке горутин и каналов. В отличие от Python, Go не имеет сборщика мусора с задержками, а его производительность близка к C, что важно для высоконагруженных приложений.

### 5. Какие знаешь типы в go?

В Go основные типы следующие:

- **Простые типы**: int, float32, float64, bool, string.
- **Массивы**: фиксированная длина, например, `[5]int`.
- **Слайсы**: динамическая структура данных, например, `[]int`.
- **Карты**: ассоциативные массивы, например, `map[string]int`.
- **Структуры**: объединяют различные типы в один, например, `struct {Name string; Age int}`.
- **Указатели**: позволяют работать с памятью напрямую.
- **Интерфейсы**: позволяют работать с типами, не зная о них заранее.
- **Горутины и каналы**: для работы с параллелизмом и синхронизацией.

### 6. В чем разница когда мы пишем int() и int32, и т.д.?

В Go, `int` — это тип с размером, зависящим от архитектуры (32 или 64 бита), тогда как `int32`, `int64` — это конкретные типы с фиксированным размером. Выбор между `int` и `int32/64` зависит от требуемой совместимости с другими системами и от памяти.

- **int**: может быть 32 или 64 бита в зависимости от архитектуры.
- **int32** и **int64**: фиксированная длина, удобны, если требуется конкретный размер, например, для работы с файлами или сетевыми протоколами.

### 7. В чем отличие питоновского list от слайса?

**Python list** — это динамический массив, который может содержать элементы разных типов, и он работает с переменной длиной. Также списки в Python могут менять размер во время выполнения, и они занимают память для обеспечения гибкости.

**Go слайс** — это гибкая структура данных, основанная на массиве, которая может динамически изменять свой размер. Но слайсы имеют свойство, называемое **вместимостью** (`cap`), и они представляют собой подмассив из массива.

### 8. Какая сложность нахождения элемента внутри слайса?

Поиск элемента в слайсе — операция с **временем O(n)**, где `n` — это количество элементов в слайсе. Go не предоставляет встроенных методов для быстрого поиска, так что приходится использовать цикл для перебора элементов слайса.

### 9. Как работает горутина. Почему питон хуже в плане асинхронности?

Горутины — это легковесные потоки в Go, которые управляются планировщиком Go. Это позволяет эффективно выполнять асинхронные задачи без необходимости создавать полноценные потоки (что требует больше памяти и времени на создание). Горутин в Go можно запускать с помощью ключевого слова `go`, и Go сам будет решать, когда и на каком потоке выполнять каждую горутину.

В Python асинхронность реализована через **асинхронные функции** и **событийные циклы**. Несмотря на поддержку асинхронности через `asyncio`, Python по-прежнему ограничен глобальной блокировкой интерпретатора (GIL), что не позволяет эффективно использовать многопроцессорные системы для параллельных вычислений.

### 10. Как ты себе представляешь каналы. Если бы ты был разработчиком Go как ты бы реализовал каналы?

Каналы в Go используются для синхронизации и обмена данными между горутинами. Канал представляет собой тип, через который данные могут быть переданы между горутинами.

Я бы реализовал каналы так, чтобы они были как абстракция для безопасного обмена данными между параллельными задачами. Это бы позволило разработчику не беспокоиться о блокировках и синхронизации вручную, полагаясь на механизм Go для безопасного взаимодействия.

### 11. Какие инструменты синхронизации ты знаешь?

- **Мьютексы (Mutex)**: используются для блокировки ресурса, чтобы только одна горутина могла его использовать.
- **Рачлоки (RWMutex)**: позволяют нескольким горутинам одновременно читать данные, но блокируют записи.
- **Каналы**: сами по себе являются инструментом синхронизации, так как позволяют горутинам обмениваться данными.
- **WaitGroups**: позволяют ожидать завершения всех горутин.
- **Once**: используется для выполнения кода только один раз.

### 12. Вопрос про performance. Каким образом пытаться получать доступ к общим переменным?

Для работы с общими переменными в многозадачных программах следует использовать **мьютексы** или **каналы** для синхронизации. Мьютексы блокируют доступ к ресурсу, пока другая горутина его использует, а каналы позволяют передавать данные между горутинами безопасно.

### 13. Как представляешь себе питоновские генераторы, что это за грубо говоря мапы (или только ключи)?

**Генераторы** в Python — это функции, которые возвращают итераторы. Они позволяют вычислять значения по мере их запроса, экономя память.

Что касается мапов, это скорее **ассоциативные массивы**, в которых каждый элемент связан с уникальным ключом. В Go это тип **map**.

### 14. Скрин. Как нужно вывести не только список, но и вычислить ошибку.

Нужно передать ошибку и вывести её при необходимости. Например:

```go
result, err := someFunction()
if err != nil {
    fmt.Println("Error:", err)
} else {
    fmt.Println("Result:", result)
}
```

### 16. Какие проблемы с реализацией, как бы ты реализовал базы данных?

Реализация базы данных требует внимания к масштабируемости, согласованности данных, а также продуманной системы индексации. Для распределенных баз данных важно обеспечить **CAP-теорему** (Consistency, Availability, Partition Tolerance). Кроме того, необходимо решить проблемы с конкурентным доступом, обработкой транзакций и репликацией данных.

### 17. Сколько нужно времени чтобы выполнить индексы в PostgreSQL?

Время создания индекса зависит от нескольких факторов, таких как размер таблицы, тип индекса и ресурсы системы. Например, для больших таблиц время может составлять от нескольких секунд до минут. Однако, если таблица очень большая, может потребоваться больше времени. В реальных приложениях индексы обычно создаются заранее.
