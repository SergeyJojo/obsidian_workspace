### **Виды тестирования программного обеспечения (QA)**  

Тестирование ПО — это процесс проверки соответствия продукта требованиям и поиска дефектов. Оно делится на **функциональное** (проверка работы функций) и **нефункциональное** (проверка производительности, безопасности и др.).  

---

## **1. Функциональное тестирование**  
Проверяет, **что** делает система и **как** она это делает.  

### **1.1. По уровню детализации**  
| Вид тестирования       | Описание                                                                 | Пример |  
|------------------------|--------------------------------------------------------------------------|--------|  
| **Модульное (Unit)**   | Тестирование отдельных функций/методов.                                  | Проверка функции сложения чисел. |  
| **Интеграционное**     | Проверка взаимодействия модулей/сервисов.                                | Тест API, который вызывает базу данных. |  
| **Системное**          | Тестирование всей системы целиком.                                       | Проверка работы интернет-магазина от входа до оплаты. |  
| **Приемочное (UAT)**   | Проверка заказчиком перед релизом.                                       | Клиент тестирует финальную версию. |  

### **1.2. По сценариям**  
| Вид тестирования       | Описание                                                                 | Пример |  
|------------------------|--------------------------------------------------------------------------|--------|  
| **Дымовое (Smoke)**    | Быстрая проверка основного функционала после сборки.                     | Проверка входа в систему. |  
| **Регрессионное**      | Проверка, что новые изменения не сломали старый функционал.              | Тест всех форм после обновления. |  
| **Санитарное (Sanity)**| Углубленная проверка после дымового тестирования.                        | Проверка только измененных модулей. |  

---

## **2. Нефункциональное тестирование**  
Проверяет, **как** система работает под нагрузкой, насколько она безопасна и удобна.  

| Вид тестирования       | Описание                                                                 | Инструменты |  
|------------------------|--------------------------------------------------------------------------|-------------|  
| **Нагрузочное**        | Проверка производительности под высокой нагрузкой.                       | JMeter, k6 |  
| **Стрессовое**         | Проверка работы системы в экстремальных условиях (например, нехватка памяти). | Locust |  
| **Стабильности**       | Проверка на утечки памяти и ошибки при длительной работе.                | Gatling |  
| **Юзабилити**          | Оценка удобства интерфейса для пользователей.                            | Figma, Hotjar |  
| **Безопасности**       | Поиск уязвимостей (SQL-инъекции, XSS).                                  | OWASP ZAP, Burp Suite |  
| **Совместимости**      | Проверка работы на разных устройствах, ОС, браузерах.                   | BrowserStack, Sauce Labs |  

---

## **3. По способу выполнения**  
| Вид тестирования       | Описание                                                                 | Когда использовать? |  
|------------------------|--------------------------------------------------------------------------|---------------------|  
| **Ручное**             | Тестировщик вручную проверяет сценарии.                                  | На старте проекта, для UX-тестов. |  
| **Автоматизированное** | Тесты выполняются скриптами (Selenium, Playwright).                      | Для регресса, нагрузочных тестов. |  

**Пример автоматизации на Python (Selenium):**  
```python
def test_login():
    driver = webdriver.Chrome()
    driver.get("https://example.com/login")
    driver.find_element("id", "username").send_keys("admin")
    driver.find_element("id", "password").send_keys("12345")
    driver.find_element("id", "submit").click()
    assert "Welcome" in driver.title
    driver.quit()
```

## **4. Специальные виды тестирования**  
| Вид тестирования     | Описание                                                                   |     |
| -------------------- | -------------------------------------------------------------------------- | --- |
| **API-тестирование** | Проверка REST/gRPC-сервисов (без UI).                                      |     |
| **Контрактное**      | Проверка, что микросервисы соблюдают соглашения (например, через Swagger). |     |
| **A/B-тестирование** | Сравнение двух версий интерфейса для выбора лучшей.                        |     |

**Пример API-теста (Postman):**  
```http
GET https://api.example.com/users/1  
Ожидаемый статус: 200  
Ожидаемый JSON: { "id": 1, "name": "John" }
```

---

## **5. Как выбрать тип тестирования?**  
1. **На старте проекта**:  
   - Модульные тесты (Unit) + дымовые (Smoke).  
2. **Перед релизом**:  
   - Регрессионные + нагрузочные + безопасность.  
3. **После обновлений**:  
   - Санитарные (Sanity) + проверка багфиксов.  

---

### **Итог**  
- **Функциональное тестирование** отвечает на вопрос *"Работает ли система правильно?"*.  
- **Нефункциональное** — *"Как быстро/безопасно/удобно?"*.  
- **Автоматизация** ускоряет рутинные проверки.
