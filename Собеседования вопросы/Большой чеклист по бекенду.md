
Давайте пройдем по каждому вопросу:

---

### 1. **Конкурентные, параллельные и асинхронные вычисления. Разница между ними и преимущества каждого.**

- **Конкурентные вычисления** — это выполнение нескольких задач одновременно, но не обязательно параллельно. Это может быть имитация параллельности через переключение контекста (например, многозадачность). Например, две задачи могут выполняться на одном потоке, но поочередно.
    
    Преимущества: более эффективное использование ресурсов, упрощает управление зависимостями.
    
- **Параллельные вычисления** — это реальное выполнение нескольких задач одновременно, часто на разных процессорах или ядрах. Задачи могут выполняться одновременно, не прерывая друг друга.
    
    Преимущества: ускорение обработки данных, эффективное использование многоядерных процессоров.
    
- **Асинхронные вычисления** — это когда задача выполняется в фоновом режиме, и результат доступен позже. Это позволяет не блокировать основное выполнение программы, пока ожидается результат.
    
    Преимущества: хороши для операций ввода-вывода, например, работы с сетью или файловой системой.
    

---

### 2. **Микросервисные вычисления. Преимущества.**

Микросервисные вычисления подразумевают разбиение системы на независимые сервисы, каждый из которых выполняет свою задачу.

Преимущества:

- Масштабируемость: можно масштабировать отдельные сервисы, а не всю систему.
- Независимость: каждый сервис может быть написан на разных языках, и их можно обновлять независимо друг от друга.
- Устойчивость: отказ одного сервиса не влияет на другие сервисы.

---

### 3. **Преимущества последовательных вычислений**

Преимущества:

- Простота: легко понять и реализовать, особенно для задач, которые не требуют параллелизма.
- Отсутствие синхронизации: не требуется управление параллельным доступом к данным.
- Минимизация накладных расходов на контекст и синхронизацию.

---

### 4. **Конвейерные вычисления**

Конвейерные вычисления — это процесс, в котором данные проходят через серию последовательных этапов, каждый из которых выполняет свою задачу (например, обработки данных).

Пример: обработка данных в ETL-процессах (извлечение, трансформация, загрузка).

Преимущества:

- Повышение эффективности: каждый этап может быть выполнен независимо.
- Упрощение масштабирования: каждый этап можно масштабировать отдельно.

---

### 5. **Влияние эффекта масштаба на вычисления**

При увеличении объема данных или количества операций можно столкнуться с увеличением сложности и времени вычислений. Эффект масштаба — это увеличение затрат (по времени, памяти) при увеличении нагрузки. Эффект масштаба часто приводит к необходимости оптимизации алгоритмов или перехода к более мощным системам.

---

### 6. **Когда нужно пустить под нож: синхронизацию в вычислениях, результат вычислений, безопасность данных, скорость вычислений, количество живых горутин**

- **Скорость вычислений** — если нужно максимально быстро обработать данные и при этом можно пожертвовать безопасностью или точностью.
- **Безопасность данных** — когда сохранение данных имеет высший приоритет (например, в банковских или медицинских системах).
- **Количество живых горутин** — минимизировать их, чтобы избежать излишней нагрузки на систему (например, использовать очереди задач).

---

### 7. **Как гарантировать: скорость, синхронность, параллельность вычислений, а также безопасность данных и отказоустойчивость**

- **Скорость**: оптимизация алгоритмов и распределение нагрузки.
- **Синхронность**: использование правильных механизмов синхронизации (мьютексы, каналы).
- **Параллельность**: использование многозадачности и многозадочности (например, горутины).
- **Безопасность данных**: правильное использование блокировок и транзакций.
- **Отказоустойчивость**: создание резервных копий, репликация и распределенные системы.

---

### 8. **panic access; panic nil pointer; panic conversion**

- **panic access** — ошибка доступа к данным в недоступном контексте.
- **panic nil pointer** — попытка разыменовать нулевой указатель.
- **panic conversion** — попытка неправильного преобразования типа, например, использование `type assertion` для неверного типа.

---

### 9. **Является ли переменная созданная в init() глобальной**

Переменная, созданная в функции `init()`, является **локальной** для того пакета, в котором она была определена. Но если вы присваиваете значение глобальной переменной в `init()`, она будет доступна глобально.

---

### 10. **Когда стоит (и когда не стоит) использовать глобальные переменные**

- **Стоит использовать**: когда данные должны быть доступны всем частям программы и не изменяются.
- **Не стоит использовать**: когда переменные изменяются, что может привести к путанице и трудностям в тестировании, из-за изменения состояния в разных частях программы.

---

### 11. **Как создать свою область видимости**

Можно использовать **блоки** или **функции**, чтобы создать локальную область видимости.

```go
func example() {
    // Это локальная область видимости
}
```

---

### 12. **Как создать глобальную переменную для одного пакета**

Просто объявите переменную в пакете, но вне функции, чтобы она была доступна во всем пакете.

```go
package main

var globalVar int

func main() {
    globalVar = 10
}
```

---

### 13. **Как реализовать FIFO циклом**

Используйте структуру данных типа **очереди** с операциями enqueue (добавление в конец) и dequeue (удаление из начала).

---

### 14. **Как итерироваться в for по функции**

```go
for i := range someSlice {
    // Выполняйте операцию с someSlice[i]
}
```

---

### 15. **В чем особенность области видимости for**

Переменные в `for` цикле могут быть видимыми только внутри этого цикла. После завершения цикла они теряют область видимости.

---

### 16. **Как выйти из бесконечного цикла без break**

Можно использовать `return` или условие выхода:

```go
for {
    if someCondition {
        return
    }
}
```

---

### 17. **Что происходит, когда цикл, итерирующийся по массиву, становится бесконечным**

Цикл будет продолжать выполняться бесконечно, пока не произойдёт явное прекращение работы программы (например, отмена процесса).

---

### 18. **main() содержит вызов горутины или нет**

В функции `main()` может быть вызов горутины через ключевое слово `go`, например: `go someFunction()`.

---

### 19. **Чем отличается убийство процесса от убийства горутины**

Процесс — это отдельная программа, которая может содержать несколько горутин. Убийство процесса завершает все его горутины, в то время как убийство горутины останавливает только её выполнение.

---

### 20. **Можно ли запустить программу без main()**

Нет, функция `main()` обязательна для выполнения программы в Go.

---

### 21. **Сколько потоков/рутин может одновременно писать в stdout**

Go использует поток вывода для всех горутин, и они могут одновременно писать в `stdout`. Однако это может привести к состояниям гонки, если синхронизация не будет использована.

---

### 22. **Как убить конкретную горутину**

Для завершения горутины обычно используют каналы, контексты или механизмы завершения.

---

### 23. **Когда нужно внедрять кэш**

Когда данные часто запрашиваются, но их стоимость или время получения высоки, можно использовать кэш.

---

### 24. **Когда нужно добавлять ресурсы**

Если система становится медленной или нестабильной, добавление ресурсов может помочь. Это важно, когда есть ресурсы, ограничивающие производительность.

---

### 25. **Когда нужно оптимизировать код**

Когда выполнение программы становится слишком медленным или если возникают проблемы с масштабируемостью.

---

### 26. **Когда нужно распараллелить вычисления**

Когда операции независимы друг от друга и могут быть выполнены одновременно.

---

### 27. **Что быстрее: функция или анонимная функция**

В большинстве случаев анонимные функции немного медленнее из-за необходимости их создания, но это отличие незначительно.

---

### 28. **Что быстрее: метод класса или анонимная функция**

Методы обычно немного быстрее, так как они связаны с типами и имеют меньше накладных расходов по сравнению с анонимными функциями.

---

### 29. **Что быстрее: функция или метод класса**

Методы могут иметь накладные расходы, если они работают с указателями, но разница часто минимальна.

---

### 30. **Что быстрее выполнится при вызове горутины (go func() ...): анонимная функция или обычная функция**

Обычная функция будет немного быстрее, так как анонимная функция требует создания.

---

### 31. **Где быстрее функция в рутине или в fork(процессе)**

Горутины быстрее, так как они работают в пределах одного процесса и не требуют создания нового процесса, как в случае с `fork`.

---

### 32. **В одном контейнере с Go программой запускаете другую и "другая" жестко тормозит - что происходит в данном случае и как исправить**

Возможно, другая программа перегружает ресурсы контейнера (CPU, память). Нужно проверить использование ресурсов и оптимизировать конфигурацию контейнера.

---

### 33. **Что лучше GET с query или POST с body**

GET с query быстрее и проще, но POST используется для передачи больших объёмов данных и более безопасен для передачи чувствительной информации.

---

### 34. **Устройство строк**

Строки в Go являются неизменяемыми последовательностями байтов.

---

### 35. **Устройство слайсов**

Слайсы — это динамические массивы, которые предоставляют более гибкий способ работы с массивами.

---

### 36. **Устройство мап**

Мапы — это ассоциативные массивы, использующие хеш-таблицы для быстрого доступа по ключу.

---

### 37. **Устройство интерфейсов**

Интерфейсы в Go определяют набор методов, которые должен реализовать тип, чтобы считаться типом этого интерфейса.

---

### 38. **Устройство каналов**

Каналы — это структуры данных, которые позволяют передавать значения между горутинами.

---

### 39. **Примитивы синхронизации**

Примитивы синхронизации в Go включают мьютексы, каналы и ожидания (WaitGroup).

---

### 40. **Работа планировщика**

Планировщик в Go управляет горутинами, распределяя их по доступным потокам.

---

### 41. **Работа аллокатора, рантайма**

Аллокатор управляет выделением и освобождением памяти, а рантайм управляет выполнением программы.

---

### 42. **Работа сборщика мусора**

Сборщик мусора в Go управляет удалением неиспользуемых объектов из памяти.

---

### 43. **Стек и куча**

Стек используется для хранения локальных переменных и вызовов функций, куча — для динамически выделенной памяти.

---

### 44. **Модель OSI**

Модель OSI описывает уровни, через которые проходят данные при передаче по сети (например, физический, канальный и сетевой уровни).

---

### 45. **SOLID**

SOLID — это принципы объектно-ориентированного проектирования: единственная ответственность, открытость/закрытость, подстановка Лисков, разделение интерфейса, инверсия зависимостей.

---

### 46. **Паттерны проектирования**

Паттерны проектирования — это шаблоны решения повторяющихся задач при проектировании.

---

### 47. **Принципы ООП и реализация в Go**

Go поддерживает ООП через композицию и интерфейсы, но не через наследование.

---

### 48. **Точное определение горутины**

Горутина — это легковесный поток исполнения, который планируется и управляется планировщиком Go.
