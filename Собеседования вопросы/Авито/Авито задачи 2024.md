### Слияние двух отсортированных массивов

**Условие задачи**  
Даны 2 отсортированных (по возрастанию) массива A и B длины M и N. Нужно слить их в один отсортированный (по возрастанию) массив, состоящий из элементов первых двух.

**Пример 1**  
Ввод:  
`[1, 2, 5]`  
`[1, 2, 3, 4, 6]`  
Вывод:  
`[1, 1, 2, 2, 3, 4, 5, 6]`

**Пример 2**  
Ввод:  
`[4, 7, 13]`  
`[3, 5, 8, 9, 11]`  
Вывод:  
`[3, 4, 5, 7, 8, 9, 11, 13]`

**Алгоритмическая сложность:**  
`O(N+M)`

### Собери команду

**Условие задачи**  
Вашему TL поставили задачу собрать максимально "ровную" команду по уровню. Он делегировал эту задачу вам, попросив написать функцию.  
Мы считаем "ровность" команды тем больше, чем меньше разница между минимальным и максимальным уровнем выбранных инженеров.

У вас есть N бекендеров, N3 фронтендеров, N4 тестировщиков и N4 дизайнеров, мы знаем уровень каждого из них. Мы получаем уровни инженеров по функциям уже отсортированными.

Соберите команду из 4-х человек по одному из каждой функции. Если есть несколько вариантов, предложить любой.



---

### Пример 1

```go
# Ввод
engineers = {
  backend: [1, 2, 2, 3],  # уже отсортированы
  frontend: [1, 3],  # уже отсортированы
  qa: [3, 4, 4],  # уже отсортированы
  design: [2, 3],  # уже отсортированы
}

# Вывод
example_result = { backend: 3, frontend: 3, qa: 3, design: 3 }
```

### Пример 2

```go
# Ввод
engineers = {
  backend: [5],
  frontend: [3, 6, 7, 10],
  qa: [3, 9, 11, 18],
  design: [20],
}

# Вывод
example_result = { backend: 5, frontend: 6, qa: 9, design: 20 }
```

**Алгоритмическая сложность**  
— Ожидаемая сложность O(N1 + N2 + N3 + N4) → O(N), так как Ni — это нечто большее

**Потребление памяти**  
— Ожидаемое потребление O(1)  
— Для унифицированного решения для K функций O(K + N1 + ... + NK) → O(K + N) и меньше  
— K — выделять память под все функции  
— Ni — выделять память под каждый i-й функции

### Сумма чисел двух массивов

**Условие задачи**  
Мы хотим складывать очень большие числа, которые превышают емкость базовых типов, поэтому числа храним их в виде массива неотрицательных чисел.

Нужно написать функцию, которая примет на вход два таких массива, вычислит сумму чисел, представленных массивами, и вернет результат в виде такого же массива.



---

### Пример 1

```go
# Ввод
arr1 = [1, 2, 3] # число 123
arr2 = [4, 5, 6] # число 456

# Вывод
res = [5, 7, 9] # число 579. Допустим ответ с первым незначащим нулем [0, 5, 7, 9]
```

### Пример 2

```go
# Ввод
arr1 = [5, 4, 4] # число 544
arr2 = [4, 5, 6] # число 456

# Вывод
res = [1, 0, 0, 0] # число 1000
```

**Алгоритмическая сложность**  
— Ожидаемая сложность O(N)  
— Потребление памяти O(N), где N <= Max(Len(arr1), Len(arr2)) + 1

### Поиск пар в списке чисел

**Условие задачи**  
Дан список целых неповторяющихся чисел и целое число.  
Необходимо найти все пары в списке, сумма которых равна заданному числу. Перестановки (i, j) и (j, i) считаются одной и той же парой, нужно вывести только одну из них (любую).

**Входные параметры**  
Массив целых чисел размера N. Целое число.

**Вывод**  
Список пар.

**Пример**

```go
# Ввод
[2, 4, 5, 3]
7

# Вывод
[[2, 5], [4, 3]]
```

**Ожидаемая сложность решения**  
— самый простой перебор O(n^2) по времени и O(n) по памяти  
— решение с hashmap за один проход O(n) по времени и O(n) по памяти  
— решение с предварительной сортировкой O(n*log(n)) (сортируем и идем с двух концов или бинарный поиск)

### Сравнение версий

**Условие задачи**  
Даны две строки с версиями. Нужно реализовать функцию, которая сравнит версии между собой и вернёт ответ в less-формате (0, 1, -1). Каждая версия задаётся строкой следующего формата:

1. буква "v"
2. комбинация точек и чисел
3. другие знаки не разрешены
### Пример

```go
v11.22.44
v11.22.45

Ответ: 1
```

```go
v11.22.44
v11.22.44

Ответ: 0
```

Можно предложить подумать над корнер-кейсами и давать потом:

```go
v11.22.44
v11.22.44.0

Ответ: 0
```

```go
v1.12.3
v1.3.4

Ответ: -1
```

**Варианты решения**

1. разбить строки в массивы
2. массивы потенциально разной длины
3. "дотянуть" короткий массив до длинного "младшими" нулями и работать с ними при помощи одного указателя
4. использовать 2 указателя и проверять выход за границы
