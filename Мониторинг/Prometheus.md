Если вы готовитесь к собеседованию на тему **Prometheus** и метрик, важно понимать основные принципы работы с метриками, как их правильно использовать и как они могут быть полезны для мониторинга систем. Вот важные моменты, которые стоит учесть:

### 1. **Типы метрик в Prometheus**

Prometheus предоставляет несколько типов метрик для мониторинга различных аспектов работы системы. Знание их и правильное применение — ключевое при работе с Prometheus.

#### a. **Counter (Счетчик)**:

- **Описание**: Это метрика, которая только увеличивается (например, количество запросов, количество ошибок, обработанных задач).
- **Когда использовать**: Когда необходимо отслеживать непрерывно увеличивающиеся значения, такие как:
    - Количество запросов (например, HTTP-запросы).
    - Число ошибок или исключений.
    - Количество транзакций.
- **Пример**: Количество успешных запросов:
    
    ```prometheus
    http_requests_total{status="200"}
    ```
    

#### b. **Gauge (Измеритель)**:

- **Описание**: Это метрика, которая может как увеличиваться, так и уменьшаться. Используется для отслеживания переменных значений, например, текущей нагрузки.
- **Когда использовать**: Для отслеживания:
    - Загруженности CPU.
    - Использования памяти.
    - Температуры.
    - Активных соединений в базе данных.
- **Пример**: Текущая загрузка CPU:
    
    ```prometheus
    cpu_load_average_1m
    ```
    

#### c. **Histogram (Гистограмма)**:

- **Описание**: Эта метрика используется для измерения распределения значений (например, времени ответа). Гистограммы могут разбивать значения по бинам и сохранять сумму, количество и количество наблюдений в каждом бине.
- **Когда использовать**: Для метрик, которые измеряют задержки, время ответа и другие данные с распределением значений.
- **Пример**: Время ответа HTTP-запросов:
    
    ```prometheus
    http_request_duration_seconds
    ```
    

#### d. **Summary (Сводка)**:

- **Описание**: Сводка также используется для измерения распределений, но она хранит фиксированные квантильные значения (например, 0.5, 0.9, 0.99) и предоставляет больше информации для точных статистик.
- **Когда использовать**: Если нужно получать информацию о квантильных значениях (например, медиану или 99-й процентиль).
- **Пример**: Время ответа запросов:
    
    ```prometheus
    http_request_duration_seconds{quantile="0.99"}
    ```
    

### 2. **Как и когда собирать метрики**

- **Экспортеры**: В Prometheus для сбора метрик используется концепция экспортера — программы, которые предоставляют метрики о состоянии системы через HTTP-интерфейс. Некоторые популярные экспортеры:
    
    - **node_exporter**: Для мониторинга системных метрик, таких как загрузка CPU, использование памяти, дисковое пространство и др.
    - **mysql_exporter**: Для сбора метрик с MySQL.
    - **blackbox_exporter**: Для мониторинга доступности сервисов через HTTP, DNS, TCP, ICMP и т.д.
- **Периодичность сбора данных**: Важно правильно настроить периодичность сбора метрик с помощью `scrape_interval` в конфигурации Prometheus. Например, если у вас критичный сервис, вам может понадобиться собирать метрики каждую секунду, а для менее важного — каждые 30 секунд.
    
- **Сбор только важных метрик**: Не стоит собирать все метрики подряд. Нужно определить ключевые метрики, которые отражают состояние системы или приложения. Например, для web-сервиса важно отслеживать:
    
    - Время отклика.
    - Количество запросов.
    - Ошибки.

### 3. **Что полезно знать при работе с метриками**

#### a. **Labeling (Метки)**:

- Метки (labels) в Prometheus позволяют добавлять контекст к меткам. Например, метка `status` может показывать состояние запроса (200, 404, 500).
- **Когда использовать**: Метки полезны для разделения данных по различным критериям (например, статусу HTTP-запросов, регионам, сервисам и т.д.).

**Пример**:

```prometheus
http_requests_total{status="200", method="GET"}
```

#### b. **Метрики, отражающие бизнес-показатели**:

- Важно отслеживать не только системные метрики, но и бизнес-метрики. Например, количество успешных транзакций, количество заказов или количества клиентов.

#### c. **Агрегирование и запросы в PromQL**:

- Использование языка запросов PromQL позволяет агрегировать данные и извлекать нужную информацию. Основные агрегирующие функции:
    - `sum()`: Суммирует значения по меткам.
    - `avg()`: Среднее значение.
    - `rate()`: Используется для вычисления скорости изменения счетчиков.
    - `histogram_quantile()`: Для квантилей в гистограммах.

**Пример**:

- Количество успешных запросов по HTTP-методам:
    
    ```prometheus
    sum(http_requests_total{status="200"}) by (method)
    ```
    

#### d. **Alerts (Оповещения)**:

- Настройка оповещений в Prometheus позволяет получать уведомления о проблемах в системе. В Prometheus используется Alertmanager для отправки уведомлений в Slack, email, или другие системы.
- Оповещения могут быть настроены на основе пороговых значений метрик (например, если время ответа превышает 2 секунды или если нагрузка на CPU больше 90%).

**Пример**:

```yaml
groups:
  - name: example_alerts
    rules:
      - alert: HighRequestDuration
        expr: http_request_duration_seconds_bucket{le="2"} > 100
        for: 5m
        labels:
          severity: critical
        annotations:
          description: "Request duration is above 2s for the last 5 minutes."
```

#### e. **Хранение метрик и ретеншн-период**:

- Prometheus хранит метрики по времени, но важно настроить **retention** (период хранения данных), так как данные быстро накапливаются. Если не настроить удаление старых данных, это приведет к заполнению диска.
- В конфигурации Prometheus можно настроить параметры `--storage.tsdb.retention.time` и `--storage.tsdb.retention.size` для ограничения времени и размера хранения данных.



### 1. **Основные принципы работы с метриками**

- **Как они собираются**:
    
    - **Prometheus** собирает метрики с помощью HTTP-протокола, в котором они представлены как текстовые данные. Сервисы и приложения, которые нужно мониторить, предоставляют свои метрики через эндпоинты, например, `http://localhost:9090/metrics`. Prometheus регулярно извлекает данные с этих эндпоинтов по заранее определённому расписанию (`scrape_interval`).
- **Типы метрик**:
    
    - **Counter** — метрика, которая увеличивается с течением времени (например, количество запросов, количество ошибок).
    - **Gauge** — метрика, которая может как увеличиваться, так и уменьшаться (например, использование памяти или количество активных подключений).
    - **Histogram** — метрика для сбора статистики по распределению значений, например, времени отклика (имеет бины, по которым группируются данные).
    - **Summary** — метрика для сбора статистики по распределению значений, но вместо бинов даёт квантильные значения (например, 0.5, 0.9, 0.99), что позволяет получать точные данные по определённым процентилям.
- **Как использовать экспортеры**:
    
    - Экспортеры — это сервисы или утилиты, которые предоставляют метрики с различных систем, например:
        - **node_exporter** — для сбора метрик с серверов (CPU, память, диск, сеть).
        - **mysql_exporter** — для сбора метрик из MySQL.
        - **blackbox_exporter** — для проверки доступности внешних сервисов.
    - Эти экспортеры настраиваются на стороне Prometheus, и он будет собирать метрики с них по расписанию.

### 2. **Знание PromQL**

- **Что такое PromQL**:
    
    - PromQL (Prometheus Query Language) — это язык запросов, используемый для извлечения и агрегации метрик в Prometheus. Он позволяет агрегировать данные, фильтровать по меткам, применять математические функции и даже строить временные графики.
- **Пример запроса**:
    
    - Чтобы получить количество успешных HTTP-запросов с кодом ответа 200:
        
        ```prometheus
        sum(http_requests_total{status="200"})
        ```
        
    - Чтобы узнать среднее время ответа за последние 5 минут:
        
        ```prometheus
        avg(http_request_duration_seconds[5m])
        ```
        
    - Чтобы получить скорость изменения счётчика:
        
        ```prometheus
        rate(http_requests_total[1m])
        ```
        
- **Ключевые функции PromQL**:
    
    - **`sum()`** — суммирует метрики.
    - **`avg()`** — вычисляет среднее значение.
    - **`rate()`** — вычисляет скорость изменения счётчика.
    - **`count()`** — подсчитывает количество записей.
    - **`histogram_quantile()`** — вычисляет квантиль для гистограмм.

### 3. **Настройка оповещений**

- **Как настроить алерты в Prometheus**:
    
    - Настройка оповещений в Prometheus осуществляется через конфигурацию правил оповещений в файле `alert.rules`. Например, для уведомления, если время ответа на запросы больше 2 секунд:
        
        ```yaml
        groups:
          - name: example_alerts
            rules:
              - alert: HighRequestDuration
                expr: http_request_duration_seconds_bucket{le="2"} > 100
                for: 5m
                labels:
                  severity: critical
                annotations:
                  description: "Request duration is above 2s for the last 5 minutes."
        ```
        
- **Alertmanager**:
    
    - Для обработки и отправки уведомлений используется **Alertmanager**. Он поддерживает различные каналы уведомлений, такие как email, Slack, PagerDuty, и т.д.
    - Например, чтобы настроить отправку уведомлений в Slack, в конфигурации Alertmanager указываем вебхук:
        
        ```yaml
        receivers:
          - name: 'slack-notifications'
            slack_configs:
              - channel: '#alerts'
                send_resolved: true
                api_url: 'https://hooks.slack.com/services/...'
        ```

### 4. **Мониторинг с помощью Prometheus**

- **Как выбирать метрики для мониторинга**:
    
    - Важно отслеживать ключевые показатели, которые влияют на работоспособность вашего приложения или сервиса. Например:
        - **Для веб-сервисов**: количество запросов, количество ошибок, время отклика.
        - **Для баз данных**: использование памяти, количество подключений, время ответа.
        - **Для серверов**: загрузка CPU, использование памяти, дисковое пространство, сетевые ошибки.
    - При выборе метрик важно избегать избыточности — собирайте только те, которые действительно помогут в обнаружении проблем.
- **Типы сервисов и метрики для них**:
    
    - **Веб-сервисы**: Метрики времени отклика, количество запросов, количество ошибок, код статуса ответа.
    - **Базы данных**: Метрики по подключению, времени запроса, загрузке процессора и использования памяти.
    - **Инфраструктура**: Использование дисков, CPU, памяти, сетевых интерфейсов.

### 5. **Оптимизация производительности Prometheus**

- **Как работать с большими объёмами данных**:
    
    - **Фильтрация и агрегация**: Использование агрегаций в запросах PromQL для уменьшения объёма данных. Например, использование `rate()`, `sum()` или `avg()` для уменьшения данных по времени.
    - **Разделение хранилища**: Использование меток для разделения данных и хранения их в разных хранилищах (например, для различных сервисов или типов метрик).
- **Настройка хранения метрик**:
    
    - В Prometheus можно настроить параметры хранения данных: `--storage.tsdb.retention.time` и `--storage.tsdb.retention.size`.
    - Для больших объёмов данных важно настроить удаление старых данных через **retention**:
        - `--storage.tsdb.retention.time=30d` — хранить данные в течение 30 дней.
        - Также важно следить за **метками** и разделением метрик, чтобы не накапливать слишком много данных за короткий период.

### 6. **Частые вопросы на собеседованиях**

- **Что такое Prometheus и как он работает?**
    
    - **Prometheus** — это система мониторинга и временных рядов, которая собирает и хранит метрики через HTTP-интерфейсы. Она использует pull-модель (запрашивает метрики с сервисов) и предоставляет мощный язык запросов PromQL для анализа данных.
- **Чем отличаются Counter, Gauge, Histogram и Summary?**
    
    - **Counter** — только увеличивается (например, количество запросов).
    - **Gauge** — может увеличиваться и уменьшаться (например, температура).
    - **Histogram** — используется для распределения данных по бинам (например, время отклика).
    - **Summary** — позволяет работать с квантилями и процентилями.
- **Как настроить Prometheus для сбора метрик с веб-приложения?**
    
    - Настроить экспортер (например, **`prometheus_client`** для Python или **`prometheus-net`** для C#) для экспорта метрик в формате Prometheus. Затем в конфигурации Prometheus добавить target (URL) для сбора метрик.
- **Как работает PromQL? Пример запроса.**
    
    - **PromQL** позволяет выбирать метрики, агрегировать их и фильтровать. Пример запроса:
        
        ```prometheus
        avg(http_request_duration_seconds{status="200"}[5m])
        ```
        
- **Как настроить Alertmanager для оповещений?**
    
    - Настроить правила оповещений в Prometheus, а затем отправить эти оповещения в **Alertmanager**. В Alertmanager настроить каналы уведомлений (например, Slack, email).
- **Как оптимизировать производительность Prometheus при сборе метрик с большого количества серверов?**
    
    - Использование агрегаций в запросах, правильная настройка retention-политики, разделение хранилища и настройка частоты выборки.

package main

import (
    "net/http"
    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promhttp"
)

// Создаём метрику
var httpRequests = prometheus.NewCounter(
    prometheus.CounterOpts{
        Name: "http_requests_total",
        Help: "Total number of HTTP requests",
    })

func main() {
    // Регистрируем метрику
    prometheus.MustRegister(httpRequests)

    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        httpRequests.Inc() // Увеличиваем счётчик при каждом запросе
        w.Write([]byte("Hello, Prometheus!"))
    })

    // Эндпоинт для сбора метрик
    http.Handle("/metrics", promhttp.Handler())

    http.ListenAndServe(":8080", nil)
}
