
В Linux приоритет процессов контролируется с помощью значения **`nice`**, которое определяет относительное использование процессора процессом. Чем ниже значение `nice`, тем выше приоритет процесса.

---

### **Основные концепции `nice` и `renice`**

1. **Диапазон значений `nice`:**
   - Значения `nice` варьируются от **-20** (наивысший приоритет) до **19** (наименьший приоритет).
   - Процессы с более низким значением `nice` получают больше процессорного времени по сравнению с процессами с более высоким значением `nice`.

2. **Основные значения:**
   - **0 (по умолчанию):** Стандартный приоритет для большинства процессов.
   - **Отрицательные значения:** Высокий приоритет (используется для критически важных задач).
   - **Положительные значения:** Низкий приоритет (используется для фоновых задач, например, резервного копирования).

3. **Влияние `nice`:**
   - Значение `nice` влияет только на относительный приоритет процессов, конкурирующих за процессорное время.
   - Это не гарантирует процессу определённое количество процессорного времени, а лишь изменяет его шансы в конкуренции с другими процессами.

---

### **Команды для работы с `nice`**

#### **1. Запуск процесса с заданным приоритетом (`nice`)**

```bash
nice -n <value> <command>
```

- Примеры:
  ```bash
  nice -n 10 tar -czf backup.tar.gz /home/user  # Запуск с низким приоритетом
  nice -n -5 ./important_task                  # Запуск с высоким приоритетом
  ```
- Если не указать `-n`, будет применено значение по умолчанию `10`.

#### **2. Изменение приоритета запущенного процесса (`renice`)**

```bash
renice <value> -p <pid>
```

- Примеры:
  ```bash
  renice 5 -p 1234        # Установить приоритет 5 для процесса с PID 1234
  renice -10 -p 5678      # Установить приоритет -10 для процесса с PID 5678
  ```

- Изменение приоритета для всех процессов пользователя:
  ```bash
  renice 10 -u username
  ```

#### **3. Проверка приоритета процесса**

```bash
ps -o pid,ni,comm -p <pid>
```

- Пример:
  ```bash
  ps -o pid,ni,comm -p 1234
  ```
  Вывод:
  ```
    PID  NI COMMAND
   1234   5 my_process
  ```

---

### **Пример использования**

#### Запуск двух процессов с разными приоритетами:

```bash
nice -n 19 dd if=/dev/zero of=/dev/null &
nice -n -10 dd if=/dev/zero of=/dev/null &
```

- Первый процесс (`nice 19`) будет получать меньше процессорного времени.
- Второй процесс (`nice -10`) будет получать больше процессорного времени.

---

### **Кто может устанавливать значения `nice`**

1. **Обычные пользователи:**
   - Могут только увеличивать значение `nice` (снижать приоритет).
   - Не могут устанавливать отрицательные значения.

2. **Суперпользователь (root):**
   - Может устанавливать как отрицательные, так и положительные значения `nice`.

---

### **Практическое применение значений `nice`**

- **-20 ... -1 (высокий приоритет):**
  - Используется для критических задач, например, реального времени или сервисов, требующих низкой задержки.

- **0 (по умолчанию):**
  - Большинство пользовательских процессов.

- **1 ... 19 (низкий приоритет):**
  - Фоновые задачи, такие как резервное копирование, архивирование или длительные вычисления.

---

### **Пример вывода `top` с колонкой `NI`:**

```bash
top
```

Вывод:
```
  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
 1234 user      20   0   123m   456m   789m R  50.0   1.2   0:02.34 my_process
 5678 root      20  -5   789m   234m   123m S  30.0   0.9   0:01.12 critical_task
 9101 user      20  10   456m   123m    89m S   5.0   0.3   0:00.02 backup_task
```

- Колонка `NI` показывает значение `nice`:
  - `0` для обычного процесса.
  - `-5` для процесса с более высоким приоритетом.
  - `10` для процесса с более низким приоритетом.

---

### **Итоги**
- **`nice` и `renice`** позволяют управлять приоритетами процессов для оптимального использования ресурсов.
- Используйте отрицательные значения для критически важных задач (только с правами `root`).
- Для фоновых задач устанавливайте высокие значения `nice` (например, `19`).
