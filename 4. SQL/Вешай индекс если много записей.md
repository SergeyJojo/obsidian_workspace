## ✅ Индекс на колонку с **маленьким числом уникальных значений** (low cardinality)

➡️ Если у тебя таблица с **миллионами строк**, но колонка хранит всего **5 возможных значений** (например: "draft", "published", "archived", "deleted", "hidden"), индекс **можно делать**, но эффективность зависит от ситуации.

---

## ✅ Когда индекс **будет полезен**:

| Когда                                                                                             | Почему                                             |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 🔎 Когда часто фильтруешь по этим значениям (`WHERE status = 'published'`)                        | Даже простой фильтр с LIMIT может работать быстрее |
| 🏷 Когда значения сильно неравномерные (например, 90% "published", 1% "archived")                 | Индекс поможет быстро найти редкие значения        |
| 🏃‍♂️ Когда используешь в индексах покрывающие запросы (`status` + `id`, `status` + `created_at`) | Составной индекс даст прирост                      |
|                                                                                                   |                                                    |

---

## ✅ Когда индекс **будет бесполезен / хуже**:

| Когда                                                                              | Почему                                        |
| ---------------------------------------------------------------------------------- | --------------------------------------------- |
| ❌ Когда значения распределены равномерно (20% published, 20% draft и т.д.)         | Селективность плохая, индекс почти бесполезен |
| ❌ Когда запросы возвращают много строк (ты всё равно будешь читать данные с диска) | PostgreSQL может предпочесть seq scan         |
| ❌ Когда по колонке редко делают фильтры или join'ы                                 | Индекс только занимает место                  |

---

## ✅ PostgreSQL поведение:

- Если селективность плохая (большая доля таблицы подходит под WHERE), **PostgreSQL не будет использовать индекс** → выберет **seq scan** (посмотрит по статистике).
    
- Индекс все равно поможет при **LIMIT** (если тебе надо 100 записей с rare-значением).
    

---

## ✅ Альтернатива:

- **Partial Index** — супер эффективен для таких колонок:
    
    ```sql
    CREATE INDEX idx_status_archived ON my_table(id)
    WHERE status = 'archived';
    ```
    
    ➡️ Такой индекс хранит только нужные строки → маленький, быстрый.
    

---

## ✅ Итог:

|Вопрос|Ответ|
|---|---|
|Делать индекс на колонку с 5 значениями?|✅ Да, **если ты активно фильтруешь по ней**|
|Делать обычный индекс?|Лучше делать **partial индекс для редких значений**|
|Составной индекс?|✅ Полезен, если фильтруешь по status + другие колонки (например, сортировка, ограничения)|
