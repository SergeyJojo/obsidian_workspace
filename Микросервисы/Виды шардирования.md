
# **Типы горизонтального разделения (шардинга) баз данных**

Горизонтальное разделение (шардинг) — это метод распределения данных между несколькими серверами по определённым правилам. Вот основные типы шардинга:

## **1. Шардинг по диапазону (Range Sharding)**
**Принцип:**  
Данные распределяются по диапазонам значений ключа.

**Пример:**  
```sql
-- Шард 1: user_id от 1 до 1000000
-- Шард 2: user_id от 1000001 до 2000000
```

**Плюсы:**  
✔ Простота реализации  
✔ Эффективен для диапазонных запросов (`BETWEEN`, `>`, `<`)  

**Минусы:**  
✖ Риск неравномерного распределения (горячие шарды)  
✖ Сложность ребалансировки  

**Использование:**  
- Временные данные (например, по месяцам)  
- Логи с временными метками  

---

## **2. Хэш-шардинг (Hash Sharding)**
**Принцип:**  
Ключ шардинга пропускается через хэш-функцию, результат определяет шард.

**Пример:**  
```python
shard_id = hash(user_id) % 10  # Распределение по 10 шардам
```

**Плюсы:**  
✔ Равномерное распределение данных  
✔ Простота добавления новых шардов  

**Минусы:**  
✖ Невозможность выполнения диапазонных запросов  
✖ Сложность перераспределения при изменении числа шардов  

**Использование:**  
- Пользовательские профили  
- Ключ-значение хранилища  

---

## **3. Шардинг по списку (List Sharding)**
**Принцип:**  
Явное указание, какие значения попадают в какой шард.

**Пример:**  
```sql
-- Шард 1: country IN ('US', 'CA')  
-- Шард 2: country IN ('DE', 'FR')  
```

**Плюсы:**  
✔ Гибкость в распределении  
✔ Подходит для категориальных данных  

**Минусы:**  
✖ Ручное управление  
✖ Неравномерность при плохом выборе ключа  

**Использование:**  
- Географически распределённые данные  
- Мультитенантные системы  

---

## **4. Шардинг по составному ключу (Composite Sharding)**
**Принцип:**  
Комбинация нескольких методов (например, сначала по диапазону, затем по хэшу).

**Пример:**  
```python
shard_id = (user_id // 1000000) + (hash(country) % 3)
```

**Плюсы:**  
✔ Гибкость  
✔ Уменьшает горячие шарды  

**Минусы:**  
✖ Сложная логика  
✖ Трудоёмкость ребалансировки  

**Использование:**  
- Социальные сети (комбинация user_id + региона)  
- Крупные SaaS-платформы  

---

## **5. Шардинг по словарю (Directory-Based Sharding)**
**Принцип:**  
Отдельная таблица (словарь) хранит соответствие ключей и шардов.

**Пример:**  
```sql
-- Таблица-маршрутизатор
CREATE TABLE shard_routing (
    user_id BIGINT PRIMARY KEY,
    shard_id INT
);
```

**Плюсы:**  
✔ Максимальная гибкость  
✔ Возможность динамического перераспределения  

**Минусы:**  
✖ Дополнительные запросы для определения шарда  
✖ Единая точка отказа (если словарь не реплицирован)  

**Использование:**  
- Системы с часто меняющимися правилами шардинга  

---

## **6. Геошардинг (Geo Sharding)**
**Принцип:**  
Данные распределяются по физическому расположению (страна, регион).

**Пример:**  
```sql
-- Шард в ЕС: EU_*
-- Шард в США: US_*
```

**Плюсы:**  
✔ Низкая задержка для локальных запросов  
✔ Соответствие GDPR и другим регуляциям  

**Минусы:**  
✖ Сложность кросс-регионных запросов  

**Использование:**  
- Глобальные SaaS-приложения  
- Финансовые системы  

---

## **Сравнение методов**
| Метод               | Равномерность | Диапазонные запросы | Гибкость | Сложность |
|---------------------|---------------|----------------------|----------|-----------|
| **По диапазону**    | Низкая        | Да                   | Низкая   | Низкая    |
| **Хэш**             | Высокая       | Нет                  | Средняя  | Средняя   |
| **По списку**       | Средняя       | Частично             | Высокая  | Средняя   |
| **Составной**       | Высокая       | Частично             | Высокая  | Высокая   |
| **Словарь**         | Любая         | Да                   | Макс.    | Высокая   |
| **Геошардинг**      | Зависит       | Нет                  | Высокая  | Высокая   |

---

## **Проблемы шардинга**
1. **Кросс-шардовые запросы**  
   - Решение: дублирование данных или отдельный агрегирующий сервис.

2. **Транзакции**  
   - 2PC (Two-Phase Commit) или Saga-паттерн.

3. **Ребалансировка**  
   - Инструменты вроде Vitess или CockroachDB.

4. **Роутинг запросов**  
   - Прокси-слой (например, ProxySQL).

---

## **Выбор стратегии**
- **Равномерность** → Хэш  
- **Диапазонные запросы** → По диапазону  
- **Гибкость** → Словарь  
- **Геоограничения** → Геошардинг  

Шардинг — это компромисс между производительностью и сложностью. Выбор зависит от паттернов доступа к данным.
