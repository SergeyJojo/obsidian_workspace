## **1. Глубинная оптимизация Kubernetes**

---

### **1.1. Настройка Kubernetes для High Availability (HA)**

Kubernetes поддерживает архитектуру высокой доступности для критически важных приложений.

#### **Архитектура HA Control Plane**

1. **API-серверы**:
    
    - Реплицируются на всех узлах Control Plane.
    - Балансируются через Load Balancer (например, NGINX, HAProxy).
2. **etcd**:
    
    - Должен быть кластеризован для отказоустойчивости (рекомендуется 3-5 узлов).
    - Используйте TLS для шифрования трафика между узлами etcd.
3. **Scheduler и Controller Manager**:
    
    - Работают в активном/резервном режиме с лидером, избираемым через etcd.

#### **Пример HA-конфигурации API-сервера**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: kube-apiserver
  namespace: kube-system
spec:
  containers:
    - name: kube-apiserver
      image: k8s.gcr.io/kube-apiserver:v1.27
      command:
        - kube-apiserver
        - --advertise-address=192.168.1.100
        - --etcd-servers=https://etcd-cluster:2379
        - --tls-cert-file=/etc/kubernetes/pki/apiserver.crt
        - --tls-private-key-file=/etc/kubernetes/pki/apiserver.key
```

### **1.2. Автообновления Kubernetes-кластера**

Используйте **kubeadm** или **Cluster API** для автоматического обновления Control Plane и Worker Nodes.

1. **Обновление Control Plane:**
    
    ```bash
    kubeadm upgrade plan
    kubeadm upgrade apply v1.27.3
    ```
    
2. **Обновление Worker Nodes:**
    
    ```bash
    kubectl drain <node_name> --ignore-daemonsets
    kubeadm upgrade node
    kubectl uncordon <node_name>
    ```
    

---

### **1.3. Управление ресурсами через QoS (Quality of Service)**

Kubernetes разделяет поды на три категории QoS:

1. **Guaranteed**:
    
    - Если `requests` и `limits` равны.
    
    ```yaml
    resources:
      requests:
        memory: "512Mi"
        cpu: "500m"
      limits:
        memory: "512Mi"
        cpu: "500m"
    ```
    
2. **Burstable**:
    
    - Если `requests` заданы, но `limits` больше `requests`.
    
    ```yaml
    resources:
      requests:
        memory: "256Mi"
        cpu: "250m"
      limits:
        memory: "1Gi"
        cpu: "1"
    ```
    
3. **BestEffort**:
    
    - Никакие ресурсы не указаны. Под имеет низший приоритет.

## **2. Сетевая магия Kubernetes**

---

### **2.1. eBPF для Kubernetes**

**eBPF (extended Berkeley Packet Filter)** позволяет внедрять пользовательский код в ядро Linux для анализа сетевого трафика без накладных расходов.

#### **Использование eBPF с Cilium**

Cilium — это сетевой плагин (CNI), основанный на eBPF. Он обеспечивает высокую производительность и мощные возможности.

1. **Установка Cilium**:
    
    ```bash
    helm repo add cilium https://helm.cilium.io/
    helm install cilium cilium/cilium --namespace kube-system
    ```
    
2. **Пример политики eBPF для блокировки нежелательного трафика**:
    
    ```yaml
    apiVersion: cilium.io/v2
    kind: CiliumNetworkPolicy
    metadata:
      name: block-external-traffic
    spec:
      endpointSelector:
        matchLabels:
          app: backend
      ingress:
        - fromEndpoints:
            - matchLabels:
                app: frontend
    ```
    

---

### **2.2. Использование Ingress на steroids**

#### **Traefik Ingress Controller**

Traefik — это мощный Ingress Controller с поддержкой динамических конфигураций.

1. Установка Traefik через Helm:
    
    ```bash
    helm repo add traefik https://traefik.github.io/charts
    helm install traefik traefik/traefik
    ```
    
2. Настройка HTTPS через Let's Encrypt:
    
    ```yaml
    apiVersion: traefik.containo.us/v1alpha1
    kind: IngressRoute
    metadata:
      name: my-app
    spec:
      entryPoints:
        - websecure
      routes:
        - match: Host(`my-app.example.com`)
          kind: Rule
          services:
            - name: my-service
              port: 80
      tls:
        certResolver: myresolver
    ```

## **3. Автоматизация и GitOps**

---

### **3.1. GitOps с Flux**

Flux позволяет синхронизировать состояние инфраструктуры с Git.

1. Установка Flux:
    
    ```bash
    flux install
    ```
    
2. Пример декларации приложения:
    
    ```yaml
    apiVersion: kustomize.toolkit.fluxcd.io/v1beta2
    kind: Kustomization
    metadata:
      name: my-app
    spec:
      interval: 10m
      path: "./deploy"
      prune: true
      sourceRef:
        kind: GitRepository
        name: my-repo
    ```
    

---

### **3.2. CI/CD с Argo Workflows**

Argo Workflows — это Kubernetes-ориентированная система для создания CI/CD-пайплайнов.

1. Установка:
    
    ```bash
    kubectl create namespace argo
    kubectl apply -n argo -f https://raw.githubusercontent.com/argoproj/argo-workflows/stable/manifests/install.yaml
    ```
    
2. Пример Workflow:
    
    ```yaml
    apiVersion: argoproj.io/v1alpha1
    kind: Workflow
    metadata:
      generateName: my-pipeline-
    spec:
      entrypoint: main
      templates:
        - name: main
          steps:
            - - name: build
                template: build
            - - name: deploy
                template: deploy
        - name: build
          container:
            image: golang:1.20
            command: ["go", "build", "./..."]
        - name: deploy
          container:
            image: kubectl
            command: ["kubectl", "apply", "-f", "manifests/"]
    ```

## **4. Безопасность Kubernetes**

---

### **4.1. Seccomp для контейнеров**

Seccomp ограничивает системные вызовы.

1. Включение Seccomp:
    
    ```yaml
    apiVersion: v1
    kind: Pod
    metadata:
      name: my-pod
    spec:
      securityContext:
        seccompProfile:
          type: RuntimeDefault
    ```
    

---

### **4.2. Настройка аудита**

Включите аудит для отслеживания операций над ресурсами.

1. Файл конфигурации аудита:
    
    ```yaml
    apiVersion: audit.k8s.io/v1
    kind: Policy
    rules:
      - level: Metadata
        resources:
          - group: ""
            resources: ["pods"]
    ```
    
2. Подключение политики аудита:
    
    ```bash
    kube-apiserver --audit-policy-file=/etc/kubernetes/audit-policy.yaml
    ```
