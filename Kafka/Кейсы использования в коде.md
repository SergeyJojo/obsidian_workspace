### Основные кейсы операций с Kafka в Go

#### 1. Создание топика (Topic Creation)
- **Что**: Создание топика для хранения сообщений (обычно делается администратором, но можно через API).
- **Как**: Используем `AdminClient` для создания топика.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
  )

  func main() {
      admin, err := kafka.NewAdminClient(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
      })
      if err != nil {
          fmt.Printf("Failed to create Admin client: %s\n", err)
          return
      }
      defer admin.Close()

      topic := "reminders"
      result, err := admin.CreateTopics(
          []kafka.TopicSpecification{{
              Topic:             topic,
              NumPartitions:     1,
              ReplicationFactor: 1,
          }},
      )
      if err != nil {
          fmt.Printf("Failed to create topic: %s\n", err)
          return
      }
      fmt.Printf("Topic %s created: %v\n", topic, result)
  }
  ```
- **Связь с проектом**: Создаём топик `reminders` для Reminder Service, куда будут отправляться события `question_added`.

#### 2. Отправка сообщения (Producing Messages)
- **Что**: Производитель (Producer) отправляет сообщения в топик.
- **Как**: Создаём `Producer` и используем `Produce`.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
  )

  func main() {
      p, err := kafka.NewProducer(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
      })
      if err != nil {
          fmt.Printf("Failed to create producer: %s\n", err)
          return
      }
      defer p.Close()

      topic := "reminders"
      msg := &kafka.Message{
          TopicPartition: kafka.TopicPartition{Topic: &topic, Partition: kafka.PartitionAny},
          Value:          []byte("Question added for user 123"),
          Key:            []byte("user:123"), // Для шардирования
      }

      err = p.Produce(msg, nil)
      if err != nil {
          fmt.Printf("Failed to produce message: %s\n", err)
      }

      // Ждём доставку
      p.Flush(15 * 1000) // 15 секунд
      fmt.Println("Message sent")
  }
  ```
- **Связь с проектом**: Content Service отправляет событие `question_added` в топик `reminders` после добавления вопроса.

#### 3. Чтение сообщений (Consuming Messages)
- **Что**: Потребитель (Consumer) читает сообщения из топика.
- **Как**: Создаём `Consumer`, подписываемся на топик и читаем через цикл.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
  )

  func main() {
      c, err := kafka.NewConsumer(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
          "group.id":          "reminder-group",
          "auto.offset.reset": "earliest",
      })
      if err != nil {
          fmt.Printf("Failed to create consumer: %s\n", err)
          return
      }
      defer c.Close()

      topic := "reminders"
      c.SubscribeTopics([]string{topic}, nil)

      for {
          msg, err := c.ReadMessage(-1) // Блокирующий вызов
          if err == nil {
              fmt.Printf("Received: %s (Key: %s)\n", string(msg.Value), string(msg.Key))
          } else {
              fmt.Printf("Consumer error: %v\n", err)
              break
          }
      }
  }
  ```
- **Связь с проектом**: Reminder Service читает сообщения из `reminders` и отправляет напоминания пользователям.

#### 4. Асинхронная обработка с подтверждением (Committing Offsets)
- **Что**: Подтверждение обработки сообщений для управления offset’ами.
- **Как**: Используем `CommitMessage` после обработки.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
  )

  func main() {
      c, err := kafka.NewConsumer(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
          "group.id":          "reminder-group",
          "auto.offset.reset": "earliest",
      })
      if err != nil {
          fmt.Printf("Failed to create consumer: %s\n", err)
          return
      }
      defer c.Close()

      c.SubscribeTopics([]string{"reminders"}, nil)

      for {
          msg, err := c.ReadMessage(-1)
          if err == nil {
              fmt.Printf("Processing: %s\n", string(msg.Value))
              c.CommitMessage(msg) // Подтверждаем offset
          } else {
              fmt.Printf("Error: %v\n", err)
              break
          }
      }
  }
  ```
- **Связь с проектом**: Гарантирует, что Reminder Service не пропустит и не обработает сообщение дважды.

#### 5. Параллельная обработка с несколькими горутинами
- **Что**: Распределяем сообщения между горутинами для повышения производительности.
- **Как**: Используем каналы для передачи сообщений.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
      "sync"
  )

  func main() {
      c, err := kafka.NewConsumer(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
          "group.id":          "reminder-group",
          "auto.offset.reset": "earliest",
      })
      if err != nil {
          fmt.Printf("Failed to create consumer: %s\n", err)
          return
      }
      defer c.Close()

      c.SubscribeTopics([]string{"reminders"}, nil)
      messages := make(chan *kafka.Message, 100)
      var wg sync.WaitGroup

      // Запускаем воркеров
      for i := 0; i < 3; i++ {
          wg.Add(1)
          go func(id int) {
              defer wg.Done()
              for msg := range messages {
                  fmt.Printf("Worker %d: %s\n", id, string(msg.Value))
                  c.CommitMessage(msg)
              }
          }(i)
      }

      // Читаем сообщения
      for {
          msg, err := c.ReadMessage(-1)
          if err == nil {
              messages <- msg
          } else {
              fmt.Printf("Error: %v\n", err)
              break
          }
      }
  }
  ```
- **Связь с проектом**: Ускоряет обработку напоминаний в Reminder Service.

#### 6. Проверка состояния топика (Topic Metadata)
- **Что**: Получение информации о топике (партиции, offset’ы).
- **Как**: Используем `GetMetadata`.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
  )

  func main() {
      c, err := kafka.NewConsumer(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
          "group.id":          "reminder-group",
      })
      if err != nil {
          fmt.Printf("Failed to create consumer: %s\n", err)
          return
      }
      defer c.Close()

      metadata, err := c.GetMetadata(&kafka.TopicMetadata{Topic: "reminders"}, false, 1000)
      if err != nil {
          fmt.Printf("Failed to get metadata: %s\n", err)
          return
      }
      for _, topic := range metadata.Topics {
          fmt.Printf("Topic: %s, Partitions: %d\n", topic.Topic, len(topic.Partitions))
      }
  }
  ```
- **Связь с проектом**: Полезно для отладки Reminder Service или проверки топика.

#### 7. Удаление топика (Topic Deletion)
- **Что**: Удаление топика (административная операция).
- **Как**: Используем `DeleteTopics`.
- **Пример**:
  ```go
  package main

  import (
      "fmt"
      "github.com/confluentinc/confluent-kafka-go/kafka"
  )

  func main() {
      admin, err := kafka.NewAdminClient(&kafka.ConfigMap{
          "bootstrap.servers": "localhost:9092",
      })
      if err != nil {
          fmt.Printf("Failed to create admin: %s\n", err)
          return
      }
      defer admin.Close()

      topic := "reminders"
      result, err := admin.DeleteTopics([]string{topic})
      if err != nil {
          fmt.Printf("Failed to delete topic: %s\n", err)
          return
      }
      fmt.Printf("Topic deletion result: %v\n", result)
  }
  ```
- **Связь с проектом**: Используется для очистки устаревших топиков в Reminder Service.
