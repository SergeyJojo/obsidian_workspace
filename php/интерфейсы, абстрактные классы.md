
В PHP **интерфейсы** и **абстрактные классы** — это два ключевых инструмента для реализации абстракции и полиморфизма в ООП. Они помогают структурировать код, но используются в разных сценариях. Разберём их подробно.

---

## **1. Интерфейсы (Interfaces)**
### **Что это?**
Интерфейс — это **контракт**, который определяет, **какие методы должен реализовать класс**. Он содержит только сигнатуры методов (без реализации).

### **Особенности:**
- Все методы в интерфейсе **публичные** (`public`) и **абстрактные** (не имеют тела).
- Класс может реализовывать **несколько интерфейсов**.
- Интерфейсы могут наследоваться друг от друга.

### **Пример:**
```php
interface LoggerInterface {
    public function log(string $message): void;
}

interface NotifierInterface {
    public function send(string $recipient, string $message): bool;
}

class FileLogger implements LoggerInterface {
    public function log(string $message): void {
        file_put_contents('log.txt', $message, FILE_APPEND);
    }
}

class EmailNotifier implements LoggerInterface, NotifierInterface {
    public function log(string $message): void {
        // Реализация логирования
    }

    public function send(string $recipient, string $message): bool {
        // Реализация отправки email
        return true;
    }
}
```

### **Когда использовать?**
- Когда нужно **обязать класс** реализовать конкретные методы.
- Для реализации **множественного наследования** (в PHP нет множественного наследования классов).
- В **библиотеках и API**, чтобы пользователи следовали определённому контракту.

## **2. Абстрактные классы (Abstract Classes)**
### **Что это?**
Абстрактный класс — это **частично реализованный класс**, который нельзя инстанцировать (создавать объекты). Может содержать как абстрактные методы (без реализации), так и обычные.

### **Особенности:**
- Может включать **реализованные методы** и **свойства**.
- Абстрактные методы **не имеют тела** и должны быть реализованы в дочерних классах.
- Класс может наследовать **только один** абстрактный класс.

### **Пример:**
```php
abstract class Animal {
    protected string $name;

    public function __construct(string $name) {
        $this->name = $name;
    }

    // Абстрактный метод (без реализации)
    abstract public function makeSound(): string;

    // Обычный метод
    public function eat(): string {
        return $this->name . " ест.";
    }
}

class Dog extends Animal {
    public function makeSound(): string {
        return "Гав!";
    }
}

$dog = new Dog("Бобик");
echo $dog->makeSound();  // "Гав!"
echo $dog->eat();        // "Бобик ест."
```

### **Когда использовать?**
- Когда **несколько классов** имеют общую логику, но требуют разной реализации некоторых методов.
- Для создания **базового функционала**, который будет расширяться.
- Если нужно **ограничить создание объектов** базового класса.

## **3. Сравнение интерфейсов и абстрактных классов**
| Критерий               | Интерфейсы                          | Абстрактные классы               |
|------------------------|-------------------------------------|----------------------------------|
| **Реализация методов** | Только сигнатуры                   | Могут быть реализованные методы  |
| **Наследование**       | Множественное (`implements`)       | Единичное (`extends`)            |
| **Свойства**           | Не могут содержать свойства        | Могут содержать свойства         |
| **Модификаторы доступа**| Только `public`                    | Любые (`public`, `protected`, `private`) |
| **Когда использовать** | Для контрактов, полиморфизма       | Для общего кода + расширения     |

## **4. Комбинирование интерфейсов и абстрактных классов**
Интерфейсы и абстрактные классы могут работать вместе:

```php
interface Drawable {
    public function draw(): void;
}

abstract class Shape implements Drawable {
    protected string $color;

    public function setColor(string $color): void {
        $this->color = $color;
    }

    // Абстрактный метод из интерфейса
    abstract public function draw(): void;
}

class Circle extends Shape {
    public function draw(): void {
        echo "Рисуем круг цветом " . $this->color;
    }
}

$circle = new Circle();
$circle->setColor("красный");
$circle->draw();  // "Рисуем круг цветом красный"
```

## **5. Практические примеры**
### **Интерфейс для репозиториев (Dependency Injection)**
```php
interface UserRepositoryInterface {
    public function findById(int $id): ?User;
}

class DatabaseUserRepository implements UserRepositoryInterface {
    public function findById(int $id): ?User {
        // Запрос к БД
    }
}

class UserService {
    public function __construct(private UserRepositoryInterface $repository) {}
}
```

### **Абстрактный класс для шаблонного метода**
```php
abstract class ReportGenerator {
    // Шаблонный метод
    final public function generate(): string {
        $data = $this->fetchData();
        return $this->format($data);
    }

    abstract protected function fetchData(): array;
    abstract protected function format(array $data): string;
}

class PdfReport extends ReportGenerator {
    protected function fetchData(): array {
        return ["title" => "Отчёт"];
    }

    protected function format(array $data): string {
        return "PDF: " . $data['title'];
    }
}
```

## **6. Что выбрать?**
- **Интерфейс**, если:
  - Нужно определить контракт для разных классов.
  - Требуется множественное наследование.
- **Абстрактный класс**, если:
  - Есть общая логика для наследования.
  - Нужно частично реализовать функционал.

---

## **Итог**
- **Интерфейсы** — для полиморфизма и контрактов.
- **Абстрактные классы** — для переиспользуемой базовой логики.
- В современных PHP-проектах часто используют **оба подхода** вместе (например, в паттернах Repository, Strategy).
