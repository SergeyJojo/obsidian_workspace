### Что такое сетевые порты?
Сетевые порты — это виртуальные точки в сетевом взаимодействии, которые используются для идентификации конкретного процесса или службы на устройстве в рамках протоколов транспортного уровня (TCP или UDP). Они представляют собой 16-битные числа (от 0 до 65535), добавляемые к IP-адресу, чтобы направить трафик к нужному приложению.

#### Структура
- **IP-адрес**: Указывает устройство в сети (например, `192.168.1.1`).
- **Порт**: Указывает процесс на этом устройстве (например, `80` для HTTP).
- Вместе: `192.168.1.1:80`.

---

### Для чего нужны сетевые порты?
Сетевые порты решают проблему: как одно устройство с одним IP-адресом может одновременно обслуживать несколько приложений (например, веб-сервер, базу данных, мессенджер)? Они нужны для:

1. **Мультиплексирование**:
   - Позволяют нескольким приложениям использовать одну сетевую карту.
   - Пример: На сервере `10.0.0.1` веб-сервер слушает порт `80`, а база данных — `5432`.

2. **Идентификация службы**:
   - Порты стандартизированы для популярных протоколов (IANA):
     - `80`: HTTP.
     - `443`: HTTPS.
     - `5432`: PostgreSQL.
   - Это упрощает подключение клиентов.

3. **Управление соединениями**:
   - TCP использует порты для установления и отслеживания соединений (сессий).
   - UDP — для отправки датаграмм.

4. **Безопасность**:
   - Файрволы фильтруют трафик по портам (например, открыть `22` для SSH, закрыть всё остальное).

---

### Как работают сетевые порты?
#### Механизм
1. **Слушающий порт (Server)**:
   - Сервер привязывается к порту через сокет (`bind`).
   - Пример: Веб-сервер слушает `0.0.0.0:80`.
2. **Исходящий порт (Client)**:
   - Клиент получает случайный свободный порт (эпемерный, ephemeral port, обычно > 1024) от ОС.
   - Пример: Браузер подключается с `192.168.1.100:49152` к `10.0.0.1:80`.
3. **Соединение**:
   - TCP: Устанавливается пара "IP:порт" (source → destination).
   - UDP: Датаграммы отправляются без соединения.

#### Пример TCP-соединения
- Клиент: `192.168.1.100:49152`.
- Сервер: `10.0.0.1:80`.
- Пакет: "От 192.168.1.100:49152 к 10.0.0.1:80" → сервер знает, куда вернуть ответ.

---

### Диапазоны портов
1. **0–1023**: Зарезервированные (well-known ports).
   - `22`: SSH.
   - `25`: SMTP.
   - `80`: HTTP.
2. **1024–49151**: Регистрируемые порты (для приложений).
   - `5432`: PostgreSQL.
   - `6379`: Redis.
3. **49152–65535**: Эпемерные порты (для клиентов).

### Связь с "Learning Repeater"
#### Применение
1. **Content Service**:
   - REST API на порту `8080`:
     ```go
     http.ListenAndServe(":8080", nil)
     ```
   - PostgreSQL на `5432`:
     ```go
     db, _ := sql.Open("postgres", "host=localhost port=5432 user=postgres dbname=content")
     ```
   - Клиент (например, фронтенд) подключается с ephemeral порта.

2. **Progress Service**:
   - Redis на `6379`:
     ```go
     redis.NewClient(&redis.Options{Addr: "localhost:6379"})
     ```
   - Аналитика доступна через API на `8081`.

3. **Reminder Service**:
   - Kafka брокер на `9092`:
     ```go
     producer, _ := kafka.NewProducer(&kafka.ConfigMap{"bootstrap.servers": "localhost:9092"})
     ```
   - Consumer слушает тот же порт.

#### Проблемы и решения
- **Конфликт портов**: Если два сервиса пытаются занять `8080`, возникает ошибка "address already in use".
  - Решение: Указать разные порты в конфиге или Docker (`-p 8080:8080`).
- **Безопасность**: Открытые порты (например, `5432`) уязвимы.
  - Решение: Использовать Network Policies в Kubernetes, закрывать порты файрволом.

#### Пример в Kubernetes
```yaml
apiVersion: v1
kind: Service
metadata:
  name: content-service
spec:
  ports:
  - port: 8080
    targetPort: 8080
  selector:
    app: content
```
