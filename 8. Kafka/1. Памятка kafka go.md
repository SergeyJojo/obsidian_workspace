# **Памятка по работе с Kafka на Go**  
Краткий гайд по подключению, настройке и использованию Apache Kafka в Go-приложениях с примерами кода.

---

## **1. Подключение Kafka в Go**  
Установите библиотеку `confluent-kafka-go` (официальная обертка над `librdkafka`):  
```bash
go get github.com/confluentinc/confluent-kafka-go/v2/kafka
```

---

## **2. Основные компоненты**  
### **Producer (отправка сообщений)**  
```go
package main

import (
	"fmt"
	"github.com/confluentinc/confluent-kafka-go/v2/kafka"
)

func main() {
	config := &kafka.ConfigMap{
		"bootstrap.servers": "localhost:9092", // Адрес Kafka-брокера
	}

	producer, err := kafka.NewProducer(config)
	if err != nil {
		panic(err)
	}
	defer producer.Close()

	topic := "test-topic"
	msg := &kafka.Message{
		TopicPartition: kafka.TopicPartition{Topic: &topic, Partition: kafka.PartitionAny},
		Value:          []byte("Hello, Kafka!"),
	}

	err = producer.Produce(msg, nil)
	if err != nil {
		fmt.Printf("Failed to produce message: %v\n", err)
	} else {
		fmt.Printf("Produced message to %s\n", *msg.TopicPartition.Topic)
	}

	producer.Flush(15 * 1000) // Ожидаем отправки всех сообщений
}
```

---

### **Consumer (чтение сообщений)**  
```go
func main() {
	config := &kafka.ConfigMap{
		"bootstrap.servers": "localhost:9092",
		"group.id":          "my-group",       // Группа потребителей
		"auto.offset.reset": "earliest",       // Чтение с начала топика
	}

	consumer, err := kafka.NewConsumer(config)
	if err != nil {
		panic(err)
	}
	defer consumer.Close()

	err = consumer.SubscribeTopics([]string{"test-topic"}, nil)
	if err != nil {
		panic(err)
	}

	for {
		msg, err := consumer.ReadMessage(-1) // Блокирующее чтение
		if err != nil {
			fmt.Printf("Consumer error: %v\n", err)
			continue
		}
		fmt.Printf("Received message: %s\n", string(msg.Value))
	}
}
```

## **3. Настройки Kafka**  
### **Важные параметры Producer**  
```go
config := &kafka.ConfigMap{
	"bootstrap.servers": "kafka1:9092,kafka2:9092", // Несколько брокеров
	"acks":             "all",                     // Гарантированная запись
	"retries":          3,                         // Число попыток при ошибке
	"compression.type": "snappy",                  // Сжатие сообщений
}
```

### **Важные параметры Consumer**  
```go
config := &kafka.ConfigMap{
	"group.id":           "my-app-group",
	"enable.auto.commit": false, // Ручное подтверждение (at-least-once)
	"auto.offset.reset":  "earliest",
}
```

## **4. Обработка ошибок**  
### **Producer**  
```go
deliveryChan := make(chan kafka.Event)
err = producer.Produce(&kafka.Message{
	TopicPartition: kafka.TopicPartition{Topic: &topic, Partition: kafka.PartitionAny},
	Value:          []byte("message"),
}, deliveryChan)

e := <-deliveryChan
msg := e.(*kafka.Message)
if msg.TopicPartition.Error != nil {
	fmt.Printf("Delivery failed: %v\n", msg.TopicPartition.Error)
} else {
	fmt.Printf("Delivered to %v\n", msg.TopicPartition)
}
```

### **Consumer (ручное подтверждение)**  
```go
msg, err := consumer.ReadMessage(-1)
if err == nil {
	fmt.Printf("Message: %s\n", string(msg.Value))
	_, err := consumer.CommitMessage(msg) // Подтверждаем обработку
	if err != nil {
		fmt.Printf("Commit error: %v\n", err)
	}
}
```

## **5. Продвинутые сценарии**  
### **Создание топика через Admin API**  
```go
admin, err := kafka.NewAdminClient(&kafka.ConfigMap{"bootstrap.servers": "localhost:9092"})
if err != nil {
	panic(err)
}
defer admin.Close()

_, err = admin.CreateTopics(context.Background(), []kafka.TopicSpecification{{
	Topic:             "new-topic",
	NumPartitions:     3,
	ReplicationFactor: 1,
}})
if err != nil {
	fmt.Printf("Failed to create topic: %v\n", err)
}
```

### **Consumer Groups**  
```go
config := &kafka.ConfigMap{
	"bootstrap.servers": "localhost:9092",
	"group.id":          "my-group",
	"auto.offset.reset": "earliest",
}

consumer, err := kafka.NewConsumer(config)
// ... подписка и чтение как в примере выше
```

## **Чек-лист перед продакшеном**  
1. Настройте **партиционирование** (если нужен порядок сообщений).  
2. Проверьте **настройки репликации** (минимум `replication.factor=2`).  
3. Реализуйте **повторную обработку ошибок** (Dead Letter Queue).  
4. Мониторьте **лаг потребителей** (например, через `kafka-consumer-groups.sh`).
