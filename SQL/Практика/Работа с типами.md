### Основные категории типов данных в PostgreSQL
PostgreSQL предлагает богатый набор типов данных, которые делятся на категории:
1. **Числовые** (Numeric)
2. **Текстовые** (Character)
3. **Дата и время** (Date/Time)
4. **Логические** (Boolean)
5. **JSON и JSONB**
6. **Массивы** (Arrays)
7. **Специализированные** (UUID, Geometry, etc.)

Я опишу ключевые типы, их применение и best practices.

---

### 1. Числовые типы (Numeric Types)
#### Основные типы
- **`smallint`** (2 байта, -32768 до 32767):
  - Когда: Маленькие целые числа (например, возраст, рейтинг).
  - Best Practice: Используйте для экономии места, если диапазон достаточен.
- **`integer`** (4 байта, -2^31 до 2^31-1):
  - Когда: Стандартный выбор для ID, счётчиков.
  - Best Practice: Дефолтный тип для целых чисел.
- **`bigint`** (8 байт, -2^63 до 2^63-1):
  - Когда: Большие числа (например, глобальные ID, большие счётчики).
  - Best Practice: Используйте, если ожидается рост данных.
- **`numeric(precision, scale)`** (переменная длина):
  - Когда: Точные десятичные числа (например, деньги).
  - Best Practice: Указывайте точность (например, `numeric(10,2)` для 10 цифр, 2 после запятой).
- **`real`** (4 байта, с плавающей точкой):
  - Когда: Приближённые числа (например, статистика).
- **`double precision`** (8 байт, с плавающей точкой):
  - Когда: Более точные вычисления (например, научные данные).

#### Пример
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,           -- integer с автоинкрементом
    age SMALLINT,                    -- возраст пользователя
    balance NUMERIC(10,2)            -- баланс в валюте
);
```
- **Связь с проектом**: `id` для пользователей, `age` для ограниченного диапазона, `balance` для точных расчётов.

#### Best Practices
- Используйте `SERIAL` (или `BIGSERIAL`) для автоинкрементных ID.
- Избегайте `real`/`double` для финансов, так как они неточные.

### 2. Текстовые типы (Character Types)
#### Основные типы
- **`char(n)`** (фиксированная длина):
  - Когда: Редко, только если длина всегда фиксирована (например, коды).
- **`varchar(n)`** (переменная длина с лимитом):
  - Когда: Ограниченные строки (например, имена до 255 символов).
- **`text`** (без ограничения длины):
  - Когда: Произвольный текст (например, тело вопроса).

#### Пример
```sql
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    title VARCHAR(100),              -- заголовок вопроса
    body TEXT                        -- текст вопроса
);
```
- **Связь с проектом**: `title` для кратких заголовков, `body` для длинных текстов в Content Service.

#### Best Practices
- Используйте `text` вместо `varchar` без `n`, если лимит не нужен (производительность одинакова).
- Избегайте `char(n)`, так как он дополняет пробелами.

---

### 3. Дата и время (Date/Time Types)
#### Основные типы
- **`date`** (только дата):
  - Когда: Хранение дат (например, день рождения).
- **`time`** (только время):
  - Когда: Время без даты (редко).
- **`timestamp`** (дата + время без часового пояса):
  - Когда: Точные моменты без учёта зон.
- **`timestamptz`** (дата + время с часовым поясом):
  - Когда: Глобальные события (рекомендуемый тип).

#### Пример
```sql
CREATE TABLE progress (
    id SERIAL PRIMARY KEY,
    user_id INTEGER,
    last_reviewed TIMESTAMPTZ        -- время последнего просмотра
);
```
- **Связь с проектом**: `last_reviewed` в Progress Service для отслеживания активности.

#### Best Practices
- Используйте `timestamptz` для всех временных меток, чтобы избежать путаницы с зонами.
- Добавляйте `DEFAULT NOW()` для автоматической простановки текущего времени:
  ```sql
  last_reviewed TIMESTAMPTZ DEFAULT NOW()
  ```

### 4. Логический тип (Boolean)
#### Основной тип
- **`boolean`** (true, false, null):
  - Когда: Двоичные состояния (например, завершён ли вопрос).

#### Пример
```sql
ALTER TABLE questions ADD COLUMN is_completed BOOLEAN DEFAULT FALSE;
```
- **Связь с проектом**: `is_completed` в Content Service для статуса вопроса.

#### Best Practices
- Используйте с `DEFAULT` для начального значения.
- Не заменяйте `enum`, если нужно больше двух состояний.

---

### 5. JSON и JSONB
#### Основные типы
- **`json`** (текст в формате JSON):
  - Когда: Редко, только для хранения без частых запросов.
- **`jsonb`** (бинарный JSON):
  - Когда: Неструктурированные данные с индексацией и запросами.

#### Пример
```sql
CREATE TABLE user_settings (
    id SERIAL PRIMARY KEY,
    user_id INTEGER,
    settings JSONB                   -- настройки пользователя
);

INSERT INTO user_settings (user_id, settings)
VALUES (1, '{"theme": "dark", "notifications": true}');
```
- **Связь с проектом**: Хранение настроек в Reminder Service.

#### Best Practices
- Используйте `jsonb` вместо `json` (быстрее, индексируется).
- Создавайте индексы GIN для частых запросов:
  ```sql
  CREATE INDEX idx_settings ON user_settings USING GIN (settings);
  ```

---

### 6. Массивы (Array Types)
#### Основной тип
- **`type[]`** (массив любого типа):
  - Когда: Списки данных (например, теги).

#### Пример
```sql
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    tags TEXT[]                     -- массив тегов
);

INSERT INTO questions (tags) VALUES (ARRAY['math', 'algebra']);
```
- **Связь с проектом**: `tags` в Content Service для категоризации вопросов.

#### Best Practices
- Используйте массивы вместо отдельных таблиц, если связи простые.
- Индексируйте с GIN для поиска:
  ```sql
  CREATE INDEX idx_tags ON questions USING GIN (tags);
  ```

---

### 7. Специализированные типы
#### UUID
- **`uuid`** (уникальный идентификатор):
  - Когда: Глобальные ID вместо `SERIAL`.
- **Пример**:
  ```sql
  CREATE TABLE users (
      id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      name TEXT
  );
  ```
- **Связь**: Замена `SERIAL` для распределённых систем.

#### Best Practices
- Используйте с `gen_random_uuid()` (требует拡張 `pgcrypto`).
- Подходит для микросервисов с независимыми базами.

#### Пример других
- **`inet`**: IP-адреса (например, логирование).
- **`geometry`**: Пространственные данные (не для вашего проекта).

---

### Общие Best Practices
1. **Выбор типа**:
   - Минимизируйте размер данных (`smallint` вместо `bigint`, если хватает).
   - Используйте типы, соответствующие домену (например, `numeric` для денег).
2. **Индексы**:
   - Добавляйте на часто запрашиваемые поля (`id`, `user_id`).
   - Используйте GIN для `jsonb` и массивов.
3. **NULL vs NOT NULL**:
   - Указывайте `NOT NULL` с `DEFAULT`, если поле обязательно:
     ```sql
     name TEXT NOT NULL DEFAULT ''
     ```
4. **Производительность**:
   - Избегайте избыточных типов (например, `varchar(10000)` вместо `text`).

### Связь с "Learning Repeater"
#### Content Service
```sql
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    title VARCHAR(100) NOT NULL,
    body TEXT,
    tags TEXT[],
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```
- `id`: Уникальный ключ.
- `user_id`: Связь с пользователем.
- `tags`: Массив для фильтрации.

#### Progress Service
```sql
CREATE TABLE progress (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    question_id INTEGER,
    learned_count INTEGER DEFAULT 0,
    last_reviewed TIMESTAMPTZ DEFAULT NOW()
);
```
- `learned_count`: Счётчик прогресса.
- `last_reviewed`: Время активности.

#### Reminder Service
```sql
CREATE TABLE reminders (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    question_id INTEGER,
    scheduled_at TIMESTAMPTZ,
    metadata JSONB
);
```
- `scheduled_at`: Время напоминания.
- `metadata`: Дополнительные данные.

### Итог
- **Числовые**: `integer`/`SERIAL` для ID, `numeric` для денег.
- **Текстовые**: `text` для произвольных строк, `varchar(n)` для ограниченных.
- **Дата/время**: `timestamptz` для событий.
- **JSONB**: Для гибких данных.
- **Массивы**: Для списков.
- **Проект**: Применяйте для оптимизации хранения и запросов в сервисах.

Если хотите углубиться (например, индексы или миграции), дайте знать!
