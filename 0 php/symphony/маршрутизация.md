# 🚀 Что такое маршрутизация в Symfony

**Маршрутизатор (Routing Component)** — это механизм, который:

1. Принимает входящий HTTP-запрос.
    
2. Находит соответствующий маршрут по URL и HTTP методу.
    
3. Передаёт управление нужному контроллеру.
    
4. Передаёт параметры, извлечённые из URL.
    

Symfony маршрутизация очень гибкая: поддерживает параметры, регулярки, локализацию, методы, префиксы, аннотации, YAML, PHP-конфиги.

---

# 🧠 Как маршрутизатор работает под капотом

В Symfony за маршруты отвечает компонент:

```
symfony/routing
```

Его задача:

1. **RouteCollection** — хранит список маршрутов.
    
2. **UrlMatcher** — ищет соответствие request.path → маршрут.
    
3. **CompiledRoute** — компилирует маршруты в быстрый RegExp.
    
4. **UrlGenerator** — может генерировать ссылки по имени маршрута.
    

Пример: запрос `/product/17` → матчит маршрут `/product/{id}` → вызывает контроллер `ProductController::show()` с параметром `id = 17`.

# 📍 Где определяются маршруты?

В Symfony есть 3 основных способа:

### 1️⃣ Аннотации / Атрибуты (современный подход) — **самый популярный**

Пример:

```php
use Symfony\Component\Routing\Annotation\Route;

class ProductController
{
    #[Route('/product/{id}', name: 'product_show', methods: ['GET'])]
    public function show($id)
    {
        // ...
    }
}
```

---

### 2️⃣ YAML — `config/routes.yaml`

```yaml
product_show:
  path: /product/{id}
  controller: App\Controller\ProductController::show
  methods: [GET]
```

---

### 3️⃣ PHP-конфигурация — `routes.php`

```php
use Symfony\Component\Routing\Loader\Configurator\RoutingConfigurator;

return function (RoutingConfigurator $routes) {
    $routes->add('product_show', '/product/{id}')
        ->controller([App\Controller\ProductController::class, 'show'])
        ->methods(['GET']);
};
```

---

# 📌 Как Symfony выбирает маршрут?

Заводим пример:

```
/blog/2024/symfony-routing
```

В `routes.yaml`:

```yaml
blog_post:
  path: /blog/{year}/{slug}
  controller: App\Controller\BlogController::post
  requirements:
    year: '\d{4}'
```

✔ год 2024 пройдёт  
✘ год `abcd` — не пройдёт из-за `requirements`

# ✳️ Параметры маршрутов

```yaml
path: /product/{category}/{id}
```

Symfony вытащит:

```
category = "phones"
id = "123"
```

Они автоматически попадут в аргументы метода контроллера:

```php
public function show(string $category, int $id)
```

✔ Авто-каст типов работает  
✔ Ошибка, если тип несовместим

---

# 📏 Ограничения параметров (регулярки)

```yaml
requirements:
  id: '\d+'
  category: '[a-z]+'
```

---

# 🎯 Значения по умолчанию

```yaml
defaults:
  page: 1
```

Например:

```
/news → page = 1
/news/5 → page = 5
```

---

# 🧩 Генерация URL по имени маршрута

Пример:

```php
$this->generateUrl('product_show', ['id' => 42]);
```

Вернёт:

```
/product/42
```

Используется:

- в перенаправлениях
    
- в ссылках
    
- в шаблонах Twig (`path()`)
    

---

# 🚫 Фильтрация по методам

```php
methods: ['POST']
```

Если отправить GET — возвращается `405 Method Not Allowed`.

---

# 📦 Префиксы маршрутов

Внутри контроллера:

```php
#[Route('/admin')]
class AdminController
{
    #[Route('/dashboard')]
    public function dashboard() { }
}
```

Маршрут будет:

```
/admin/dashboard
```

---

# 🧠 Performance: как Symfony ускоряет маршрутизацию

1. Все маршруты **компилируются в огромный оптимизированный RegExp**.
    
2. Кэшируется в `var/cache/*/url_matching_routes.php`.
    
3. Поиск маршрута — это фактически одно регулярное выражение.
    

Поэтому Symfony быстрый, несмотря на гибкость.

# 🔥 Примеры полезных фишек маршрутизации

### ✔️ Локализация маршрутов

```php
#[Route('/contact', name: 'contact', locale: 'en')]
#[Route('/kontakt', name: 'kontakt', locale: 'de')]
```

### ✔️ Host Matching

```yaml
path: /
host: '{subdomain}.example.com'
```

### ✔️ Condition (условие Expression Language)

```yaml
condition: "context.getMethod() == 'GET' and context.getHost() matches '/^api\./'"
```
