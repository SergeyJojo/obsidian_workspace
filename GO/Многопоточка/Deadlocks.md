
Дедлоки (deadlocks) в Go — это ситуации, когда две или более горутины блокируют друг друга, ожидая освобождения ресурсов, которые никогда не будут освобождены. Это приводит к тому, что программа "зависает" и не может продолжить выполнение. Давай разберём, как возникают дедлоки в Go, и как их избежать.

---

## **1. Что такое дедлок?**

Дедлок — это ситуация, при которой две или более горутины блокируют друг друга, ожидая освобождения ресурсов (например, мьютексов), которые никогда не будут освобождены. Это происходит из-за неправильного порядка захвата и освобождения ресурсов.

---

## **2. Условия возникновения дедлока**

Для возникновения дедлока должны выполняться четыре условия (условия Коффмана):
1. **Взаимное исключение (Mutual Exclusion)**:
   - Ресурсы могут использоваться только одной горутиной одновременно.
2. **Удержание и ожидание (Hold and Wait)**:
   - Горутина удерживает один ресурс и ожидает освобождения другого.
3. **Отсутствие вытеснения (No Preemption)**:
   - Ресурсы не могут быть принудительно отобраны у горутин.
4. **Круговое ожидание (Circular Wait)**:
   - Горутины ожидают друг друга, образуя цикл.

---

## **3. Пример дедлока в Go**

Рассмотрим классический пример дедлока с использованием мьютексов:

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

func main() {
    var mu1, mu2 sync.Mutex

    go func() {
        mu1.Lock()
        defer mu1.Unlock()

        time.Sleep(100 * time.Millisecond)  // Имитация работы

        mu2.Lock()
        defer mu2.Unlock()

        fmt.Println("Горутина 1 завершила работу")
    }()

    go func() {
        mu2.Lock()
        defer mu2.Unlock()

        time.Sleep(100 * time.Millisecond)  // Имитация работы

        mu1.Lock()
        defer mu1.Unlock()

        fmt.Println("Горутина 2 завершила работу")
    }()

    time.Sleep(1 * time.Second)
    fmt.Println("Программа завершена")
}
```

### **Что происходит?**
1. Горутина 1 захватывает `mu1` и ждёт `mu2`.
2. Горутина 2 захватывает `mu2` и ждёт `mu1`.
3. Обе горутины блокируют друг друга, и программа зависает.

## **4. Как избежать дедлоков?**

### **1. Упорядоченный захват ресурсов**
- Всегда захватывайте ресурсы в одном и том же порядке. Это предотвращает круговое ожидание.

### **Пример:**
```go
func main() {
    var mu1, mu2 sync.Mutex

    go func() {
        mu1.Lock()
        defer mu1.Unlock()

        time.Sleep(100 * time.Millisecond)

        mu2.Lock()
        defer mu2.Unlock()

        fmt.Println("Горутина 1 завершила работу")
    }()

    go func() {
        mu1.Lock()
        defer mu1.Unlock()

        time.Sleep(100 * time.Millisecond)

        mu2.Lock()
        defer mu2.Unlock()

        fmt.Println("Горутина 2 завершила работу")
    }()

    time.Sleep(1 * time.Second)
    fmt.Println("Программа завершена")
}
```

Теперь обе горутины захватывают `mu1` перед `mu2`, и дедлок исключён.

---

### **2. Использование тайм-аутов**
- Используйте `select` с тайм-аутом для предотвращения бесконечного ожидания.

### **Пример:**
```go
func main() {
    var mu1, mu2 sync.Mutex

    go func() {
        mu1.Lock()
        defer mu1.Unlock()

        time.Sleep(100 * time.Millisecond)

        if !tryLockWithTimeout(&mu2, 100*time.Millisecond) {
            fmt.Println("Горутина 1: не удалось захватить mu2")
            return
        }
        defer mu2.Unlock()

        fmt.Println("Горутина 1 завершила работу")
    }()

    go func() {
        mu2.Lock()
        defer mu2.Unlock()

        time.Sleep(100 * time.Millisecond)

        if !tryLockWithTimeout(&mu1, 100*time.Millisecond) {
            fmt.Println("Горутина 2: не удалось захватить mu1")
            return
        }
        defer mu1.Unlock()

        fmt.Println("Горутина 2 завершила работу")
    }()

    time.Sleep(1 * time.Second)
    fmt.Println("Программа завершена")
}

func tryLockWithTimeout(mu *sync.Mutex, timeout time.Duration) bool {
    ch := make(chan struct{})
    go func() {
        mu.Lock()
        close(ch)
    }()

    select {
    case <-ch:
        return true
    case <-time.After(timeout):
        return false
    }
}
```

### **3. Использование `sync.RWMutex`**
- Если возможно, используйте `sync.RWMutex` вместо `sync.Mutex`, чтобы разрешить множественное чтение.

### **4. Уменьшение времени удержания блокировок**
- Минимизируйте время, в течение которого горутина удерживает блокировку. Это снижает вероятность дедлока.
