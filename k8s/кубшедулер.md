---

## 🧠 Что такое kube-scheduler

`kube-scheduler` — это **компонент, который выбирает, на каком worker-ноде запускать Pod**, если для него **ещё не определён узел**.

Он:

- **не запускает** Pod
    
- **не принимает** решения о содержимом Pod
    
- он только **выбирает наиболее подходящий узел** (`Node`), основываясь на:
    
    - ресурсах
        
    - ограничениях (`taints`, `affinity`, `topology`, и т.д.)
        
    - политике приоритета
        

👉 Фактически, это **планировщик задач**, только для кластеров.

---

## 📦 Где находится в архитектуре Kubernetes

```plaintext
+---------------------------+
| kube-apiserver           |
|   ↑                      |
|   | create pod (no node) |
|   ↓                      |
| kube-scheduler           |
|   ↓                      |
| select Node              |
|   ↓                      |
| PATCH pod.nodeName       |
|   ↓                      |
| kubelet на выбранной ноде|
+---------------------------+
```

Когда ты создаёшь Pod:

1. Он **попадает в API Server**
    
2. Его `spec.nodeName` **ещё не установлен**
    
3. `kube-scheduler` видит его и:
    
    - выбирает Node
        
    - **записывает** выбор обратно в Pod через API
        
4. На ноде `kubelet` видит "мне надо запустить Pod" → и запускает
    

---

## 🔎 Что учитывает kube-scheduler при выборе ноды

### ⚖️ Фильтры (Predicates) — отсекают неподходящие узлы

- CPU/Memory requests
    
- `nodeSelector`
    
- `affinity` / `anti-affinity`
    
- `taints` / `tolerations`
    
- volumes (`hostPath`, `emptyDir`, `PV`)
    
- topology spread
    

### 📈 Score (Priorities) — рейтингует оставшиеся

- LeastRequested (наименее нагруженный)
    
- BalancedResourceAllocation
    
- Topology-aware
    
- NodeAffinity
    
- Image locality (у кого уже есть нужный image)
    

📌 Все эти скоры комбинируются → выбирается лучшая нода

---

## 🧪 Пример на практике

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: heavy-job
spec:
  containers:
  - name: worker
    image: ubuntu
    resources:
      requests:
        memory: "8Gi"
        cpu: "4"
```

→ `kube-scheduler` не будет рассматривать ноды, где:

- нет 8ГБ RAM
    
- нет 4 CPU
    
- или где Pod не может быть размещён из-за `taint`
    

---

## 🔥 Какие бывают проблемы

|Проблема|Причина|
|---|---|
|Pod остаётся в `Pending`|Нет подходящих нод (res, taints, volume)|
|Распределение неравномерное|Отсутствует topology-aware scheduling|
|Поды размещаются "пачкой"|Не настроены `affinity/anti-affinity`|
|Один Pod вытесняет другие|Не настроены `priority` и `preemption`|

---

## 🎛️ kube-scheduler можно **расширять**

- Плагины через `Scheduler Framework`
    
- Свои scoring и filtering
    
- Использование `extenders`, чтобы подключить стороннюю логику (например, NUMA, GPU-awareness, storage-aware)
    

---

## 📦 kube-scheduler vs kubelet vs controller-manager

|Компонент|Задача|
|---|---|
|`kube-scheduler`|**Решает, где запускать Pod**|
|`kubelet`|**Запускает контейнер на ноде**, если ему его назначили|
|`kube-controller-manager`|Контролирует `ReplicaSet`, создает нужное кол-во Pod'ов и т.д.|

| Что это | Планировщик Pod'ов в Kubernetes |

| Что использует | Фильтры, скоры, приоритеты |  
| Как влияет | От распределения Pod'ов до отказоустойчивости |  
| Можно ли расширять| Да, плагины и кастомный scheduler |
