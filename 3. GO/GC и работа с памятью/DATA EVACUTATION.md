В Go **эвакуация данных** (data evacuation) — это процесс, связанный с работой сборщика мусора (Garbage Collector, GC). Этот термин описывает ситуацию, когда данные перемещаются из одной области памяти в другую, чтобы оптимизировать использование памяти и предотвратить утечки.

---

## **Что такое эвакуация данных**

Эвакуация данных происходит в следующих контекстах:

1. **Сборщик мусора (GC):**
    
    - Go использует **трёхцветный алгоритм** для управления памятью. Во время сборки мусора может потребоваться перемещение "живых" объектов (тех, которые всё ещё используются) из области памяти, помеченной для очистки, в другую область.
    - Это оптимизирует использование памяти и обеспечивает целостность данных.
2. **Увеличение размера среза или карты:**
    
    - Когда срез (`slice`) или карта (`map`) превышают свою вместимость, Go автоматически перемещает данные в новую область памяти с большей ёмкостью.

---

## **Когда применяется эвакуация данных**

### **1. Сборщик мусора**

- Если объект всё ещё используется (ссылается на него другая часть программы), но находится в области памяти, которая должна быть очищена, этот объект эвакуируется (копируется) в "живую" область.
- Эвакуация помогает избежать утечек памяти и упрощает управление объектами.

**Пример:**

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	runtime.GC() // Принудительный запуск сборщика мусора
	fmt.Println("Garbage collection triggered")
}
```

- После запуска GC объекты, которые всё ещё используются, могут быть перемещены в другую область памяти.

---

### **2. Расширение среза**

- Когда срез в Go увеличивается за пределы своей текущей ёмкости, создаётся новый массив большего размера, и данные из старого массива копируются в новый.

**Пример:**

```go
package main

import "fmt"

func main() {
	slice := make([]int, 3, 3)
	slice[0], slice[1], slice[2] = 1, 2, 3
	fmt.Printf("Before append: len=%d cap=%d\n", len(slice), cap(slice))

	// Увеличиваем срез за пределы его ёмкости
	slice = append(slice, 4)
	fmt.Printf("After append: len=%d cap=%d\n", len(slice), cap(slice))
}
```

**Результат:**

```
Before append: len=3 cap=3
After append: len=4 cap=6
```

- Ёмкость среза увеличилась с 3 до 6, и данные были эвакуированы в новый массив.

---

### **3. Увеличение карты (map)**

- Когда карта переполняется из-за большого количества ключей, создаётся новый внутренний хранилище, и все данные переносятся в новую область памяти.

**Пример:**

```go
package main

import "fmt"

func main() {
	m := make(map[int]string)
	for i := 0; i < 100; i++ {
		m[i] = fmt.Sprintf("Value %d", i)
	}
	fmt.Println("Map resized during insertion")
}
```

- При значительном увеличении количества элементов карта перераспределяет память, чтобы вместить новые данные.

---

## **Особенности эвакуации данных**

1. **Преимущества:**
    
    - Эффективное использование памяти.
    - Избежание утечек памяти.
    - Оптимизация производительности при работе с динамическими структурами (срезами, картами).
2. **Недостатки:**
    
    - **Затраты на копирование:** Эвакуация требует дополнительного времени для перемещения данных.
    - **Временные задержки:** Во время эвакуации может наблюдаться увеличение времени выполнения, особенно при частом перераспределении памяти.

---

## **Как минимизировать влияние эвакуации данных**

1. **Для срезов:**
    
    - Предварительно выделяйте память с запасом:
        
        ```go
        slice := make([]int, 0, 100) // Создаём срез с ёмкостью 100
        ```
        
2. **Для карт:**
    
    - Используйте начальную вместимость:
        
        ```go
        m := make(map[int]string, 100) // Карта с ёмкостью для 100 элементов
        ```
        
3. **Сборщик мусора:**
    
    - Оптимизируйте выделение и освобождение памяти, чтобы уменьшить нагрузку на GC.
    - Профилируйте приложение с помощью `pprof` для обнаружения узких мест.

---

## **Итог**

Эвакуация данных в Go — это естественная часть работы сборщика мусора и динамических структур данных, таких как срезы и карты. Она используется для оптимизации памяти, но требует понимания механизмов работы, чтобы избежать избыточных затрат на производительность. Правильное управление памятью и предварительное выделение ресурсов помогут минимизировать влияние эвакуации.
