В PostgreSQL блокировки данных (или **locking**) происходят с целью обеспечения согласованности данных и предотвращения конфликтов между несколькими параллельно выполняющимися транзакциями. Блокировки помогают предотвратить такие проблемы, как **потеря данных**, **грязное чтение** или **дублирование данных**.

Когда транзакции выполняют такие запросы, как `INSERT`, `UPDATE`, `DELETE` или даже `SELECT` (с определёнными условиями), PostgreSQL использует различные типы блокировок для управления доступом к данным. Рассмотрим, как именно блокируются данные в различных ситуациях:

### 1. **Типы блокировок в PostgreSQL**

PostgreSQL использует несколько типов блокировок, которые могут применяться к строкам или таблицам:

- **Row-Level Locks (Блокировки строк)**: Эти блокировки накладываются на отдельные строки данных, что позволяет параллельно изменять другие строки в той же таблице.
- **Table-Level Locks (Блокировки таблиц)**: Эти блокировки накладываются на всю таблицу, предотвращая изменение структуры или данных таблицы, пока блокировка активна.

Основные типы блокировок:

- **AccessShareLock**: Это самая лёгкая блокировка, которая используется для чтения данных (`SELECT`). Она не блокирует другие операции чтения и записи, но препятствует изменениям структуры таблицы (например, `ALTER TABLE`).
    
- **RowShareLock**: Этот тип блокировки используется в случае, если транзакция читает данные и хочет предотвратить их удаление или изменение другой транзакцией, например, при выполнении запроса с `FOR UPDATE`.
    
- **RowExclusiveLock**: Используется для операций, которые изменяют данные (например, `UPDATE`, `DELETE` или `INSERT`). Эти блокировки позволяют другим транзакциям читать или изменять другие строки, но не позволяют другим транзакциям изменять или удалять строки, которые заблокированы.
    
- **ShareLock**: Этот тип блокировки предотвращает другие транзакции от модификации данных, но позволяет читать их. Обычно используется в операциях, таких как `SELECT FOR SHARE`.
    
- **ExclusiveLock**: Применяется в случае операций, которые могут изменить таблицу или структуру данных, например, при выполнении `ALTER TABLE`, `TRUNCATE` или `DROP`.
    
- **AccessExclusiveLock**: Это самая жёсткая блокировка, которая используется для операций, изменяющих структуру таблицы, таких как `DROP TABLE`, `TRUNCATE` или `REINDEX`. Она блокирует всю таблицу для любых операций, включая чтение.
    

### 2. **Блокировки при различных типах запросов**

#### `INSERT`

Когда выполняется запрос `INSERT`, блокировка накладывается на строки, которые добавляются в таблицу. Однако, в случае, если вставляется несколько строк, блокировка может применяться к каждой строке индивидуально. Запросы `INSERT` обычно используют **RowExclusiveLock**, что позволяет вставлять данные, но не позволяет другим транзакциям модифицировать те же строки.

Пример:

```sql
BEGIN;
INSERT INTO users (name, age) VALUES ('Alice', 30); -- Блокировка строки
COMMIT;
```

#### `UPDATE`

Запросы `UPDATE` блокируют те строки, которые изменяются. Это позволяет другим транзакциям читать эти строки, но они не могут их изменить, пока текущая транзакция не завершится. В случае с `UPDATE` обычно используется **RowExclusiveLock**, которая блокирует только те строки, которые изменяются, но не мешает другим транзакциям читать или изменять другие строки.

Пример:

```sql
BEGIN;
UPDATE users SET age = 31 WHERE name = 'Alice'; -- Блокировка строки
COMMIT;
```

#### `DELETE`

Запросы `DELETE` также блокируют строки, которые должны быть удалены. Эти блокировки предотвращают другие транзакции от изменения или удаления тех же строк, но позволяют чтение данных.

Пример:

```sql
BEGIN;
DELETE FROM users WHERE name = 'Alice'; -- Блокировка строки
COMMIT;
```

#### `SELECT`

Операции `SELECT` в PostgreSQL могут использовать разные блокировки в зависимости от того, как они выполняются. В обычных случаях `SELECT` использует **AccessShareLock**, что позволяет другим транзакциям читать данные, но блокирует их изменение.

Однако при использовании `SELECT FOR UPDATE` или `SELECT FOR SHARE` будет использоваться более жёсткая блокировка, которая блокирует строки, чтобы предотвратить их изменение другими транзакциями.

Пример с блокировкой:

```sql
BEGIN;
SELECT * FROM users WHERE name = 'Alice' FOR UPDATE; -- Блокировка строки
COMMIT;
```

#### `TRUNCATE`

Запрос `TRUNCATE` — это операция, которая удаляет все строки из таблицы. Она использует **AccessExclusiveLock**, что блокирует таблицу для всех других операций, включая чтение.

Пример:

```sql
BEGIN;
TRUNCATE TABLE users; -- Блокировка таблицы
COMMIT;
```

### 3. **Конфликты и дедлоки**

В PostgreSQL могут возникать **дедлоки**, если несколько транзакций блокируют данные так, что каждая из них ждёт, пока другая завершит операцию. Например, если транзакция A блокирует строку 1 и ждёт строку 2, а транзакция B блокирует строку 2 и ждёт строку 1, то это приводит к дедлоку.

PostgreSQL использует механизм обнаружения дедлоков, который автоматически отменяет одну из транзакций, чтобы разрешить конфликт.

### 4. **Уровни изоляции транзакций и блокировки**

PostgreSQL поддерживает несколько уровней изоляции транзакций, которые влияют на то, какие блокировки будут использоваться:

- **Read Uncommitted**: Этот уровень изоляции позволяет транзакциям читать незафиксированные данные. Он может привести к **грязным чтениям**.
    
- **Read Committed**: Это стандартный уровень, при котором транзакция видит только те данные, которые были зафиксированы другими транзакциями до начала чтения.
    
- **Repeatable Read**: Этот уровень изоляции предотвращает **фантомные чтения**, обеспечивая, что данные, прочитанные транзакцией, не изменятся до её завершения.
    
- **Serializable**: Наивысший уровень изоляции, который блокирует данные так, чтобы транзакции выполнялись последовательно, как если бы они были выполнены по очереди.
    

### Заключение

В PostgreSQL блокировки играют ключевую роль в обеспечении согласованности данных и предотвращении конфликтов между транзакциями. Разные типы запросов используют различные виды блокировок, чтобы эффективно управлять доступом к данным. Точное понимание того, как работают блокировки в PostgreSQL, поможет избегать проблем с производительностью и дедлоками.

## 📘 Блокировки в PostgreSQL

Разделим их на:

### 1. **Табличные блокировки** — _explicit & implicit locks_

Эти блокировки захватываются:

- при выполнении DDL (`ALTER`, `DROP`, `TRUNCATE`)
    
- при выполнении DML (`SELECT ... FOR UPDATE`)
    
- вручную (`LOCK TABLE ... IN ... MODE`)
    

Вот **основные типы табличных блокировок**, от самой "лёгкой" до самой "тяжёлой":

| Тип блокировки           | Описание                                                                       |
| ------------------------ | ------------------------------------------------------------------------------ |
| `ACCESS SHARE`           | Когда читаем таблицу (`SELECT`). Совместима со всеми, кроме `ACCESS EXCLUSIVE` |
| `ROW SHARE`              | При `SELECT ... FOR UPDATE` или `FOR SHARE` — лёгкий DML                       |
| `ROW EXCLUSIVE`          | При `INSERT`, `UPDATE`, `DELETE`, `SELECT FOR UPDATE`                          |
| `SHARE UPDATE EXCLUSIVE` | Для операций, не меняющих структуру, но блокирующих некоторые DDL              |
| `SHARE`                  | Разрешает параллельное чтение, запрещает DML                                   |
| `SHARE ROW EXCLUSIVE`    | Редкий гость: смесь `SHARE` и `ROW EXCLUSIVE`                                  |
| `EXCLUSIVE`              | Почти как `ACCESS EXCLUSIVE`, но разрешает читать                              |
| `ACCESS EXCLUSIVE`       | Самая строгая: всё блочит. Например, `ALTER TABLE`, `DROP TABLE`, `TRUNCATE`   |

## 2. **Строчные блокировки** (tuple-level locks)

Когда ты используешь:

- `SELECT ... FOR UPDATE` → **exclusive row lock**
    
- `SELECT ... FOR SHARE` → **shared row lock**
    
- `UPDATE`, `DELETE` — **автоматически захватывают row exclusive**
    

Они не видны напрямую, но можно смотреть в `pg_locks`.

---

## 🧠 Как взаимодействуют?

- Табличные блокировки **влияют на DDL/DML в других сессиях**.
    
- Строчные блокировки **влияют на конкурентные запросы к одним и тем же строкам**.
    
- Табличные и строчные блокировки **живут вместе** — сначала таблицу, потом строку.
    

---

## 🔍 Пример 1: SELECT + ALTER

```sql
-- Сессия 1
BEGIN;
SELECT * FROM users;

-- Сессия 2
ALTER TABLE users ADD COLUMN is_active BOOLEAN;
-- ❗ будет ждать, потому что SELECT держит ACCESS SHARE, а ALTER требует ACCESS EXCLUSIVE
```

---

## 🔍 Пример 2: UPDATE + FOR UPDATE

```sql
-- Сессия 1
BEGIN;
SELECT * FROM users WHERE id = 1 FOR UPDATE;

-- Сессия 2
BEGIN;
UPDATE users SET name = 'New' WHERE id = 1;
-- ❗ будет ждать, потому что строка уже заблокирована FOR UPDATE
```

## 👁 Как смотреть блокировки?

```sql
SELECT * FROM pg_locks l
JOIN pg_stat_activity a ON l.pid = a.pid
WHERE NOT granted;
```
