
Вот переписанный код на Go:

```go
package main

import "fmt"

// WorkerPool представляет пул рабочих.
type WorkerPool struct {
	workersNumber int
	taskChannel   chan func() // Канал для передачи задач.
	stopChannel   chan bool   // Канал для остановки пула.
}

// NewWorkerPool создает новый пул рабочих с указанным количеством работников.
func NewWorkerPool(workersNumber int) *WorkerPool {
	return &WorkerPool{
		workersNumber: workersNumber,
		taskChannel:   make(chan func()),
		stopChannel:   make(chan bool),
	}
}

// run запускает указанный пул рабочих и управляет их жизненными циклами.
func (wp *WorkerPool) run() {
	for i := 0; i < wp.workersNumber; i++ {
		go func(workerID int) {
			for {
				select {
				case task := <-wp.taskChannel: // Получаем задачу
					task() // Выполняем задачу
				case <-wp.stopChannel: // Если поступил сигнал на остановку
					fmt.Printf("Worker %d stopped\n", workerID)
					return
				}
			}
		}(i)
	}
}

// AddTask добавляет новую задачу в пул для выполнения.
func (wp *WorkerPool) AddTask(task func()) error {
	select {
	case wp.taskChannel <- task:
		return nil
	default:
		return fmt.Errorf("task channel is full")
	}
}

// Shutdown инициирует корректное завершение работы пула рабочих.
func (wp *WorkerPool) Shutdown() {
	close(wp.stopChannel) // Закрываем канал для остановки рабочих
}

func main() {
	// Пример использования WorkerPool
	pool := NewWorkerPool(3) // Создаем пул с 3 рабочими
	pool.run()               // Запускаем пул рабочих

	// Добавляем задачи
	for i := 0; i < 5; i++ {
		task := func() {
			fmt.Println("Task executed!")
		}
		pool.AddTask(task)
	}

	// Останавливаем пул рабочих
	pool.Shutdown()
}
```

### Объяснение:

1. **Тип `WorkerPool`**:
    
    - Он содержит количество рабочих (`workersNumber`), канал для передачи задач (`taskChannel`) и канал для остановки пула (`stopChannel`).
2. **Функция `NewWorkerPool`**:
    
    - Создаёт новый пул рабочих, инициируя каналы для задач и остановки.
3. **Метод `run`**:
    
    - Создаёт рабочие горутины, которые будут ожидать задачи на выполнение через канал. Когда задачи добавляются в канал, горутины начинают их выполнять. Если приходит сигнал на остановку через `stopChannel`, рабочий завершается.
4. **Метод `AddTask`**:
    
    - Добавляет задачу в канал. Если канал полон (например, если все рабочие заняты), возвращается ошибка.
5. **Метод `Shutdown`**:
    
    - Останавливает пул рабочих, закрывая канал `stopChannel`, что приводит к завершению работы всех горутин.

### Как это работает:

- Пример в `main` создаёт пул из 3 рабочих, добавляет 5 задач, и затем останавливает пул.

Этот код реализует концепцию пула рабочих с использованием каналов и горутин для многозадачности.

Для того чтобы одновременно разблокировать выполнение всех трёх горутин в Go, можно использовать механизм синхронизации с использованием **`sync.WaitGroup`** или **`sync.Once`**. В этом случае можно использовать канал или мьютекс, чтобы гарантировать синхронный запуск.

### Решение с использованием канала:

Мы можем использовать канал для того, чтобы все горутины начали выполнение после того, как будет вызвана функция `steady()`.

```go
package main  
  
import (  
    "fmt"  
    "sync")  
  
func main() {  
    wg := sync.WaitGroup{}  
    wg.Add(3)  
  
    runnerStart(&wg)  
    wg.Wait()  
}  
  
func runnerStart(wg *sync.WaitGroup) {  
    start := make(chan struct{})  
  
    // Запускаем горутины  
    go ready(start, wg)  
    go ready(start, wg)  
    go ready(start, wg)  
  
    // Вызываем steady, чтобы одновременно разблокировать все горутины  
    steady(start)  
}  
  
func steady(start chan struct{}) {  
    // Разблокируем все горутины  
    close(start)  
}  
  
func ready(start chan struct{}, wg *sync.WaitGroup) {  
    defer wg.Done()  
    run()  
    <-start  
}  
  
func run() {  
    fmt.Println("Running...")  
}
```

### Объяснение:

1. **Канал `start`**: Мы создаём канал `start`, который будет использоваться для синхронизации. Когда канал закрывается, все горутины, которые на него подписаны (ожидают получение данных), могут продолжить выполнение.
2. **Горутины**: Когда вызывается `ready`, она ожидает, пока канал `start` не будет закрыт. Это предотвращает их немедленный запуск.
3. **Функция `steady`**: Когда вызывается `steady`, она закрывает канал, и все горутины, которые ожидают на этом канале, начинают выполнять функцию `run()` одновременно.

### Результат:

Все три горутины начнут выполнение одновременно после того, как будет вызвана функция `steady()`, благодаря синхронизации через канал.

### Альтернатива с использованием `sync.WaitGroup`:

Если нужно обеспечить точную синхронизацию с учётом ожидания всех горутин, можно использовать `sync.WaitGroup`.

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	runnerStart()
}

func runnerStart() {
	var wg sync.WaitGroup

	// Запускаем горутины
	wg.Add(3)
	go ready(&wg)
	go ready(&wg)
	go ready(&wg)

	// Вызываем steady, чтобы одновременно разблокировать все горутины
	steady(&wg)
}

func steady(wg *sync.WaitGroup) {
	// Разблокируем все горутины
	wg.Wait()
}

func ready(wg *sync.WaitGroup) {
	// Отметим, что горутина завершена
	defer wg.Done()
	run()
}

func run() {
	fmt.Println("Running...")
}
```

Для того чтобы выполнить задачу асинхронно с ограничением на количество одновременных запросов, можно использовать `sync.WaitGroup` для ожидания завершения горутин и канал для контроля параллельности. Мы ограничим количество горутин, выполняющихся одновременно, с помощью канала с буфером.

Вот пример, как это можно реализовать:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	// Make this code asynchronous with controlled parallel request numbers
	// Ограничиваем количество одновременных запросов
	limit := 5
	semaphore := make(chan struct{}, limit) // Канал с ограниченным буфером

	var wg sync.WaitGroup

	for _, val := range getData() {
		wg.Add(1)

		// Запускаем асинхронно, но с ограничением по количеству горутин
		go func(val string) {
			defer wg.Done()
			semaphore <- struct{}{} // Захватываем место в канале, блокируем горутину, если лимит превышен

			// Асинхронная задача
			if !checkDomain(val) {
				fmt.Printf("%s is bad\n", val)
			}

			<-semaphore // Освобождаем место в канале, что позволяет другим горутинам выполняться
		}(val)
	}

	// Ожидаем завершения всех горутин
	wg.Wait()
}

func getData() []string {
	return []string{"1.test", "2.test", "3.test", "4.test", "5.test", "6.test", "7.test", "8.test", "9.test", "10.test"}
}

func checkDomain(host string) bool {
	// Симуляция проверки домена
	return true
}
```

### Объяснение:

1. **Канал `semaphore`**:
    
    - Канал с буфером используется для ограничения количества одновременно выполняющихся горутин. В данном примере канал имеет размер `limit` (например, 5), что ограничивает количество параллельных запросов.
2. **`sync.WaitGroup`**:
    
    - `sync.WaitGroup` используется для того, чтобы основной поток дождался завершения всех асинхронных горутин. Мы увеличиваем счетчик на 1 перед запуском каждой горутины и уменьшаем его в `defer wg.Done()`.
3. **`semaphore <- struct{}{}`**:
    
    - Когда горутина запускается, она пытается захватить "место" в канале. Если канал переполнен (то есть максимальное количество одновременных горутин достигнуто), горутина блокируется до тех пор, пока не появится место в канале.
4. **`<-semaphore`**:
    
    - После завершения работы горутины, она освобождает место в канале, позволяя другим горутинам быть выполненными.

### Результат:

- Код выполняется асинхронно, но не более 5 горутин могут работать одновременно. Когда лимит горутин исчерпан, новая горутина будет ждать, пока не освободится место в канале.

Для решения вашей задачи разделим её на две части:

1. **Задача по слиянию двух отсортированных массивов**.
2. **Асинхронное выполнение с ограничением на количество параллельных запросов**.

### 1. Слияние двух отсортированных массивов

Мы можем объединить два отсортированных массива в один отсортированный массив, используя два указателя, которые будут двигаться по обоим массивам. Это классический подход, который используется в алгоритме слияния.

```go
package main

import "fmt"

// Функция для слияния двух отсортированных массивов
func mergeSorted(a []int, b []int) []int {
	merged := []int{}
	i, j := 0, 0

	// Пока есть элементы в обоих массивах
	for i < len(a) && j < len(b) {
		if a[i] < b[j] {
			merged = append(merged, a[i])
			i++
		} else {
			merged = append(merged, b[j])
			j++
		}
	}

	// Добавляем оставшиеся элементы из массива a
	for i < len(a) {
		merged = append(merged, a[i])
		i++
	}

	// Добавляем оставшиеся элементы из массива b
	for j < len(b) {
		merged = append(merged, b[j])
		j++
	}

	return merged
}

func main() {
	// a, b - отсортированные срезы
	var a = []int{1, 5, 6, 18, 99}
	var b = []int{2, 4, 9, 11}

	// Выводим объединённый отсортированный массив
	fmt.Println(mergeSorted(a, b))
}
```

**Результат**:

```
[1 2 4 5 6 9 11 18 99]
```

### 2. Асинхронные запросы с ограничением на количество параллельных горутин

Теперь мы добавим логику для выполнения асинхронных запросов с ограничением на количество параллельных горутин. Это можно сделать с помощью канала (для ограничения количества горутин) и `sync.WaitGroup` (для ожидания завершения всех горутин).

Вот как это можно реализовать:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	// Задано ограничение на количество параллельных горутин
	limit := 5
	semaphore := make(chan struct{}, limit) // Канал с буфером для ограничения

	var wg sync.WaitGroup

	// Обрабатываем данные асинхронно
	for _, val := range getData() {
		wg.Add(1)

		// Запускаем горутину с ограничением параллельных задач
		go func(val string) {
			defer wg.Done()

			// Ограничиваем количество одновременных горутин
			semaphore <- struct{}{} // Захватываем место в канале

			// Асинхронная проверка
			if !checkDomain(val) {
				fmt.Printf("%s is bad\n", val)
			}

			// Освобождаем место в канале
			<-semaphore
		}(val)
	}

	// Ожидаем завершения всех горутин
	wg.Wait()
}

// Функция для получения данных
func getData() []string {
	return []string{"1.test", "2.test", "3.test", "4.test", "5.test", "6.test", "7.test", "8.test", "9.test", "10.test"}
}

// Функция для проверки домена
func checkDomain(host string) bool {
	// Симуляция проверки домена
	return true
}
```

### Объяснение:

1. **Канал `semaphore`**:
    
    - Канал с ограниченным буфером (`limit`) используется для того, чтобы ограничить количество одновременных горутин. Например, если мы установим `limit := 5`, то в любое время не более 5 горутин смогут работать одновременно.
2. **`sync.WaitGroup`**:
    
    - `sync.WaitGroup` используется для того, чтобы главный поток ожидал завершения всех горутин. Мы увеличиваем счётчик перед запуском каждой горутины и уменьшаем его в `defer wg.Done()`.
3. **Горутины**:
    
    - Для каждой задачи создаём горутину, которая будет обрабатывать проверку домена.
    - Горутина будет ждать, если лимит по количеству горутин будет достигнут, благодаря каналу `semaphore`.
4. **Ожидание завершения**:
    
    - `wg.Wait()` ждёт завершения всех горутин перед тем, как программа продолжит выполнение.

### Результат:

В результате эта программа будет обрабатывать запросы асинхронно, но не более чем 5 горутин одновременно, и печатать "is bad" для каждого домена, который не прошёл проверку.
