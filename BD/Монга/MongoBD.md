## **Что такое MongoDB?**

MongoDB — это **NoSQL документо-ориентированная база данных**, которая хранит данные в формате, похожем на JSON (BSON — Binary JSON). Она предназначена для работы с большими объёмами неструктурированных или слабоструктурированных данных и обеспечивает высокую производительность, горизонтальную масштабируемость и гибкость.

---

## **Ключевые особенности MongoDB**

1. **Документно-ориентированная**:
   - Данные хранятся в виде документов (BSON), которые похожи на JSON.
   - Пример документа:
     ```json
     {
       "_id": ObjectId("507f1f77bcf86cd799439011"),
       "name": "Alice",
       "age": 25,
       "address": {
         "city": "New York",
         "zip": "10001"
       },
       "hobbies": ["reading", "traveling"]
     }
     ```

2. **Гибкая схема**:
   - Документы в одной коллекции могут иметь разную структуру.
   - Это позволяет легко изменять структуру данных без необходимости миграций.

3. **Горизонтальная масштабируемость**:
   - MongoDB поддерживает шардирование (sharding), что позволяет распределять данные на несколько серверов.

4. **Высокая производительность**:
   - Встроенная поддержка индексов, агрегаций и вложенных документов.

5. **Репликация**:
   - Поддержка репликации для обеспечения отказоустойчивости и высокой доступности.

---

## **Архитектура MongoDB**

### **Основные компоненты:**
1. **Документ (Document)**:
   - Основная единица хранения данных (аналог строки в реляционных базах).
   - Пример:
     ```json
     {
       "name": "Bob",
       "age": 30
     }
     ```

2. **Коллекция (Collection)**:
   - Группа документов (аналог таблицы в реляционных базах).
   - Пример: коллекция `users`.

3. **База данных (Database)**:
   - Контейнер для коллекций.
   - Пример: база данных `myapp`.

4. **Кластер (Cluster)**:
   - Группа серверов, которые хранят данные.
   - Включает шарды (shards) и реплики (replicas).

---

## **Преимущества MongoDB**

1. **Гибкость**:
   - Подходит для данных с изменяющейся структурой.

2. **Масштабируемость**:
   - Легко масштабируется горизонтально с помощью шардирования.

3. **Высокая производительность**:
   - Поддержка индексов и агрегаций.

4. **Отказоустойчивость**:
   - Репликация обеспечивает высокую доступность.

5. **Простота разработки**:
   - JSON-подобный формат данных удобен для разработчиков.

---

## **Недостатки MongoDB**

1. **Нет поддержки JOIN**:
   - В MongoDB нет встроенной поддержки JOIN, как в реляционных базах.

2. **Ограниченная поддержка транзакций**:
   - Транзакции поддерживаются только в версиях 4.0 и выше.

3. **Высокие требования к памяти**:
   - MongoDB активно использует оперативную память для кэширования данных.

4. **Сложность администрирования**:
   - Настройка шардирования и репликации требует опыта.

## **Основные команды MongoDB**

### **Создание базы данных**
```javascript
use mydb;  // Создаёт или переключается на базу данных mydb
```

### **Создание коллекции**
```javascript
db.createCollection("users");  // Создаёт коллекцию users
```

### **Вставка документа**
```javascript
db.users.insertOne({
  name: "Alice",
  age: 25,
  city: "New York"
});
```

### **Поиск документов**
```javascript
db.users.find({ age: { $gt: 20 } });  // Найти пользователей старше 20 лет
```

### **Обновление документа**
```javascript
db.users.updateOne(
  { name: "Alice" },
  { $set: { age: 26 } }
);  // Обновить возраст Alice
```

### **Удаление документа**
```javascript
db.users.deleteOne({ name: "Alice" });  // Удалить пользователя Alice
```

### **Создание индекса**
```javascript
db.users.createIndex({ name: 1 });  // Создать индекс по полю name
```

## **Агрегации в MongoDB**

Агрегации позволяют выполнять сложные операции с данными, такие как группировка, фильтрация, сортировка.

### **Пример агрегации:**
```javascript
db.orders.aggregate([
  { $match: { status: "completed" } },  // Фильтрация
  { $group: { _id: "$customer", total: { $sum: "$amount" } } },  // Группировка
  { $sort: { total: -1 } }  // Сортировка
]);
```

## **Шардирование и репликация**

### **Шардирование (Sharding)**:
- Разделение данных на несколько серверов (шардов) для горизонтального масштабирования.
- Пример:
  ```javascript
  sh.enableSharding("mydb");  // Включить шардирование для базы данных mydb
  sh.shardCollection("mydb.users", { _id: "hashed" });  // Шардировать коллекцию users
  ```

### **Репликация (Replication)**:
- Создание копий данных на нескольких серверах для отказоустойчивости.
- Пример:
  ```javascript
  rs.initiate();  // Инициализация репликации
  rs.add("replica1:27017");  // Добавление реплики
  ```

## **Часто задаваемые вопросы на собеседовании**

1. **Что такое MongoDB?**
   - Это документо-ориентированная NoSQL база данных, которая хранит данные в формате BSON.

2. **Какие преимущества у MongoDB?**
   - Гибкость, масштабируемость, высокая производительность, отказоустойчивость.

3. **Какие недостатки у MongoDB?**
   - Нет поддержки JOIN, ограниченная поддержка транзакций, высокие требования к памяти.

4. **Как работает шардирование в MongoDB?**
   - Данные разделяются на несколько серверов (шардов) для горизонтального масштабирования.

5. **Как работает репликация в MongoDB?**
   - Данные копируются на несколько серверов для обеспечения отказоустойчивости.

6. **Как выполнить агрегацию в MongoDB?**
   - С помощью метода `aggregate`, который поддерживает операции фильтрации, группировки, сортировки и другие.

7. **Как создать индекс в MongoDB?**
   - С помощью метода `createIndex`.

8. **Какие типы индексов поддерживает MongoDB?**
   - Одноуровневые, составные, уникальные, текстовые, геопространственные и другие.

## **Пример задачи с MongoDB**

### **Задача: Анализ данных о продажах**
- Есть коллекция `orders` с документами:
  ```json
  {
    "order_id": 1,
    "customer": "Alice",
    "amount": 100,
    "status": "completed"
  }
  ```
- Нужно найти общую сумму заказов для каждого клиента.

### **Решение:**
```javascript
db.orders.aggregate([
  { $match: { status: "completed" } },  // Фильтрация по статусу
  { $group: { _id: "$customer", total: { $sum: "$amount" } } },  // Группировка по клиенту
  { $sort: { total: -1 } }  // Сортировка по убыванию суммы
]);
```
