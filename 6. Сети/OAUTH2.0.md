
**OAuth 2.0** — это протокол авторизации, который позволяет предоставлять доступ к ресурсам на сервере без необходимости делиться своим паролем. Вместо этого OAuth 2.0 позволяет сторонним приложениям получать **ограниченный доступ** к защищённым ресурсам, используя токены доступа.

### Основные компоненты OAuth 2.0

OAuth 2.0 использует несколько ключевых компонентов для работы:

1. **Ресурсный сервер** (Resource Server) — сервер, который хранит защищённые ресурсы (например, данные пользователя).
2. **Сервер авторизации** (Authorization Server) — сервер, который выдает **токены доступа** и обрабатывает процесс аутентификации и авторизации.
3. **Клиент** (Client) — стороннее приложение или сервис, который запрашивает доступ к защищённым ресурсам на сервере.
4. **Пользователь** (Resource Owner) — субъект, который имеет доступ к защищённым ресурсам и может разрешить или отклонить доступ к ним сторонним приложениям.

### 4 Основных потока OAuth 2.0

OAuth 2.0 предлагает несколько **гранулярных потоков авторизации**, каждый из которых подходит для разных случаев использования. Рассмотрим основные потоки:

#### 1. **Authorization Code Flow (Авторизационный код)**

Используется для серверных приложений, когда необходимо обеспечить высокий уровень безопасности.

- **Процесс**:
    
    1. Клиент перенаправляет пользователя на сервер авторизации.
    2. Пользователь аутентифицируется на сервере авторизации и разрешает доступ к своим данным.
    3. Сервер авторизации перенаправляет пользователя обратно в приложение с **авторизационным кодом**.
    4. Приложение использует этот код, чтобы запросить **токен доступа** на сервере авторизации.
    
    **Преимущество**: Используется для серверных приложений, где код может быть безопасно передан с использованием защищённых каналов (например, HTTPS).

#### 2. **Implicit Flow (Неявный поток)**

Используется для одностраничных приложений (SPA), когда нельзя безопасно хранить секреты клиента.

- **Процесс**:
    
    1. Клиент перенаправляет пользователя на сервер авторизации.
    2. Пользователь аутентифицируется и разрешает доступ.
    3. Вместо авторизационного кода сервер авторизации немедленно возвращает **токен доступа** через URL.
    
    **Преимущество**: Простота для приложений, где нет возможности безопасно хранить клиентские секреты.
    

#### 3. **Resource Owner Password Credentials Flow (Поток учетных данных владельца ресурса)**

Используется для приложений, которым доверяют пользователи, например, в мобильных приложениях.

- **Процесс**:
    
    1. Пользователь предоставляет своё имя пользователя и пароль напрямую клиенту.
    2. Клиент использует эти данные для получения **токена доступа** у сервера авторизации.
    
    **Преимущество**: Удобен для доверенных приложений, где пользователь готов передавать свои учетные данные.
    

#### 4. **Client Credentials Flow (Поток учетных данных клиента)**

Используется для получения доступа к ресурсам **от имени самого приложения**, а не от имени пользователя (например, для сервисных аккаунтов).

- **Процесс**:
    
    1. Приложение отправляет свой **клиентский идентификатор** и **секрет** на сервер авторизации.
    2. В ответ приложение получает **токен доступа**.
    
    **Преимущество**: Используется для сценариев, когда клиентский сервис или приложение должно получить доступ к защищённым ресурсам без взаимодействия с пользователем.
    

### Токены в OAuth 2.0

#### 1. **Токен доступа (Access Token)**

Токен, который предоставляет приложению доступ к защищённым ресурсам. Он передается в заголовке HTTP-запроса, обычно как `Authorization: Bearer <token>`.

#### 2. **Токен обновления (Refresh Token)**

Токен, который используется для получения нового токена доступа, если старый срок годности истёк. Токен обновления используется только с сервером авторизации и не передаётся при обращении к ресурсному серверу.

### Пример потока OAuth 2.0 (Authorization Code Flow)

1. **Клиент направляет пользователя к серверу авторизации**:
    
    ```http
    GET /authorize?response_type=code&client_id=CLIENT_ID&redirect_uri=REDIRECT_URI&scope=read_profile
    ```
    
2. **Пользователь аутентифицируется и подтверждает разрешение**:
    
    - После успешного входа сервер авторизации перенаправляет пользователя обратно в приложение с авторизационным кодом:
    
    ```http
    GET /redirect_uri?code=AUTHORIZATION_CODE
    ```
    
3. **Клиент обменивает авторизационный код на токен доступа**:
    
    ```http
    POST /token
    Host: authorization-server.com
    Content-Type: application/x-www-form-urlencoded
    
    client_id=CLIENT_ID
    &client_secret=CLIENT_SECRET
    &code=AUTHORIZATION_CODE
    &redirect_uri=REDIRECT_URI
    ```
    
    Ответ:
    
    ```json
    {
        "access_token": "ACCESS_TOKEN",
        "refresh_token": "REFRESH_TOKEN",
        "expires_in": 3600
    }
    ```
    
4. **Клиент использует токен доступа для доступа к защищённым ресурсам**:
    
    ```http
    GET /protected-resource
    Host: resource-server.com
    Authorization: Bearer ACCESS_TOKEN
    ```
    

### Преимущества OAuth 2.0

- **Безопасность**: Позволяет предоставить доступ к данным без передачи паролей третьим сторонам.
- **Гибкость**: Поддержка различных потоков авторизации для различных типов приложений (веб-приложения, мобильные, серверные).
- **Широкая поддержка**: Поддерживается множеством сервисов и API (Google, Facebook, GitHub и другие).

### Заключение

OAuth 2.0 — это мощный и гибкий протокол для авторизации, который позволяет безопасно передавать доступ к защищённым ресурсам без необходимости делиться паролями. Он используется во многих сервисах для интеграции с другими приложениями, чтобы дать им доступ к данным пользователей без риска компрометации учетных данных.
