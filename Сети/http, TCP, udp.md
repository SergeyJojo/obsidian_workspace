# **Сетевой уровень: HTTP, UDP, TCP**

---

## **1. Основы сетевых протоколов**

---

Сетевые протоколы — это стандарты, которые определяют, как данные передаются по сети.

- **TCP/IP Стек** (модель):
    1. **Прикладной уровень (Application)**: HTTP, FTP, DNS, SMTP.
    2. **Транспортный уровень (Transport)**: TCP, UDP.
    3. **Сетевой уровень (Network)**: IP.
    4. **Канальный уровень (Data Link)**: Ethernet, Wi-Fi.

---

## **2. TCP (Transmission Control Protocol)**

TCP — это **надёжный, ориентированный на соединение протокол**. Он гарантирует, что данные доставлены полностью и в правильном порядке.

---

### **2.1. Как работает TCP**

#### **Соединение (3-way handshake)**:

1. **SYN**: Клиент отправляет серверу запрос на соединение.
2. **SYN-ACK**: Сервер подтверждает запрос.
3. **ACK**: Клиент подтверждает получение.

После этого устанавливается соединение.

#### **Передача данных**:

1. Данные разбиваются на сегменты.
    
2. Каждый сегмент имеет:
    
    - **Номер последовательности** (Sequence Number).
    - **Номер подтверждения** (Acknowledgment Number).
3. Если сегмент теряется, TCP перезапрашивает его (механизм повторной передачи).
    

#### **Закрытие соединения (4-way handshake)**:

1. Клиент отправляет **FIN**.
2. Сервер подтверждает **ACK**.
3. Сервер отправляет свой **FIN**.
4. Клиент подтверждает **ACK**.

---

### **2.2. Особенности TCP**

1. **Гарантия доставки**:
    
    - Данные доставляются полностью или не доставляются вообще.
2. **Контроль потока**:
    
    - Используется окно скольжения (Sliding Window), чтобы предотвратить перегрузку.
3. **Управление перегрузкой**:
    
    - TCP автоматически уменьшает скорость передачи, если сеть перегружена.

---

### **2.3. Преимущества TCP**

- Надёжность.
- Защита от потерь данных.
- Упорядоченность данных.

---

### **2.4. Недостатки TCP**

- Высокая задержка из-за установки соединения и подтверждений.
- Низкая производительность при больших задержках в сети (high-latency network).

---

### **2.5. Когда использовать TCP**

- Веб-приложения (HTTP/HTTPS).
- Файловые передачи (FTP).
- Почтовые службы (SMTP, IMAP).

---

## **3. UDP (User Datagram Protocol)**

UDP — это **ненадёжный, без соединения протокол**, который отправляет данные без проверки их доставки.

---

### **3.1. Как работает UDP**

1. Данные (датаграммы) отправляются напрямую без установки соединения.
2. Сервер не подтверждает приём данных.
3. Потери данных или их повторная передача не контролируются.

---

### **3.2. Особенности UDP**

1. **Лёгкость**:
    - Не тратится время на установку соединения.
2. **Нет гарантий**:
    - Нет проверки доставки.
3. **Нет упорядоченности**:
    - Данные могут приходить в любом порядке.

---

### **3.3. Преимущества UDP**

- Очень быстро.
- Минимальные накладные расходы.
- Подходит для real-time приложений.

---

### **3.4. Недостатки UDP**

- Отсутствие гарантии доставки.
- Нет защиты от дублирования или потерь.

---

### **3.5. Когда использовать UDP**

- Видеоконференции и стриминг (YouTube, Zoom).
- Онлайн-игры.
- DNS-запросы.

---

## **4. HTTP (Hypertext Transfer Protocol)**

HTTP работает на **прикладном уровне** и использует **TCP** для передачи данных.

---

### **4.1. Как работает HTTP**

#### **Клиент-серверная модель**:

1. Клиент (например, браузер) отправляет **HTTP-запрос**.
2. Сервер обрабатывает запрос и возвращает **HTTP-ответ**.

---

#### **Методы HTTP-запросов**

1. **GET**: Получение данных.
2. **POST**: Отправка данных на сервер.
3. **PUT**: Обновление данных.
4. **DELETE**: Удаление данных.

---

### **4.2. Эволюция HTTP**

#### **HTTP/1.1**:

- Поддержка keep-alive соединений.
- Передача данных последовательными запросами.

#### **HTTP/2**:

- Мультиплексирование: несколько запросов обрабатываются параллельно.
- Сжатие заголовков (HPACK).

#### **HTTP/3**:

- Использует **QUIC** (основан на UDP).
- Уменьшает задержки.
- Улучшает производительность в сетях с высоким RTT.

---

### **4.3. Преимущества HTTP**

- Простота использования.
- Огромная экосистема (веб-браузеры, REST API).

---

### **4.4. Недостатки HTTP**

- Большая задержка в HTTP/1.1 из-за последовательных запросов.
- Проблемы безопасности (без HTTPS).

---

### **4.5. Когда использовать HTTP**

- Веб-приложения.
- RESTful API.
- Обмен данными между микросервисами.

---

## **5. Сравнение TCP, UDP и HTTP**

|**Характеристика**|**TCP**|**UDP**|**HTTP (поверх TCP)**|
|---|---|---|---|
|Надёжность|Высокая|Низкая|Высокая|
|Производительность|Средняя|Высокая|Средняя|
|Гарантия доставки|Да|Нет|Да|
|Упорядоченность|Да|Нет|Да|
|Примеры использования|HTTP, FTP, SMTP|Стриминг, DNS, онлайн-игры|Веб-приложения, REST API|

## **6. Реальные кейсы использования**

---

### **6.1. Кейсы TCP**

#### **Кейс 1: Онлайн-магазин**

- Протокол: **TCP**.
- Причина: Гарантия доставки заказа (например, через HTTP/HTTPS).

---

#### **Кейс 2: Банковское приложение**

- Протокол: **TCP**.
- Причина: Конфиденциальность данных (TLS поверх TCP).

---

### **6.2. Кейсы UDP**

#### **Кейс 1: Видеоконференции**

- Протокол: **UDP**.
- Причина: Высокая скорость важнее, чем потеря отдельных пакетов.

---

#### **Кейс 2: Онлайн-игры**

- Протокол: **UDP**.
- Причина: Минимизация задержек важнее, чем полная доставка данных.

---

### **6.3. Кейсы HTTP**

#### **Кейс 1: REST API**

- Протокол: **HTTP поверх TCP**.
- Причина: Простота и предсказуемость взаимодействия.

#### **Кейс 2: Микросервисы**

- Протокол: **HTTP/2 или gRPC**.
- Причина: Мультиплексирование и уменьшение задержек.

## **1. Продвинутая работа с TCP**

---

### **1.1. Тюнинг TCP для высоконагруженных систем**

#### **1.1.1. Увеличение производительности соединений**

1. **Настройка TCP Keepalive**:
    
    - Уменьшение времени ожидания мёртвых соединений:
        
        ```bash
        sysctl -w net.ipv4.tcp_keepalive_time=120
        sysctl -w net.ipv4.tcp_keepalive_intvl=30
        sysctl -w net.ipv4.tcp_keepalive_probes=5
        ```
        
2. **Увеличение количества одновременных соединений**:
    
    - Увеличьте лимиты портов:
        
        ```bash
        sysctl -w net.ipv4.ip_local_port_range="1024 65535"
        ```
        
    - Увеличьте максимальное количество файловых дескрипторов:
        
        ```bash
        ulimit -n 100000
        ```
        
3. **Настройка очереди соединений**:
    
    ```bash
    sysctl -w net.core.somaxconn=4096
    ```
    

---

#### **1.1.2. Борьба с задержками**

1. **Отключение Nagle's Algorithm**:
    
    - Это уменьшает задержки для небольших пакетов.
    
    ```bash
    sysctl -w net.ipv4.tcp_low_latency=1
    ```
    
2. **Увеличение TCP Window Size**:
    
    - Позволяет передавать больше данных за один RTT:
        
        ```bash
        sysctl -w net.ipv4.tcp_rmem="4096 87380 16777216"
        sysctl -w net.ipv4.tcp_wmem="4096 65536 16777216"
        ```
        
3. **Настройка времени ожидания**:
    
    ```bash
    sysctl -w net.ipv4.tcp_fin_timeout=15
    ```
    

---

#### **1.1.3. Мониторинг TCP**

1. **Отслеживание активных соединений**:
    
    ```bash
    ss -t -a
    ```
    
2. **Состояние буферов**:
    
    ```bash
    netstat -s | grep -i tcp
    ```
    
3. **Проверка пропускной способности**:
    
    - Используйте `iperf`:
        
        ```bash
        iperf -s # На сервере
        iperf -c <ip_сервера> # На клиенте
        ```

### **1.2. TLS поверх TCP**

#### **1.2.1. Как работает TLS**

TLS добавляет шифрование поверх TCP, обеспечивая:

1. **Конфиденциальность**: Данные шифруются.
2. **Целостность**: Используются HMAC для проверки.
3. **Аутентификация**: Используются цифровые сертификаты.

---

#### **1.2.2. Как настроить TLS**

1. **Создание сертификата с OpenSSL**:
    
    ```bash
    openssl req -new -x509 -days 365 -nodes -out server.crt -keyout server.key
    ```
    
2. **Конфигурация NGINX для TLS**:
    
    ```nginx
    server {
        listen 443 ssl;
        ssl_certificate /path/to/server.crt;
        ssl_certificate_key /path/to/server.key;
    
        location / {
            proxy_pass http://localhost:8080;
        }
    }
    ```
    

---

#### **1.2.3. Диагностика TLS**

1. **Проверка сертификата**:
    
    ```bash
    openssl s_client -connect example.com:443
    ```
    
2. **Отладка с curl**:
    
    ```bash
    curl -v -k https://example.com
    ```

## **3. Углубляемся в HTTP**

---

### **3.1. HTTP/2: глубинная магия**

1. **Мультиплексирование**:
    
    - HTTP/2 позволяет отправлять несколько запросов одновременно через одно соединение.
2. **Сжатие заголовков (HPACK)**:
    
    - Уменьшает размер HTTP-заголовков.
3. **Потоки (Streams)**:
    
    - Каждый запрос — это поток с приоритетом.
4. **Настройка HTTP/2 в NGINX**:
    
    ```nginx
    server {
        listen 443 ssl http2;
        ssl_certificate /path/to/server.crt;
        ssl_certificate_key /path/to/server.key;
    
        location / {
            proxy_pass http://localhost:8080;
        }
    }
    ```
    

---

### **3.2. HTTP/3: QUIC на основе UDP**

1. **Особенности HTTP/3**:
    
    - Использует UDP вместо TCP.
    - Уменьшает задержки благодаря минимизации round-trip.
2. **Настройка HTTP/3 в NGINX**:
    
    - Установите NGINX с поддержкой QUIC.
    
    ```nginx
    server {
        listen 443 quic;
        ssl_certificate /path/to/server.crt;
        ssl_certificate_key /path/to/server.key;
        http3_max_concurrent_streams 128;
    }
    ```
    
3. **Проверка поддержки HTTP/3**:
    
    ```bash
    curl --http3 -v https://example.com
    ```

## **1. Глубокий разбор TCP: что происходит под капотом**

---

### **1.1. TCP-пакет: внутренняя структура**

TCP-пакет состоит из следующих полей:

| Поле                 | Описание                                            |
| -------------------- | --------------------------------------------------- |
| **Source Port**      | Порт отправителя.                                   |
| **Destination Port** | Порт получателя.                                    |
| **Sequence Number**  | Порядковый номер пакета.                            |
| **Acknowledgment**   | Подтверждение получения пакета.                     |
| **Flags**            | Управляют соединением (`SYN`, `ACK`, `FIN`, `RST`). |
| **Window Size**      | Размер окна скольжения.                             |
| **Checksum**         | Проверка целостности пакета.                        |

#### **Пример анализа TCP-пакета с tcpdump**

```bash
sudo tcpdump -i eth0 -nn -v tcp
```

- Посмотреть детали пакетов:
    
    ```bash
    tcpdump -X -i eth0 tcp
    ```
    

---

### **1.2. Проблемы TCP и их решения**

#### **1.2.1. Проблема: "Head-of-Line Blocking"**

- При потере одного сегмента, весь последующий трафик задерживается.
- **Решение**: Использовать HTTP/3 (QUIC), который работает поверх UDP.

---

#### **1.2.2. Проблема: "Silly Window Syndrome"**

- Возникает, когда маленькие порции данных отправляются слишком часто.
- **Решение**:
    - Включите алгоритм Нейгла:
        
        ```bash
        sysctl -w net.ipv4.tcp_slow_start_after_idle=1
        ```
        

---

#### **1.2.3. Проблема: Congestion Control (управление перегрузками)**

- Если сеть перегружена, TCP замедляет передачу.
- **Решение**:
    - Настройка алгоритма управления перегрузкой:
        
        ```bash
        sysctl -w net.ipv4.tcp_congestion_control=bbr
        ```

## **2. UDP: напиши свой протокол поверх UDP**

---

### **2.1. Написание кастомного протокола**

#### **2.1.1. Минимальный сервер на Go**

```go
package main

import (
	"fmt"
	"net"
)

func main() {
	conn, _ := net.ListenPacket("udp", ":8080")
	defer conn.Close()

	buffer := make([]byte, 1024)
	for {
		n, addr, _ := conn.ReadFrom(buffer)
		fmt.Printf("Получено от %s: %s\n", addr, string(buffer[:n]))
		conn.WriteTo([]byte("Принято!"), addr)
	}
}
```

#### **2.1.2. Клиент**

```go
package main

import (
	"net"
)

func main() {
	conn, _ := net.Dial("udp", "127.0.0.1:8080")
	defer conn.Close()

	conn.Write([]byte("Привет, сервер!"))
	buffer := make([]byte, 1024)
	n, _ := conn.Read(buffer)
	println(string(buffer[:n]))
}
```

---

### **2.2. Добавление подтверждений и таймаутов**

1. **Подтверждения (ACK)**:
    
    - Клиент отправляет пакет → сервер отвечает ACK → клиент считает пакет доставленным.
2. **Таймауты**:
    
    - Если клиент не получает ACK за определённое время, он повторяет отправку.

### **3.2. HTTP/2: реальные преимущества**

#### **Особенности HTTP/2**:

1. **Мультиплексирование**:
    
    - Позволяет отправлять несколько запросов по одному TCP-соединению.

# **Ещё глубже: полный разнос по сетям**

## **1. Глубокий разбор TCP: что происходит под капотом**

---

### **1.1. TCP-пакет: внутренняя структура**

TCP-пакет состоит из следующих полей:

|Поле|Описание|
|---|---|
|**Source Port**|Порт отправителя.|
|**Destination Port**|Порт получателя.|
|**Sequence Number**|Порядковый номер пакета.|
|**Acknowledgment**|Подтверждение получения пакета.|
|**Flags**|Управляют соединением (`SYN`, `ACK`, `FIN`, `RST`).|
|**Window Size**|Размер окна скольжения.|
|**Checksum**|Проверка целостности пакета.|

#### **Пример анализа TCP-пакета с tcpdump**

```bash
sudo tcpdump -i eth0 -nn -v tcp
```

- Посмотреть детали пакетов:
    
    ```bash
    tcpdump -X -i eth0 tcp
    ```
    

---

### **1.2. Проблемы TCP и их решения**

#### **1.2.1. Проблема: "Head-of-Line Blocking"**

- При потере одного сегмента, весь последующий трафик задерживается.
- **Решение**: Использовать HTTP/3 (QUIC), который работает поверх UDP.

---

#### **1.2.2. Проблема: "Silly Window Syndrome"**

- Возникает, когда маленькие порции данных отправляются слишком часто.
- **Решение**:
    - Включите алгоритм Нейгла:
        
        ```bash
        sysctl -w net.ipv4.tcp_slow_start_after_idle=1
        ```
        

---

#### **1.2.3. Проблема: Congestion Control (управление перегрузками)**

- Если сеть перегружена, TCP замедляет передачу.
- **Решение**:
    - Настройка алгоритма управления перегрузкой:
        
        ```bash
        sysctl -w net.ipv4.tcp_congestion_control=bbr
        ```

## **2. UDP: напиши свой протокол поверх UDP**

---

### **2.1. Написание кастомного протокола**

#### **2.1.1. Минимальный сервер на Go**

```go
package main

import (
	"fmt"
	"net"
)

func main() {
	conn, _ := net.ListenPacket("udp", ":8080")
	defer conn.Close()

	buffer := make([]byte, 1024)
	for {
		n, addr, _ := conn.ReadFrom(buffer)
		fmt.Printf("Получено от %s: %s\n", addr, string(buffer[:n]))
		conn.WriteTo([]byte("Принято!"), addr)
	}
}
```

#### **2.1.2. Клиент**

```go
package main

import (
	"net"
)

func main() {
	conn, _ := net.Dial("udp", "127.0.0.1:8080")
	defer conn.Close()

	conn.Write([]byte("Привет, сервер!"))
	buffer := make([]byte, 1024)
	n, _ := conn.Read(buffer)
	println(string(buffer[:n]))
}
```

---

### **2.2. Добавление подтверждений и таймаутов**

1. **Подтверждения (ACK)**:
    
    - Клиент отправляет пакет → сервер отвечает ACK → клиент считает пакет доставленным.
2. **Таймауты**:
    
    - Если клиент не получает ACK за определённое время, он повторяет отправку.

### **3.2. HTTP/2: реальные преимущества**

#### **Особенности HTTP/2**:

1. **Мультиплексирование**:
    
    - Позволяет отправлять несколько запросов по одному TCP-соединению.
2. **Сжатие заголовков**:
    
    - Уменьшает размер HTTP-заголовков.
3. **Потоковая передача**:
    
    - Каждое соединение разбивается на потоки.

#### **Как включить HTTP/2 в NGINX**

```nginx
server {
    listen 443 ssl http2;
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://localhost:8080;
    }
}
```
