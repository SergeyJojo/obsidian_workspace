
### **Глубокий разбор работы каналов в Go: структуры, блокировки и планировщик**

---

#### **1. Внутренняя структура канала (`hchan`)**
Каналы в Go реализованы как структура `hchan` в рантайме (файл `runtime/chan.go`):

```go
type hchan struct {
    qcount   uint           // Количество элементов в буфере
    dataqsiz uint           // Размер буфера (capacity)
    buf      unsafe.Pointer // Указатель на кольцевой буфер
    elemsize uint16         // Размер одного элемента
    closed   uint32         // Флаг закрытия канала
    elemtype *_type         // Тип элемента (для проверок типов)
    sendx    uint           // Индекс записи в буфер (send index)
    recvx    uint           // Индекс чтения из буфер (receive index)
    recvq    waitq          // Очередь заблокированных получателей (goroutines)
    sendq    waitq          // Очередь заблокированных отправителей (goroutines)
    lock     mutex          // Мьютекс для защиты доступа к каналу
}
```

---

#### **2. Очереди блокированных горутин (`waitq`)**
```go
type waitq struct {
    first *sudog  // Первая горутина в очереди
    last  *sudog  // Последняя горутина в очереди
}

// sudog - это обёртка над горутиной в очереди ожидания
type sudog struct {
    g     *g          // Указатель на горутину
    next  *sudog      // Следующий элемент в очереди
    prev  *sudog      // Предыдущий элемент в очереди
    elem  unsafe.Pointer // Элемент данных (для send/recv)
    // ... другие поля
}
```

---

#### **3. Механизм блокировки и разблокировки горутин**

##### **3.1. Отправка данных (`ch <- x`)**
1. **Буфер неполный**:  
   - Элемент копируется в `buf[sendx]`.  
   - `sendx = (sendx + 1) % dataqsiz`.  
   - `qcount++`.  

2. **Буфер полный или его нет (небуферизированный канал)**:  
   - Текущая горутина создает `sudog` и добавляет в `sendq`.  
   - Вызов `gopark` для блокировки (перевод в режим ожидания).  
   ```go
   gopark(chanparkcommit, unsafe.Pointer(&c.lock), waitReasonChanSend, traceEvGoBlockSend, 2)
   ```

##### **3.2. Получение данных (`<-ch`)**
1. **Буфер непустой**:  
   - Чтение из `buf[recvx]`.  
   - `recvx = (recvx + 1) % dataqsiz`.  
   - `qcount--`.  

2. **Буфер пустой**:  
   - Горутина создает `sudog` и добавляет в `recvq`.  
   - Вызов `gopark` для блокировки.  

##### **3.3. Разблокировка (`goready`)**
Когда происходит противоположная операция:
1. **Отправитель разблокирует получателя** (или наоборот):  
   - Из очереди `sendq/recvq` извлекается `sudog`.  
   - Данные копируются напрямую между горутинами (если канал небуферизированный).  
   - Вызов `goready(gp, skip)` для пробуждения горутины `gp`.  

---

#### **4. Планировщик и каналы**
- **`gopark`**:  
  - Переводит горутину в состояние `Gwaiting`.  
  - Планировщик (`schedule()`) исключает её из выполнения, пока не будет `goready`.  

- **`goready`**:  
  - Переводит горутину в `Grunnable`.  
  - Добавляет в локальную очередь планировщика (`runq`).  

---

#### **5. Особенности для разных типов каналов**

##### **5.1. Небуферизированный канал (`make(chan int)`)**
- **Отправка и получение синхронны**:  
  - Отправитель блокируется, пока получатель не готов, и наоборот.  
- **Данные копируются напрямую** между стеком отправителя и получателя.  

##### **5.2. Буферизированный канал (`make(chan int, 5)`)**
- **Блокировка только при переполнении/опустошении буфера**.  
- **Кольцевой буфер** (`buf`) уменьшает накладные расходы.  

---

#### **6. Пример работы с блокировками**
```go
ch := make(chan int, 1)
go func() {
    ch <- 42  // 1. Записывает в буфер
    ch <- 100 // 2. Блокируется (буфер полон)
}()
time.Sleep(time.Second)
<-ch          // 3. Читает 42, разблокирует отправитель
<-ch          // 4. Читает 100
```

---

#### **7. Системные вызовы и примитивы синхронизации**
- **Мьютекс (`lock` в `hchan`)**:  
  - Защищает доступ к полям `hchan` (атомарные операции через `atomic`).  
- **`gopark`/`goready`**:  
  - Используют низкоуровневые вызовы планировщика (`runtime.schedule()`).  

---

#### **8. Оптимизации**
- **Быстрый путь (fast path)**:  
  - При отсутствии блокировок операции выполняются без входа в мьютекс.  
- **Select с неблокирующими операциями**:  
  ```go
  select {
  case x := <-ch: // non-blocking
  default:
  }
  ```
  Проверяет `qcount` без блокировки.

---

### **Вывод**
1. **Канал — это `hchan`** с кольцевым буфером и очередями ожидания.  
2. **Блокировка** через `gopark` с переводом в `Gwaiting`.  
3. **Разблокировка** через `goready` с возвратом в `Grunnable`.  
4. **Синхронизация** между горутинами происходит без активного ожидания (CPU не нагружается).  

**Аналог из мира UNIX**:  
Каналы Go похожи на pipe + poll/epoll, но реализованы на уровне пользовательского пространства с оптимизациями под планировщик горутин.
