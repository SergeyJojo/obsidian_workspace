Штрихи корпоративной разработки на Go

Эти штрихи можно вставить в любую легенду — они добавят веса и убедительности.

---

1. Работа в команде и процессы

- Код-ревью: "Все изменения проходили код-ревью в GitLab, обычно я оставлял 2-3 аппрува от коллег перед мерджем."
    
- Планирование: "Работали по спринтам в Jira, задачи брали из backlog’а, оценивали в story points."
    
- Коммуникация: "Синкались с командой на daily standup’ах, раз в неделю обсуждали архитектуру на техмитингах."
    
- Документация: "Писал техдоки в Confluence — например, схему взаимодействия сервисов с Kafka."
    

Пример в легенде: "Разрабатывал сервис аутентификации, использовал gin и PostgreSQL. Все PR’ы шли через GitHub с код-ревью, я часто предлагал рефакторинг коллегам — например, заменил sync.Mutex на каналы для читаемости."

---

2. Инструменты и CI/CD

- CI/CD: "Настраивал пайплайны в GitLab CI: билд, тесты с go test -race, деплой в Kubernetes через Helm."
    
- Контейнеры: "Писал Dockerfile’ы с multi-stage build, чтобы уменьшить размер образов до 20-30 МБ."
    
- Тестирование: "Покрывал код unit-тестами с testify, гонял интеграционные тесты в Testcontainers."
    
- Линтинг: "Перед коммитом прогонял golangci-lint с кастомным .yml — ловил проблемы вроде неиспользуемых переменных."
    

Пример в легенде: "Оптимизировал обработку запросов в микросервисе, добавил кэш Redis. Деплоил через Jenkins в Docker Swarm, настроил stage для тестов с go vet и staticcheck."

---

3. Мониторинг и отладка

- Мониторинг: "Использовал Prometheus для метрик (latency, error rate), визуализировал в Grafana."
    
- Профилирование: "Ловил узкие места с pprof — например, нашёл лишние аллокации в горячей функции."
    
- Логи: "Настроил структурированные логи с zerolog, отправлял их в ELK через Filebeat."
    
- Алёрты: "Добавлял алёрты в Slack на 500-е ошибки и превышение latency SLA."
    

Пример в легенде: "Писал сервис для обработки заказов, интегрировал Kafka. После релиза поймал дедлоки через runtime.Stack, добавил метрики в Prometheus — после фикса uptime вырос до 99.9%."

---

4. Архитектура и масштабируемость

- Микросервисы: "Работал с архитектурой микросервисов, связывал их через gRPC с proto-файлами."
    
- Базы: "Шардировал PostgreSQL по customer_id, использовал pgx с connection pool’ом."
    
- Очереди: "Разделял нагрузку с помощью RabbitMQ, настраивал retry для failed сообщений."
    
- Кэш: "Внедрял groupcache для распределённого кэширования между нодами."
    

Пример в легенде: "Разрабатывал платёжный шлюз, использовал gRPC для общения с биллингом. Настроил репликацию MySQL через master-slave, добавил Redis для сессий — latency упал с 150 мс до 40 мс."

---

5. Безопасность и надёжность

- Graceful Shutdown: "Добавлял os.Signal и context для graceful завершения сервиса."
    
- Таймауты: "Ставил таймауты на HTTP-клиенты через http.Client — избежали зависаний на 3rd-party API."
    
- Идемпотентность: "Реализовал идемпотентные эндпоинты с токенами для повторных запросов."
    
- Ошибки: "Обрабатывал ошибки через errors.Is и errors.As, возвращал кастомные http.Status."
    

Пример в легенде: "Писал API для аналитики, добавил JWT-авторизацию с golang-jwt/jwt. Внедрил Circuit Breaker через gobreaker, чтобы не заваливать внешний сервис при сбоях."

---

6. Корпоративный сленг и детали

- SLA: "Держали SLA на 99.95% uptime, мониторили через Datadog."
    
- OKR: "Закрывали OKR по снижению P95 latency на 20% за квартал."
    
- On-call: "Был в ротации on-call, тушил пожары с помощью kubectl logs и pprof."
    
- Рефакторинг: "Проводил рефакторинг legacy-кода, вынес логику в пакеты с interface."
    

Пример в легенде: "Работал над сервисом уведомлений, использовал zap для логов и Kafka. Участвовал в планировании OKR, предложил миграцию с httprouter на chi для лучшей читаемости — код-ревью стало проще."

---

Как встроить в легенду

- Выбери 3-5 штрихов и миксуй их с задачами.
    
- Добавь 1-2 термина в каждую историю: "микросервис", "CI/CD", "SLA".
    
- Упомяни инструменты, которые реально знаешь (или выучил на уровне "что это").
    

Пример готовой легенды с штрихами: "Год работал в компании по обработке данных, писал микросервисы на Go. Один из них — парсер логов, использовал fiber и ClickHouse через clickhouse-go. Настраивал CI/CD в GitLab: билд, тесты с go test -cover, деплой в Kubernetes через Helm. Оптимизировал парсинг, заменил strings.Split на bytes.Buffer — ускорил обработку на 35%. Добавлял метрики в Prometheus, ловил утечки памяти с pprof. Работали по спринтам в Jira, я вёл пару задач для джуна на код-ревью. Ушёл, потому что хотел больше высоконагрузки."

---

Фишки и советы

- Конкретика: Назови версию Go ("1.21"), библиотеку (zerolog), метрику ("P99 50 мс").
    
- Провал: Добавь историю с уроком: "Перегрузил Redis кэш, пришлось rollback’нуть и внедрить eviction policy."
    
- Практика: Проговори вслух, чтобы не запинаться на "graceful shutdown" или "gRPC".
