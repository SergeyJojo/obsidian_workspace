### Задача 1: `uniqRandn` — генерация уникальных случайных чисел

Ваша текущая попытка решить задачу не совсем верна. В частности, вы неправильно проверяете уникальность чисел. Вместо того чтобы использовать цикл с вложенными проверками, проще использовать **мапу** (map) для отслеживания уникальности.

Вот исправленный и улучшенный вариант функции, которая генерирует уникальные случайные числа:

```go
package main

import (
	"fmt"
	"math/rand"
)

func main() {
	fmt.Println(uniqRandn(10))
}

// uniqRandn возвращает слайс с заданным количеством случайных уникальных чисел
func uniqRandn(n int) []int {
	uniqueNumbers := make(map[int]struct{})
	var result []int

	for len(uniqueNumbers) < n {
		num := rand.Int()
		if _, exists := uniqueNumbers[num]; !exists {
			uniqueNumbers[num] = struct{}{}
			result = append(result, num)
		}
	}

	return result
}
```

**Пояснение:**

- Используется мапа `uniqueNumbers` для хранения уникальных чисел.
- В цикле генерируются случайные числа, и если число еще не встречалось, оно добавляется в мапу и в результат.
- Цикл продолжается до тех пор, пока количество уникальных чисел не достигнет заданного значения `n`.

### Задача 3: Итерация по строке с учётом UTF-8 символов

В Go строки являются последовательностью байтов, и когда символы могут быть многобайтовыми (например, кириллица или символы с диакритическими знаками), важно использовать `range` для правильной обработки символов.

Вот пример правильной итерации по строке с учётом UTF-8 символов:

```go
package main

import "fmt"

func main() {
	s := "hêllo"
	for i, c := range s {
		fmt.Printf("position %d: %c\n", i, c)
	}
	fmt.Printf("len=%d\n", len(s)) // длина строки в байтах
}
```

**Пояснение:**

- В цикле `for i, c := range s` переменная `c` будет содержать символ (rune), а не байт. Это гарантирует корректную работу с многобайтовыми символами.

### Задача 4: Реализация worker pool

Для реализации worker pool в Go нужно создать несколько горутин (воркеров), которые будут обрабатывать задачи, при этом не больше `n` воркеров могут работать одновременно.

Вот исправленная версия с использованием горутин, каналов и `sync.WaitGroup`:

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	var wg sync.WaitGroup
	n := 3               // Количество воркеров
	c := make(chan struct{}, n) // Канал для ограничения количества активных воркеров

	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(i int) {
			defer wg.Done()
			c <- struct{}{} // Блокируем канал до тех пор, пока не освободится место для воркера
			defer func() { <-c }() // Освобождаем канал

			// Симуляция выполнения задачи
			time.Sleep(1 * time.Second)
			fmt.Printf("Worker %d finished task %d\n", i%n, i)
		}(i)
	}

	wg.Wait() // Ждем завершения всех горутин
}
```

**Пояснение:**

- Мы создаём канал с буфером размером `n`, чтобы ограничить количество активных воркеров.
- Каждый воркер выполняет задачу (в данном случае просто засыпает на 1 секунду) и выводит свой номер.
- Мы используем `sync.WaitGroup`, чтобы дождаться завершения всех горутин.

### Задача 1: Какое поведение у кода ниже?

```go
func main() {
    for i := 0; i < 5; i++ {
        go func() {
            fmt.Println(i)
        }()
    }
}
```

**Ответ**: Все горутины в этом случае могут завершиться после того, как переменная `i` изменится в главной горутине. В силу асинхронности работы горутин, все они скорее всего выведут одно и то же значение для `i` — `5`. Это происходит, потому что в момент выполнения горутины переменная `i` уже будет равна 5.


**Ответ**: Код создает 10,000 горутин, но переменная `count` не изменяется, так как нет кода для инкрементации или обработки результатов. Программа завершится, выводя `0`, потому что все горутины выполняются параллельно, но ни одна из них не влияет на `count`. Кроме того, отсутствие синхронизации (например, с использованием `sync.WaitGroup`) приводит к тому, что вывод происходит до того, как горутины завершат свою работу.

### Задача 7: Написать нагрузочное тестирование (простое). В результате должно быть количество успешных запросов, время на каждый и среднее время выполнения запроса.

Пример простого нагрузочного теста:

```go
package main

import (
    "fmt"
    "time"
)

func testRequest(i int) {
    time.Sleep(time.Millisecond * 10) // Имитируем задержку запроса
    fmt.Printf("Request %d completed\n", i)
}

func main() {
    start := time.Now()
    successfulRequests := 0
    totalRequests := 1000

    for i := 1; i <= totalRequests; i++ {
        go func(i int) {
            testRequest(i)
            successfulRequests++
        }(i)
    }

    // Подождем, пока все запросы завершатся
    time.Sleep(time.Second)

    duration := time.Since(start)
    avgTime := duration / time.Duration(totalRequests)

    fmt.Printf("Total Requests: %d\n", totalRequests)
    fmt.Printf("Successful Requests: %d\n", successfulRequests)
    fmt.Printf("Total Time: %s\n", duration)
    fmt.Printf("Average Time per Request: %s\n", avgTime)
}
```

**Ответ**: Этот код имитирует нагрузочное тестирование, где мы запускаем 1000 запросов, измеряем время их выполнения и выводим статистику о времени на каждый запрос и общей продолжительности работы.
