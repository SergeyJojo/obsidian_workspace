# ✅ **Что такое ORM в целом**

ORM (Object–Relational Mapping) — это подход, когда объекты языка (PHP/Go/Java/Python) сопоставляются с таблицами реляционной БД.

Но **ORM ≠ одна технология**. Существует множество типов ORM с разной философией работы.

---

# 🧩 **1. Active Record (AR)**

_(Самый известный, самый простой, часто используется в PHP)_

### 📌 Суть:

Модель = и объект, и логика сохранения в БД одновременно.

```
$user = User::find(1)
$user->name = "Сергей"
$user->save()
```

### 📌 Примеры:

- Yii1 / Yii2 ActiveRecord
    
- Laravel Eloquent
    
- Ruby on Rails ActiveRecord
    
- CodeIgniter Model
    

### 📌 Плюсы:

- простота
    
- низкий порог входа
    
- CRUD пишется очень быстро
    

### 📌 Минусы:

- смешение доменной логики и persistence
    
- плохо подходит для чистой архитектуры
    
- сложно поддерживать большие проекты
    

---

# 🧩 **2. Data Mapper (DM)**

_(Более чистая и архитектурно строгая версия ORM)_

### 📌 Суть:

Модель = только бизнес-логика  
Mapper/Repository = работа с БД

```
$user = $userRepository->find(1)
$user->changeName("Сергей")
$userRepository->save($user)
```

### 📌 Примеры:

- Doctrine ORM (PHP)
    
- Hibernate (Java)
    
- Entity Framework (C#, частично)
    
- SQLAlchemy (Python, частично)
    

### 📌 Плюсы:

- чистая архитектура
    
- тестируемость
    
- нет смешения слоёв
    

### 📌 Минусы:

- сложнее изучать
    
- требует больше boilerplate
    

---

# 🧩 **3. Query Builder ORM (гибрид)**

_(часто называют "полу-ORM")_

### 📌 Суть:

Есть удобный API для запросов, но нет полноценного сопоставления объектов.

```
DB::table("users")
   ->where("age", ">", 18)
   ->get()
```

### 📌 Примеры:

- Laravel Query Builder
    
- Yii2 Query Builder
    
- Knex.js (JS)
    
- Kysely (TS)
    
- Go: squirrel, goqu (не ORM, но QB)
    

### 📌 Плюсы:

- выразительность
    
- скорость
    
- контроль над SQL
    

### 📌 Минусы:

- нет объектной модели
    
- нет полноценного мэппинга
    

---

# 🧩 **4. Micro ORM**

Минимальный мэппинг объектов без сложных фич.

### 📌 Суть:

Таблицы в объекты → да  
Сложные связи, отслеживание состояния → нет

### 📌 Примеры:

- Dapper (C#)
    
- GORM (Go) — частично
    
- Orator (Python)
    
- Sqlx macro models (Rust)
    

### 📌 Плюсы:

- скорость
    
- низкая магия
    
- простые структуры
    

### 📌 Минусы:

- меньше возможностей
    

---

# 🧩 **5. Full-feature ORM**

(тяжёлые ORM с трекингом изменений, lazy loading, DI и т.д.)

### 📌 Примеры:

- Doctrine (PHP)
    
- Hibernate (Java)
    
- Django ORM (Python)
    
- EF Core (C#)
    
- NHibernate (.NET)
    

### 📌 Возможности:

- lazy loading
    
- cascade operations
    
- identity map
    
- unit of work
    
- second-level cache
    
- advanced relations
    

### 📌 Плюсы:

- мощь
    
- гибкость
    
- enterprise-уровень
    

### 📌 Минусы:

- сложность
    
- тяжёлые для highload без оптимизаций
    

---

# 🧩 **6. NoSQL ORM / ODM**

ORM для документных БД:

### 📌 Примеры:

- MongoDB ODM (PHP)
    
- Mongoose (Node.js)
    
- Spring Data MongoDB (Java)
    

### 📌 Плюсы:

- удобство работы с документами
    
- валидация
    
- схемы
    

### 📌 Минусы:

- слабая консистентность схем
    

---

# 🧩 **7. Active Data Record (ADR) / Hybrid ORM**

Смешанный паттерн AR + Data Mapper.

Примеры:

- Yii2 ActiveRecord (гибрид)
    
- Eloquent (гибрид)
    
- GORM (Go)
    

---

# 🔥 **8. ORM-less подход (e.g., Go style)**

Некоторые языки (Go, Rust) часто рекомендуют не использовать ORM вовсе.

### Причины:

- полный контроль
    
- производительность
    
- прозрачность запросов
    

### Пример в Go через pgx:

```
err = conn.QueryRow(ctx, "SELECT id, name FROM users WHERE id=$1", id).Scan(&u.ID, &u.Name)
```

Это не ORM, но встречается как противоположный подход.
