## 1️⃣ Настройка OPcache в `php.ini`

OPcache — это расширение PHP, которое компилирует скрипты в байткод и держит их в памяти, чтобы не парсить и не компилировать заново. Ключевые настройки:

```ini
; Включаем OPcache
opcache.enable=1

; Включаем OPcache для CLI (иногда полезно при скриптах)
opcache.enable_cli=1

; Сколько памяти выделяем под кэш
opcache.memory_consumption=256

; Сколько файлов хранить в кэше (чем больше проект, тем выше)
opcache.max_accelerated_files=10000

; Время жизни кэша, после которого файлы проверяются на изменения (в секундах)
opcache.revalidate_freq=2

; Хранить ли timestamps для проверки изменений
opcache.validate_timestamps=1

; Сохранять функции в оптимизированном виде
opcache.optimization_level=0x7FFFBFFF

; Включить ускоренную загрузку файлов и включений
opcache.file_cache=/var/www/php_opcache_file_cache
```

**Совет:** для продакшена `opcache.validate_timestamps=0` ускоряет работу, но тогда нужно сбрасывать кэш вручную при деплое.

## 2️⃣ Практики кода для OPcache

OPcache работает лучше, если код **статичен и предсказуем**:

### a) Минимизируем динамические include/require

```php
// Плохо:
include $path . '/file.php';

// Лучше:
include __DIR__ . '/file.php';
```

OPcache лучше кэширует файлы с **фиксированными путями**, без динамических вычислений.

### b) Константы вместо магических строк

```php
// Плохо
if ($userRole === 'admin') { ... }

// Лучше
define('ROLE_ADMIN', 'admin');
if ($userRole === ROLE_ADMIN) { ... }
```

Это уменьшает нагрузку на интерпретатор и ускоряет работу с кодом.

### c) Статические методы и свойства

OPcache может оптимизировать статические вызовы лучше, чем динамические.

```php
class Math {
    public static function square($x) { return $x * $x; }
}
$result = Math::square(5); // OPcache оптимизирует быстрее
```

### d) Минимизируем eval, create_function и генерацию кода

Любой динамический код ломает кэширование и снижает эффект OPcache.

## 3️⃣ Настройка автозагрузки (Composer)

- Composer создаёт autoload через `vendor/autoload.php`.
    
- Используй `composer dump-autoload -o` для генерации **оптимизированного класса map**, чтобы OPcache не тратился на поиск классов.
    

```bash
composer dump-autoload -o
```

- Не оставляй PSR-4 автозагрузку без оптимизации на продакшене.
    

---

## 4️⃣ Сокращаем количество проверок

- OPcache проверяет `filemtime` для изменений. Если проект на проде стабилен, можно отключить:
    

```ini
opcache.validate_timestamps=0
```

- Или увеличить интервал:
    

```ini
opcache.revalidate_freq=60
```

---

## 5️⃣ Мониторинг и сброс кэша

- Проверить состояние OPcache через PHP:
    

```php
<?php
print_r(opcache_get_status());
```

- Сбросить кэш вручную:
    

```php
opcache_reset();
```

- Для больших проектов полезно иметь **web-интерфейс мониторинга**, например [OPcache GUI](https://github.com/amnuts/opcache-gui).
    

---

## 6️⃣ Дополнительные «хитрости» ускорения

1. Использовать **OPcache file cache** для ускорения cold start при перезапуске PHP-FPM.
    
2. Минимизировать `include`/`require` внутри функций — лучше подключать файлы на верхнем уровне.
    
3. Избегать слишком глубокой вложенности namespace: OPcache быстрее работает с короткими путями классов.
    
4. Писать меньше анонимных функций внутри циклов — OPcache их кэширует хуже.
