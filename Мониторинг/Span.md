
**Span** — это основная единица работы в системе распределённого трассирования, такой как OpenTracing или другие системы трассировки, например, Jaeger или Zipkin.

**Span** представляет собой единичную операцию или шаг, выполняемый в процессе обработки запроса в распределённой системе. Например, это может быть запрос в базу данных, HTTP-запрос между микросервисами или выполнение какой-то задачи внутри сервиса.

### **Что включает в себя Span?**

1. **Имя** — название операции, которое описывает, что происходит в этом спане. Это может быть, например, `GET /users` для HTTP-запроса, `DatabaseQuery` для запроса к базе данных или `HandlePayment` для обработки платёжной операции.
    
2. **Время начала и окончания** — спан записывает время начала и окончания операции. Это позволяет точно измерять продолжительность выполнения операции.
    
3. **Теги (Tags)** — ключ-значение пары, которые добавляют дополнительную информацию о спане. Например:
    
    - `http.status_code` — статус HTTP-ответа.
        
    - `error` — флаг, который указывает, произошла ли ошибка в процессе выполнения.
        
    - `user_id` — идентификатор пользователя, если операция связана с данным пользователем.
        
4. **Логирование событий (Logs)** — спан может содержать временные метки с подробной информацией о ключевых событиях в процессе выполнения операции. Например, логирование события об успешном или неудачном завершении транзакции.
    
5. **Связи с другими спанами (Links)** — спан может быть связан с другими спанами, создавая структуру зависимостей между ними. Это особенно важно в распределённых системах, где запросы могут проходить через несколько микросервисов или компонентов.
    
6. **Родительский спан (Parent Span)** — если спан является частью более крупной трассировки (например, запрос к серверу, который вызывает другие сервисы), то у него будет родительский спан. Это позволяет строить деревья зависимостей, которые показывают, как запросы движутся через систему.
    
7. **Идентификатор** — каждый спан имеет уникальный идентификатор (SpanID), который используется для связывания его с другими спанами в рамках общей трассировки.
    

### **Пример использования Span в контексте OpenTracing**

1. **Создание спана**: Когда приложение выполняет какую-либо операцию, например, HTTP-запрос или обращение к базе данных, оно создаёт спан, чтобы зафиксировать начало этой операции.
    
2. **Завершение спана**: После завершения операции, спан фиксирует время окончания и передаёт информацию в систему трассировки (например, Jaeger или Zipkin).
    

### **Пример:**

Предположим, что мы делаем запрос в базу данных через REST API, и хотим создать спан для этого запроса. Код на Go с использованием OpenTracing может выглядеть так:

```go
package main

import (
	"fmt"
	"log"
	"github.com/opentracing/opentracing-go"
	"github.com/jaegertracing/jaeger-client-go"
)

func main() {
	// Инициализация Jaeger Tracer
	cfg := jaeger.Config{
		ServiceName: "my-service",
	}
	tracer, closer, err := cfg.NewTracer(jaeger.Sampler(jaeger.NewConstSampler(true)))
	if err != nil {
		log.Fatalf("Не удалось создать Jaeger tracer: %v", err)
	}
	defer closer.Close()

	// Создание нового спана
	span := tracer.StartSpan("DatabaseQuery")
	defer span.Finish()

	// Добавление тегов
	span.SetTag("db.type", "SQL")
	span.SetTag("db.statement", "SELECT * FROM users WHERE id = ?")

	// Логирование событий
	span.LogKV("event", "Database query started")

	// Выполнение запроса к базе данных (имитируем)
	fmt.Println("Executing database query...")

	// Логирование завершения события
	span.LogKV("event", "Database query finished")
}
```

В этом примере создаётся спан для выполнения SQL-запроса, добавляются теги, логируются события, а затем спан завершается.

### **Важность Span**

1. **Измерение производительности**: Spans помогают измерить, сколько времени заняла конкретная операция в системе (например, запрос к базе данных или внешнему API). Это помогает выявлять узкие места и оптимизировать производительность.
    
2. **Отслеживание ошибок**: Если в какой-то операции возникает ошибка, она может быть зафиксирована в спане с соответствующими тегами и логами, что облегчает диагностику.
    
3. **Понимание взаимосвязей между сервисами**: В распределённой системе запрос может пройти через несколько сервисов. Спаны помогают понять, как различные компоненты взаимодействуют друг с другом и какой сервис вызвал задержки.
    

### **Когда использовать Span?**

1. **В распределённых системах**: Когда запрос проходит через несколько микросервисов или компонентов.
    
2. **Для мониторинга и оптимизации производительности**: Чтобы измерить время выполнения операций и найти узкие места.
    
3. **Для диагностики ошибок**: Для того чтобы логировать и отслеживать все этапы выполнения запросов и найти место возникновения ошибки.
    

### **Резюме**

**Span** — это единица работы в системе распределённого трассирования, представляющая собой операцию, которая выполняется в рамках более крупной трассировки. Он включает в себя информацию о времени начала и окончания операции, дополнительные метаданные, теги, события и связи с другими спанами. Span помогает анализировать производительность, выявлять ошибки и понимать, как различные части системы взаимодействуют между собой.
