## **4. Внутреннее устройство компилятора gc**

### **4.1. Основные модули компилятора Go (gc)**

Компилятор Go состоит из трёх крупных компонентов:

1. **Фронтенд (Frontend):**
    
    - Разбирает исходный код, строит **AST** и проводит проверку типов.
    - Код написан на самом Go.
    - Пакеты: `go/scanner`, `go/parser`, `go/ast`, `go/types`.
2. **Мидленд (Middleend):**
    
    - Генерирует промежуточное представление (IR) и оптимизирует его.
    - Использует формат **SSA (Static Single Assignment)**, где каждая переменная присваивается только один раз.
    - Модуль: `cmd/compile/internal/ssa`.
3. **Бэкенд (Backend):**
    
    - Преобразует IR в машинный код.
    - Генерация машинного кода производится для конкретной архитектуры: x86, ARM и др.

---

### **4.2. Промежуточное представление SSA**

SSA — это ядро оптимизации компилятора Go.

#### **Особенности SSA:**

1. Все переменные являются уникальными:
    
    ```plaintext
    x1 = 10
    x2 = x1 + 20
    ```
    
2. Удобно для оптимизаций:
    - Устранение общих подвыражений.
    - Инлайнинг функций.
    - Удаление мёртвого кода.

#### **Пример: преобразование Go-кода в SSA**

Go-код:

```go
func add(a, b int) int {
    return a + b
}
```

SSA:

```plaintext
entry:
    t0 = Add a b
    Ret t0
```

### **4.3. Escape Analysis: Управление памятью**

Компилятор решает, где размещать переменные: в стеке или в куче.

#### **Как работает Escape Analysis:**

1. Если переменная "выживает" за пределами своей функции (например, передаётся по ссылке), она размещается в куче.
2. Пример:
    
    ```go
    func foo() *int {
        x := 42
        return &x // Escape в кучу
    }
    ```
    

#### **Оптимизация:**

Если переменная остаётся локальной для функции, она размещается в стеке, что быстрее.

## **5. Взаимодействие с операционной системой**

### **5.1. Планировщик Go (Go Scheduler)**

Планировщик Go управляет выполнением горутин.

#### **Архитектура планировщика:**

1. **M (Machine):**
    - Соответствует потоку ОС (операционной системы).
2. **P (Processor):**
    - Логический процессор для выполнения горутин.
    - Число `P` задаётся через `GOMAXPROCS`.
3. **G (Goroutine):**
    - Лёгковесный поток, исполняемый на `M`.

#### **Как это работает:**

- Горутины ставятся в очередь `P`.
- Потоки `M` вытягивают горутины из очереди и исполняют их.

---

### **5.2. Preemption (Прерывание)**

Go поддерживает **кооперативное многозадачное планирование**.

#### **Как работает Preemption:**

1. Компилятор вставляет точки проверки (`checkpoints`) в код.
2. Когда горутина долго выполняется, её выполнение прерывается в ближайшей точке.

#### **Пример кода Preemption в IR:**

```plaintext
CALL runtime.gosched
```

---

### **5.3. Работа с памятью: Garbage Collector**

Go использует **трассирующий сборщик мусора**.

#### **Как работает сборщик мусора:**

1. **Маркировка (Mark):**
    - Помечает все используемые объекты.
2. **Очистка (Sweep):**
    - Удаляет объекты, которые больше не используются.

#### **Оптимизации:**

1. Параллельный сбор:
    - Сбор мусора выполняется одновременно с основным кодом.
2. Конкурентный режим:
    - Операции остановки минимальны.

## **6. Особенности бэкенда и генерация кода**

### **6.1. Регистр-аллокатор**

Бэкенд компилятора решает, какие переменные хранятся в регистрах процессора, а какие — в памяти.

#### **Алгоритм размещения:**

1. Используется **алгоритм графового раскраса** для оптимального использования регистров.
2. Если регистров не хватает, компилятор генерирует инструкции для использования памяти.

---

### **6.2. Генерация кода для архитектур**

Go поддерживает множество архитектур:

1. **x86/x86_64:**
    - Оптимизация под SIMD для числовых операций.
2. **ARM/ARM64:**
    - Используется для мобильных устройств и встроенных систем.
3. **RISC-V:**
    - Экспериментальная поддержка.
