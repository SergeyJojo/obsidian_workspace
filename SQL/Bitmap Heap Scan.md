
### **Что такое Bitmap Heap Scan в PostgreSQL?**

**Bitmap Heap Scan** — это метод доступа к данным в PostgreSQL, который сочетает в себе эффективность битовых карт (*bitmaps*) и операций в памяти для оптимизации сложных запросов. Он используется, когда нужно выбрать много строк из таблицы по условию, особенно при работе с индексами.

---

## **1. Как это работает?**
Процесс состоит из двух этапов:

### **① Bitmap Index Scan**
- PostgreSQL сначала сканирует **индекс** (например, B-tree) и создаёт **битовую карту** (bitmap), где:
  - Каждый бит соответствует строке в таблице.
  - `1` — строка подходит под условие.
  - `0` — не подходит.

### **② Bitmap Heap Scan**
- Затем СУБД читает **саму таблицу (heap)** только для строк, отмеченных `1` в битовой карте.
- Данные загружаются страницами (не по одной строке), что уменьшает I/O-операции.

---

## **2. Пример запроса с Bitmap Heap Scan**
```sql
EXPLAIN SELECT * FROM users WHERE age > 30 AND salary < 5000;
```
**Результат в `EXPLAIN`**:
```sql
Bitmap Heap Scan on users  (cost=4.29..14.34 rows=6 width=36)
  Recheck Cond: ((age > 30) AND (salary < 5000))
  ->  BitmapAnd  (cost=4.29..4.29 rows=6 width=0)
        ->  Bitmap Index Scan on users_age_idx  (cost=0.00..2.12 rows=10 width=0)
              Index Cond: (age > 30)
        ->  Bitmap Index Scan on users_salary_idx  (cost=0.00..2.12 rows=10 width=0)
              Index Cond: (salary < 5000)
```

**Что здесь происходит?**
1. Сканируются два индекса: `users_age_idx` и `users_salary_idx`.
2. Результаты объединяются операцией `BitmapAnd` (логическое И).
3. Битовые карты помогают быстро найти строки, где `age > 30` **и** `salary < 5000`.
4. Затем данные читаются из таблицы (`heap`) только для этих строк.

---

## **3. Когда PostgreSQL использует Bitmap Heap Scan?**
- **Несколько условий в `WHERE`** (особенно с индексами).
- **Большой % строк таблицы** (но не все) — например, 10–50%.
- **Комбинация индексов** через `AND`/`OR`.

**Когда НЕ используется?**
- Если условие покрывает **все строки** (выгоднее `Sequential Scan`).
- Если нужно **очень мало строк** (выгоднее `Index Scan`).

---

## **4. Плюсы и минусы**
| **Плюсы**                          | **Минусы**                          |
|------------------------------------|-------------------------------------|
| ⚡ Экономит I/O — читает только нужные страницы | Требует памяти для битовых карт |
| 📊 Оптимален для средних по селективности запросов | Неэффективен для очень маленьких/больших выборок |
| 🔍 Позволяет комбинировать несколько индексов | Дополнительные вычисления для битовых операций (`AND`, `OR`) |

---

## **5. Оптимизация запросов с Bitmap Heap Scan**
1. **Добавьте индексы** на часто используемые столбцы в `WHERE`.
2. **Увеличьте `work_mem`**, если битовые карты не помещаются в память:
   ```sql
   SET work_mem = '64MB';  -- Для сложных запросов
   ```
3. **Избегайте условий с низкой селективностью** (например, `status = 'active'`, если 90% строк активны).

---

## **6. Сравнение с другими методами доступа**
| Метод                | Когда используется?                 | Память | I/O       |
|----------------------|------------------------------------|--------|-----------|
| **Sequential Scan**  | Чтение всей таблицы                 | Низкая | Максимум  |
| **Index Scan**       | Точечный доступ (1–100 строк)      | Низкая | Минимум   |
| **Bitmap Heap Scan** | Средняя селективность (100–100K строк) | Средняя | Оптимальный |

---

## **7. Как проверить, что запрос использует Bitmap Heap Scan?**
Запустите `EXPLAIN ANALYZE`:
```sql
EXPLAIN ANALYZE SELECT * FROM large_table WHERE column1 = 'A' AND column2 = 'B';
```
Если в плане есть `Bitmap Heap Scan` — PostgreSQL выбрал этот метод.

---

### **Итог**
**Bitmap Heap Scan** — это «золотая середина» между `Sequential Scan` (чтение всего подряд) и `Index Scan` (точечный доступ). Он идеален для запросов с:
- Средней селективностью.
- Несколькими условиями в `WHERE`.
- Наличием индексов.

Для сложных аналитических запросов это один из самых эффективных методов!
