
В контексте работы с памятью в современных процессорах (x86/x86-64) и операционных системах, **CR3, PGD, PMD, PTE** — это компоненты механизма трансляции виртуальных адресов в физические. Разберём их по порядку, а также объясним, что такое физические адреса и флаги (`R/W`, `Present`).

---

## **1. Иерархия трансляции адресов**
В архитектуре x86-64 используется **4-уровневая (или 5-уровневая) страничная адресация**:
1. **CR3** — корневой указатель на таблицы страниц (Page Global Directory, PGD).  
2. **PGD (Page Global Directory)** — первый уровень трансляции.  
3. **PMD (Page Middle Directory)** — второй уровень.  
4. **PTE (Page Table Entry)** — финальный уровень, указывает на физическую страницу.  

```
Виртуальный адрес (64 бита) разбивается на части:
[63:48] — неиспользуемые (знаковое расширение)  
[47:39] — индекс в PGD  
[38:30] — индекс в PMD  
[29:21] — индекс в PTE  
[20:0]  — смещение внутри страницы (4 KiB)
```

---

## **2. Что делает каждый компонент?**
### **(1) CR3 (Control Register 3)**
- **Физический адрес PGD** (таблицы страниц верхнего уровня).  
- Устанавливается ОС при переключении процессов (у каждого процесса свой CR3).  
- Пример (в коде ядра Linux):
  ```c
  void switch_mm(struct mm_struct *mm) {
      write_cr3(mm->pgd); // Загрузка нового CR3
  }
  ```

### **(2) PGD (Page Global Directory)**
- Содержит **указатели на PMD**.  
- Каждая запись — 64 бита (включая флаги).  

### **(3) PMD (Page Middle Directory)**
- Содержит **указатели на PTE**.  

### **(4) PTE (Page Table Entry)**
- Содержит **физический адрес страницы** (4 KiB) + флаги доступа.  
- Пример структуры PTE:
  ```c
  typedef struct {
      uint64_t present    : 1;  // Страница в памяти?
      uint64_t rw         : 1;  // Read/Write (1) или Read-only (0)
      uint64_t user       : 1;  // Доступна ли из userspace?
      uint64_t accessed   : 1;  // Была ли страница использована?
      uint64_t dirty      : 1;  // Была ли запись в страницу?
      uint64_t phys_addr  : 40; // Физический адрес (выровненный)
      // ... другие флаги
  } pte_t;
  ```

---

## **3. Физические адреса**
- Это **реальные адреса в оперативной памяти (RAM)**, с которыми работает процессор.  
- Виртуальные адреса (которые использует программа) транслируются в физические через таблицы страниц.  
- Пример трансляции:
  ```
  Виртуальный адрес: 0x7ffc12345678  
  → CR3 указывает на PGD  
  → PGD[индекс1] → PMD  
  → PMD[индекс2] → PTE  
  → PTE[индекс3] → Физическая страница (например, 0x12345000)  
  → Физический адрес = 0x12345000 + смещение (0x678)
  ```

---

## **4. Ключевые флаги в PTE**
| Флаг       | Описание                                                                 |
|------------|--------------------------------------------------------------------------|
| **Present** (1 бит) | Страница загружена в RAM. Если `0` — происходит Page Fault (исключение). |
| **R/W**    | `1` = Read/Write, `0` = Read-only. Запрещает запись (например, для .text). |
| **User**   | `1` = Доступна из userspace (иначе только для ядра).                     |
| **Accessed** | Страница была прочитана (используется для алгоритмов замещения страниц). |
| **Dirty**  | Страница была изменена (требуется сброс на диск для swap-страниц).       |

---

## **5. Пример работы в Linux**
### **(1) Обход таблиц страниц**
В ядре Linux можно пройти по всей цепочке:
```c
pgd_t *pgd = pgd_offset(mm, address); // Получить PGD из CR3
pmd_t *pmd = pmd_offset(pgd, address); // PMD
pte_t *pte = pte_offset_map(pmd, address); // PTE
if (pte_present(*pte)) {
    phys_addr = pte_val(*pte) & PAGE_MASK; // Физический адрес
}
```

### **(2) Обработка Page Fault**
Если процесс обращается к странице с `Present=0`, возникает исключение.  
Ядро может:
- Загрузить страницу с диска (swap).  
- Заполнить нулями (для новых страниц).  
- Завершить процесс (Segmentation Fault).  

---

## **6. Зачем это нужно?**
1. **Виртуальная память** — у каждого процесса своё адресное пространство.  
2. **Защита памяти** — флаги `R/W` и `User` предотвращают повреждение данных.  
3. **Swap** — страницы могут выгружаться на диск.  
4. **Shared Memory** — одна физическая страница может быть отображена в несколько процессов.  

---

## **Итог**
- **CR3 → PGD → PMD → PTE** — цепочка трансляции виртуальных адресов.  
- **Физический адрес** — итоговое местоположение в RAM.  
- **Флаги (Present, R/W)** контролируют доступ и жизненный цикл страниц.  

Это основа работы защищённой памяти в современных ОС!
