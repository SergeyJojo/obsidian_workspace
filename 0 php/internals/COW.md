Отличный вопрос — это **одна из ключевых внутренних оптимизаций PHP**, которую часто упускают, но она напрямую влияет на производительность и поведение при передаче переменных в функции.

Разберём глубоко 👇

---

## 🧩 Что такое Copy-on-Write (COW)

**Copy-on-Write (копирование при записи)** — это **механизм оптимизации памяти**, при котором при **копировании переменной** данные **не копируются сразу**, а **делятся между переменными** до тех пор, пока кто-то не попытается их изменить.

> То есть: PHP _не делает полную копию данных_, пока это не становится действительно нужно.

---

## 🔧 Пример на практике

```php
$a = [1, 2, 3];
$b = $a;  // здесь копия не создаётся!
```

На этом этапе и `$a`, и `$b` **ссылаются на один и тот же zval (внутренний буфер данных)**, просто с разными "контейнерами".

📦

```
$a → [1, 2, 3]
$b → [1, 2, 3]
(оба указывают на один и тот же блок памяти)
```

---

### 🧠 Что произойдёт при изменении:

```php
$b[0] = 99;
```

Теперь PHP **создаёт копию массива**, потому что `$b` пытается изменить содержимое.  
Это и есть момент _write_ (записи).

После этого:

```
$a → [1, 2, 3]
$b → [99, 2, 3]
```

PHP скопировал данные **только в момент изменения**, а не при обычном присвоении.

---

## 📊 Зачем это нужно

PHP — язык, где **переменные по умолчанию передаются по значению** (не по ссылке).  
Без COW любое присвоение массивов, строк и т.д. приводило бы к _дорогим копиям памяти_.

Механизм Copy-on-Write позволяет:

- экономить память,
    
- ускорять операции,
    
- оставаться при этом «по значению» снаружи (с точки зрения разработчика).
    

---

## 🧠 То же самое со строками

```php
$a = "Hello";
$b = $a;  // копия не создаётся

$b .= " world";  // вот тут создаётся новая строка
```

Пока `$b` не изменялась, обе переменные указывали на одну и ту же строку в памяти.  
Когда `$b` изменилась — PHP создал новую.

---

## 🧩 Внутренности (zval + refcount)

В PHP каждая переменная — это структура `zval`, содержащая:

- значение (строка, массив, число),
    
- счётчик ссылок (`refcount`),
    
- флаг `is_ref` (если переменная передана по ссылке).
    

Примерно так:

```
zval {
  type = IS_ARRAY
  refcount = 2
  is_ref = 0
}
```

Когда `$b = $a`, `refcount` увеличивается.  
Когда `$b` изменяется, `refcount` для `$a` уменьшается, а PHP делает _detach_ и копию.

---

## 🧩 Влияние на производительность

Это значит, что такой код:

```php
$arr = range(1, 1000000);
$copy = $arr;
```

не копирует миллион элементов — всего лишь увеличивает счётчик ссылок.  
Копия делается **только при изменении** (`$copy[0] = 42;`).

---

## ⚠️ Но с объектами — по-другому

С COW **работают только строки и массивы**.  
Объекты в PHP **всегда передаются по ссылке по умолчанию**, даже без `&`.

Пример:

```php
class User {}
$a = new User();
$b = $a;

$b->name = 'Alex';
var_dump($a === $b); // true
```

Здесь `$a` и `$b` — **указывают на один и тот же объект**.  
COW тут не применяется.

---

## 📘 Коротко:

|Тип данных|Copy-on-Write работает?|Поведение|
|---|---|---|
|Массив|✅ Да|Копируется только при изменении|
|Строка|✅ Да|Копируется при изменении|
|Объект|❌ Нет|Всегда ссылка|
|Ресурс (file, socket)|❌ Нет|Ссылка|
|Число, bool, null|🔸 Нет смысла|Примитивные значения, копируются дешево|
