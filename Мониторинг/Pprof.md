### Полное описание инструмента pprof и работа с ним

**pprof** — это мощный инструмент для профилирования и анализа производительности приложений, написанных на языке Go. Он позволяет разработчикам собирать данные о потреблении ресурсов (CPU, память, блокировки) и визуализировать их для нахождения узких мест производительности.

---

### 1. **Основные возможности pprof**
- **Сбор профилей**: Позволяет собирать данные о потреблении CPU, памяти (heap), блокировках и других аспектах работы вашего приложения.
- **Анализ**: Предоставляет интерактивные команды для анализа собранных данных.
- **Визуализация**: Возможность строить графы для лучшего понимания взаимодействий между функциями.

---

### 2. **Установка и подключение к проекту**
pprof является частью стандартной библиотеки Go, и его не нужно устанавливать отдельно. Чтобы использовать pprof, выполните следующие шаги:

#### 2.1. Импортируйте пакет
Добавьте импорт в ваш Go-код:

```go
import _ "net/http/pprof"
```

#### 2.2. Запустите HTTP-сервер
Запустите HTTP-сервер для предоставления доступа к данным профилирования:

```go
package main

import (
    "log"
    "net/http"
    _ "net/http/pprof"
)

func main() {
    go func() {
        log.Println(http.ListenAndServe("localhost:6060", nil))
    }()
    // Ваше приложение
}
```

Теперь данные профилирования будут доступны по адресу `http://localhost:6060/debug/pprof`.

---

### 3. **Основные эндпоинты pprof**
pprof предоставляет следующие эндпоинты:

- **`/debug/pprof/profile`**: Сбор профиля CPU.
- **`/debug/pprof/heap`**: Получение профиля использования памяти (heap).
- **`/debug/pprof/block`**: Профиль блокировок.
- **`/debug/pprof/goroutine`**: Информация о текущих горутинах.
- **`/debug/pprof/mutex`**: Профиль блокировок мьютексов.
- **`/debug/pprof/threadcreate`**: Данные о созданных потоках.

---

### 4. **Сбор данных профилирования**
Для сбора данных вы можете использовать инструмент командной строки `go tool pprof`:

```bash
go tool pprof http://localhost:6060/debug/pprof/profile
```

Эта команда откроет интерактивный режим, где можно будет исследовать собранный профиль.

---

### 5. **Анализ профилей**
В интерактивном режиме pprof вы можете использовать различные команды для анализа собранных данных:

- **`top`**: Показывает функции, потребляющие наибольшее количество ресурсов. 
- **`list <функция>`**: Показать исходный код определенной функции с аннотациями профилирования.
- **`web`**: Открыть графическое представление профиля в браузере.
- **`svg`**: Сохранить графическое представление профиля в формате SVG.
- **`peek <функция>`**: Показать все вызовы указанной функции.

Пример команды `top`:

```bash
(pprof) top
```

---

### 6. **Визуализация данных**
pprof позволяет строить графики взаимосвязей между функциями. Чтобы построить график, вам понадобится установить Graphviz. После установки используйте команду:

```bash
(pprof) web
```

Это откроет график в вашем браузере.

---

### 7. **Советы по использованию**
- **Регулярно профилируйте**: Профилирование должно стать частью вашего рабочего процесса, чтобы обеспечить стабильную производительность приложения.
- **Сравнение профилей**: Используйте команду `diff` для сравнения разных профилей и выявления изменений в производительности.
- **Используйте метрики**: Обратите внимание на количественные показатели, чтобы выделить функции с высоким потреблением ресурсов.
- **Изучение блокировок**: Для выявления проблем с конкуренцией используйте профили блокировок и мьютексов.

Конечно! В `pprof` есть несколько дополнительных команд и флагов, которые помогают в профилировании и анализе Go-программ. Давайте рассмотрим ключевые команды и некоторые дополнительные флаги, такие как `-race`.

### Основные команды в pprof

1. **`top`**: 
   - **Описание**: Показывает функции, которые используют наибольшее количество ресурсов (CPU или память).
   - **Использование**: Запустив команду, вы увидите список функций с указанием использованных ресурсов.
   ```bash
   (pprof) top
   ```

2. **`list <функция>`**: 
   - **Описание**: Показывает исходный код указанной функции с аннотациями, показывающими, сколько ресурсов она использует.
   - **Использование**: 
   ```bash
   (pprof) list myFunction
   ```

3. **`web`**: 
   - **Описание**: Создает графическое представление профиля и открывает его в браузере.
   - **Использование**: Просто введите команду, чтобы увидеть графики.
   ```bash
   (pprof) web
   ```

4. **`svg`**: 
   - **Описание**: Сохраняет графическое представление профиля в формате SVG.
   - **Использование**: Удобно для сохранения графиков для дальнейшего анализа.
   ```bash
   (pprof) svg > profile.svg
   ```

5. **`trace`**: 
   - **Описание**: Показывает подробную таймлинию, как выполнялся код.
   - **Использование**: После выполнения команды, вы сможете увидеть, как время выполнения распределялось между горутинами.
   ```bash
   (pprof) trace
   ```

6. **`peek <функция>`**: 
   - **Описание**: Показать количество вызовов и затрачиваемое время для указанной функции и ее вызовов.
   - **Использование**: 
   ```bash
   (pprof) peek myFunction
   ```

7. **`diff`**: 
   - **Описание**: Сравнивает два профиля или состояния, чтобы выявить изменения в производительности.
   - **Использование**: 
   ```bash
   go tool pprof -base oldProfile.pb.gz newProfile.pb.gz
   ```

### Дополнительные флаги и их использование

1. **`-race`**:
   - **Описание**: Этот флаг используется для обнаружения состояний гонки в коде. Он не является частью `pprof`, но его стоит упомянуть, так как он полезен в контексте производительности.
   - **Использование**: Чтобы использовать этот флаг, добавьте его при запуске вашего приложения. Это позволит вам выявлять гонки (race conditions) между горутинами.
   ```bash
   go run -race my_app.go
   ```

   Это полезно, когда вы хотите убедиться, что ваше приложение работает корректно с несколькими горутинами, особенно если вы видите странное поведение или снижения производительности.

2. **`-cpuprofile`**:
   - **Описание**: Позволяет вам указать файл, в который будет сохранен профиль CPU.
   - **Использование**: 
   ```bash
   go run -cpuprofile=cpu.profile my_app.go
   ```
   После выполнения вы можете анализировать полученный профиль с помощью `go tool pprof cpu.profile`.

3. **`-memprofile`**:
   - **Описание**: Позволяет сохранить профиль распределения памяти в файл.
   - **Использование**: 
   ```bash
   go run -memprofile=mem.profile my_app.go
   ```
   Анализируйте с помощью `go tool pprof mem.profile`.

4. **`-blockprofile`**:
   - **Описание**: Используется для анализа блокировок, которые происходят в вашем приложении.
   - **Использование**:
   ```bash
   go run -blockprofile=block.profile my_app.go
   ```
   Потом вы можете загружать профиль через `go tool pprof block.profile`.

### Когда использовать команды и флаги

- **`top`, `list`, `web`**: Используйте эти команды, когда хотите определить проблемы с производительностью, узкие места или просто получить представление о состоянии вашего приложения.
  
- **`trace`**: Подходит для глубокого анализа задержек и понимания, как время тратится в разных частях кода, особенно в многопоточных приложениях.

- **`peek`**: Полезно, когда нужно быстро исследовать определенные функции и их затраты по времени.

- **`diff`**: Используйте, когда у вас есть разные версии профилей, и вы хотите понять, что изменилось между запусками.

- **`-race`**: Не забывайте использовать этот флаг во время разработки, чтобы поймать состояния гонки, которые могут негативно повлиять на стабильность и производительность приложения.

## **1️⃣ Что такое `pprof` и для чего он нужен?**

❓ **Вопрос:**  
_Как вы используете `pprof` в Go и какие проблемы он решает?_

✅ **Ответ:**  
`pprof` – это инструмент профилирования, встроенный в Go. Он позволяет анализировать:

Используется для **оптимизации производительности** и **поиска узких мест**.

import _ "net/http/pprof"

}()
```

```

## **3️⃣ Как `pprof` собирает CPU-профили?**

❓ **Вопрос:**  
_Как `pprof` собирает данные о загрузке процессора?_

✅ **Ответ:**  
Go использует **семплирование (sampling profiling)**.

- **Горутинный планировщик** каждые **10 мс** (по умолчанию) прерывает выполнение программы и записывает **стек вызовов активной горутины**.
- Чем чаще функция встречается в профиле, тем больше времени она потребляет.

🔹 **Пример ручного CPU-профилирования в коде**:

```go
import (
	"log"
	"os"
	"runtime/pprof"
	"time"
)

func work() {
	for i := 0; i < 1e8; i++ {
		_ = i * i
	}
}

func main() {
	f, err := os.Create("cpu.prof")
	if err != nil {
		log.Fatal(err)
	}
	pprof.StartCPUProfile(f)
	defer pprof.StopCPUProfile()

	work()
	time.Sleep(2 * time.Second)
}
```

🔹 **Анализируем профиль CPU**:

```sh
go tool pprof cpu.prof
(pprof) top
(pprof) list work
(pprof) web  # Графическая визуализация
```

## **5️⃣ Как найти утечки горутин?**

❓ **Вопрос:**  
_Как `pprof` помогает находить утечки горутин?_

✅ **Ответ:**  
Когда горутины не завершаются, их количество растет и может **привести к утечке памяти или блокировкам**.

🔹 **Получить дамп горутин**:

```sh

```

🔹 **Показать самые активные горутины**:

```sh
(pprof) top
```

🔹 **Вывести стеки вызовов активных горутин**:

```sh
(pprof) list main.someFunction
```

📌 **Признаки утечки горутин**:

- Количество горутин **постоянно растет**.
- В `pprof` видно **зависшие горутины** (`chan recv` или `select` без таймера).

## **🔥 7️⃣ Как работает профилирование CPU в Go на низком уровне?**

❓ **Вопрос:**  
_Как `pprof` собирает данные о CPU? Как он влияет на производительность?_

✅ **Ответ:**

- Go использует **семплирование (sampling profiling)**.
- Запускается **таймер**, который **каждые 10 миллисекунд** вызывает обработчик `SIGPROF`.
- Обработчик анализирует **стек вызовов активной горутины** и сохраняет сэмпл.
- Если функция вызывается **очень часто**, то ее вклад в `pprof` будет большим.
- `pprof` **не влияет на скорость исполнения кода**, потому что использует **асинхронный механизм семплирования**.

📌 **Пример включения CPU-профиля вручную**:

```go
import (
	"log"
	"os"
	"runtime/pprof"
)

func work() {
	for i := 0; i < 1e8; i++ {
		_ = i * i
	}
}

func main() {
	f, err := os.Create("cpu.prof")
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	pprof.StartCPUProfile(f) // Включаем CPU-профиль
	defer pprof.StopCPUProfile() // Выключаем после завершения

	work()
}
```

🔹 **Анализ профиля:**

```sh
go tool pprof cpu.prof
(pprof) top
(pprof) list work
(pprof) web
```

## **🛠 8️⃣ Как профилировать выделение памяти в Go? (`heap`)**

❓ **Вопрос:**  
_Как `pprof` анализирует использование памяти? Как найти утечки?_

✅ **Ответ:**  
Go **не освобождает память мгновенно**. Она управляется **GC (Garbage Collector)**, поэтому иногда память кажется занятой, хотя уже не используется.

📌 **Чтобы получить точную картину, перед сбором профиля вызываем `runtime.GC()`**:

```go
import (
	"log"
	"os"
	"runtime"
	"runtime/pprof"
)

func allocateMemory() {
	data := make([]byte, 10*1024*1024) // 10 MB
	_ = data
}

func main() {
	f, err := os.Create("heap.prof")
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	allocateMemory()
	runtime.GC() // Принудительно запускаем GC перед профилированием
	pprof.WriteHeapProfile(f)
}
```

🔹 **Анализ `heap` профиля**:

```sh
go tool pprof heap.prof
(pprof) top
(pprof) list allocateMemory
(pprof) web
```

📌 **Что делать, если утечка памяти?**

- Проверить `heap`-профиль, какие структуры занимают больше всего памяти.
- Добавить `debug.FreeOSMemory()` для ручного вызова GC.

## **🚦 9️⃣ Как находить утечки горутин? (`goroutine`)**

❓ **Вопрос:**  
_Что делать, если программа зависает? Как найти утечки горутин?_

✅ **Ответ:**  
Если программа **не завершает горутины** (например, при `for {}` без `select`), то со временем число горутин растет.

📌 **Проверка количества горутин через `pprof`**:

```sh
go tool pprof http://localhost:6060/debug/pprof/goroutine
(pprof) top
(pprof) list main.someFunction
```

📌 **Пример утечки горутин:**

```go
package main

import (
	"fmt"
	"time"
)

func goroutineLeak() {
	ch := make(chan int)
	go func() {
		for {
			select {
			case <-ch:
				fmt.Println("Received data")
			}
			// ПРОБЛЕМА: горутина остается висеть
		}
	}()
}

func main() {
	for i := 0; i < 100; i++ {
		goroutineLeak()
	}
	time.Sleep(5 * time.Second)
}
```

📌 **Как исправить?**  
Добавить **таймер или закрытие канала**:

```go
	select {
	case <-ch:
		fmt.Println("Received data")
	case <-time.After(5 * time.Second):
		fmt.Println("Timeout! Exiting goroutine.")
		return
	}
```

## **🔒 1️⃣0️⃣ Как анализировать блокировки (`block` и `mutex`)?**

❓ **Вопрос:**  
_Как `pprof` помогает находить блокировки и проблемы с `sync.Mutex`?_

✅ **Ответ:**

- `block` **анализирует время ожидания горутин** (например, из-за `sync.Mutex`).
- `mutex` **показывает конкуренцию за мьютексы**.

📌 **Пример кода с блокировкой**:

```go
import (
	"fmt"
	"sync"
	"time"
)

var mu sync.Mutex

func slowFunction() {
	mu.Lock()
	defer mu.Unlock()
	time.Sleep(2 * time.Second) // Долгий захват мьютекса
}

func main() {
	for i := 0; i < 10; i++ {
		go slowFunction()
	}
	time.Sleep(5 * time.Second)
}
```

📌 **Анализ блокировок:**

```sh
go tool pprof http://localhost:6060/debug/pprof/block
```

📌 **Анализ конкуренции за мьютекс:**

```sh
go tool pprof http://localhost:6060/debug/pprof/mutex
```

📌 **Как исправить?**  
Использовать `sync.RWMutex` для чтения или убрать лишние блокировки.

## **🌟 1️⃣1️⃣ Что такое `pprof`+ `trace` и как его использовать?**

❓ **Вопрос:**  
_Чем `trace` отличается от `pprof`?_

✅ **Ответ:**

- `pprof` **анализирует** среднюю загрузку CPU, памяти, горутин.
- `trace` **отслеживает** ВСЕ события в коде, включая работу горутин, IO, `syscall`.

📌 **Пример включения `trace`**:

```go
import (
	"log"
	"os"
	"runtime/trace"
)

func main() {
	f, err := os.Create("trace.out")
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	trace.Start(f)
	defer trace.Stop()

	// Код для анализа
}
```

📌 **Анализ с `trace`**:

```sh
go tool trace trace.out
```

Откроется **визуальный анализатор** в браузере.

Какие бывают "флаги" (профили), какие команды есть в консоли, параметры просмотра и что делает программа.

---

## 1. **Что такое pprof и зачем нужен**

`pprof` — это инструмент для профилирования Go-программ: помогает находить "узкие места" (CPU, память, блокировки и др.), визуализировать эти данные, оптимизировать код.

---

## 2. **Виды профилей (флаги)**

Флашами часто называют виды профилей (profile types), которые доступны в Go:

- **heap** — профиль памяти (распределение памяти по функциям)
- **cpu** — профиль процессорного времени (что грузит CPU)
- **goroutine** — стек вызовов всех горутин
- **block** — где происходят блокировки goroutine (runtime.SetBlockProfileRate)
- **mutex** — где происходят конкуренции за мьютексы (runtime.SetMutexProfileFraction)
- **threadcreate** — где создавались ОС-потоки

**Использование:**
- `http://localhost:6060/debug/pprof/heap`
- `http://localhost:6060/debug/pprof/profile` (CPU, по умолчанию 30s)
- `http://localhost:6060/debug/pprof/goroutine`
- и т.д.

---

## 3. **Запуск профилирования**

Обычно в коде:
```go
import _ "net/http/pprof"

go func() {
    log.Println(http.ListenAndServe("localhost:6060", nil))
}()
```
Далее можно смотреть профили по адресу http://localhost:6060/debug/pprof/

---

## 4. **Ключевые команды pprof в консоли**

### Сбор профиля в файл:
- **CPU**:  
  `go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30`
- **Heap**:  
  `go tool pprof http://localhost:6060/debug/pprof/heap`
- **Goroutine**:  
  `go tool pprof http://localhost:6060/debug/pprof/goroutine`
- **Block**:  
  `go tool pprof http://localhost:6060/debug/pprof/block`
- **Mutex**:  
  `go tool pprof http://localhost:6060/debug/pprof/mutex`

### Открыть локальный профиль:
- `go tool pprof cpu.pprof`
- `go tool pprof heap.pprof`

---

## 5. **Ключевые команды внутри интерактивной консоли pprof**

- `top` — показать топ функций по времени/памяти
- `list <func>` — подробный разбор конкретной функции (с исходником)
- `web` — открыть SVG-граф вызовов (нужен graphviz)
- `svg` — сохранить SVG-граф
- `png` — сохранить PNG-граф
- `tree` — выводит дерево вызовов
- `callgrind` — экспорт в формат callgrind (для KCachegrind)
- `help` — список всех команд

---

## 6. **Параметры просмотра (важные флаги pprof)**

- `-http=:8080` — запустить web-интерфейс pprof (`go tool pprof -http=:8081 cpu.pprof`)
- `-text` — текстовый вывод (по умолчанию)
- `-pdf` — PDF-граф
- `-proto` — protobuf-вывод

---

## 7. **Что делает pprof-программа (в целом)**

- Позволяет собрать данные о работе программы в рантайме (CPU, память, блокировки и др.)
- Позволяет визуализировать, анализировать эти данные
- Помогает находить медленные или "жадные" по ресурсам функции

---

## 8. **Пример быстрой работы**

1. В коде:  
   ```go
   import _ "net/http/pprof"
   go http.ListenAndServe(":6060", nil)
   ```
2. Запустить программу, нагрузить её.
3. В консоли собрать профиль:  
   `go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30`
4. В интерактивном pprof:
   - `top`
   - `list main.expensiveFunction`
   - `web`

---

## 9. **Дополнительно**

- Для сбора профиля можно использовать переменные окружения (например, `GODEBUG=gctrace=1` для GC).
- Для глубокого анализа часто комбинируют несколько профилей (CPU+heap+block).
- Для production часто используют профилирование на реальных нагрузках.
