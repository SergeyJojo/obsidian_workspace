
В распределенных системах, помимо классического метода **остатка от деления (`hash % N`)**, существует несколько альтернативных способов определения номера шарда по хешу. Каждый из них имеет свои преимущества и недостатки в зависимости от сценария использования.

---

## **1. Consistent Hashing (Консистентное хеширование)**
**Принцип:**  
- Ключи и шарды размещаются на **виртуальном кольце** (хеш-кольце).  
- Шард для ключа определяется как ближайший узел **по часовой стрелке**.  

**Преимущества:**  
✅ Минимизация перераспределения данных при добавлении/удалении шардов (меняется только `1/N` данных).  
✅ Подходит для динамически масштабируемых систем (например, CDN, распределенные кэши).  

**Недостатки:**  
❌ Сложнее реализовать, чем остаток от деления.  
❌ Может потребоваться балансировка (виртуальные узлы).  

**Пример:**  
```python
import hashlib

def get_shard(key, shards):
    hash_val = int(hashlib.md5(key.encode()).hexdigest(), 16)
    angle = hash_val % 360  # Представляем кольцо как 360 градусов
    
    for shard in sorted(shards):
        if angle <= shard['angle']:
            return shard['id']
    return shards[0]['id']  # Замыкание кольца
```

## **2. Rendezvous Hashing (Highest Random Weight)**
**Принцип:**  
- Для каждого ключа вычисляется **вес** (`weight`) с каждым шардом.  
- Выбирается шард с **наибольшим весом**.  

**Формула:**  
```
weight = hash(key + shard_id)
```

**Преимущества:**  
✅ Равномерное распределение.  
✅ Минимальное перемещение данных при изменении числа шардов.  

**Недостатки:**  
❌ Вычислительно дороже (нужно считать хеш для каждого шарда).  

**Пример:**  
```python
def get_shard(key, shards):
    max_weight = -1
    selected_shard = None
    
    for shard in shards:
        weight = int(hashlib.md5(f"{key}_{shard}".encode()).hexdigest(), 16)
        if weight > max_weight:
            max_weight = weight
            selected_shard = shard
    return selected_shard
```

## **3. Jump Consistent Hash**
**Принцип:**  
- Детерминированный алгоритм на основе **линейного сканирования с прыжками**.  
- Эмулирует случайное распределение без хранения состояния.  

**Преимущества:**  
✅ Очень быстрый (`O(ln N)`).  
✅ Не требует хранения состояния (нет виртуального кольца).  

**Недостатки:**  
❌ Не поддерживает произвольное удаление шардов (только последовательное добавление в конец).  

**Пример (на Go):**  
```go
func JumpHash(key uint64, buckets int) int {
    var b, j int64
    for j < int64(buckets) {
        b = j
        key = key*2862933555777941757 + 1
        j = int64(float64(b+1) * (float64(1<<31) / float64((key>>33)+1)))
    }
    return int(b)
}
```

## **4. Maglev Hashing**
**Принцип:**  
- Использует **таблицу поиска** (lookup table), построенную на основе хешей.  
- Популярен в балансировщиках нагрузки (например, Google Maglev).  

**Преимущества:**  
✅ Почти нулевые затраты при поиске шарда (`O(1)`).  
✅ Минимальное перемещение данных.  

**Недостатки:**  
❌ Сложная инициализация таблицы.  
❌ Не подходит для очень динамичных кластеров.  

---

## **5. Range-Based Sharding (Диапазонный шардинг)**
**Принцип:**  
- Ключи сортируются, и шарды отвечают за **диапазоны** (например, `A-F`, `G-M`).  
- Хеш преобразуется в строку/число, которое попадает в диапазон.  

**Пример:**  
```python
def get_shard(key, ranges):
    hash_val = hash(key)  # Приводим к числу
    for shard, (start, end) in ranges.items():
        if start <= hash_val <= end:
            return shard
    return ranges[-1]  # fallback
```

---

## **6. CRC32/MurmurHash с битовыми масками**
**Принцип:**  
- Хеш преобразуется в битовую маску для определения шарда.  
- Полезно, когда число шардов — степень двойки (`2^N`).  

**Пример:**  
```python
def get_shard(key, shard_count):
    hash_val = zlib.crc32(key.encode()) & 0xffffffff
    return hash_val & (shard_count - 1)  # shard_count должно быть 2^N
```

## **Сравнение методов**
| Метод                   | Равномерность | Изменение числа шардов | Производительность | Сложность |
|--------------------------|---------------|------------------------|--------------------|-----------|
| **Остаток от деления**   | Средняя       | Плохо (`O(N)` изменений) | `O(1)`             | Низкая    |
| **Consistent Hashing**   | Высокая       | Хорошо (`O(1/N)`)       | `O(log N)`         | Средняя   |
| **Rendezvous Hashing**   | Очень высокая | Отлично (`O(1)`)        | `O(N)`             | Высокая   |
| **Jump Hash**            | Высокая       | Только добавление       | `O(ln N)`          | Низкая    |
| **Maglev**               | Высокая       | Хорошо                  | `O(1)`             | Очень высокая |
| **Range-Based**          | Зависит       | Средне                  | `O(log N)`         | Средняя   |

---

## **Выбор метода**
- **Динамические кластеры** → Consistent Hashing или Rendezvous.  
- **Статические кластеры** → Остаток от деления или Jump Hash.  
- **Максимальная скорость** → Maglev или битовые маски.  

Для CS:GO-подобных систем (например, шардинг игровых серверов) чаще используют **Consistent Hashing** или **Rendezvous**.
