Паттерн **Bulkhead** (от англ. _переборка_, как в корабле) — это **архитектурный шаблон отказоустойчивости**, цель которого — **ограничить распространение сбоев** между компонентами системы.

---

## 🚢 Метафора из судостроения:

> Корабль разделён на герметичные отсеки (bulkheads).  
> Если один отсек затопило — остальные продолжают работать, и корабль не тонет.

---

## 💡 Идея в софте:

Разделить систему на **изолированные зоны (отсеки)**, чтобы:

- сбой или перегрузка **одной части** не повлияла на **другие**
    
- например, отказ в одном внешнем сервисе не "утянул" за собой весь процесс
    

---

## 🔧 Как реализуется в практике:

### 1. **Ограничение ресурсов на изолированные блоки**

- У каждой задачи/сервиса/типа запроса — **свой пул потоков / горутин / соединений**
    
- Один сервис не может занять все ресурсы и "задушить" остальные
    

### 2. **Очереди и лимиты на уровне компонента**

- Каждому клиенту — свой rate limit или очередь
    
- Например, пользователь A не может повлиять на пользователя B
    

### 3. **Пулы подключения к разным зависимостям**

- БД A и БД B имеют **раздельные пулы**
    
- Если одна зависимость зависла — другая работает
    

---

## 📦 Примеры в разных технологиях

|Контекст|Bulkhead-подход|
|---|---|
|Goroutines|Пул воркеров с каналами для каждого типа задачи|
|Thread pool (Java)|Разделение thread pool'ов по задачам|
|API Gateway|Раздельные rate limits по клиентам или сервисам|
|Kubernetes|Поддержка через **ресурсные лимиты + горизонтальное масштабирование**|
|Istio / Service Mesh|Выделенные лимиты запросов, очереди и retries|

---

## 🤕 Без Bulkhead-а

Если нет изоляции, может случиться так:

- внешний сервис A завис — и "захватил" все потоки
    
- все пользователи ждут ответа, и система полностью зависает
    
- **эффект каскадного отказа (cascading failure)**
    

---

## ✅ С Bulkhead

- Завис A → мы просто **отключаем его зону**, но остальная система продолжает работать
    
- Можно показать заглушку или временный ответ
    

---

## 🧠 Часто сочетается с:

- **Circuit Breaker** — разрывает соединение при ошибках
    
- **Retry / Timeout** — попытки повтора с ограничениями
    
- **Rate Limiter** — ограничивает частоту
    

---

## 📌 Пример (Go)

```go
// Пулы для разных сервисов
type Bulkhead struct {
	semaphore chan struct{}
}

func NewBulkhead(limit int) *Bulkhead {
	return &Bulkhead{semaphore: make(chan struct{}, limit)}
}

func (b *Bulkhead) Execute(fn func()) {
	b.semaphore <- struct{}{} // если есть место
	go func() {
		defer func() { <-b.semaphore }()
		fn()
	}()
}
```

## 🧾 Вывод

**Bulkhead-паттерн** — это способ **изолировать части системы**, чтобы одна часть не "утопила" всё остальное.  
Простой, но **очень эффективный** механизм устойчивости и доступности.
