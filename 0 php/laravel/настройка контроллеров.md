В Laravel работа с контроллерами гибко настраивается благодаря множеству встроенных возможностей. Ниже — **полный обзор опций и подходов**, доступных при использовании контроллеров в Laravel (актуально для версий 8–11+, особенно с учётом современных практик, включая микросервисы и лёгкие архитектуры).

---

## 🔹 1. **Типы контроллеров**

### ✅ **Обычные (Invokable) контроллеры**
Если контроллер выполняет **одну задачу**, можно использовать `__invoke()`:
```php
class ShowProfileController extends Controller
{
    public function __invoke($id)
    {
        return view('profile', ['user' => User::findOrFail($id)]);
    }
}
```
Маршрут:
```php
Route::get('/profile/{id}', ShowProfileController::class);
```

> Подходит для **микросервисных или легковесных** приложений — минимум boilerplate.

---

### ✅ **Resource-контроллеры**
Генерируют полный набор CRUD-методов:
```bash
php artisan make:controller PostController --resource
```
Содержит методы: `index`, `create`, `store`, `show`, `edit`, `update`, `destroy`.

Маршрут:
```php
Route::resource('posts', PostController::class);
```

Для API (без `create`/`edit`):
```bash
php artisan make:controller API/PostController --api
```
→ Используется в **API-only или headless-проектах**.

---

### ✅ **Singleton-контроллеры** (Laravel 8+)
Для ресурсов, существующих в единственном экземпляре (например, профиль):
```php
Route::singleton('profile', ProfileController::class);
```
Генерирует маршруты: `show`, `edit`, `update` (без `index`/`create`/`destroy`).

---

## 🔹 2. **Привязка к маршрутам**

### 📌 Через массив:
```php
Route::get('/users', [UserController::class, 'index']);
```

### 📌 Через строку (устаревший стиль, не рекомендуется в новых версиях):
```php
Route::get('/users', 'UserController@index'); // Laravel ≤7
```

> **Современный Laravel требует указания класса как `[Class::class, 'method']`**.

---

## 🔹 3. **Middleware в контроллерах**

### На уровне всего контроллера:
```php
class DashboardController extends Controller
{
    public function __construct()
    {
        $this->middleware('auth');
        $this->middleware('verified')->only('show');
    }
}
```

### Через атрибуты (PHP 8+, Laravel 9+):
```php
use Illuminate\Routing\Controllers\Middleware;

#[Middleware('auth')]
class DashboardController extends Controller
{
    #[Middleware('role:admin')]
    public function destroy($id) { ... }
}
```

> Атрибуты — **более чистый и декларативный способ**, особенно в микросервисах.

---

## 🔹 4. **Автоматическая привязка (Implicit Binding)**

Laravel автоматически подставляет модель по ID:
```php
public function show(User $user)
{
    return view('user', compact('user'));
}
```
→ `GET /users/5` → `$user = User::findOrFail(5)`

### Кастомизация ключа:
```php
// В модели User
public function getRouteKeyName()
{
    return 'slug'; // вместо id
}
```

### Явная привязка (в RouteServiceProvider):
```php
Route::bind('user', function ($value) {
    return User::where('external_id', $value)->firstOrFail();
});
```

## 🔹 5. **Формирование ответов**

Контроллеры могут возвращать:
- **View**: `return view('welcome');`
- **JSON**: `return response()->json(['data' => $posts]);`
- **Redirect**: `return redirect()->route('posts.index');`
- **Ошибка**: `abort(403, 'Access denied');`
- **Поток/файл**: `return response()->download($path);`

В **API-контроллерах** часто возвращают **Resource-коллекции**:
```php
return PostResource::collection(Post::all());
```

---

## 🔹 6. **Validation и Form Request**

Вместо валидации в контроллере — выносите в **Form Request**:
```bash
php artisan make:request StorePostRequest
```
```php
public function store(StorePostRequest $request)
{
    $post = Post::create($request->validated());
    return redirect()->route('posts.show', $post);
}
```

> Улучшает читаемость и тестируемость — особенно важно в **сложных или распределённых системах**.

---

## 🔹 7. **Конструктор и DI (Dependency Injection)**

Вы можете внедрять зависимости прямо в методы:
```php
public function store(StorePostRequest $request, Mailer $mailer)
{
    // $mailer автоматически внедряется
}
```

Также — в конструктор:
```php
public function __construct(
    private PostService $postService
) {}
```

> PHP 8+ **promoted properties** упрощают DI.

---

## 🔹 8. **Организация контроллеров**

### По слоям:
- `Http/Controllers/` — веб-контроллеры
- `Http/Controllers/API/` — API-контроллеры
- `Http/Controllers/Admin/` — админка

### В микросервисах:
- Часто **один контроллер = один endpoint**
- Или вообще **без контроллеров** — только **замыкания в маршрутах** (для ultra-lightweight сервисов)

---

## 🔹 9. **Автоматическая регистрация (Controller Discovery)**

Laravel **не требует явной регистрации контроллеров** — они autoload'ятся через PSR-4.

Но можно использовать **explicit binding** через `Route::controller()` (редко):
```php
Route::controller(UserController::class)->group(function () {
    Route::get('/users', 'index');
    Route::get('/users/{id}', 'show');
});
```

> Не рекомендуется — теряется прозрачность маршрутов.

---

## 🔹 10. **Тестирование контроллеров**

Laravel позволяет легко тестировать действия контроллеров:
```php
$response = $this->get('/users/1');
$response->assertOk();
$response->assertViewHas('user');
```

Или через вызов метода напрямую (в unit-тестах):
```php
$controller = new UserController();
$result = $controller->show(User::factory()->create());
```

---

## ✅ Итог

Laravel предлагает **многоуровневую и гибкую работу с контроллерами**:
- От **invokable-контроллеров** (микросервисы) до **resource-контроллеров** (CRUD)
- Поддержка **middleware через конструктор или атрибуты**
- **Автоматическая привязка моделей**
- **Чистая архитектура** через Form Requests и Service-слои
- Полная совместимость с **API, SPA, очередями, event-системой**

Если вы настраиваете **лёгкий Laravel-стек** или **микросервис**, рекомендуется:
- Использовать **invokable-контроллеры** или **замыкания**
- Минимизировать логику в контроллерах (выносить в сервисы)
- Применять **атрибуты вместо конструктора** для middleware
