## 📁 Что содержит `/proc` в Linux

Каталог `/proc` — это **виртуальная файловая система**, отображающая **текущее состояние ядра и процессов**. Она **не хранится на диске**, а создаётся **в оперативной памяти ядром** в реальном времени.

### Основное содержимое:

- `/proc/[PID]/` — информация о конкретном процессе:
    
    - `cmdline` — команда запуска
        
    - `cwd` — текущая рабочая директория
        
    - `fd/` — открытые файловые дескрипторы
        
    - `status`, `stat`, `maps`, `limits` и т. д.
        
- Общесистемные файлы:
    
    - `/proc/cpuinfo` — информация о CPU
        
    - `/proc/meminfo` — о RAM
        
    - `/proc/uptime` — время работы
        
    - `/proc/modules` — загруженные модули ядра
        
    - `/proc/sys/` — дерево параметров для настройки ядра (через `sysctl`)
        
    - `/proc/filesystems` — поддерживаемые ФС
        
    - `/proc/mounts` — монтированные файловые системы
        
    - `/proc/net/` — сетевые настройки

## 🧩 Какие технологии изоляции предоставляет Linux

Linux предоставляет **низкоуровневые механизмы**, на которых основаны контейнеры:

|Изоляция|Механизм|Назначение|
|---|---|---|
|🧱 Пространство имён (namespaces)|`CLONE_NEW*` flags (`unshare`, `setns`)|Изолируют ресурсы между процессами: `pid`, `net`, `mnt`, `ipc`, `uts`, `user`, `time`|
|📈 Контроль ресурсов|**cgroups (Control Groups)**|Ограничивают CPU, память, I/O, сеть и др.|
|🔒 Capability drop|`capabilities(7)`|Удаление прав root, например `CAP_NET_ADMIN`|
|🧑 Пользователи|**User namespaces**|У root внутри контейнера нет прав снаружи|
|📦 seccomp|`seccomp-bpf` фильтры|Ограничение системных вызовов|
|🧼 AppArmor / SELinux|Мандатное управление доступом (MAC)|Ограничение поведения процессов|

## 📦 Какие есть системы контейнеризации

> Контейнеризация — упаковка приложения и его окружения в **изолированную среду**.

### Основные контейнерные платформы:

|Система|Особенности|
|---|---|
|**Docker**|Самая популярная. Удобный API, образы, volume, network|
|**Podman**|Альтернатива Docker от Red Hat, без демона (`daemonless`)|
|**LXC / LXD**|Более близко к системным контейнерам, чем Docker|
|**systemd-nspawn**|Минималистичная альтернатива от systemd|
|**rkt** (устаревший)|Проект CoreOS, заменён|

---

## ⚙️ Какие есть системы оркестрации

> Оркестрация — управление **множеством контейнеров**: запуск, масштабирование, отказоустойчивость и сеть.

### Популярные оркестраторы:

|Оркестратор|Характеристика|
|---|---|
|**Kubernetes**|Де-факто стандарт. Поддержка масштабирования, HA, service discovery, namespaces|
|**Docker Swarm**|Более простой, встроен в Docker, но менее гибкий|
|**Nomad** (от HashiCorp)|Лёгкий, можно запускать не только контейнеры|
|**OpenShift**|Enterprise-решение на базе Kubernetes|
|**Mesos / Marathon**|Ранее популярные, сейчас утратили позиции|
