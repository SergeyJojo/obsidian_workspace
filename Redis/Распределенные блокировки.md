В Redis механизм блокировок — это способ организовать взаимное исключение (mutual exclusion) между несколькими клиентами в распределённой системе, чтобы в один момент времени только один клиент мог работать с общим ресурсом.

### 🔒 Как устроена базовая блокировка

Основной и самый надёжный способ создания блокировки в Redis — использование команды `SET` с особыми параметрами.

```bash
SET resource_name my_random_value NX PX 30000
```

Эта команда работает так:
*   **NX**: Убедиться, что ключ (`resource_name`) **не существует**, прежде чем установить его. Это основа взаимного исключения.
*   **PX 30000**: Установить для ключа **время жизни** в миллисекундах (здесь — 30000 мс, или 30 секунд). Это предотвращает вечную блокировку, если клиент внезапно "упадёт".
*   **my_random_value**: **Уникальное значение**, которое генерируется каждым клиентом. Оно необходимо для безопасного освобождения блокировки.

Чтобы безопасно отпустить блокировку, используется скрипт на Lua, который проверяет, совпадает ли значение в ключе с тем, которое установил клиент, и только тогда удаляет его.

```lua
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
```

### 🛡️ Алгоритм Redlock для надёжных систем

Одиночный экземпляр Redis становится единой точкой отказа. Если он недоступен, механизм блокировок перестанет работать. Для создания отказоустойчивого менеджера распределённых блокировок (DLM) был предложен алгоритм **Redlock**.

Redlock требует наличия **независимых мастер-экземпляров Redis** (рекомендуется 5). Клиент, чтобы получить блокировку:
1.  Засекает текущее время.
2.  Последовательно пытается установить одну и ту же блокировку (с одинаковым именем и случайным значением) на каждом из N экземпляров.
3.  Блокировка считается полученной, если она установлена на **большинстве** экземпляров (например, на 3 из 5), и при этом общее время, затраченное на получение, **меньше срока жизни блокировки**.

### ⚠️ Важные особенности и гарантии

При работе с блокировками в Redis важно понимать предоставляемые гарантии и ограничения.

| Гарантия / Особенность | Описание |
| :--- | :--- |
| **Безопасность (Взаимное исключение)** | В любой момент времени блокировку может удерживать только один клиент. |
| **Отсутствие взаимных блокировок (Deadlock-free)** | Блокировка в конечном счёте будет получена, даже если текущий владелец отключится (благодаря TTL). |
| **Отказоустойчивость** | Redlock остаётся работоспособным, пока функционирует большинство узлов Redis. |
| **Автоматическое освобождение** | Время жизни (TTL) гарантирует, что блокировка будет автоматически отпущена по его истечении. |
