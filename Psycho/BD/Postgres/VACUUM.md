
В PostgreSQL команда VACUUM используется для очистки и оптимизации таблиц, освобождения пространства, занятого "мёртвыми кортежами" (dead tuples), и обновления статистики для планировщика запросов. Однако VACUUM не является однотипной операцией — у неё есть несколько вариантов и модификаций, которые применяются в зависимости от задачи. Давайте разберём основные виды VACUUM, их назначение и особенности.

---

Основные виды VACUUM

1. Обычный VACUUM
    
    sql
    
    ```sql
    VACUUM [имя_таблицы];
    ```
    
    - Что делает:
        
        - Убирает "мёртвые кортежи" из кучи, освобождая пространство для повторного использования внутри таблицы.
            
        - Не возвращает освободившееся место операционной системе (размер файла таблицы на диске не уменьшается).
            
        - Обновляет указатели в индексах, чтобы они не ссылались на мёртвые кортежи.
            
    - Особенности:
        
        - Не блокирует таблицу для чтения или записи (работает параллельно с другими операциями).
            
        - Подходит для регулярного обслуживания.
            
    - Когда использовать: Если нужно просто очистить таблицу от мёртвых кортежей без изменения её структуры.
        
2. VACUUM FULL
    
    sql
    
    ```sql
    VACUUM FULL [имя_таблицы];
    ```
    
    - Что делает:
        
        - Полностью перестраивает таблицу, удаляя мёртвые кортежи и сжимая её.
            
        - Возвращает освободившееся место операционной системе (уменьшает физический размер файла таблицы).
            
        - Переписывает все данные в новый файл, устраняя фрагментацию.
            
    - Особенности:
        
        - Требует эксклюзивной блокировки таблицы (другие операции с таблицей невозможны во время выполнения).
            
        - Более ресурсоёмкий процесс, чем обычный VACUUM.
            
    - Когда использовать: Когда таблица сильно фрагментирована, и нужно вернуть место на диск.
        
3. VACUUM ANALYZE
    
    sql
    
    ```sql
    VACUUM ANALYZE [имя_таблицы];
    ```
    
    - Что делает:
        
        - Выполняет обычный VACUUM (освобождает пространство в таблице).
            
        - Дополнительно обновляет статистику планировщика запросов (например, распределение значений в столбцах).
            
    - Особенности:
        
        - Не блокирует таблицу, как и обычный VACUUM.
            
        - Статистика помогает планировщику выбирать оптимальные планы выполнения запросов.
            
    - Когда использовать: После значительных изменений данных (много вставок, обновлений, удалений), чтобы улучшить производительность запросов.
        

---

Дополнительные модификации

PostgreSQL позволяет комбинировать VACUUM с опциями для более точного управления:

1. VACUUM FREEZE
    
    sql
    
    ```sql
    VACUUM FREEZE [имя_таблицы];
    ```
    
    - Что делает:
        
        - "Замораживает" идентификаторы транзакций (Transaction ID, XID) в строках, чтобы предотвратить проблему "обёртывания транзакций" (transaction ID wraparound).
            
        - Помечает старые строки как "замороженные", чтобы они больше не зависели от текущих XID.
            
    - Особенности:
        
        - Полезно для старых таблиц с редко изменяемыми данными.
            
        - Может быть ресурсоёмким, так как переписывает метаданные строк.
            
    - Когда использовать: Когда приближается лимит XID (около 2 миллиардов транзакций), чтобы избежать необходимости экстренного вмешательства.
        
2. VACUUM с конкретными столбцами (с версии 14)
    
    sql
    
    ```sql
    VACUUM (INDEX_CLEANUP OFF) [имя_таблицы];
    ```
    
    - Что делает:
        
        - Позволяет управлять очисткой индексов отдельно от кучи.
            
        - Опция INDEX_CLEANUP OFF отключает очистку индексов, что ускоряет процесс, если индексы не требуют внимания.
            
    - Особенности:
        
        - Гибкость в управлении производительностью.
            
    - Когда использовать: Если нужно минимизировать время выполнения VACUUM и индексы уже в порядке.
        
3. VERBOSE
    
    sql
    
    ```sql
    VACUUM VERBOSE [имя_таблицы];
    ```
    
    - Что делает:
        
        - Выводит подробную информацию о процессе: сколько строк обработано, сколько места освобождено и т.д.
            
    - Особенности:
        
        - Не изменяет поведение VACUUM, только добавляет логирование.
            
    - Когда использовать: Для диагностики или анализа состояния таблицы.
        

---

Автоматический VACUUM (Autovacuum)

- Что это: Встроенный процесс в PostgreSQL, который автоматически запускает VACUUM и ANALYZE на таблицах, где накопилось много мёртвых кортежей.
    
- Как работает:
    
    - Контролируется параметрами в postgresql.conf, например:
        
        - autovacuum (включён по умолчанию).
            
        - autovacuum_vacuum_threshold (минимальное количество мёртвых кортежей для запуска).
            
        - autovacuum_vacuum_scale_factor (доля таблицы, которая должна измениться).
            
    - Работает в фоновом режиме, не блокируя таблицы.
        
- Особенности:
    
    - Предотвращает накопление мёртвых кортежей и проблему обёртывания XID.
        
    - Настраивается для каждой таблицы индивидуально через ALTER TABLE.
        
- Когда использовать: В большинстве случаев достаточно полагаться на autovacuum, но в высоконагруженных системах может потребоваться ручная настройка.
    

---

Примеры использования

1. Очистка конкретной таблицы:
    
    sql
    
    ```sql
    VACUUM users;
    ```
    
2. Полное сжатие таблицы с возвратом места:
    
    sql
    
    ```sql
    VACUUM FULL users;
    ```
    
3. Очистка с обновлением статистики:
    
    sql
    
    ```sql
    VACUUM ANALYZE users;
    ```
    
4. Диагностика состояния таблицы:
    
    sql
    
    ```sql
    VACUUM VERBOSE users;
    ```
    
5. Предотвращение обёртывания XID:
    
    sql
    
    ```sql
    VACUUM FREEZE users;
    ```
    

---

Итог

- Обычный VACUUM: Лёгкая очистка без блокировок.
    
- VACUUM FULL: Глубокая очистка с сжатием, но с блокировкой.
    
- VACUUM ANALYZE: Очистка + обновление статистики.
    
- VACUUM FREEZE: Защита от обёртывания XID.
    
- Autovacuum: Автоматизация обслуживания.
    

Выбор типа зависит от задачи: регулярное обслуживание (обычный VACUUM или autovacuum), освобождение места (FULL), улучшение запросов (ANALYZE) или защита от редких проблем (FREEZE). Если у вас есть конкретный сценарий, могу помочь подобрать оптимальный подход!
