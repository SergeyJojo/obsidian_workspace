#linux

Вот 20 карточек по внутреннему устройству Linux

**Q: Что такое ядро Linux?** ::A: Центральный компонент ОС, управляющий ресурсами, процессами, памятью и драйверами устройств.
<!--SR:!2025-07-11,8,250-->

**Q: Чем отличается clone и fork** ::A: В Linux, `fork()` и `clone()` оба используются для создания новых процессов, но имеют разные уровни контроля над разделяемыми ресурсами. `fork()` создает точную копию вызывающего процесса, включая его память, файловые дескрипторы и другие ресурсы, с новым PID. `clone()` же позволяет более тонко настраивать, какие ресурсы будут разделяться между родительским и дочерним процессами, что позволяет создавать потоки или процессы с частичным разделением памяти.
<!--SR:!2025-07-11,8,250-->

**Q: Как работает системный вызов (syscall)?** ::A: Переключение из пользовательского режима в режим ядра через специальные инструкции процессора (например, int 0x80 или syscall).
<!--SR:!2025-07-01,3,250-->

**Q: Что такое процесс в Linux?** ::A: Экземпляр выполняемой программы с собственным виртуальным адресным пространством и ресурсами.
<!--SR:!2025-07-09,8,250-->

**Q: Как ядро хранит информацию о процессах?** ::A: В структуре task_struct, содержащей PID, состояние, регистры CPU, открытые файлы и другую метаинформацию.
<!--SR:!2025-07-25,17,250-->

**Q: Что такое демон (daemon)?** ::A: Фоновый процесс, обычно запускаемый при старте системы и не привязанный к терминалу.
<!--SR:!2025-07-01,3,250-->

**Q: Как работает планировщик процессов?** ::A: Использует алгоритм CFS (Completely Fair Scheduler) для распределения времени CPU между процессами.
<!--SR:!2025-07-10,9,250-->

**Q: Что такое inode в Linux?** ::A: Структура данных, описывающая файл (права, владельца, размер, расположение блоков на диске и т.д.).
<!--SR:!2025-07-10,9,250-->

**Q: Как организована виртуальная файловая система (VFS)?** ::A: Предоставляет унифицированный интерфейс для работы с разными ФС (ext4, NTFS, proc и др.) через общие структуры (inode, dentry).

**Q: Что такое procfs?** ::A: Виртуальная ФС, предоставляющая информацию о процессах и системе через файлы (/proc/[pid]/status, /proc/meminfo и др.).
<!--SR:!2025-07-11,8,250-->

**Q: Как работает механизм отображения файлов в память (mmap)?** ::A: Связывает файл или устройство с областью виртуальной памяти, загружая данные по требованию через page faults.
<!--SR:!2025-07-10,7,250-->

**Q: Что такое cgroups?** ::A: Механизм ядра для ограничения и мониторинга ресурсов (CPU, память, I/O) групп процессов.
<!--SR:!2025-07-10,7,250-->

**Q: Как работают пространства имен (namespaces)?** ::A: Обеспечивают изоляцию процессов (PID, сеть, точки монтирования и т.д.), используется в контейнерах.
<!--SR:!2025-07-01,3,250-->

**Q: Что такое модули ядра?** ::A: Загружаемые компоненты, расширяющие функциональность ядра без перезагрузки (драйверы, ФС и т.д.).
<!--SR:!2025-07-15,7,250-->

**Q: Как организована память в Linux?** ::A: Виртуальная память с разбиением на страницы (обычно 4KB), управляемая через MMU и таблицы страниц.
<!--SR:!2025-07-26,18,250-->

**Q: Что такое OOM killer?** ::A: Компонент ядра, завершающий процессы при нехватке памяти на основе "плохости" (oom_score).
<!--SR:!2025-07-09,8,250-->

**Q: Как работает механизм сигналов?** ::A: Асинхронные уведомления процессам (например, SIGTERM для завершения), обрабатываются обработчиками сигналов.
<!--SR:!2025-07-10,7,250-->

**Q: Что такое initramfs?** ::A: Временная корневая ФС в памяти, используемая на ранних этапах загрузки для монтирования реальной ФС.
<!--SR:!2025-07-10,7,250-->

**Q: Как работает механизм pipe?** ::A: Однонаправленный канал между процессами, реализованный через буфер в ядре (обычно 64KB).
<!--SR:!2025-07-11,8,250-->

**Q: Что такое udev?** ::A: Подсистема ядра для динамического управления устройствами (создание узлов в /dev, загрузка драйверов).
<!--SR:!2025-07-01,3,250-->

**Q: Как работает системный демон journald?** ::A: Собирает и хранит логи в бинарном формате с метаданными (systemd-journald).
<!--SR:!2025-07-18,9,250-->

Вот еще 20 карточек по внутреннему устройству Linux:

**Q: Что такое системный вызов fork()?** ::A: Создает точную копию процесса-родителя, отличающуюся только PID и некоторыми метаданными.
<!--SR:!2025-07-10,7,250-->

**Q: Как работает Copy-On-Write (COW) при fork()?** ::A: Память процессов делится до тех пор, пока один из них не попытается изменить данные - тогда создается отдельная копия.
<!--SR:!2025-07-16,7,250-->

**Q: Что такое демон kthreadd?** ::A: Специальный процесс ядра (PID=2), отвечающий за создание всех остальных потоков ядра.
<!--SR:!2025-07-12,9,250-->

**Q: Как работает механизм epoll?** ::A: Эффективный API для мониторинга множества файловых дескрипторов, использует callback-механизм вместо линейного сканирования.
<!--SR:!2025-07-03,3,250-->

**Q: Что такое slab-аллокатор?** ::A: Менеджер памяти ядра для эффективного выделения/освобождения часто используемых структур фиксированного размера.
<!--SR:!2025-07-12,9,250-->

**Q: Как работает механизм swap?** ::A: Выгрузка редко используемых страниц памяти на диск в специальный раздел или файл подкачки.
<!--SR:!2025-07-10,7,250-->

**Q: Что такое TTY в Linux?** ::A: Подсистема терминалов, включающая виртуальные консоли (/dev/ttyX), псевдотерминалы (/dev/pts) и последовательные порты.
<!--SR:!2025-07-11,8,250-->

**Q: Как работает аудит (auditd)?** ::A: Подсистема ядра для логирования системных событий (вызовы процессов, доступ к файлам и т.д.) по заданным правилам.
<!--SR:!2025-07-12,9,250-->

**Q: Что такое BPF (eBPF)?** ::A: Виртуальная машина в ядре для безопасного выполнения пользовательских программ на событиях ядра (трассировка, фильтрация и т.д.).
<!--SR:!2025-07-12,9,250-->

**Q: Как работает механизм netfilter?** ::A: Фреймворк ядра для фильтрации и модификации сетевых пакетов (основа iptables/nftables).
<!--SR:!2025-07-03,3,250-->

**Q: Что такое cgroups v2?** ::A: Новая версия контрольных групп с унифицированной иерархией и улучшенным управлением ресурсами.
<!--SR:!2025-07-02,3,250-->

**Q: Как работает файловая система tmpfs?** ::A: ФС в оперативной памяти, используемая для /dev/shm, /run и других временных данных.
<!--SR:!2025-07-12,9,250-->

**Q: Что такое демон systemd-udevd?** ::A: Современная замена udev, обрабатывающая события устройств и загружающая соответствующие модули ядра.

**Q: Как работает механизм fanotify?** ::A: API ядра для мониторинга изменений в файловой системе (используется антивирусами и backup-программами).

**Q: Что такое namespaces mount?** ::A: Изолированное дерево монтирования для группы процессов (используется в контейнерах).

**Q: Как работает демон dbus-daemon?** ::A: Системная шина сообщений между процессами, обеспечивающая IPC (межпроцессное взаимодействие).
<!--SR:!2025-07-11,8,250-->

**Q: Что такое KVM?** ::A: Модуль ядра для аппаратной виртуализации, использующий расширения процессора (Intel VT-x/AMD-V).
<!--SR:!2025-07-12,9,250-->

**Q: Как работает механизм seccomp?** ::A: Фильтрация системных вызовов для ограничения возможностей процессов (используется в Docker, Chrome).
<!--SR:!2025-07-12,9,250-->

**Q: Что такое демон rsyslogd?** ::A: Системный демон для обработки и маршрутизации логов (альтернатива journald).
<!--SR:!2025-07-02,3,250-->

**Q: Как работает файловая система devtmpfs?** ::A: Автоматически создает и управляет узлами устройств в /dev, интегрирована с udev.
<!--SR:!2025-07-10,7,250-->

Вот еще 20 карточек по внутреннему устройству Linux, сфокусированных на практических аспектах и тонкостях работы системы:

**Q: Как работает механизм transparent hugepages?** ::A: Автоматическое объединение 4KB страниц в огромные (2MB/1GB) для уменьшения TLB misses и ускорения работы с памятью (управляется через /sys/kernel/mm/transparent_hugepage/enabled).
<!--SR:!2025-07-12,9,250-->

**Q: Что такое dirty_ratio и как он влияет на производительность?** ::A: Процент памяти (по умолчанию 20%), при котором процессы блокируются для принудительной записи "грязных" страниц на диск (слишком низкое значение может вызвать лавину I/O).

**Q: Как работает O_DIRECT при открытии файлов?** ::A: Позволяет обходить кэш страниц ядра, напрямую работая с диском (используется в СУБД для контроля за кэшированием).
<!--SR:!2025-07-10,7,250-->

**Q: Что такое vDSO и зачем он нужен?** ::A: Виртуальная динамическая библиотека, ускоряющая частые системные вызовы (например, gettimeofday) без переключения в режим ядра.

**Q: Как работает механизм coredump?** ::A: При падении процесса ядро сохраняет его память в файл (обычно core.PID), анализируемый потом gdb (управляется ulimit -c и /proc/sys/kernel/core_pattern).
<!--SR:!2025-07-11,8,250-->

**Q: Что такое swapiness и как его настраивать?** ::A: Параметр (от 0 до 100 в /proc/sys/vm/swappiness), определяющий склонность ядра к использованию swap (0 = минимум свопинга, 100 = агрессивный свопинг).
<!--SR:!2025-07-12,9,250-->

**Q: Как работает файловая система overlayfs?** ::A: Объединяет несколько слоев ФС (read-only нижний + writeable верхний), используется в Docker для контейнеров.
<!--SR:!2025-07-03,3,250-->

**Q: Что такое ionice и как он влияет на I/O?** ::A: Утилита для задания приоритета ввода-вывода (от 0 - высший до 7 - низший), влияет на распределение времени доступа к диску.
<!--SR:!2025-07-17,8,250-->

**Q: Как работает механизм user namespaces?** ::A: Позволяет отображать UID/GID внутри контейнера в другие UID/GID на хосте (используется в rootless-контейнерах).
<!--SR:!2025-07-16,8,250-->

**Q: Что такое PSI (Pressure Stall Information)?** ::A: Метрики в /proc/pressure/ показывают нехватку ресурсов (CPU, память, I/O) - используются для proactive monitoring.
<!--SR:!2025-07-11,8,250-->

**Q: Как работает файловая система sysfs?** ::A: Виртуальная ФС (/sys), предоставляющая доступ к параметрам устройств и подсистем ядра в виде иерархии файлов.
<!--SR:!2025-07-17,9,250-->

**Q: Что такое cgroup freezer?** ::A: Подсистема cgroups, позволяющая "замораживать" все процессы в группе (приостанавливать выполнение без убийства).

**Q: Как работает механизм kprobes?** ::A: Позволяет ставить точки останова на функции ядра для отладки и трассировки без перезагрузки.
<!--SR:!2025-07-03,3,250-->

**Q: Что такое mlock() и когда его использовать?** ::A: Системный вызов для запрета выгрузки страниц памяти в swap (критично для СУБД и low-latency приложений).
<!--SR:!2025-07-03,3,250-->

**Q: Как работает демон irqbalance?** ::A: Распределяет аппаратные прерывания (IRQ) между ядрами CPU для оптимальной загрузки (особенно важно для сетевых пакетов).
<!--SR:!2025-07-16,8,250-->

**Q: Что такое splice() и vmsplice()?** ::A: Системные вызовы для эффективной передачи данных между файловыми дескрипторами и памятью без копирования (zero-copy).

**Q: Как работает механизм timerfd?** ::A: API для создания таймеров, интегрируемых в event loop (возвращает файловый дескриптор, срабатывающий по времени).
<!--SR:!2025-07-11,8,250-->

**Q: Что такое memory cgroup и как он ограничивает память?** ::A: Подсистема cgroups для контроля использования памяти (лимиты, учет, автоматическое убийство процессов при превышении).
<!--SR:!2025-07-10,7,250-->

**Q: Как работает файловая система configfs?** ::A: Виртуальная ФС (/sys/kernel/config) для динамической конфигурации модулей ядра через файловый интерфейс.

**Q: Что такое SCHED_DEADLINE и как настроить?** ::A: Политика планирования для real-time задач с гарантированным временем выполнения (настраивается через sched_setattr()).
<!--SR:!2025-07-16,7,250-->
