
### 1. **Основные компоненты Docker**:

- **Docker Engine**:
    
    - Основной компонент, который управляет контейнерами. Состоит из двух частей:
        - **Docker Daemon** (`dockerd`): Серверная часть, которая управляет контейнерами, образами, сетями и хранилищем данных.
        - **Docker CLI** (`docker`): Клиентская часть, с помощью которой ты взаимодействуешь с Docker через командную строку.
- **Контейнер**:
    
    - Легковесный, изолированный процесс, который запускает приложение и его зависимости. Контейнеры используют образ как шаблон для своей работы.
- **Образ (Image)**:
    
    - Шаблон для создания контейнеров, содержащий все необходимые файлы, зависимости, библиотеки и настройки для запуска приложения.
    - Docker образ является неизменяемым и состоит из слоев. Каждый слой — это изменение, внесенное в образ (например, установка пакета или создание файла).
- **Dockerfile**:
    
    - Скрипт, который описывает, как создать Docker образ. Содержит набор инструкций, таких как `FROM`, `RUN`, `COPY`, `CMD`, которые определяют, как будет построен образ.
- **Docker Hub**:
    
    - Официальный публичный реестр Docker образов. Ты можешь найти и загрузить образы для множества популярных приложений и сервисов.

### 2. **Основные команды Docker**:

- **Запуск контейнера**:
    
    ```bash
    docker run -d --name <container-name> <image-name>
    ```
    
- **Просмотр запущенных контейнеров**:
    
    ```bash
    docker ps
    ```
    
- **Просмотр всех контейнеров, включая остановленные**:
    
    ```bash
    docker ps -a
    ```
    
- **Остановка контейнера**:
    
    ```bash
    docker stop <container-name>
    ```
    
- **Запуск остановленного контейнера**:
    
    ```bash
    docker start <container-name>
    ```
    
- **Удаление контейнера**:
    
    ```bash
    docker rm <container-name>
    ```
    
- **Удаление образа**:
    
    ```bash
    docker rmi <image-name>
    ```
    
- **Просмотр логов контейнера**:
    
    ```bash
    docker logs <container-name>
    ```
    

### 3. **Работа с Dockerfile**:

- **Создание Dockerfile**: Dockerfile описывает, как строить образы. Вот базовый пример:
    
    ```dockerfile
    # Указание базового образа
    FROM ubuntu:20.04
    
    # Установка пакетов
    RUN apt-get update && apt-get install -y python3 python3-pip
    
    # Копирование файлов в контейнер
    COPY . /app
    
    # Установка зависимостей
    WORKDIR /app
    RUN pip install -r requirements.txt
    
    # Открытие порта
    EXPOSE 8080
    
    # Команда для запуска приложения
    CMD ["python3", "app.py"]
    ```
    
- **Построение образа**:
    
    ```bash
    docker build -t <image-name> .
    ```
    
- **Проверка образов**:
    
    ```bash
    docker images
    ```
    

### 4. **Сетевые компоненты Docker**:

- **Сеть**: Docker контейнеры могут общаться между собой через сети. Контейнеры, подключенные к одной сети, могут обмениваться данными напрямую.
    
- **Типы сетей**:
    
    - **bridge** (по умолчанию): Для изолированных сетей, когда контейнеры общаются друг с другом.
    - **host**: Контейнеры используют IP хоста для сетевого взаимодействия.
    - **none**: Нет сети, контейнеры не могут общаться с внешним миром.
    - **overlay**: Используется для связи контейнеров, работающих на разных хостах (например, в кластере Docker Swarm).
- **Создание сети**:
    
    ```bash
    docker network create <network-name>
    ```
    
- **Запуск контейнера с привязкой к сети**:
    
    ```bash
    docker run --network <network-name> -d <image-name>
    ```
    

### 5. **Хранение данных в Docker**:

- **Тома (Volumes)**:
    
    - Это механизм для хранения данных вне контейнера. Данные, хранящиеся в томах, сохраняются даже при удалении контейнера.
- **Создание тома**:
    
    ```bash
    docker volume create <volume-name>
    ```
    
- **Привязка тома к контейнеру**:
    
    ```bash
    docker run -d -v <volume-name>:<path-inside-container> <image-name>
    ```
    
- **Просмотр томов**:
    
    ```bash
    docker volume ls
    ```
    
- **Удаление тома**:
    
    ```bash
    docker volume rm <volume-name>
    ```
    

### 6. **Docker Compose**:

- **Что такое Docker Compose**:
    
    - Инструмент для работы с многоконтейнерными приложениями. Он использует файл `docker-compose.yml` для описания всех сервисов, сетей и томов, которые необходимы для работы приложения.
- **Пример файла `docker-compose.yml`**:
    
    ```yaml
    version: '3'
    services:
      web:
        image: nginx
        ports:
          - "80:80"
      app:
        build: .
        volumes:
          - ./app:/app
        environment:
          - APP_ENV=production
    ```
    
- **Запуск приложения с помощью Docker Compose**:
    
    ```bash
    docker-compose up -d
    ```
    
- **Остановка приложения**:
    
    ```bash
    docker-compose down
    ```
    

### 7. **Управление Docker-образами и реестры**:

- **Docker Hub**:
    
    - Официальный публичный реестр Docker, где можно найти образы для большинства приложений и сервисов.
- **Загрузка образа с Docker Hub**:
    
    ```bash
    docker pull <image-name>
    ```
    
- **Загрузка образа в Docker Hub**:
    
    ```bash
    docker push <image-name>
    ```
    
- **Использование собственного реестра**: Docker позволяет настроить приватный реестр, используя инструмент **Docker Registry**.
    

### 8. **Docker Swarm**:

- **Что такое Docker Swarm**:
    
    - Встроенная система оркестрации для Docker, которая позволяет управлять кластером Docker-узлов.
- **Инициализация кластера Swarm**:
    
    ```bash
    docker swarm init
    ```
    
- **Добавление узлов в кластер**:
    
    ```bash
    docker swarm join --token <join-token> <manager-ip>:2377
    ```
    
- **Управление сервисами Swarm**: Docker Swarm позволяет запускать сервисы, которые автоматически масштабируются и управляются.
    

### 9. **Безопасность Docker**:

- **Управление правами доступа**:
    
    - Docker использует модели безопасности для контейнеров, в том числе через настройки безопасности на уровне ядра (например, `seccomp`, `AppArmor`).
- **Использование Docker в защищенных режимах**:
    
    - Применение принципа наименьших привилегий, запуск контейнеров с минимальными правами.
