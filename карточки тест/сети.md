#net

Вот 20 карточек по компьютерным сетям

---  

**Q: Что такое модель OSI?** ::A: 7-уровневая модель взаимодействия сетевых протоколов (Физический, Канальный, Сетевой, Транспортный, Сеансовый, Представления, Прикладной).
<!--SR:!2025-07-02,3,250-->

**Q: Чем TCP отличается от UDP?** ::A: TCP гарантирует доставку (установка соединения, контроль ошибок), UDP — нет (быстрее, но ненадёжно).
<!--SR:!2025-07-08,7,250-->

**Q: Что такое NAT?** ::A: Преобразование приватных IP в публичные (и обратно) для выхода в интернет с локальных устройств.
<!--SR:!2025-07-10,7,250-->

**Q: Как работает DHCP?** ::A: Автоматически назначает IP-адреса устройствам в сети (Discover, Offer, Request, Acknowledge).
<!--SR:!2025-07-02,3,250-->

**Q: Что такое DNS и как он работает?** ::A: Система доменных имён, преобразует "example.com" в IP-адрес через иерархию серверов (корневые, TLD, авторитативные).
<!--SR:!2025-07-12,9,250-->

**Q: Что такое VLAN?** ::A: Виртуальное разделение одной физической сети на несколько логических (для безопасности/управления трафиком).
<!--SR:!2025-07-04,3,252-->

**Q: Чем отличается коммутатор (switch) от маршрутизатора (router)?** ::A: Коммутатор работает на канальном уровне (MAC-адреса), маршрутизатор — на сетевом (IP-адреса).
<!--SR:!2025-07-12,9,250-->

**Q: Что такое MTU?** ::A: Maximum Transmission Unit — максимальный размер пакета без фрагментации (например, 1500 байт для Ethernet).
<!--SR:!2025-07-11,8,250-->

**Q: Как проверить доступность хоста?** ::A: Команда `ping` (отправляет ICMP-пакеты).
<!--SR:!2025-07-10,9,250-->

**Q: Что такое ICMP?** ::A: Протокол для диагностики сети (используется в `ping` и `traceroute`).
<!--SR:!2025-07-08,7,250-->

**Q: Что такое subnet mask?** ::A: Определяет, какая часть IP-адреса относится к сети, а какая — к хосту (например, 255.255.255.0).
<!--SR:!2025-07-09,8,250-->

**Q: Как разделить сеть на подсети?** ::A: Через CIDR (например, 192.168.1.0/24 — 254 хоста, /25 — 126 хостов).
<!--SR:!2025-07-11,8,250-->

**Q: Что такое BGP?** ::A: Протокол динамической маршрутизации между автономными системами (AS) в интернете.
<!--SR:!2025-07-04,3,252-->

**Q: Как работает firewall?** ::A: Фильтрует трафик по правилам (блокировка портов, IP-адресов и т.д.).
<!--SR:!2025-07-09,8,250-->

**Q: Что такое SYN-флуд?** ::A: DDoS-атака, когда злоумышленник отправляет множество SYN-запросов, не завершая handshake TCP.
<!--SR:!2025-07-11,8,250-->

Q: Как защитить JWT? ::A: HTTPS, короткий срок жизни, проверка подписи

**Q: Что такое HTTP/2?** ::A: Бинарный протокол, основанный на мультиплексировании потоков через один TCP-канал.
<!--SR:!2025-07-13,10,270-->
**Q: Какие ключевые особенности HTTP/2?** ::A: Мультиплексирование, серверный push, бинарный формат, HPACK-сжатие заголовков.
<!--SR:!2025-07-04,3,252-->
**Q: Что такое HPACK в HTTP/2?** ::A: Алгоритм сжатия заголовков, уменьшающий трафик.
<!--SR:!2025-07-08,5,230-->
**Q: Что такое Stream в HTTP/2?** ::A: Логический канал для передачи запроса/ответа внутри одного TCP-соединения.  
**Q: Что такое Server Push в HTTP/2?** ::A: Возможность сервера отправить ресурсы заранее, до запроса клиента.  
**Q: Для чего нужен Frame в HTTP/2?** ::A: Для передачи данных в виде фрагментов (headers, data, priority и др.).
<!--SR:!2025-07-11,8,250-->
**Q: Как работает QoS в HTTP/2?** ::A: Поддерживается через приоритезацию stream'ов.
<!--SR:!2025-07-04,3,252-->

**Q: Что такое HTTP/3?** ::A: Третья версия HTTP, работающая поверх QUIC вместо TCP.  
**Q: На чём основан HTTP/3?** ::A: На протоколе QUIC, который использует UDP и обеспечивает быструю установку соединений.  
**Q: Какие преимущества у HTTP/3?** ::A: Отсутствие head-of-line блокировок, более быстрая установка соединения, встроенное TLS.  
**Q: Почему HTTP/3 лучше при плохой сети?** ::A: Из-за использования QUIC, который лучше восстанавливается после потерь.  
**Q: Что такое QUIC?** ::A: Транспортный протокол, сочетающий лучшее из TCP и TLS, с возможностью множества потоков внутри одного соединения.  
**Q: Как происходит миграция клиента между сетями в HTTP/3?** ::A: По ID соединения QUIC, а не по IP-адресу.

**Q: Что такое UDP?** ::A: Транспортный протокол, обеспечивающий дейтаграммы без гарантий доставки.
<!--SR:!2025-07-04,3,252-->
**Q: Чем UDP отличается от TCP?** ::A: Нет установки соединения, очередности, подтверждений или повторных попыток.  
**Q: Где применяется UDP?** ::A: VoIP, игры, DNS, DHCP, streaming.
<!--SR:!2025-07-02,3,250-->
**Q: Как проверить UDP-запросы?** ::A: Используя `tcpdump`, `Wireshark`, `nc`, `dig`.
<!--SR:!2025-07-04,3,252-->
**Q: Что такое UDP hole punching?** ::A: Техника обхода NAT через одновременные исходящие пакеты.
<!--SR:!2025-07-04,3,252-->
**Q: Может ли UDP быть надёжным?** ::A: Только если реализовать механизм подтверждений сверху.
<!--SR:!2025-07-02,3,250-->

**Q: Что такое ICMP?** ::A: Сетевой протокол, используемый для диагностики (ping, traceroute) и сообщений об ошибках.  
**Q: Как ping использует ICMP?** ::A: Посылает ECHO_REQUEST и ожидает ECHO_REPLY.  
**Q: Что делает командa traceroute?** ::A: Отправляет пакеты с увеличением TTL, чтобы получить ICMP Time Exceeded.  
**Q: Может ли ICMP работать через UDP?** ::A: Да, но чаще используется в связке с IP.  
**Q: Что такое Type и Code в ICMP?** ::A: Type — тип сообщения (echo request, unreachable и т.д.), Code — дополнительный код ошибки.  
**Q: Можно ли блокировать ICMP?** ::A: Да, через фаерволы, но это может помешать диагностике.
<!--SR:!2025-07-04,3,252-->

**Q: Что такое DHCP?** ::A: Протокол динамического получения IP-адреса и других параметров сети.
<!--SR:!2025-07-12,9,250-->
**Q: Как DHCP получает IP-адрес?** ::A: Через 4 шага: DISCOVER → OFFER → REQUEST → ACK.  
**Q: Какие порты использует DHCP?** ::A: UDP порты 67 (сервер) и 68 (клиент).  
**Q: Что такое DHCPv6?** ::A: Версия протокола для IPv6, работает поверх UDP и порта 546/547.
<!--SR:!2025-07-02,3,250-->
**Q: Что такое DORA в DHCP?** ::A: Аббревиатура: Discover, Offer, Request, Acknowledgement.

**Q: Что такое Cookie Jar?** ::A: Контейнер в браузере, хранящий все cookies для доменов.
