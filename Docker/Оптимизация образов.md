
### **Как уменьшить количество слоёв и оптимизировать Dockerfile**  
Чем меньше слоёв — тем быстрее сборка, меньше размер образа и эффективнее кеширование. Вот **практические правила**:

---

## **1. Объединяй команды в один `RUN`**  
Каждый `RUN` создаёт новый слой. Вместо:  
```dockerfile
RUN apt update
RUN apt install -y curl
RUN rm -rf /var/lib/apt/lists/*
```  
**Делай так**:  
```dockerfile
RUN apt update && \
    apt install -y curl && \
    rm -rf /var/lib/apt/lists/*
```  
**Почему**:  
- 1 слой вместо 3.  
- Удаление кеша (`rm -rf`) в том же слое, где он создан (не увеличивает размер образа).  

---

## **2. Сортируй команды по частоте изменений**  
**Порядок в Dockerfile**:  
1. **Редко меняющиеся** (база, установка пакетов).  
2. **Часто меняющиеся** (код, конфиги).  

**Пример**:  
```dockerfile
FROM python:3.9-slim

# 1. Установка зависимостей (кешируется, пока не меняется requirements.txt)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 2. Копирование кода (часто меняется → идёт последним)
COPY . .
```  
**Почему**:  
- Если изменился только код (`COPY . .`), Docker использует кеш до этого шага.  

---

## **3. Используй `.dockerignore`**  
Исключи ненужные файлы (`.git`, `__pycache__`, `node_modules`):  
```text
.git
__pycache__
*.log
Dockerfile
```  
**Почему**:  
- Уменьшит размер контекста сборки (и время `COPY`).  

---

## **4. Многоступенчатая сборка (`multi-stage`)**  
Для языков с компиляцией (Go, Rust) или минимизации размера:  
```dockerfile
# Этап 1: Сборка
FROM golang:1.18 as builder
WORKDIR /app
COPY . .
RUN go build -o myapp .

# Этап 2: Финальный образ (только бинарник)
FROM alpine:latest
COPY --from=builder /app/myapp /usr/local/bin/
CMD ["myapp"]
```  
**Почему**:  
- В финальном образе только бинарник (без компилятора и исходников).  

---

## **5. Чисти мусор в том же слое**  
Удаляй временные файлы **в том же `RUN`**, где они созданы:  
```dockerfile
RUN wget https://example.com/bigfile.tar.gz && \
    tar -xzf bigfile.tar.gz && \
    rm bigfile.tar.gz  # Удалили в том же слое!
```  

---

## **6. Используй официальные легковесные образы**  
Выбирай базовые образы с `-slim` или `-alpine`:  
```dockerfile
FROM python:3.9-slim  # (~120 МБ) вместо python:3.9 (~900 МБ)
```  

---

## **7. Оптимизация `COPY`**  
Копируй только нужное:  
```dockerfile
COPY package.json package-lock.json ./
RUN npm install
COPY src/ ./src  # Остальное позже
```  

---

## **8. Переменные окружения (`ENV`) и точки входа (`CMD`) — в конец**  
```dockerfile
# ... остальные команды
ENV NODE_ENV=production
CMD ["node", "app.js"]
```  
**Почему**:  
- Изменение `ENV` или `CMD` не инвалидирует кеш слоёв выше.  

---

### **Итоговая схема оптимизированного Dockerfile**  
```dockerfile
# 1. Базовый образ
FROM python:3.9-slim

# 2. Редко меняющиеся зависимости
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 3. Код (часто меняется)
COPY . .

# 4. Метаданные
ENV PYTHONUNBUFFERED=1
CMD ["python", "app.py"]
```  

---

### **Проверь размер слоёв**  
Инструменты для анализа:  
```bash
docker history <image>  # Показывает размер каждого слоя
dive <image>           # Интерактивный анализ
```  

**Главное правило**:  
> «Чем меньше слоёв — тем лучше. Но иногда читаемость важнее микрооптимизаций».  

Оптимизированный Dockerfile ускорит сборку в CI/CD и сэкономит место на диске! 🚀
