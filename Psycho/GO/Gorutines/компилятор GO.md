## **2. Архитектура и процесс компиляции Go**

### **2.1. Этапы работы компилятора Go**

1. **Лексический анализ (Lexical Analysis):**
    
    - Входной код разбивается на токены (слова: `if`, `func`, `for`, `:=` и т.д.).
    - Используется встроенный лексер (находится в пакете `go/scanner`).
2. **Синтаксический анализ (Parsing):**
    
    - Токены преобразуются в абстрактное синтаксическое дерево (AST).
    - Используется пакет `go/parser`.
    - Пример AST:
        
        ```plaintext
        func add(x int, y int) int {
            return x + y
        }
        ```
        
        Дерево:
        
        ```
        Function:
          Name: add
          Params: [x:int, y:int]
          ReturnType: int
          Body:
            Return: x + y
        ```
        
3. **Анализ типов (Type Checking):**
    
    - Выполняется проверка, соответствуют ли переменные и функции их типам.
    - Пакет: `go/types`.
4. **Генерация промежуточного представления (IR):**
    
    - Программа преобразуется в оптимизированный "псевдокод".
    - Пример IR:
        
        ```plaintext
        LOAD R1, x
        LOAD R2, y
        ADD R3, R1, R2
        RETURN R3
        ```
        
5. **Оптимизация:**
    
    - Упрощение выражений, устранение лишних переменных, инлайн-функции и т.д.
6. **Генерация машинного кода:**
    
    - IR преобразуется в команды для целевой платформы (x86, ARM и др.).

---

### **2.2. Промежуточное представление (IR)**

#### **Что это такое?**

IR — это низкоуровневое представление кода, которое используется для анализа и оптимизации. Оно проще и ближе к машинному коду, чем исходный код.

#### **Особенности IR в Go:**

1. Линеаризованный код: упрощённая форма с использованием трёхадресной нотации.
2. Пример IR для `x = a + b * c`:
    
    ```plaintext
    T1 = b * c
    x = a + T1
    ```
    

---

### **2.3. Поддержка многопоточности на уровне компилятора**

Go имеет встроенную поддержку горутин и канальных операций, которые управляются не операционной системой, а **планировщиком Go (Go Scheduler)**.

#### **Как это связано с компилятором?**

1. **Планировщик (Goroutine Scheduler):**
    
    - Компилятор внедряет вызовы к планировщику в ключевых точках (например, при ожидании в канале).
    - IR включает инструкции для работы с горутинами:
        
        ```plaintext
        CALL runtime.newproc
        CALL runtime.gopark
        ```
        
2. **Конкурентные структуры:**
    
    - Каналы (`chan`) и мьютексы (`sync.Mutex`) реализуются через встроенные библиотеки, оптимизированные на уровне компилятора.
3. **Preemption (Прерывание):**
    
    - Компилятор вставляет точки прерывания для безопасной остановки горутин.

## **3. Оптимизации компилятора Go**

### **3.1. Основные оптимизации**

1. **Inlining:**
    
    - Маленькие функции вставляются прямо в вызывающий код.
    - Пример:
        
        ```go
        func add(x, y int) int {
            return x + y
        }
        ```
        
        После инлайнинга:
        
        ```plaintext
        R1 = x + y
        RETURN R1
        ```
        
2. **Escape Analysis:**
    
    - Определяет, должна ли переменная находиться в стеке или в куче.
    - Пример:
        
        ```go
        func foo() *int {
            x := 42
            return &x // Escape в кучу
        }
        ```
        
3. **Dead Code Elimination:**
    
    - Удаление неиспользуемого кода.
    - Пример:
        
        ```go
        func unused() int {
            return 42
        }
        ```
        
        Если `unused()` не вызывается, она будет удалена.
4. **Loop Unrolling:**
    
    - Упрощение циклов для повышения производительности.
    - Пример:
        
        ```go
        for i := 0; i < 4; i++ {
            process(i)
        }
        ```
        
        После оптимизации:
        
        ```plaintext
        process(0)
        process(1)
        process(2)
        process(3)
        ```
