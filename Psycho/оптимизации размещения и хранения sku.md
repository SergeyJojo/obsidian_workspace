
Отличный и практический вопрос. Как разработчику, тебе нужно понимать **основные метрики, задачи и алгоритмы**, стоящие за оптимизацией размещения и перемещения товаров в WMS (Warehouse Management System).

---

## 📦 Что такое фрагментация на складе?

**Фрагментация** — это ситуация, когда:

- одинаковые или близкие по назначению товары разбросаны по разным частям склада,
    
- полки заняты неэффективно,
    
- перемещения сборщика занимают много времени.
    

Примеры:

- В одной ячейке 2 коробки из 10 возможных.
    
- Один SKU в 7 разных местах.
    
- Частые «пустые» проходы сборщика.
    

---

## 🔧 Цель: как разработчик может решить проблему

### 🔹 1. **Оптимизация размещения (slotting)**

#### ✅ Что делаем:

- Алгоритм подбирает **оптимальную ячейку** для размещения товара:
    
    - ближе к зоне отгрузки — для ходовых SKU,
        
    - рядом с часто покупаемыми товарами — для совместной сборки,
        
    - с учётом ограничений по весу/объёму/совместимости.
        

#### 💻 Как реализовать:

- Сбор статистики: частота заказов, объем, вес, путь сборки.
    
- Кластеризация: какие товары часто покупаются вместе?
    
- Расчёт **heat map склада** (навигационная карта загрузки).
    
- Простое эвристическое решение:
    
    ```go
    type Slot struct {
        DistanceToPackingZone int
        AvailableVolume       float64
        GroupingScore         float64
    }
    
    func rankSlots(slots []Slot) []Slot {
        sort.Slice(slots, func(i, j int) bool {
            return slots[i].DistanceToPackingZone + slots[i].GroupingScore < 
                   slots[j].DistanceToPackingZone + slots[j].GroupingScore
        })
        return slots
    }
    ```
    

---

### 🔹 2. **Маршруты сборки (picking path optimization)**

#### ✅ Что делаем:

- Строим кратчайший путь между ячейками, где лежат нужные товары.
    
- Выбираем наиболее выгодный маршрут с учётом типа склада (одно- или двухсторонний проход, зоны, препятствия и т.д.).
    

#### 📐 Алгоритмы:

- Классика: **TSP (Travelling Salesman Problem)**.
    
- Упрощение: **жадный алгоритм** (сначала к ближайшей ячейке).
    
- Более умно: **A* или Dijkstra** по ячейкам с весами.
    

---

### 🔹 3. **Динамическое перепрофилирование ячеек**

#### ✅ Что делаем:

- Отслеживаем загрузку зон: если зона перегружена, часть товара перемещаем в менее загруженную.
    
- Автоматически создаём задания на перемещение.
    

#### 💻 Пример кейса:

```go
if zoneA.LoadFactor > 0.9 && zoneB.LoadFactor < 0.5 {
    createMoveTask(from: zoneA.hotSKU, to: zoneB.emptySlots)
}
```

---

### 🔹 4. **Уменьшение фрагментации**

#### ✅ Что делаем:

- Анализируем SKU, разбросанные по многим ячейкам (например, 1 SKU в 8 местах).
    
- Планируем слияние партий при поступлении новых поставок.
    
- Оптимизируем **пополнение зон** из резервных ячеек (replenishment).
    

#### Метрика:

- Кол-во SKU / кол-во ячеек с этим SKU = **степень фрагментации**
    
- Цель — минимизировать это значение.
    

---

### 🔹 5. **Использование ML (если продвинутый уровень)**

- Модель предсказывает, где будет оптимально разместить SKU на следующей неделе.
    
- Обучается на истории перемещений, продаж, сезонности.
    

Пример (в идее, не коде):

```python
input_features = [sku_sales_speed, co_purchased_skus, slot_distance]
model.predict_optimal_slot(input_features)
```
