## **1. Внутреннее устройство планировщика Go**

### **1.1. Основные структуры данных**

Планировщик Go использует несколько ключевых структур для управления выполнением горутин:

1. **G (goroutine):**
    
    - Представляет горутину.
    - Основные поля:
        
        ```go
        type g struct {
            stack     stack    // Указатель на стек
            sched     gobuf    // Регистры и PC для восстановления контекста
            status    uint32   // Статус горутины (например, runnable, waiting)
            waitreason string  // Причина блокировки (если есть)
        }
        ```
        
2. **P (Processor):**
    
    - Логический процессор для выполнения горутин.
    - Основные поля:
        
        ```go
        type p struct {
            runq      [256]g    // Очередь локальных горутин
            runqhead  uint32    // Указатель на начало очереди
            runqtail  uint32    // Указатель на конец очереди
            m         *m        // Связанный поток
        }
        ```
        
3. **M (Machine):**
    
    - Поток ОС, который выполняет горутины.
    - Основные поля:
        
        ```go
        type m struct {
            g0        *g        // Горутина для выполнения системных вызовов
            curg      *g        // Текущая горутина
            p         *p        // Привязанный процессор
            nextp     *p        // Следующий процессор для выполнения
        }
        ```
        

---

### **1.2. Жизненный цикл горутины**

Горутина (`g`) проходит через несколько состояний:

1. **Gidle:** Горутина ещё не запущена.
2. **Grunnable:** Горутина готова к выполнению.
3. **Grunning:** Горутина исполняется.
4. **Gwaiting:** Горутина ждёт выполнения (например, I/O, `select`).
5. **Gdead:** Горутина завершила выполнение.

---

### **1.3. Как происходит планирование**

1. **Запуск новой горутины (`go func() {...}`):**
    
    - Горутина добавляется в очередь `runq` связанного P.
    - Если очередь P переполнена, горутина перемещается в глобальную очередь.
2. **Выбор следующей горутины:**
    
    - Сначала планировщик выбирает горутину из локальной очереди P.
    - Если локальная очередь пуста, P "крадёт" горутину из другого P или глобальной очереди.
3. **Выполнение горутины:**
    
    - Поток M выполняет выбранную горутину.
    - Если горутина блокируется (например, ожидает I/O), поток переключается на другую горутину.

## **2. Netpoll и асинхронный I/O**

Netpoll — это механизм асинхронного ввода-вывода в Go, который позволяет эффективно обрабатывать сетевые соединения и файлы. Он интегрирован в планировщик.

### **2.1. Как работает Netpoll**

1. Планировщик регистрирует файловый дескриптор в системе через **epoll** (Linux), **kqueue** (macOS) или **IOCP** (Windows).
2. Если горутина блокируется на I/O, её статус меняется на `Gwaiting`.
3. Когда дескриптор становится готовым, Netpoll уведомляет планировщик, который переводит горутину обратно в состояние `Grunnable`.

---

### **2.2. Код Netpoll**

Основные функции:

- **`netpollinit`:** Инициализация Netpoll.
- **`netpollblock`:** Блокировка горутины до готовности дескриптора.
- **`netpollunblock`:** Разблокировка горутины.

Пример кода (упрощённый):

```go
func netpollblock(fd int, mode int, timeout int64) *g {
    g := getg()        // Получаем текущую горутину
    g.waitreason = "network"
    netpollregister(fd, mode)
    goparkunlock(&g.lock, "network", traceEvGoBlockNet)
    return g
}
```

## **3. Прерывания (Preemption)**

Прерывание (preemption) — это механизм, позволяющий планировщику приостанавливать долгоживущие горутины.

### **3.1. Как работает прерывание**

1. Компилятор Go вставляет точки прерывания (preemption points) в код, где можно безопасно остановить горутину.
2. Если горутина работает слишком долго, планировщик вызывает функцию прерывания:
    - `runtime.preemptone`.

---

### **3.2. Код для прерывания**

Пример точки прерывания:

```go
CALL runtime.gopreempt
```

Когда планировщик вызывает `gopreempt`, состояние горутины сохраняется, и управление передаётся следующей.

## **4. Производительность**

### **4.1. Минимизация накладных расходов**

- Управление стеками и горутинами происходит на уровне пользовательского пространства.
- Планировщик Go минимизирует системные вызовы.

### **4.2. Оптимизация очередей**

1. Локальные очереди `P` уменьшают конкуренцию между потоками.
2. Воровство работы (work stealing) позволяет эффективно использовать все процессоры.

## **5. Код создания горутины**

Когда вы пишете `go func()`, происходит следующее:

1. Горутина создаётся с минимальным стеком (2 КБ).
2. Её состояние (`g`) сохраняется в памяти.
3. Горутина добавляется в очередь `P`.

Код создания горутины (упрощённый):

```go
func newproc(size int32, fn *funcval) {
    g := acquireg()           // Создание новой горутины
    g.fn = fn                 // Сохранение функции
    g.stack = allocstack()    // Выделение стека
    injectg(g)                // Добавление в очередь P
}
```

## **1. Как Go Scheduler управляет нагрузкой**

Go Scheduler — это **асимметричный планировщик**, который стремится минимизировать затраты на переключение контекста и эффективно распределить задачи по доступным процессорам.

### **1.1. Основные этапы планирования**

1. **Создание горутины:**
    
    - Горутина добавляется в локальную очередь `P` (Processor).
    - Если локальная очередь заполнена, горутина перемещается в глобальную очередь.
2. **Исполнение горутин:**
    
    - Поток `M` вытягивает горутину из `P` для выполнения.
    - Если `M` не привязано к `P`, оно пытается найти свободный `P`.
3. **Блокировка горутин:**
    
    - Если горутина блокируется (например, ожидает I/O), `M` освобождается для выполнения других горутин.
4. **Work Stealing:**
    
    - Если `P` пуст, оно "крадёт" горутины из других `P` или глобальной очереди.

---

### **1.2. Очереди задач**

1. **Локальная очередь `runq`:**
    
    - Каждый `P` имеет локальную очередь горутин.
    - При добавлении новых горутин в очередь используется структура **кольцевого буфера** (ring buffer).
2. **Глобальная очередь:**
    
    - Если локальная очередь переполнена, горутины добавляются в глобальную очередь.
    - Глобальная очередь используется, если локальная пуста.

#### **Алгоритм выбора горутин:**

1. Сначала проверяется локальная очередь.
2. Если локальная очередь пуста, планировщик ищет горутины в глобальной очереди.
3. Если глобальная очередь пуста, выполняется "воровство работы" из другой `P`.

---

### **1.3. Алгоритм Work Stealing**

Go Scheduler реализует "воровство работы", чтобы распределять нагрузку:

1. Каждый `P` периодически проверяет локальные очереди других `P`.
2. Если в другой очереди есть задачи, `P` забирает половину задач.

**Преимущество:**

- Это позволяет эффективно использовать ресурсы процессора, минимизируя простои.

---

## **2. Управление памятью горутин**

### **2.1. Выделение стека**

- Новый стек горутины имеет размер 2 КБ.
- Если требуется больше памяти, стек динамически увеличивается вдвое:
    - 2 КБ → 4 КБ → 8 КБ и т.д.

### **2.2. Оптимизация копирования стека**

- При увеличении стека используется линейное копирование.
- Пустое пространство в стеке минимизируется с помощью механизма "сжатия".

### **2.3. Управление памятью планировщика**

- Горутине требуется минимальная память для хранения:
    - Регистров.
    - Указателя на стек.
    - Полей структуры `g`.

---

## **3. Системные вызовы и их влияние**

Системные вызовы (например, чтение файла, сетевой ввод-вывод) могут заблокировать выполнение потока `M`. Чтобы избежать простоя:

1. **Блокирующие вызовы:**
    
    - Горутина, выполняющая системный вызов, приостанавливается.
    - Планировщик выделяет другой поток `M` для выполнения оставшихся горутин.
2. **Асинхронный ввод-вывод:**
    
    - Используется Netpoll для асинхронного управления файлами и сокетами.
    - Когда дескриптор становится готовым, горутина разблокируется.

## **4. Точки прерывания (Preemption Points)**

Прерывания (preemption) — важный механизм для предотвращения "залипания" долгоживущих горутин.

### **4.1. Как это работает?**

1. Компилятор Go вставляет точки проверки (safepoints) в код:
    
    - В местах вызова функций.
    - Внутри циклов.
2. Если горутина работает слишком долго, планировщик вызывает прерывание:
    
    ```plaintext
    CALL runtime.gopreempt
    ```
    
3. Горутина сохраняет своё состояние и передаёт управление следующей.
    

---

### **4.2. Пример реализации в Go Runtime**

Код прерывания горутины:

```go
func gopreempt_m(gp *g) {
    if gp.preempt {
        // Сохранение состояния
        saveState(gp)
        // Возврат в планировщик
        schedule()
    }
}
```

## **5. Балансировка потоков**

### **5.1. Проблема:**

- Количество потоков `M` может быть больше, чем процессоров `P`.
- Лишние потоки вызывают накладные расходы.

### **5.2. Решение:**

- Go Scheduler ограничивает количество потоков на основе `GOMAXPROCS`.
- Если поток не может получить `P`, он переходит в состояние ожидания.

---

## **6. Производительность переключения горутин**

### **6.1. Минимизация накладных расходов**

- Для переключения горутин требуется:
    
    1. Сохранение регистров.
    2. Изменение указателя стека.
    3. Обновление программного счётчика (PC).
- Время переключения горутины: **~50-100 наносекунд**.
    
- Время переключения потока: **~10 микросекунд** (в 100 раз медленнее).
    

---

## **7. Глубокая оптимизация планировщика**

### **7.1. Планировщик "на лету"**

- Планировщик не использует глобальную блокировку (global lock), что улучшает масштабируемость.
- Каждая `P` действует независимо.

### **7.2. Оптимизация lock-free структур**

1. Очереди задач (`runq`) реализованы как кольцевые буферы.
2. Для минимизации конфликтов используется атомарное обновление указателей.

## **8. Кодовые примеры**

### **8.1. Создание горутины**

Когда вы вызываете `go func() {...}`, происходит следующее:

1. Горутина создаётся:
    
    ```go
    g := new(g)
    g.fn = function
    g.stack = allocStack()
    ```
    
2. Горутина добавляется в очередь:
    
    ```go
    runqput(p, g)
    ```
    
3. Поток `M` выбирает горутину для выполнения:
    
    ```go
    g := runqget(p)
    ```
    

---

### **8.2. Прерывание горутины**

Если горутина работает слишком долго:

1. Планировщик вызывает `runtime.gopreempt`.
2. Горутина приостанавливается:
    
    ```go
    func gopreempt() {
        saveState()
        schedule()
    }
    ```
