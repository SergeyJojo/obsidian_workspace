
Docker — это инструмент для контейнеризации, который позволяет запускать приложения в изолированных контейнерах. Контейнеры используют ресурсы хостовой операционной системы, но при этом изолированы друг от друга. Docker предоставляет удобный способ упаковки, распространения и запуска приложений.

Внутреннее устройство Docker включает в себя несколько компонентов:

### 1. **Docker Engine**

Docker Engine — это основная часть Docker, которая состоит из нескольких компонентов:

#### a) **Docker Daemon (dockerd)**

- Это серверная часть Docker, которая работает в фоновом режиме.
- Docker Daemon отвечает за управление контейнерами, их создание, выполнение, остановку и удаление.
- Он также управляет образами, сборкой образов и взаимодействует с Docker Registry.
- Docker Daemon обрабатывает запросы от Docker CLI и API.

#### b) **Docker Client (docker)**

- Это интерфейс командной строки (CLI), с помощью которого пользователи взаимодействуют с Docker Daemon.
- Команды, введенные в терминале (например, `docker run` или `docker ps`), отправляются через Docker Client на Docker Daemon для выполнения.

#### c) **Docker API**

- Docker Daemon предоставляет REST API, с помощью которого можно программно взаимодействовать с Docker. Это позволяет интегрировать Docker с другими системами.

### 2. **Docker Images**

- **Docker Images** — это шаблоны или слои файловой системы, которые используют контейнеры для их создания. Образы содержат все необходимые компоненты для запуска приложения, такие как зависимости, библиотеки и сам код.
- Изображения создаются с помощью Dockerfile — специального файла, который описывает процесс сборки образа.

### 3. **Docker Containers**

- **Контейнеры** — это изолированные экземпляры Docker Images, которые выполняются на хостовой системе.
- Контейнеры используют те же ядро и систему ресурсов хостовой ОС, но они изолированы от других процессов в системе. Это позволяет им работать как отдельные, независимые экземпляры.
- Контейнеры создаются, запускаются, останавливаются и удаляются с помощью Docker CLI или API.

### 4. **Union File System (UFS)**

Docker использует файловую систему, основанную на концепции Union File Systems (UFS). Она позволяет слоям файловой системы объединяться, создавая виртуальные файловые системы, которые выглядят как единый слой.

- Каждый слой — это изменение в файловой системе.
- Когда контейнер запускается, Docker использует образ и накладывает на него изменения в виде нового слоя, что позволяет экономить место и повторно использовать слои.

### 5. **Namespaces**

Docker использует механизмы изоляции операционной системы, такие как **Linux namespaces**, для обеспечения изоляции контейнеров:

- **PID namespace** — каждый контейнер имеет свой собственный процессный идентификатор (PID), и процессы внутри контейнера не видят процессы за пределами контейнера.
- **Network namespace** — каждый контейнер имеет свою сетевую конфигурацию, включая IP-адрес и порты, которые не пересекаются с другими контейнерами или хостовой системой.
- **Mount namespace** — позволяет контейнерам монтировать свои собственные файловые системы (например, для работы с томами).
- **UTS namespace** — позволяет контейнерам изменять имя хоста и доменное имя.

### 6. **Control Groups (cgroups)**

Docker использует **cgroups (Control Groups)** для управления и ограничения ресурсов, таких как CPU, память, диск и сети, для каждого контейнера:

- cgroups позволяют ограничивать количество процессорного времени, которое контейнер может использовать, и память, которую контейнер может потреблять.
- Это позволяет гарантировать, что контейнеры не будут злоупотреблять системными ресурсами и нарушать работу других контейнеров или хоста.

### 7. **Docker Networking**

Docker предоставляет несколько типов сетевых режимов для контейнеров:

- **bridge** — стандартная сеть для контейнеров, которая используется по умолчанию. Она создает виртуальный мост, к которому подключаются контейнеры.
- **host** — контейнеры используют хостовую сеть напрямую, без изоляции.
- **overlay** — используется для связи контейнеров между различными хостами в кластере Docker (например, с использованием Docker Swarm).
- **none** — контейнеры не получают доступ к сети.

### 8. **Docker Volumes**

Контейнеры обычно не сохраняют данные между запусками, так как они являются временными и могут быть удалены. Для хранения данных Docker использует **Volumes**:

- **Volumes** — это специальная область для хранения данных, которая сохраняется даже после удаления контейнера.
- Они могут быть смонтированы в один или несколько контейнеров.

### 9. **Docker Registry**

Docker Registry — это сервис для хранения и распространения Docker образов. **Docker Hub** — это публичный Docker Registry, в котором хранятся образы с открытым исходным кодом, а также образы, созданные пользователями. Пользователи могут также настроить свой собственный приватный Docker Registry.

### 10. **Docker Compose**

**Docker Compose** — это инструмент для определения и запуска многоконтейнерных Docker приложений. С помощью Docker Compose можно определить сервисы, сети и тома в одном файле `docker-compose.yml`, что позволяет запускать и управлять несколькими контейнерами как единым приложением.

### Заключение

Docker предоставляет мощные возможности для контейнеризации, благодаря использованию механизмов операционной системы, таких как namespaces и cgroups. Он решает задачи изоляции, управления ресурсами и облегчает процесс разработки и развертывания приложений.
