### Задача 1: "Дернуть N урлов с лимитом K активных запросов"

В данном случае задача состоит в том, чтобы выполнить запросы к нескольким URL с ограничением на количество активных запросов в один момент времени.

Мы будем использовать горутины для параллельного выполнения запросов, а для ограничения числа активных запросов используем **семафор** (с помощью канала). Также для синхронизации данных мы используем `sync.WaitGroup` и `sync.Mutex` для защиты от гонок.

Вот пример решения:

```go
package main

import (
	"net/http"
	"sync"
)

func callRequestsForURLs(urls []string, K int) []*http.Response {
	var wg sync.WaitGroup
	var mu sync.Mutex
	var responses []*http.Response

	// Канал с буфером для ограничения количества активных запросов
	sem := make(chan struct{}, K)

	for i, url := range urls {
		wg.Add(1)
		go func(i int, url string) {
			defer wg.Done()

			// Запрос к урлу
			sem <- struct{}{} // Добавляем элемент в канал для ограничения активных запросов
			resp, err := http.Get(url)
			<-sem // Освобождаем канал после запроса

			// Синхронизация для безопасного добавления в массив ответов
			mu.Lock()
			if err != nil {
				responses = append(responses, nil)
			} else {
				responses = append(responses, resp)
			}
			mu.Unlock()
		}(i, url)
	}

	wg.Wait()

	return responses
}
```

### Объяснение:

1. **Канал `sem`** с буфером размером `K` используется для ограничения числа одновременных запросов. Когда канал заполняется (при каждом запросе), дальнейшие горутины блокируются до тех пор, пока в канале не освободится место.
    
2. **Горутины** выполняют запросы к каждому URL. Для каждого запроса создается отдельная горутина, и запрос выполняется с помощью `http.Get`.
    
3. **Синхронизация с помощью `sync.WaitGroup`** позволяет дождаться завершения всех горутин.
    
4. **`sync.Mutex`** используется для синхронизации записи в массив `responses`, чтобы избежать гонок при добавлении новых элементов в массив.
    

### Задача 2: "Найти элемент по индексу с конца в связном списке"

Задача состоит в том, чтобы получить элемент по индексу с конца списка. Мы будем использовать два подхода:

1. Пройти список один раз, чтобы вычислить его длину, и затем пройти его еще раз для нахождения нужного элемента.
2. Или можно использовать два указателя (slow и fast) для того, чтобы вычислить элемент с конца за один проход.

Вот решение с вычислением длины:

```go
package main

import "fmt"

type Item struct {
	value int
	next  *Item
}

func main() {
	// Создаем список
	head := &Item{65, &Item{19, &Item{17, &Item{50, &Item{55, &Item{21, &Item{4, nil}}}}}}}

	fmt.Println(ItemFromEnd(0, head)) // 4
	fmt.Println(ItemFromEnd(1, head)) // 21
	fmt.Println(ItemFromEnd(3, head)) // 50
	fmt.Println(ItemFromEnd(6, head)) // 65
	fmt.Println(ItemFromEnd(9, head)) // nil
}

// ItemFromEnd возвращает элемент по индексу с конца
func ItemFromEnd(k int, head *Item) interface{} {
	// Сначала находим длину списка
	length := 0
	current := head
	for current != nil {
		length++
		current = current.next
	}

	// Если k больше длины списка, возвращаем nil
	if k >= length {
		return nil
	}

	// Преобразуем k в индекс с начала
	indexFromStart := length - k - 1
	current = head
	// Проходим по списку до нужного элемента
	for i := 0; i < indexFromStart; i++ {
		current = current.next
	}

	return current.value
}
```

### Объяснение:

1. Мы сначала вычисляем длину списка. Проходим по всем элементам списка, увеличивая переменную `length`.
    
2. Если `k` больше или равно длине списка, то возвращаем `nil`, так как элемент с таким индексом не существует.
    
3. После этого вычисляем индекс элемента с начала, используя `length - k - 1`.
    
4. Проходим по списку до нужного индекса и возвращаем значение элемента.
    

### Заключение:

- **Задача с запросами**: использует горутины и каналы для параллельной обработки запросов с ограничением на количество активных запросов одновременно.
- **Задача с элементом из конца списка**: решается либо с помощью вычисления длины списка, либо с использованием двух указателей для оптимизации.
